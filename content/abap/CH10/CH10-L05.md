## 전역에 있는 도구 불러 쓰기

[[Subroutine]]은 그 프로그램 안에서만 살았다. [[Function Module]]처럼 **전역에서
공유**되는 OO 버전이 [[Global Class]](전역 클래스, `SE24`의 `ZCL_...`)다. SAP이 기본으로
제공하는 것도 있고 동료가 만들어 둔 것도 있으니, 새로 만들기 전에 **이미 있는 것을
찾아 쓰는** 게 먼저다.

## 정적 메서드를 `=>`로 호출 — [선행 사용]

> 🔎 **[선행 사용]** 클래스를 *직접 설계*하는 법은 [Chapter 21 · OO 기초](CH21-L01.html)에서 배운다. 여기서는 이미
> 만들어진 클래스의 메서드를 **블랙박스처럼 불러 쓰기**만 한다(분석·암기 불필요).

객체를 만들지 않아도 되는 **정적 메서드**는 "클래스`=>`메서드"로 부른다.

```abap
DATA gv_text TYPE string.

gv_text = zcl_util=>format_amount( 1000 ).   " 전역 클래스의 정적 메서드
WRITE gv_text.
```

파라미터가 여러 개면 이름을 붙여 넘긴다.

```abap
DATA gv_r TYPE i.

zcl_util=>calc( EXPORTING iv_a = 1 iv_b = 2
                IMPORTING ev_r = gv_r ).
```

여기 `EXPORTING`·`IMPORTING`은 [CALL FUNCTION 기본 구조](CH10-L03.html)에서 본 것과 같은
**호출자 기준**이다. 내가 넘기는 값이 `EXPORTING`, 내가 돌려받는 값이 `IMPORTING`이다.
[Local Class로 모듈화](CH10-L04.html)에서 메서드를 *정의*할 때는 `IMPORTING`이 "받는 값"이었으니
방향이 반대로 보이는데, 한쪽이 내보내면 다른 쪽이 받는 것이라 그렇다. 돌려받는 자리의
`ev_`는 메서드가 내보내는(export) 값에 붙이는 접두어다.

상태를 가진 **객체**가 필요한 메서드는 객체를 만들어 `->`로 부르지만, 그건 본격 OO
단계의 이야기다. 지금은 "정적이면 `=>`로 바로 부른다"만 기억하면 된다.

## 표준 클래스도 많다

`CL_`로 시작하는 SAP 표준 [[Class]]가 풍부하다. 예를 들어 데이터를 표로 보여 주는
[[ALV]](ABAP List Viewer)의 `CL_SALV_TABLE`이 그렇다([Chapter 11 · SALV 1차](CH11-L01.html)).
이런 클래스는 보통 **정적 팩토리 메서드**로 시작한다. 객체를 우리가 직접 만드는 대신,
필요한 객체를 만들어 돌려주는 정적 메서드를 클래스가 하나 마련해 두는 방식이다. 지금은
이런 이름이 있다는 정도만 알면 되고, 실제 사용법은 그 챕터에서 처음부터 안내한다.

## 직접 해 보기

이미 만들어진 전역 클래스를 내부 구현을 모른 채 계약(IMPORTING/RETURNING)만 보고 호출해 보자. 필수 파라미터를 빼면 어떻게 되는지도 확인해 보자.

## 흔한 실수와 점검

- **필수 파라미터 누락** → 계약에 있는 입력을 빼면 호출이 막힌다.
- **이름을 짐작해서 쓰기** → `SE24`에서 클래스를 열어 메서드 이름과 계약을 확인하고 쓴다.
