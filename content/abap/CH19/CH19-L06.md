## 메모리 테이블도 SQL로 🧠

modern SQL은 DB 테이블뿐 아니라 **Internal Table**(메모리에 있는 표)도 소스로 조회할 수 있다. 이미 가져온 데이터를, DB를 다시 읽지 않고 **SQL 문법(필터·정렬·집계)으로 재가공**할 때 편하다.

먼저 Internal Table을 하나 만들고, 조회 조건에 쓸 변수도 선언한다(지금까지 배운 `TYPES`·`VALUE`).

```abap
TYPES: BEGIN OF ts_flight,
         carrid   TYPE sflight-carrid,
         connid   TYPE sflight-connid,
         seatsocc TYPE sflight-seatsocc,
       END OF ts_flight.
TYPES tt_flight TYPE STANDARD TABLE OF ts_flight WITH EMPTY KEY.

DATA(lt_flight) = VALUE tt_flight(
  ( carrid = 'LH' connid = '0400' seatsocc = 120 )
  ( carrid = 'LH' connid = '0401' seatsocc = 80  )
  ( carrid = 'AA' connid = '0017' seatsocc = 50  ) ).

DATA lv_carr TYPE sflight-carrid VALUE 'LH'.
```

이제 이 Internal Table을 **SQL 소스**로 조회한다.

```abap
SELECT f~carrid, f~connid, f~seatsocc
  FROM @lt_flight AS f          " 내부 테이블이 소스
  WHERE f~carrid = @lv_carr
  ORDER BY f~connid
  INTO TABLE @DATA(lt_filtered).
```

- `FROM @lt_flight` — 메모리의 Internal Table을 소스로 조회한다. 이런 조회는 보통 **ABAP 서버 안에서** 처리되지만, 항상 그런 것은 아니다(아래 🔧).
- `AS f` … `f~carrid` — Internal Table 소스에는 **`AS` 별칭(alias)이 필수**다. 별칭 덕에 출처도 분명해진다.

## 집계도 된다 ➕

[GROUP BY와 Aggregate](CH13-L03.html)에서 배운 `SUM`·`GROUP BY`를 그대로 쓴다.

```abap
SELECT f~carrid,
       SUM( f~seatsocc ) AS total_occ
  FROM @lt_flight AS f
  GROUP BY f~carrid
  INTO TABLE @DATA(lt_sum).
```

`carrid`별로 묶어 좌석을 합산한다(LH = 120 + 80 = 200). 같은 일을 ABAP에선 `LOOP`/`COLLECT`로 했지만, 여기선 SQL 한 문장이다.

## 언제 쓰나 · 언제 쓰지 말까 ⚖️

- **쓸 때**: 이미 가져온 데이터를 **다시 집계/정렬**하거나, 파일·인터페이스로 받은 데이터를 SQL식으로 다룰 때.
- **쓰지 말 때**: DB에 있는 **대량 데이터를 다 끌어와** 메모리에서 `SELECT FROM @itab`으로 집계하는 것. 보통 나쁜 방향이다. 가능하면 **DB에서 직접** 조건·집계를 처리한다.

> 🔧 **항상 메모리 안에서만 도는 건 아니다.** Internal Table을 소스로 쓰는 SELECT는 두 경우로 나뉜다. 문장의 모든 요소를 ABAP 서버의 SQL 엔진이 지원하면 **메모리 안에서** 처리하고, 이때는 DB 왕복이 없다. 하지만 DB 테이블과의 join처럼 엔진이 지원하지 못하는 요소가 섞이면 **표의 데이터를 임시로 DB에 보내서** 처리한다 — 표가 크면 그만큼 전송 비용이 든다. 그래서 이런 문장에는 시스템이 경고를 띄워 주기도 한다. 경고가 보이면 없앨 방법부터 찾지 말고, **내 데이터가 지금 DB로 가고 있는 건 아닌지**부터 확인하자.

## 흔한 실수와 점검 🚧

- **`@` 누락** → 소스 Internal Table도 ABAP 값이라 `@lt_flight`. `FROM lt_flight`는 안 된다.
- **별칭(alias) 생략** → `FROM @itab` 소스에는 `AS f` 같은 **별칭이 필수**다. 생략하면 오류.
- **DB 대용으로 남용** → 대량은 DB에서 직접. `@itab` SELECT는 **메모리 데이터 재가공용**.
- **컬럼이 하나뿐인(구조 없는) 표** → 그 한 컬럼의 이름이 `table_line`이라는 특수한 이름이 되어, `@DATA( )`로 받으려면 `AS`로 별칭을 줘야 한다. 이 레슨처럼 **구조(`TYPES BEGIN OF`)가 있는 표로 시작**하면 신경 쓸 일이 없다.
