## 결과 그릇을 미리 선언 안 해도 된다 🥣

[지난 챕터](CH18-L01.html)에서 배운 인라인 선언(`DATA( )`)을 SELECT 결과에도 쓴다. 단 SQL 문장 안이라 앞에 `@`가 붙어 **`@DATA( )`** 형태다.

```abap
" classic: 먼저 DATA로 선언한 뒤 SELECT
DATA lt_flight TYPE TABLE OF sflight.
SELECT * FROM sflight
  INTO TABLE lt_flight
  WHERE carrid = 'KE'.
```

```abap
" modern: 결과 타입을 SELECT가 알아서 만들어 준다
SELECT * FROM sflight
  WHERE carrid = 'KE'
  INTO TABLE @DATA(lt_flight).
```

`@DATA(lt_flight)`는 **SELECT 결과 구조에 맞는 Internal Table을 그 자리에서 자동 선언**한다. 이렇게 SELECT 결과를 받는 자리를 **target**(대상)이라고 부른다. 두 코드는 같은 일을 하는 별개의 예제다 — 한 프로그램 안에서 같은 이름을 두 번 선언하면 오류이니, 둘을 이어 붙여 실행하지는 말자.

## 무엇이 만들어지나 — 모양은 SELECT 목록이 정한다 🧱

`SELECT *`면 원본 테이블 행 구조에 가깝고, **컬럼을 고르면 그 컬럼만 가진** 행 구조가 만들어진다.

```abap
SELECT carrid, connid, seatsmax
  FROM sflight
  WHERE carrid = @lv_carr
  INTO TABLE @DATA(lt_flight).
" → lt_flight 한 행 = carrid · connid · seatsmax
```

> 📦 이렇게 만들어지는 표는 **Standard Table · Empty Key**(키가 비어 있는 기본 표 — 키로 빠르게 찾아 읽는 장치가 없다)다. 그래서 키로 자주 찾아 읽어야 하는 결과라면, 인라인 대신 **타입을 직접 선언**하고 알맞은 key를 주는 편이 낫다.

단건은 표가 아니라 **Structure**(구조체)로 받는다: `INTO @DATA( )`.

```abap
SELECT SINGLE carrid, carrname
  FROM scarr
  WHERE carrid = @lv_carr
  INTO @DATA(ls_carr).
" → ls_carr = carrid · carrname (구조체)
```

## 계산 컬럼엔 이름(`AS`)을 붙인다 🏷️

값을 계산해 컬럼으로 뽑을 땐 결과 컬럼에 **별칭(alias — `AS`로 붙이는 결과 컬럼의 이름)이 반드시 필요하다.** 여러 행을 받는 SELECT에서 계산식 컬럼에 별칭이 없으면, 인라인 target이 그 컬럼의 이름을 정할 수 없어 **구문 오류**다.

```abap
" 🚫 계산 컬럼에 이름이 없다 — 구문 오류(결과 컬럼의 이름을 정할 수 없음)
SELECT carrid,
       seatsmax - seatsocc
  FROM sflight
  INTO TABLE @DATA(lt_bad).

" ✅ AS 로 별칭을 준다
SELECT carrid,
       seatsmax - seatsocc AS seats_free
  FROM sflight
  INTO TABLE @DATA(lt_ok).
" → lt_ok 한 행 = carrid · seats_free
```

JOIN에서 같은 이름 컬럼이 겹칠 때도 마찬가지다. **컬럼 이름은 유일**해야 하니 `AS`로 풀어 준다.

## 흔한 실수와 점검 🚧

- **`@` 없이 `DATA( )`** → SQL 문장 안의 target은 `@DATA( )`. `DATA( )`는 SQL 밖 ABAP 문장용([Inline Declaration](CH18-L01.html)).
- **이미 선언된 이름에 `@DATA( )`** → `@DATA( )`는 **새 이름**일 때만. 기존 변수에 받으려면 `@lt_flight`처럼 **이름만** 쓴다.
- **계산·JOIN 컬럼에 별칭 없음** → 여러 행을 받는 인라인 target에선 **구문 오류**다. `AS`로 별칭을 붙인다.
- **`@FINAL( )`도 보인다** → [지난 챕터에서 배운 `FINAL( )`](CH18-L01.html)의 SQL판이다. 결과를 이후 바꾸지 않을 때 쓰지만, 시스템 릴리스에 따라 없을 수 있다. 입문 실습은 `@DATA( )`면 충분하다.
