## 가장 권장되는 확장 — BAdI

[Customer Exit](CH32-L01.html)·Enhancement Point는 *"표준 어디에 코드를 꽂나"* 가 초점이었다.
그런데 같은 시점이라도 **국가·회사코드·사업부별로 구현이 다를** 수 있고, 여러 구현을 켜고
끄거나 조건에 맞는 것만 골라야 한다. **[[BAdI]]**(Business Add-In)는 이걸 **객체지향**으로 푼다.

표준은 *"어떤 구현을 부를지"* 를 직접 모른다. 대신 **인터페이스(계약)** 의 메서드를 부르고,
고객이 그 인터페이스를 **구현**한다. [Interface 기본 설계](CH21-L05.html)에서 배운 인터페이스가
여기서 *표준–고객 사이의 계약*으로 산다.

> ℹ️ 예제 설정: 여기서는 **표준 예매 솔루션**이 이 BAdI를 제공한다고 가정한다. 확장점은
> 표준을 확장할 때 찾는 것이라, 우리가 직접 만든 Z 프로그램(콘서트 앱)이 아니라 "SAP가
> 만든 예매 표준"이 무대다.

```abap
" 표준 쪽: 구현을 직접 모르고 인터페이스만 호출
GET BADI lo_badi
  FILTERS country = lv_country.

CALL BADI lo_badi->check_booking
  EXPORTING is_booking = ls_booking.
```

고객은 그 인터페이스 메서드를 **구현**한다(`SE19`로 생성).

```abap
" 고객 구현 클래스: 인터페이스 메서드 구현
METHOD if_ex_booking_check~check_booking.
  IF is_booking-seats >= 8.
    " 고객 규칙: 대량 예매 추가 검증·메시지
  ENDIF.
ENDMETHOD.
```

- `SE18`(정의 조회)·`SE19`(구현 생성). 인터페이스 이름은 보통 `IF_EX_...` 꼴. BAdI 정의는
  **Enhancement Spot**(확장 지점을 묶어 관리하는 컨테이너) 안에 담겨 있다. `SE18`에서
  여는 게 바로 그것이다.
- **필터 BAdI** — `FILTERS`로 국가·회사코드 등 조건별 구현을 자동 선택.
- **multiple-use**는 여러 구현이 차례로, **single-use**는 하나만(빈 참조로 호출하면
  `cx_badi_initial_reference` 예외).
- **fallback 클래스** — 조건에 맞는 구현이 하나도 없을 때 대신 실행되는 **기본 구현**.
  정의에 fallback이 있으면 "구현이 없어서 아무 일도 안 일어나는" 상황 자체가 사라진다.

## 흔한 실수와 점검

- **정의(`SE18`)와 구현(`SE19`) 혼동** → 정의만 보고 "작동한다" 할 수 없고, 구현만 만들어도
  filter·activation이 안 맞으면 호출 안 된다.
- **filter를 가볍게** → filter는 부가 조건이 아니라 **구현 선택 조건**이다. 표준이
  `country='KR'`로 부르는데 구현 filter를 `US`로 두면 *로직이 완벽해도* 호출 안 된다.
- **multiple-use 순서·중복 무시** → 여러 구현이 같은 메시지를 더하면 결과가 중복된다. 구현은
  **멱등**하게, 같은 메시지 반복 방지 guard를 둔다.
- **BAdI에 화면·외부연동 직접** → BAdI는 표준 트랜잭션 중간에 실행된다. 느린 I/O·화면
  호출은 표준 전체를 불안정하게 한다. *짧게 호출·판단·반환*만, 복잡한 건 별도 서비스
  클래스로 분리한다.
- **BAdI 안에서 임의 `COMMIT WORK`** → 표준이 관리 중인 [SAP LUW](CH25-L03.html)를 중간에
  끊어 버린다(표준 트랜잭션 절반만 확정되는 최악의 사고). 커밋은 **표준의 몫**이다.

## 정리

- BAdI = 표준과 고객 구현 사이를 **인터페이스 계약**으로 분리하는 OO 확장.
- 표준은 `GET BADI`로 구현을 준비하고 `CALL BADI`로 메서드 호출, 고객은 `SE19` 구현 클래스로
  응답한다.
- Customer Exit보다 선호되는 이유 = **구조가 명확**(signature·filter·use 방식·activation으로
  관리).
