## 한 줄 한 줄 채우기 — 절차가 의도를 가린다

classic에서는 Structure 필드를 하나씩 대입하고, 테이블엔 `APPEND`를 반복했다. 절차는
분명하지만 **값의 모양이 안 읽힌다**. "C001 공연 1회차 2석 예매를 만들고 싶다"는 의도보다
"변수 만들기·필드 채우기·append"라는 작업이 더 커 보인다. 행이 늘면 `CLEAR` 누락 같은
실수도 는다.

[[VALUE]] constructor expression(값을 조립해 만드는 식 — 이 챕터에서 계속 만날 `VALUE`·
`CORRESPONDING`·`CONV` 같은 "값 생성 식" 가족의 이름이다)은 절차를 나열하는 대신
**결과가 어떤 값인지**를 표현한다. 예제로 쓸 예매 한 건은 공연 코드(`concert_id`)·회차(`perf_no`)·좌석 수(`seats`) 세 필드로 이뤄진다.

```abap
TYPES: BEGIN OF ts_book,
         concert_id TYPE c LENGTH 4,
         perf_no    TYPE n LENGTH 3,
         seats      TYPE i,
       END OF ts_book.
TYPES tt_book TYPE STANDARD TABLE OF ts_book WITH EMPTY KEY.
```

> 💡 `WITH EMPTY KEY`는 이 연습용 테이블에 **key를 두지 않겠다**는 선언이다. key가 없으니
> 중복 행을 넣어도 오류가 없다. 아래에서 나올 "중복 key 오류" 이야기는 **unique key를 가진
> 테이블**을 쓸 때의 규칙이니 구분해 두자.

## Structure 채우기

```abap
" classic
DATA ls_book TYPE ts_book.
ls_book-concert_id = 'C001'.
ls_book-perf_no    = '001'.
ls_book-seats      = 2.
```

modern으로 같은 값을 만들면 이렇다(위 classic과 **별개 프로그램** — 이어 붙이면
`ls_book` 중복 선언 오류다).

```abap
" modern — "이 값은 C001 공연 001회차 2석 예매다"로 한 덩어리로 읽힘
DATA(ls_book) = VALUE ts_book(
  concert_id = 'C001' perf_no = '001' seats = 2 ).
```

## Internal Table 채우기 — 각 `( )`가 한 행

```abap
DATA(lt_book) = VALUE tt_book(
  ( concert_id = 'C001' perf_no = '001' seats = 2 )
  ( concert_id = 'C001' perf_no = '002' seats = 3 )
  ( concert_id = 'C002' perf_no = '001' seats = 4 ) ).
```

## 기존에 더하기 — BASE

기존 테이블을 **유지하면서** 행을 더하려면 `BASE`를 쓴다. 타입 자리에 `#`만 쓴 건, 좌변
`lt_book`의 타입을 ABAP이 이미 알고 있어서 **거기서 타입을 추론**할 수 있기 때문이다.

```abap
lt_book = VALUE #( BASE lt_book
  ( concert_id = 'C003' perf_no = '001' seats = 1 ) ).
```

> ⚠️ `BASE`를 빼고 `lt_book = VALUE #( ( … ) )`를 쓰면 기존 내용이 **유지되는 게 아니라
> 새 값으로 대체**된다. `VALUE`는 "새 값을 만든다"는 성격이 강하다.

## FOR로 반복 생성

행을 일일이 적는 대신 **반복**으로 한꺼번에 만든다. 숫자 범위로 1～9회차를 한 번에:

```abap
DATA(lt_book_2) = VALUE tt_book(
  FOR i = 1 WHILE i <= 9
  ( concert_id = 'C001' perf_no = i seats = 2 ) ).   " 9행
```

이미 있는 테이블을 **돌며 변환**할 수도 있다(좌석 수를 두 배로):

```abap
DATA(lt_double) = VALUE tt_book(
  FOR line IN lt_book_2
  ( concert_id = line-concert_id perf_no = line-perf_no
    seats = line-seats * 2 ) ).
```

- `FOR i = 1 WHILE i <= 9`·`FOR line IN lt_book_2` — 반복 조건을 정하고, 그 **반복 한 번**마다 만들 **새 행 하나**를 뒤의 `( )`에 적는다.
- `i`는 따로 선언하지 않아도 **시작값 `1`에서 정수 타입으로 자동 선언**되고, 한 바퀴마다 1씩 는다.
- 원본은 그대로 두고 **새 테이블**을 만든다. `i`·`line`은 그 표현식 **안에서만** 산다.
- `perf_no`는 `n`(숫자 문자) 타입이라 `i`의 1·2·3이 `'001'`·`'002'`·`'003'`으로 채워진다.

## 직접 만들어 보기 — VALUE Builder

테이블을 `VALUE`로 만들고, `BASE`로 더하거나 `BASE` 없이 대입했을 때 기존 행이 어떻게
되는지, `FOR`로 9행을 한 번에 만드는지 확인하자. **unique key** 모드에서 중복 행을 넣으면
어떤 오류가 나는지도 본다.

## 흔한 실수와 점검

- **타입 생략 `VALUE #( )`** → 좌변 타입이 분명할 때만 `#`. 처음엔 `VALUE ts_book( … )`처럼 타입을 명시.
- **BASE 빠뜨림** → `VALUE`만 쓰면 기존 내용이 사라진다. 누적은 `BASE 기존테이블`.
- **`FOR` 변수의 수명** → `FOR line IN …`의 `line`은 그 식 **안에서만** 산다(밖에선 못 쓴다).
- **중복 key** → sorted/hashed·unique key 테이블에 `VALUE`로 중복 행을 넣으면 런타임 오류다.
  테이블 타입의 **key 규칙은 `VALUE`에서도 그대로** 적용된다.

> 💡 `VALUE #( FOR … )`가 읽기 어려울 만큼 길어지면 다시 `LOOP`가 낫다. Modern ABAP은 한 줄로
> 압축하는 대회가 아니다. 조건이 많고 중간 검증이 필요하면 절차형이 더 안전하고 교육적이다.

## 정리

- `VALUE`는 Structure·Internal Table을 **결과 모양 그대로** 만든다. 한 건은 `VALUE ts_book( … )`,
  여러 건은 `VALUE tt_book( ( … ) ( … ) )`.
- 기존을 유지하려면 `BASE`, 반복 생성엔 `FOR`. `#`의 타입 추론과 `BASE` 누락이 가장 자주 틀리는 지점이다.
