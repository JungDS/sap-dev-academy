## 변환 한 번 하려고 변수를 또 만든다

숫자·문자·날짜·금액은 서로 **다른 타입**이라고 여러 번 봤다. classic ABAP에서는 타입을
바꿀 때 **임시 변수를 하나 만들어 대입한 뒤** 그 변수를 다시 넘기는 방식이 흔했다.

```abap
DATA lv_count_text TYPE string VALUE '12'.
DATA lv_count      TYPE i.
lv_count = lv_count_text.        " 변환해서 담을 변수를 따로 만듦
```

> 💡 첫 줄의 `VALUE '12'`는 classic 선언의 **초기값 지정**이다. 두 레슨 전에 배운
> [VALUE Constructor Expression](CH18-L02.html)의 `VALUE ts_book( … )`과는 **키워드만 같고
> 다른 용법**이니 헷갈리지 말자.

값 하나 바꾸자고 변수를 또 선언하니, 정작 하려던 일보다 **준비 과정**이 더 커 보인다.

## CONV — 그 자리에서 타입을 바꾼다

[[CONV]]는 값을 **지정한 타입으로 바꾼 결과**를 그 자리에서 만든다. `CONV 타입( 값 )` 꼴이다.

```abap
DATA(lv_count) = CONV i( '12' ).   " 문자 '12' → 정수 12, 임시 변수 없이
```

`CONV`는 **손실을 감수하고라도** 변환 규칙대로 값을 만든다. 소수가 섞인 문자를 정수로
바꾸면 반올림된다.

```abap
DATA(lv_seats) = CONV i( '3.7' ).   " 4 — 0.3의 손실(반올림)을 감수하고 변환
```

## EXACT — 손실이 나면 막는다

[[EXACT]]는 **손실 없는 변환**을 요구하는 표현식이다. 값이 잘리거나 반올림돼 **의미가
달라질 수 있으면** 변환을 막는다(예외가 난다). 금액·수량처럼 한 자리도 틀리면 안 되는 값에 쓴다.

```abap
DATA(lv_price) = EXACT i( '120000' ).   " 손실 없이 딱 맞아야 통과
```

`CONV`와 `EXACT`에 **같은 입력**을 넣어 보면 차이가 그대로 드러난다.

```abap
DATA(lv_a) = CONV  i( '3.7' ).    " 4 — 반올림 손실을 감수하고 변환
DATA(lv_b) = EXACT i( '3.7' ).    " 예외! 손실이 나는 순간 변환을 거부
```

> 🔎 `EXACT`가 손실을 만나면 **예외**가 발생한다. 예외를 **잡아서 처리하는 법**은
> [Exception Class — TRY/CATCH/CX 계층](CH21-L06.html)에서 배운다. 여기서는 "손실을 강하게
> 막고 싶을 때 쓰는 도구"라는 것까지만 알면 된다.

## 직접 변환해 보기 — 타입 변환 실험실

같은 입력을 `CONV`와 `EXACT`에 나란히 넣어 보자. `'12'` 같은 딱 맞는 값, `'3.7'` 같은
손실 나는 값, `'12A'` 같은 숫자가 아닌 값에서 둘의 반응이 어떻게 갈리는지 확인한다.

## 흔한 실수와 점검

- **`CONV`는 관대, `EXACT`만 엄격이라는 오해** → `CONV`도 아예 **불가능한 변환**에는
  예외를 낸다. `'12A'`를 정수로 바꾸려 하면 `CX_SY_CONVERSION_NO_NUMBER` 예외가 나고,
  잡지 않으면 프로그램이 중단된다. 둘의 차이는 **손실 있는 변환**(반올림 등)을 `CONV`는
  허용하고 `EXACT`는 막는다는 것이다.
- **이미 같은 타입인데 `CONV`** → 불필요하면 문법 검사 경고가 날 수 있다.
- **금액·날짜를 무턱대고 변환** → 업무 의미가 큰 값은 원본 타입과 값 범위를 먼저 확인한다.
- **변환을 과하게 중첩** → 읽기 어려우면 이름 있는 변수로 분리한다.

## 정리

- `CONV 타입( 값 )`은 **임시 변환 변수를 줄이고** 그 자리에서 타입 의도를 드러낸다.
- `EXACT`는 **손실 없는 변환**을 요구한다(실패 시 예외 → CH21).
- 변환은 편의 문법이 아니라 **데이터 의미를 바꾸는 행위**다. 항상 값의 안전성을 함께 생각한다.
