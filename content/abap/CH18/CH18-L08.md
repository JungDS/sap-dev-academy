## 합계 하나 만들려고 LOOP를 또 쓴다

[[Internal Table]]을 배운 뒤로 우리는 반복해서 [[LOOP]]를 썼다. 전체 좌석 수를 합산하거나,
상태가 `N`인 예매만 모으는 코드는 매우 흔하다. `LOOP`는 명확하지만, **"합계 하나"** 나
**"조건에 맞는 행만 추출"** 처럼 패턴이 단순하면 준비 코드가 많다.

이번 레슨의 예제 데이터부터 선언해 두자. 상태(`status`)를 key로 가진 [[Sorted Table]]이다 —
왜 굳이 Sorted인지는 아래 `FILTER`에서 밝혀진다.

```abap
TYPES: BEGIN OF ts_booking,
         booking_id TYPE zbooking-booking_id,
         customer   TYPE zbooking-customer,
         seats      TYPE zbooking-seats,
         status     TYPE zbooking-status,
       END OF ts_booking.
TYPES tt_booking TYPE SORTED TABLE OF ts_booking
  WITH NON-UNIQUE KEY status.

DATA lt_booking TYPE tt_booking.      " 예매 데이터가 담겨 있다 하자
```

## REDUCE — 여러 값을 하나로 줄인다

[[REDUCE]]는 **초기값**을 만들고, 반복하며 누적 변수에 값을 더해 **최종 결과 하나**를 만든다.

```abap
DATA(lv_total_seats) = REDUCE i(
  INIT sum = 0
  FOR ls_book IN lt_booking
  NEXT sum = sum + ls_book-seats ).
```

이건 아래 classic loop와 **같은 목적**이다.

```abap
DATA lv_total_seats TYPE i.
LOOP AT lt_booking INTO DATA(ls_book).
  lv_total_seats = lv_total_seats + ls_book-seats.
ENDLOOP.
```

- `INIT sum = 0` — 누적을 **시작할 값**.
- `FOR ls_book IN lt_booking` — 한 행씩 꺼낸다.
- `NEXT sum = ...` — 다음 누적값을 계산한다(반복마다).

## FILTER — 조건에 맞는 행만 새 테이블로

[[FILTER]]는 조건에 맞는 행만 뽑아 **새 Internal Table**을 만든다. 단, 이름만 보고
"아무 조건이나 거는 도구"로 일반화하면 안 된다. **제약이 원본 테이블 쪽에 있다** —
`WHERE`에 쓸 수 있는 필드는 **원본 테이블의 sorted/hashed key 구성요소**뿐이고, key 없는
보통의 Standard Table에는 이 형태를 아예 쓸 수 없다(구문 오류). 레슨 첫머리에서
`lt_booking`을 일부러 **`status`를 key로 가진 Sorted Table**로 선언해 둔 이유가 이것이다.

```abap
" 원본 lt_booking이 status를 key로 가진 Sorted Table이라 WHERE status가 성립
DATA(lt_open) = FILTER #( lt_booking WHERE status = 'N' ).
```

`EXCEPT`를 붙이면 조건에 **맞지 않는** 행을 가져온다.

```abap
DATA(lt_not_open) = FILTER #( lt_booking EXCEPT WHERE status = 'N' ).
```

> 💡 이 `EXCEPT`는 [CORRESPONDING과 구조 매핑](CH18-L03.html)의 `EXCEPT`(필드를 결과에서
> 뺌)와 **글자만 같고 문맥이 다르다.** 거기서는 **필드**를 빼고, 여기서는 조건을 뒤집어
> **행**을 거른다.

> 🔎 Standard Table을 꼭 걸러야 하면 secondary key([Chapter 06 · Internal Table의
> 3속성](CH06-L02.html)의 key 개념을 확장한 보조 key)를 달아 `USING KEY`로 지정하는 길이
> 있지만, 이 챕터 범위 밖이다. 지금은 "FILTER는 key 있는 테이블에서"만 기억하면 된다.

## 직접 집계해 보기 — 집계·필터 실험실

예매 데이터의 상태·좌석 수를 바꿔 가며 `REDUCE`의 누적 과정(INIT→NEXT)이 한 바퀴씩
어떻게 도는지, `FILTER`의 `WHERE`/`EXCEPT WHERE`가 각각 몇 행을 골라내는지 확인하자.

## 흔한 실수와 점검

- **`REDUCE`를 처음부터 복잡하게** → 초보에게 가장 읽기 어려운 표현식 중 하나다. **단순
  합계**부터 시작한다. 누적 중간에 검증·메시지가 많으면 `LOOP`가 낫다.
- **`FILTER`에서 Key 무시** → `WHERE` 필드는 **원본 테이블의 sorted/hashed key 구성요소**여야
  한다. key 없는 Standard Table에 쓰면 구문 오류다.
- **`FILTER ... EXCEPT WHERE` 결과 감 못 잡기** → `EXCEPT WHERE 조건`은 "조건에 맞지 않는
  행 **전부**"다. `WHERE` 결과와 `EXCEPT WHERE` 결과의 행 수를 합치면 원본 행 수와 같아야
  한다 — 이걸로 결과를 검산한다.

## 정리

- `REDUCE`는 테이블을 **합계나 하나의 결과로 줄이는** 표현식이다.
- `FILTER`는 **조건에 맞는 행만 새 테이블로** 만드는 표현식이다.
- 둘 다 **단순한 반복 패턴**을 줄이는 도구다. 복잡한 업무 흐름은 여전히 `LOOP`가 나을 수 있다.
