## 숫자 다음은 글자

숫자를 계산했으니, 이번엔 **문자열**이다. 성과 이름을 한 줄로 잇고, "성:이름"을
쪼개고, 특정 글자를 찾아 바꾸는 일은 업무 프로그램에서 끝없이 나온다.

## 잇기 — `CONCATENATE` 와 `&&`

여러 문자열을 하나로 잇는다. [[CONCATENATE]]는 **사이 구분자**를 `SEPARATED BY`로
지정할 수 있다.

```abap
DATA gv_full TYPE string.

CONCATENATE '정훈영' '님' INTO gv_full.                  " 정훈영님
CONCATENATE '2026' '06' '23' INTO gv_full SEPARATED BY '-'. " 2026-06-23
```

짧게 이을 땐 **`&&` 연산자**가 더 간단하다(아주 자주 쓰여 미리 익혀 둔다).

```abap
DATA gv_short TYPE string.

gv_short = '정훈영' && '님'.       " 정훈영님
```

> 💡 `CONCATENATE`는 구분자(`SEPARATED BY`)까지 챙길 수 있어 여러 조각을 정교하게
> 이을 때 좋고, `&&`는 두어 개를 짧게 이을 때 간편하다. 상황에 맞게 고른다.

> 🧑‍💻 **다른 언어를 해 봤다면** `&&`가 논리 AND로 익숙할 텐데, ABAP에서는 **문자열을 잇는**
> 연산자다. 논리 AND는 그냥 `AND`라고 적는다(다음 레슨에서 쓴다).

## 쪼개기 · 길이 — `SPLIT` · `STRLEN`

`SPLIT`은 구분자를 기준으로 문자열을 나눈다. `strlen( )`은 글자 수를 센다.

```abap
DATA gv_id   TYPE string VALUE 'KR:정훈영'.
DATA gv_cty  TYPE string.
DATA gv_name TYPE string.
DATA gv_len  TYPE i.

SPLIT gv_id AT ':' INTO gv_cty gv_name.   " gv_cty='KR', gv_name='정훈영'
gv_len = strlen( gv_name ).               " 3
```

`strlen( )`처럼 **괄호 안에 값을 넣어 결과를 돌려주는 것**을 [[내장함수]]라 한다.
숫자용 내장함수도 있다: `abs( -5 )`(절댓값 5), `sqrt( 9 )`(3), `ipow( base = 2 exp = 8 )`(256).

`ipow`처럼 괄호 안에 **`이름 = 값`** 을 적는 함수도 있다. `base = 2 exp = 8`은
"밑은 2, 지수는 8"이라고 읽으면 된다(결과는 `2 ** 8`과 같은 256).

## 찾고 바꾸기 — `FIND` · `REPLACE`

```abap
DATA gv_text TYPE string VALUE 'SAP ABAP'.

FIND 'ABAP' IN gv_text.        " 찾으면 '찾았다'는 성공 표시가 남는다
REPLACE 'ABAP' IN gv_text WITH 'HANA'.   " gv_text = 'SAP HANA'
```

> 💡 `FIND`는 찾았는지 못 찾았는지를 **시스템이 채워 주는 자리**에 남긴다. 그 자리를 읽는
> 법은 [DO/WHILE 레슨](CH04-L05.html)에서 배운다. 지금은 "결과가 어딘가 남는다"만 알면 된다.

> 옛 코드의 `SEARCH`문은 더 쓰지 않는다(obsolete, 즉 더는 쓰지 않기로 한 낡은 문법).
> 찾기의 표준은 `FIND`다.

## 다듬기 — `CONDENSE` · `TRANSLATE` · offset 접근

[[CONDENSE]]는 **앞뒤 공백을 없애고** 중간 연속 공백을 한 칸으로 줄인다. 문자열의
일부만 떼어 보려면 [Chapter 2](CH02-L03.html)에서 배운 **offset 접근** `gv+시작(길이)`을 쓴다.

```abap
DATA gv_raw  TYPE string VALUE '   정훈영   '.
DATA gv_date TYPE c LENGTH 8 VALUE '20260623'.

CONDENSE gv_raw.                 " '정훈영'
WRITE gv_date+4(2).              " 5번째부터 2글자 → '06' (월)
```

대소문자가 뒤섞이면 비교가 어긋난다. `TRANSLATE`는 문자열을 통째로 **대문자(또는
소문자)로 바꿔** 기준을 하나로 맞춰 준다.

```abap
DATA gv_grade TYPE c LENGTH 1 VALUE 'a'.

TRANSLATE gv_grade TO UPPER CASE.   " 'a' → 'A'
```

소문자로 맞추고 싶으면 `TO LOWER CASE`라고 적으면 된다.

이 밖에 `SHIFT`(밀기)·`OVERLAY`(겹쳐쓰기)·`WRITE 값 TO 변수`(서식을 입혀 변수로 받기)도
같은 갈래의 도구다. **이름만 눈에 담아 두었다가** 필요할 때 찾아 쓰면 된다.

## 흔한 실수와 점검

- **`SPLIT` 대상 변수 개수** → 조각보다 받을 변수가 적으면 오류가 나는 게 아니라
  **마지막 변수에 남은 조각이 통째로** 들어간다. 조용히 어긋나는 자리라 조각 수만큼 맞춘다.
- **`&&` 양옆 공백** → `a && b`처럼 띄운다.
- **`CONDENSE`로 안 지워질 때** → 중간 모든 공백 제거는 `CONDENSE gv NO-GAPS`.

## 정리

문자열을 잇고·쪼개고·찾고·다듬었다. 계산도 글자 처리도 되는데, 프로그램은 아직
**언제나 똑같이** 행동한다. "값이 양수면 이렇게, 아니면 저렇게" 갈라지게 하고 싶다
→ [IF와 조건식](CH04-L03.html).
