## 언제나 똑같이 행동하는 프로그램

지금까지 만든 코드는 **입력이 무엇이든 늘 같은 일**을 한다. 하지만 진짜 프로그램은
"잔액이 부족하면 거절, 충분하면 승인"처럼 **상황을 보고 다르게** 행동해야 한다.
그 첫걸음이 [[IF]]다.

## 비교 연산자 — 참/거짓을 묻는다

두 값을 비교하면 **참**(true) 또는 **거짓**(false)이 나온다. 기호와 영문 둘 다 쓸 수 있다.

| 뜻 | 기호 | 영문 |
|---|---|---|
| 같다 / 다르다 | `=` / `<>` | `EQ` / `NE` |
| 크다 / 작다 | `>` / `<` | `GT` / `LT` |
| 크거나 같다 / 작거나 같다 | `>=` / `<=` | `GE` / `LE` |

## IF / ELSEIF / ELSE

조건이 참이면 그 블록을, 아니면 다음을 본다. 모든 [[IF]]는 `ENDIF`로 닫는다.

```abap
PARAMETERS pa_amt TYPE i.

IF pa_amt > 1000.
  WRITE: / '큰 금액'.
ELSEIF pa_amt > 0.
  WRITE: / '소액'.
ELSE.
  WRITE: / '0 또는 음수'.
ENDIF.
```

## 여러 조건 묶기 — `AND` · `OR` · `NOT` · 괄호

조건 하나로는 부족할 때가 많다. 여러 조건을 묶는 말은 셋이다.

- `AND` — **둘 다 참**이어야 참.
- `OR` — **하나라도 참**이면 참.
- `NOT` — 참·거짓을 **뒤집는다.**

`NOT`이 뒤집는 범위는 **바로 뒤에 오는 조건 하나**다. 아래 `NOT pa_block = 'X'`는
"`pa_block`이 `'X'`가 아니다"라는 뜻이고, 그 앞의 괄호까지 함께 뒤집지는 않는다.

```abap
PARAMETERS: pa_amt   TYPE i,
            pa_vip   TYPE c LENGTH 1,    " VIP 회원이면 'X'
            pa_block TYPE c LENGTH 1.    " 거래 정지면 'X'

IF pa_amt > 0 AND pa_amt <= 1000.
  WRITE: / '소액 결제 가능'.
ENDIF.

IF ( pa_amt > 5000 OR pa_vip = 'X' ) AND NOT pa_block = 'X'.
  WRITE: / 'VIP 혜택'.
ENDIF.
```

`pa_vip = 'X'`가 낯설 것이다. ABAP에는 참/거짓 전용 타입이 없어서, **한 글자짜리 문자에
`'X'`면 참·공백이면 거짓**을 담는 오랜 관례를 쓴다. 이 관례는 이 레슨 끝에서 제대로 정리한다.

> ⚠️ `AND`와 `OR`가 섞이면 **괄호 `( )`로 묶어** 의도를 분명히 한다. 괄호 안쪽도
> 연산자처럼 **앞뒤 공백**이 필요하다: `( pa_amt > 5000 )`.

## 비었는지 묻기 — `IS INITIAL`

값이 **초기값**(숫자 0·문자 공백)인지 확인할 땐 `IS INITIAL`이 깔끔하다.

```abap
IF pa_amt IS INITIAL.        " pa_amt = 0 과 같은 의미
  WRITE: / '금액이 0입니다'.
ENDIF.
```

주의할 점이 하나 있다. 숫자 변수는 **아무것도 입력하지 않아도 0, 0을 직접 입력해도 0**이라
`IS INITIAL`만으로는 그 둘을 구분하지 못한다.

> 🧑‍💻 **다른 언어를 해 봤다면** `IS INITIAL`을 null 검사로 읽기 쉽지만, 지금까지 배운 타입에는
> `null`이 아예 없다([Chapter 2](CH02-L01.html)). 선언하는 순간 타입별 초기값이 들어가 있고,
> `IS INITIAL`은 "지금 그 초기값이냐"를 묻는 것이다.

## boolean 타입 대신 `abap_bool` (중요)

ABAP에는 "참/거짓만 담는 전용 타입"이 따로 **없다**. 대신 **한 글자짜리 문자**
(`TYPE c LENGTH 1`)에 `'X'`(참)와 공백(거짓)을 담는다. 앞에서 본 `pa_vip`가 바로 그 방식이다.
이렇게 켜짐·꺼짐만 나타내는 표시값을 흔히 **플래그**라 부른다.

그런데 `TYPE c LENGTH 1`이라고만 적으면 그 변수가 참/거짓용인지 그냥 한 글자 코드인지
읽는 사람이 알 수 없다. 그래서 SAP이 권장하는 표준 타입 **`abap_bool`**(속은 똑같이 문자
한 글자)로 선언한다. 값도 `'X'`를 직접 쓰기보다 표준 [[CONSTANTS]] `abap_true`(= `'X'`)와
`abap_false`(= 공백)를 쓴다.

```abap
" DATA gv_flag TYPE c LENGTH 1.   ❌ 동작하지만 의도가 안 보임
DATA gv_flag TYPE abap_bool.      " ✅ SAP 표준 권장 타입 (속은 문자 한 글자)

gv_flag = abap_true.              " 'X'
IF gv_flag = abap_true.
  WRITE: / '플래그 켜짐'.
ENDIF.
```

> 🧑‍💻 **다른 언어를 해 봤다면** `boolean`·`bool` 원시 타입이 있던 자리를 ABAP에서는
> 이 `abap_bool` 관례가 대신한다고 보면 된다.

비교 결과를 바로 플래그에 담고 싶으면 `xsdbool( )`을 쓴다. 조건이 참이면 `'X'`,
거짓이면 공백을 돌려준다.

```abap
gv_flag = xsdbool( pa_amt > 1000 ).   " 큰 금액이면 'X'
```

> 📝 **참고** — 옛 코드에는 비슷하게 생긴 `boolc( )`도 보인다. 겉모습은 같지만 돌려주는
> 타입이 **문자열**이라, `abap_bool` 변수와 비교하거나 `IS INITIAL`로 물으면 기대와 다르게
> 어긋난다. 새로 쓸 때는 `xsdbool( )`을 고른다. (`boolc( )`는 7.02, `xsdbool( )`은 7.40
> 이상 시스템에서 쓸 수 있다. 아주 옛 실습 시스템이면 문법 오류가 날 수 있다.)

::embed CH04-L03-S04 | 값을 바꿔 xsdbool이 gv_flag 한 칸에 무엇을 담는지 보기::

> 💡 이 `abap_bool`·`abap_true`/`abap_false` 약속은 뒤의 모듈화 챕터에서 다시 만난다.
> **여기서 한 번 제대로 익혀 두면** 이후엔 자연스럽게 읽힌다.

## 흔한 실수와 점검

- **`ENDIF` 누락** → 모든 `IF`는 `ENDIF`로 닫는다.
- **`=`의 두 얼굴** → IF 안의 `=`는 "같냐?"(비교), 문장에서의 `=`는 "넣어라"(대입).
- **`'X'`를 직접 비교** → `IF gv_flag = 'X'.`도 돌아가긴 한다. 하지만 이름 있는
  `abap_true`로 쓰면 "참인지 본다"는 의도가 코드에 그대로 읽힌다.

## 정리

프로그램에 **판단**이 생겼다. 그런데 한 값을 여러 경우로 나눌 땐 `IF/ELSEIF`가
길어진다. 그럴 때 더 읽기 좋은 도구가 있다 → [CASE 분기](CH04-L04.html).
