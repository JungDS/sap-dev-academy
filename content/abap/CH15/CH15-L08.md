## 필드 하나를 넘어선 검증·도움말

[Chapter 15 · AT SELECTION-SCREEN 입력 검증](CH15-L04.html)에서
`AT SELECTION-SCREEN ON <필드>`로 한 필드를 검증했다. 그런데 실무 화면은
더 넓은 단위로 반응해야 할 때가 많다. 블록 안 여러 필드가 함께 맞아야 하고,
라디오 선택에 따라 조건이 달라지고, **F1 도움말이나 F4 입력 도움을 직접** 제공해야 한다.
선택화면은 단순 입력칸 묶음이 아니라, **작은 dialog 화면처럼 반응**할 수 있다.

## 블록 · 라디오그룹 단위 검증

필드 하나가 아니라 **블록 전체의 조합**, 또는 **라디오 그룹 선택**을 한 번에 검증한다.

> 📎 **[선행 사용]** — 아래 예제는 블록 `b_date`와 라디오 그룹 `g1`이 화면에 이미 있다고
> 치고 시작한다. 그 화면을 **그리는** 문법(`SELECTION-SCREEN BEGIN OF BLOCK …`,
> `PARAMETERS … RADIOBUTTON GROUP …`)은 바로 다음 레슨
> [Selection Screen UI 구성](CH15-L09.html)에서 정식으로 배운다. 지금은 **뜯어보거나 외울
> 필요 없다.** "이렇게 선언해 두면 `b_date`·`g1` 같은 이름이 생긴다" 정도만 눈에 담고,
> 이 레슨은 그것을 **한 단위로 검증하는 이벤트** 쪽에 집중하자.

```abap
" ── 화면 선언부 [선행 사용] — 정식 설명은 다음 레슨 ──
SELECTION-SCREEN BEGIN OF BLOCK b_date WITH FRAME.
  PARAMETERS: pa_from TYPE d,
              pa_to   TYPE d.
SELECTION-SCREEN END OF BLOCK b_date.

PARAMETERS: pa_sum RADIOBUTTON GROUP g1 DEFAULT 'X',
            pa_det RADIOBUTTON GROUP g1.

" ── 여기부터가 이번 레슨의 주제 ──
" 블록 b_date 전체의 조합 규칙을 한 번에 검증
AT SELECTION-SCREEN ON BLOCK b_date.
  IF pa_from IS INITIAL OR pa_to IS INITIAL.
    MESSAGE '기간을 모두 입력하세요' TYPE 'E'.
  ENDIF.
  IF pa_from > pa_to.
    MESSAGE '시작일이 종료일보다 늦습니다' TYPE 'E'.
  ENDIF.

" 라디오로 고른 값이 다른 입력과 맞는지 검증
AT SELECTION-SCREEN ON RADIOBUTTON GROUP g1.
  IF pa_det = 'X' AND pa_to - pa_from > 31.
    MESSAGE '상세 조회는 31일 이내 기간만 가능합니다' TYPE 'E'.
  ENDIF.
```

- `ON BLOCK <블록>` — 한 블록의 여러 필드를 묶어 **조합**을 검증.
- `ON RADIOBUTTON GROUP <그룹>` — 라디오 선택과 다른 입력의 **정합성**을 검증.

> 💡 라디오 그룹은 **항상 하나가 선택된 상태**다. 그래서 "둘 다 안 골랐나?"를 검사하는
> 코드는 아무리 기다려도 참이 되지 않는다. 이 이벤트에서 볼 것은 "골랐나"가 아니라
> **고른 값과 다른 입력이 서로 맞는가**다.

## 코드로 만드는 F1 도움말 — ON HELP-REQUEST

Data Element의 기본 문서로 부족할 때, 특정 필드의 **F1(도움말)** 을 코드로 만든다.

```abap
AT SELECTION-SCREEN ON HELP-REQUEST FOR pa_conc.
  MESSAGE '공연 코드는 ZCONCERT에 등록된 CONCERT_ID입니다' TYPE 'I'.
```

> `ON HELP-REQUEST`는 필드 의미를 보충하는 **짧은 도움말**에 적합하다.
> 긴 교육 문서를 팝업으로 띄우는 용도로 남용하지 않는다.

## 코드로 만드는 F4 입력 도움 — ON VALUE-REQUEST

선언적 Search Help([Chapter 9 · PARAMETERS와 DDIC F4 Help 연결](CH09-L06.html))로
부족할 때(목록을 **그때그때 DB에서** 만들어야 할 때) **F4 입력 도움**을 코드로 채운다.

```abap
PARAMETERS pa_carr TYPE scarr-carrid.

DATA: BEGIN OF gs_carr,
        carrid   TYPE scarr-carrid,
        carrname TYPE scarr-carrname,
      END OF gs_carr.
DATA gt_carr LIKE STANDARD TABLE OF gs_carr.

AT SELECTION-SCREEN ON VALUE-REQUEST FOR pa_carr.
  " 1) 목록 데이터를 조회 (classic)
  SELECT carrid carrname
    FROM scarr
    INTO TABLE gt_carr.

  " 2) F4 팝업으로 보여 주고, 고른 값을 화면 필드에 반영
  CALL FUNCTION 'F4IF_INT_TABLE_VALUE_REQUEST'
    EXPORTING retfield    = 'CARRID'      " 돌려줄 컬럼
              dynpprog    = sy-repid      " 지금 이 프로그램의 이름
              dynpnr      = sy-dynnr      " 지금 떠 있는 화면의 번호
              dynprofield = 'PA_CARR'     " 값을 채울 화면 필드
              value_org   = 'S'           " 목록을 '줄 단위'로 넘긴다는 표시
    TABLES    value_tab   = gt_carr.      " 보여 줄 목록
```

- `value_tab` — 팝업에 띄울 목록(코드에서 만든다).
- `retfield`/`dynprofield` — 고른 값을 **어느 화면 필드**에 돌려줄지.
- `dynpprog`·`dynpnr` — **"어느 프로그램의 몇 번 화면에 값을 꽂아 달라"** 는 주소다.
  이 함수는 우리가 만든 코드가 아니라 시스템이 제공하는 남의 코드라서, 값을 돌려줄 화면을
  스스로 알지 못한다. 그래서 `sy-repid`(지금 프로그램 이름)와 `sy-dynnr`(지금 화면 번호)를
  넘겨 알려 준다.
- `value_org = 'S'` — 넘기는 목록이 **컬럼 여러 개짜리 표**라서 한 줄씩 통째로 읽으라는 뜻이다.
  우리 `gt_carr`는 `carrid`·`carrname` 두 컬럼이라 `'S'`가 맞다. 이걸 빠뜨리면 함수가 목록을
  다른 방식으로 해석해 팝업에 값이 어긋나 보인다.
- ⚠️ 이 함수는 **고른 값을 `PA_CARR`에 운반**해 주지만, 선택화면의 **다른 필드 값까지
  자동으로 읽어 오지는 않는다.** 사용자가 다른 칸에 지금 입력해 둔 값이 필요하면
  `DYNP_VALUES_READ` 같은 별도 함수를 따로 불러야 한다.

## 직접 반응시켜 보기 — Selection Screen 반응 실험실

네 가지 고급 이벤트를 직접 일으켜 보자. 블록 날짜를 비우거나 뒤집어 **블록 검증**을,
라디오를 바꿔 **그룹 이벤트**를, `pa_conc`에서 **F1**을, `pa_carr`에서 **F4**를 호출해
어떤 ABAP 이벤트가 발생하고 선택값이 화면 필드로 어떻게 들어오는지 확인한다.

## 흔한 실수와 점검

- **F4가 필요하면 무조건 function module부터** → 먼저 DDIC Search Help·check table로
  **자동 제공**되는 도움말을 고려한다. 코드 F4는 목록이 동적이거나 특수할 때만.
- **블록 이름 불일치** → `ON BLOCK`의 이름은 정의한 BLOCK 이름과 똑같아야 한다.
- **검증 중복** → 블록 검증과 전체 검증이 같은 오류를 **두 번** 띄우지 않게 한다.
- **검증과 도움말 혼동** → `ON`·`ON BLOCK`은 **막는 것**, F1·F4는 **돕는 것**으로 목적이 다르다.

## 정리

- 선택화면은 정적 입력칸이 아니라, **블록·라디오그룹·F1·F4 이벤트**로 사용자 행동에
  반응하는 화면이다.
- **검증**(ON BLOCK·ON RADIOBUTTON GROUP)과 **도움말**(ON HELP/VALUE-REQUEST)을
  나눠서 생각한다.
- **자동 DDIC 도움말 vs 직접 구현**의 경계를 먼저 판단한다 — 되도록 선언적으로.
