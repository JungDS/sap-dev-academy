## 입력 조건을 업무 단위로 정리

선택화면도 **UI**다. 입력칸이 많아질수록 사용자는 "어떤 값이 필수인지, 어떤 조건이
같은 묶음인지"를 알기 어려워진다. [[SELECTION-SCREEN]] 문으로 **블록으로 묶고,
체크박스·라디오·버튼**을 더하면 조건을 빠르게 이해하고 실수 없이 실행할 수 있다.

> 이 레슨은 "화면을 꾸미는 문법 목록"이 아니라 **입력 조건을 업무 단위로 정리하는
> 방법**이다. 멋지게 만드는 것보다 **실행 실수를 줄이는 것**이 먼저다.

여기서 다룰 것은 크게 세 덩어리다. **① 묶고 나누기**(블록·구분선·설명) →
**② 입력 방식 고르기**(체크박스·라디오) → **③ 버튼 달기**(본문 버튼·툴바 버튼).
한 번에 다 외우려 하지 말고, 필요한 덩어리만 찾아 쓰면 된다.

> 🧱 감각 하나를 먼저 잡고 가자. 여기 나오는 문법은 **화면을 직접 그리는 코드가 아니다.**
> "이런 칸이 필요하다"고 **선언**해 두면 화면은 시스템이 알아서 만들어 준다.
> 우리가 하는 일은 그리기라기보다 **주문서 작성**에 가깝다.

## 블록 · 구분선 · 설명

```abap
SELECTION-SCREEN BEGIN OF BLOCK b_main WITH FRAME TITLE TEXT-001.
  PARAMETERS pa_conc TYPE zconcert-concert_id.
  SELECTION-SCREEN COMMENT /1(50) TEXT-002 FOR FIELD pa_conc.  " 설명 줄
  SELECTION-SCREEN ULINE.                       " 구분선
  SELECTION-SCREEN SKIP.                         " 빈 줄
SELECTION-SCREEN END OF BLOCK b_main.
```

- `BEGIN/END OF BLOCK ... WITH FRAME TITLE` — 테두리+제목으로 한 묶음.
- `COMMENT` 설명 텍스트 · `ULINE` 구분선 · `SKIP` 빈 줄.
- `TEXT-001`·`TEXT-002` 같은 표기는 [[Text Symbol|텍스트 심볼]]이다. 화면에 보일 **문구를
  코드에 직접 박지 않고** 번호로 불러 쓰는 방식이라, 나중에 문구만 바꾸거나 다른 언어로
  번역하기 쉽다. 문구 자체는 `SE38`에서 **텍스트 요소**를 열어 번호별로 등록한다.
- `/1(50)` 은 **위치와 폭**을 적은 것이다. 앞의 `/`는 "새 줄에서 시작", `1`은 **1번째 칸**부터,
  `(50)`은 **50칸 너비**라는 뜻이다. `/`를 빼면 앞 요소와 **같은 줄**에 이어 붙는다.
- ⚠️ `COMMENT`에는 가능하면 **`FOR FIELD <필드>`** 를 붙인다. 그래야 그 설명이
  특정 입력칸과 연결되어 **F1 도움말 사용성**이 살아난다.

여러 요소를 **한 줄에 나란히** 두려면 `BEGIN OF LINE`~`END OF LINE`으로 묶고
`POSITION`으로 칸 위치를 지정한다.

```abap
SELECTION-SCREEN BEGIN OF LINE.
  SELECTION-SCREEN COMMENT 1(10) TEXT-003.   " 1번 칸부터 라벨
  SELECTION-SCREEN POSITION 12.              " 12번 칸으로 이동
  PARAMETERS pa_x TYPE i.
SELECTION-SCREEN END OF LINE.
```

- `POSITION n` — 다음 요소를 n번째 칸에 둔다. 범위 입력(SELECT-OPTIONS)의 From/To
  자리는 `POS_LOW`·`POS_HIGH`로 가다듬는다.

## 체크박스 · 라디오버튼

```abap
PARAMETERS pa_all AS CHECKBOX.                       " 켜고 끄는 한 칸

PARAMETERS: pa_sum RADIOBUTTON GROUP g1 DEFAULT 'X', " 기본 선택
            pa_det RADIOBUTTON GROUP g1.
```

- `AS CHECKBOX` — 켜고 끄는 한 칸(`'X'`/공백).
- `RADIOBUTTON GROUP g1` — 같은 그룹 중 **하나만** 선택. `DEFAULT 'X'`로 기본값을
  주되, 그 기본 선택이 **업무적으로 안전한지** 따져 본다.

## 버튼 — 본문 PUSHBUTTON · 툴바 FUNCTION KEY

선택화면에는 두 종류의 버튼을 둘 수 있다. **본문 버튼**(화면 안)과 **툴바 버튼**(화면
위쪽 툴바)이다. 둘 다 누르면 그 버튼에 붙여 둔 **function code**(어떤 버튼이 눌렸는지
알려 주는 짧은 코드값)가 [[SSCRFIELDS]]의 `ucomm` 칸에 담겨 온다. 그 값을
`AT SELECTION-SCREEN`에서 읽어 "무슨 버튼이 눌렸구나"를 판단한다.

```abap
TABLES sscrfields.   " [선행 사용] — 바로 아래 설명 참고

SELECTION-SCREEN PUSHBUTTON /1(20) gv_ref USER-COMMAND ref.   " 본문 버튼
SELECTION-SCREEN FUNCTION KEY 1.                              " 툴바 버튼 FC01

INITIALIZATION.
  gv_ref = '조건 새로고침'.             " 본문 버튼 텍스트
  sscrfields-functxt_01 = '도움말'.     " 툴바 버튼 텍스트

AT SELECTION-SCREEN.
  CASE sscrfields-ucomm.                " ← sy-ucomm이 아니라 이쪽
    WHEN 'REF'.
      MESSAGE '조건을 다시 계산했습니다' TYPE 'S'.
    WHEN 'FC01'.
      MESSAGE '이 리포트는 공연 예매 조회용입니다' TYPE 'I'.
  ENDCASE.
```

- `TABLES sscrfields.` **[선행 사용]** — DB 테이블을 읽겠다는 선언이 아니다. 시스템이 화면
  관련 정보를 담아 두는 **공용 칸**(`sscrfields`)을 이 프로그램에서도 쓰겠다고 이름을 여는
  한 줄이다. 눌린 버튼 코드가 그 칸의 `ucomm`에 들어온다. `TABLES` 선언 자체의 정식 설명은
  화면을 직접 설계하는 [Chapter 16 · Module Pool 프로그램 구조](CH16-L01.html)에서 다루니,
  지금은 **"버튼을 쓰려면 이 한 줄이 필요하다"** 정도로 받아들이자.
- `gv_ref`는 버튼에 **보일 글자를 담는 변수**다. 따로 `DATA`로 선언하지 않아도 이 문장이
  같은 이름의 변수를 만들어 준다(이름은 **8자 이내**). 글자는 `INITIALIZATION`에서 넣는다.
- `FUNCTION KEY 1~5` → function code `FC01~FC05`. 텍스트는 `FUNCTXT_0n`.
- ⚠️ 나중에 화면 설계를 배우면 버튼 처리에 `SY-UCOMM`(눌린 버튼 코드가 담기는 시스템 필드)을
  쓰는 코드를 자주 보게 된다. 하지만 **선택화면에서는 그 값이 늘 제대로 채워진다는 보장이
  없다.** 여기서는 반드시 **`SSCRFIELDS-UCOMM`** 으로 받는다(공식 권고).
- ⚠️ PUSHBUTTON은 **조회 실행을 대체하는 버튼이 아니다.** 실제 조회는 Execute 흐름과
  분리해 설계한다(버튼은 화면 갱신·도움말 같은 보조 동작용).

## 조건이 더 많아지면?

조건 영역이 여러 개로 늘어나면 화면을 **탭**으로 나누는 `TABBED BLOCK`이라는 방법도 있다.
다만 탭마다 별도의 화면 조각을 연결해 줘야 해서, 화면을 직접 설계하는 법
([Chapter 16 · Module Pool 프로그램 구조](CH16-L01.html))을 배운 뒤에 훨씬 수월하다.
**지금 외울 필요는 없다** — "그런 게 있다"만 기억해 두자.

## 흔한 실수와 점검

- **BLOCK 짝 안 맞음** → `BEGIN OF BLOCK`은 `END OF BLOCK`으로 닫는다.
- **라디오 그룹 미지정** → 같은 그룹이라야 배타 선택이 된다.
- **버튼 처리에 `SY-UCOMM` 사용** → 선택화면에서는 `SSCRFIELDS-UCOMM`으로 받는다.
- **장식 과다** → 업무 단위로 묶는 게 먼저, 꾸미기는 그 다음. 한꺼번에 다 쓰면 화면만 복잡해진다.

## 정리

- 선택화면 UI 구성은 **조건을 업무 언어로 정리하는 일**이다.
- 블록으로 묶고, `COMMENT`(가능하면 `FOR FIELD`)로 보충하고, checkbox/radio로 선택
  방식을 명확히 한다.
- PUSHBUTTON·FUNCTION KEY는 **`SSCRFIELDS-UCOMM`** 으로 처리한다.
