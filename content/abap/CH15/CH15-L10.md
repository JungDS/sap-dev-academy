## 옵션을 한자리에 모아 보기

`OBLIGATORY`·`DEFAULT`·`AS CHECKBOX` 같은 옵션을 그동안
[Chapter 3 · Data Element — 의미·라벨 입히기](CH03-L02.html),
[Chapter 12 · Range Table 구조](CH12-L01.html),
[Selection Screen UI 구성](CH15-L09.html) 곳곳에서 만났다. 이 레슨은
[[PARAMETERS]]와 [[SELECT-OPTIONS]]에 붙이는 옵션을 한눈에 정리한다. 필요할 때
찾아보는 **카탈로그**다.

> 핵심 마음가짐: 입력 필수·기본값·대소문자·복수 선택·화면 제어를 **event 코드로 억지
> 구현하기 전에**, 옵션으로 해결되는지 먼저 본다.

## PARAMETERS 옵션

```abap
PARAMETERS pa_conc TYPE zconcert-concert_id OBLIGATORY.  " 필수 입력
PARAMETERS pa_note TYPE c LENGTH 20 LOWER CASE MEMORY ID znt.
PARAMETERS pa_test AS CHECKBOX.
```

| 옵션 | 뜻 | 주의 |
|---|---|---|
| `TYPE` / `LIKE` | 타입 지정 / 기존 필드와 같게 | DDIC 필드를 참조하면 라벨·F1 연결이 쉬움 |
| `OBLIGATORY` | 필수 입력(비우면 진행 불가) | 필수 여부 ≠ 업무 유효성 |
| `DEFAULT <값>` | 시작값 제안 | `MEMORY ID`보다 우선될 수 있음 |
| `LOWER CASE` | 소문자 보존(기본은 대문자 변환) | **문자형(character-like) 필드에만** 의미 있음 |
| `AS CHECKBOX` / `RADIOBUTTON GROUP g` | 체크박스 / 라디오 | 속은 길이 1짜리 문자형 필드다(`'X'`/공백) |
| [[MEMORY ID]] `<pid>` | Parameter ID와 연결 — 마지막 값 기억 | **그 사용자가 직전에 넣었던 값**이 자동으로 채워질 수 있음 |
| `VALUE CHECK` | 고정값/check table 기반 검사 | 입력 직후 자동 검증 |
| [[MODIF ID]] `<grp>` | 화면 제어용 그룹 이름 | `SCREEN-GROUP1`에 저장(아래) |

> ⚠️ `LOWER CASE`는 **문자형(character-like) 필드 전용**이다(공식문서: 문자형 필드의 대문자
> 변환을 막는 옵션). `TYPE p`(숫자) 같은 필드에 붙이는 옵션이 아니다.

> 💡 `MEMORY ID`가 값을 기억해 두는 곳은 **그 사용자의 로그인 세션에 딸린 개인 보관함**이다
> (SAP에서는 SPA/GPA Parameter라고 부른다). 그래서 사람마다 내용이 다르고, 칸 하나당 값
> 하나만 남는다. 반면 [여러 선택화면 — 화면번호·CALL·Variant](CH15-L11.html)에서 볼 Variant는
> **화면 전체의 값 묶음**을 이름 붙여 저장하고, 로그아웃해도 남으며 다른 사람도 골라 쓸 수 있다.
> "이 칸 하나만 기억" = `MEMORY ID`, "조건 세트를 통째로 보관" = Variant.

## SELECT-OPTIONS 옵션

```abap
DATA gv_date TYPE d.

SELECT-OPTIONS so_date FOR gv_date
  DEFAULT sy-datum TO sy-datum   " 첫 조건 행의 시작/끝 기본값
  OBLIGATORY                     " 조건 최소 한 줄 필수
  NO-EXTENSION                   " 다중 선택(여러 줄) 버튼 숨김
  NO INTERVALS.                  " From–To 중 To 칸 숨김
```

| 옵션 | 뜻 | 주의 |
|---|---|---|
| `DEFAULT <low> [TO <high>]` | 첫 조건 행의 시작값/범위 | 내부값(internal) 기준 |
| `OBLIGATORY` | 조건 입력 필수 | 복수 선택 UX와 함께 확인 |
| `LOWER CASE` | 소문자 보존 | 문자형 한정 |
| `NO-EXTENSION` | **다중 선택(여러 줄) 창을 여는 버튼을 숨김** | 화면에서 못 열게 할 뿐, 조건이 한 줄이라고 보장하지는 않음 |
| `NO INTERVALS` | **To 칸 숨김**(단일값만) | 단독 사용 시 다중 선택 창에서는 범위 입력이 여전히 가능할 수 있음 |
| `MEMORY ID` / `MODIF ID` | 값 기억 / 화면 제어 그룹 | |
| (SIGN·OPTION) | 부호·비교연산자 — [Chapter 12 · Range Table 구조](CH12-L01.html) | |

> ⚠️ `NO-EXTENSION`과 `NO INTERVALS`는 이름이 비슷해 헷갈리기 쉽지만 **다른 옵션**이다.
> `HIGH` 칸을 감추는 것과 조건 줄을 더 못 늘리게 하는 것은 별개의 이야기다.
> 그리고 둘 다 **화면에서 제한하는 장치**라서, "조건은 반드시 한 줄"처럼 업무 규칙으로
> 못 박아야 한다면 검증 코드로 따로 확인하는 편이 안전하다.

> 💡 위 예제에는 `DEFAULT sy-datum TO sy-datum`과 `NO INTERVALS`가 함께 있다. `TO` 뒤의 값은
> `HIGH` 칸의 기본값인데, `NO INTERVALS`가 바로 그 칸을 화면에서 감춘다. 값은 들어가 있지만
> 사용자 눈에는 안 보이는 상태라 헷갈리기 쉽다. 둘을 같이 쓸 땐 **"숨긴 칸에도 값이 들어
> 있다"** 는 걸 기억하자.

## MODIF ID — 한 그룹을 한꺼번에 제어

같은 `MODIF ID`를 준 항목들을, 화면이 뜨기 직전 **묶어서** 보이기/숨기기·잠그기 할 수 있다.

```abap
PARAMETERS: pa_basic AS CHECKBOX,
            pa_adv1  TYPE c LENGTH 10 MODIF ID adv,
            pa_adv2  TYPE c LENGTH 10 MODIF ID adv.

DATA gs_screen TYPE screen.

AT SELECTION-SCREEN OUTPUT.                  " 화면 뜨기 직전
  LOOP AT SCREEN INTO gs_screen.
    IF gs_screen-group1 = 'ADV' AND pa_basic = 'X'.  " MODIF ID adv → GROUP1='ADV'
      gs_screen-active = '0'.                " 0=숨김 (1=표시)
      MODIFY SCREEN FROM gs_screen.          " 반드시 반영
    ENDIF.
  ENDLOOP.
```

- `MODIF ID adv`는 화면 runtime에서 `SCREEN-GROUP1`에 **`ADV`(대문자)** 로 들어간다.
- [[AT SELECTION-SCREEN OUTPUT]]의 `LOOP AT SCREEN INTO gs_screen`에서 `group1`로 묶어
  `active`/`input`을 바꾸고 `MODIFY SCREEN FROM gs_screen`으로 반영한다.

## 흔한 실수와 점검

- **`OBLIGATORY`로 검증 끝이라 착각** → 필수 입력과 값의 **업무적 유효성**은 다르다.
- **`LOWER CASE`를 아무 타입에나** → 문자형 필드에만 의미가 있다.
- **`MEMORY ID` 충돌** → 같은 Parameter ID를 엉뚱한 필드에 쓰면 값이 섞인다. 고유하게.
- **`MODIF ID` 제어가 안 먹음** → `AT SELECTION-SCREEN OUTPUT`에서 `MODIFY SCREEN FROM gs_screen`까지 해야 반영된다.

## 정리

- 선택화면 옵션은 작은 문법처럼 보이지만 **사용자 경험을 크게 바꾼다.**
- 입력 필수·기본값·대소문자·복수 선택·화면 제어 group을 **옵션으로 먼저** 해결하고,
  그래도 안 되면 event 코드로 간다.
