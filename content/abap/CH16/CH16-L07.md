## 버튼을 누른 뒤 — PAI

[[PAI]](Process After Input)는 사용자가 **버튼·Enter**를 누른 뒤 실행된다. 어떤 버튼이
눌렸는지는 명령 필드 **`OK_CODE`**(화면의 OK field와 같은 이름의 ABAP 변수)로 안다.
`예매`·`뒤로`·`종료`·`취소`는 모두 다른 의미이므로, 이 판단을 제대로 해야 한다.

## 안전한 분기 — save_ok 패턴

공식 권장 패턴은 PAI 처음에 `OK_CODE`를 **보조 변수 `save_ok`로 복사한 뒤 바로
`CLEAR`** 하고, `save_ok`로 분기하는 것이다.

```abap
DATA: ok_code  TYPE sy-ucomm,
      save_ok  TYPE sy-ucomm,
      gv_seats TYPE i.               " 화면의 좌석 수 입력칸

MODULE user_command_0100 INPUT.
  save_ok = ok_code.            " 보조 변수로 복사
  CLEAR ok_code.               " OK field 즉시 비움

  CASE save_ok.
    WHEN 'SAVE'.
      PERFORM check_booking.   " 예매 검증·저장
    WHEN 'BACK'.
      LEAVE TO SCREEN 0.       " 화면 종료
    WHEN 'EXIT'.
      LEAVE PROGRAM.           " 프로그램 종료
    WHEN 'CANCEL'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.
```

> 💡 **왜 바로 `CLEAR`?** OK field를 비우지 않으면, 그 다음 Enter를 눌렀을 때 이전
> `'SAVE'`가 **그대로 남아 다시 실행**될 수 있다. 읽자마자 비우는 게 핵심이다.
> (`PERFORM`은 [FORM / PERFORM 기본 호출](CH10-L01.html)에서 본 모듈 호출이다.)

`PERFORM check_booking.`으로 부른 이상, 같은 프로그램 안에 **`FORM check_booking` 정의가
반드시 있어야** 한다. 없으면 활성화 단계에서 "부를 대상이 없다"며 막힌다. 지금은 검증
자리만 잡아 두자.

```abap
FORM check_booking.
  IF gv_seats <= 0.
    MESSAGE '좌석 수는 1 이상이어야 합니다' TYPE 'E'.
  ENDIF.
  " 잔여석 확인 같은 본격 검증은 실습(L10)에서 채운다
ENDFORM.
```

## 화면을 떠나는 문장들

| 문장 | 의미 |
|---|---|
| `LEAVE TO SCREEN 0` | next screen을 **0**으로 → 현재 **화면 sequence** 종료(이 화면을 부른 쪽으로 복귀) |
| `LEAVE PROGRAM` | 프로그램(트랜잭션) **전체** 종료 — 강한 종료 |
| `SET SCREEN <번호>` | **다음 화면 번호만 지정** — 즉시 안 나가고, 처리 끝에 그 화면 호출 |
| `LEAVE SCREEN` | 현재 화면 처리를 **즉시** 끝내고 다음 화면 호출 |

- ⚠️ `SET SCREEN`은 "다음에 갈 화면"을 정할 뿐 **즉시 떠나지 않는다.** 지금 바로
  떠나려면 `LEAVE SCREEN`(또는 `LEAVE TO SCREEN`)과 함께 쓴다.

## BACK · EXIT · CANCEL — 관례

화면 위 표준 버튼 셋은 역할이 정해져 있다.

- **BACK**(초록 화살표) — 한 단계 뒤로(`LEAVE TO SCREEN 0`).
- **EXIT** — 트랜잭션 종료(`LEAVE PROGRAM`). **한 화면 뒤로 가는 버튼에 함부로 쓰면**
  사용자가 트랜잭션 전체를 잃는다.
- **CANCEL** — 입력 취소하고 뒤로(`LEAVE TO SCREEN 0`).

> 🔶 화면에 **목록**을 보여줄 땐 Table Control 대신 [Grid ALV 기초](CH17-L01.html)를
> 쓴다(이 과정은 Table Control을 다루지 않는다).

## 값을 안 채우면 나갈 수도 없다 — AT EXIT-COMMAND

여기에 함정이 하나 있다. 화면에 **필수입력** 칸이 있거나 DDIC 필드를 얹어 자동 검사가
걸려 있으면, 사용자가 칸을 비운 채 **뒤로** 버튼을 눌러도 "값을 입력하세요" 오류만 뜬다.
입력 검사가 PAI 모듈보다 **먼저** 돌기 때문에, 우리가 만든 `CASE save_ok`까지 오지도
못한다. 사용자는 필요도 없는 값을 억지로 채워야 화면을 빠져나가는 셈이다.

그래서 **나가기 버튼은 다른 길**로 처리한다.

1. 나가기 버튼(BACK·EXIT·CANCEL)의 **function type을 `E`**(Exit command)로 지정한다.
   버튼과 그 속성을 만드는 곳은 [PF-STATUS와 TITLEBAR](CH16-L08.html)에서 배울 GUI Status다.
2. flow logic의 PAI **맨 앞**에 `AT EXIT-COMMAND` 모듈을 둔다.

```abap
PROCESS AFTER INPUT.
  MODULE exit_0100 AT EXIT-COMMAND.   " 입력 검사보다 먼저 실행
  MODULE user_command_0100.
```

```abap
MODULE exit_0100 INPUT.
  save_ok = ok_code.
  CLEAR ok_code.

  CASE save_ok.
    WHEN 'BACK' OR 'CANCEL'.
      LEAVE TO SCREEN 0.              " 화면 종료
    WHEN 'EXIT'.
      LEAVE PROGRAM.                  " 프로그램 종료
  ENDCASE.
ENDMODULE.
```

- 이 모듈은 **function type이 `E`인 버튼을 눌렀을 때만**, 그리고 **입력 검사보다 먼저**
  실행된다. 그래서 칸이 비어 있어도 화면을 떠날 수 있다.
- 반대로 저장처럼 **값이 제대로 들어와야 하는** 처리는 여기 넣지 않는다. 아직 검사를 거치지
  않은 값이라 믿을 수 없다. 그런 일은 일반 PAI 모듈(`user_command_0100`)에서 한다.

## 직접 분기시켜 보기 — OK_CODE 안전 분기 실험실

버튼을 눌러 `ok_code` → `save_ok` 복사 → `CLEAR` → `CASE` 분기를 따라가 보자. 특히
**`CLEAR`를 생략한 채 SAVE 뒤 Enter**를 누르면 이전 `SAVE`가 어떻게 재실행되는지 확인하자.

## 흔한 실수와 점검

- **`OK_CODE`를 안 비움** → 이전 명령이 남아 Enter에 재실행된다. 읽은 뒤 바로 `CLEAR`.
- **읽기 전에 `CLEAR`** → 값을 잃는다. **먼저 `save_ok`로 복사**한 뒤 비운다.
- **EXIT에 `LEAVE TO SCREEN 0`** → EXIT는 트랜잭션 종료(`LEAVE PROGRAM`)다. 화면 종료와 구분.
- **`SET SCREEN`만 쓰고 안 떠남** → 즉시 이동하려면 `LEAVE SCREEN`을 함께.
- **`PERFORM`만 있고 `FORM`이 없음** → 부르는 이름과 같은 `FORM ... ENDFORM` 정의가 없으면
  활성화가 막힌다.
- **필수입력 칸 때문에 뒤로가 안 먹힘** → 나가기 버튼은 function type `E` + `AT EXIT-COMMAND`
  모듈로 처리한다.

## 정리

- **PAI**는 사용자의 행동을 해석하는 단계다. `OK_CODE`를 **`save_ok`로 옮기고 바로
  `CLEAR`** 한 뒤 `CASE`로 분기하는 게 기본 패턴이다.
- **화면 종료(`LEAVE TO SCREEN 0`)와 프로그램 종료(`LEAVE PROGRAM`)를 구분**해야 안전한 흐름이 된다.
- 필수입력 검사에 막혀 나가지 못하는 일을 막으려면, 나가기 버튼은 function type `E`로 두고
  `AT EXIT-COMMAND` 모듈에서 처리한다.
