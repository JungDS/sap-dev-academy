## 화면 안에 컨트롤을 얹을 자리

입력칸만으로 끝나는 업무는 많지 않다. 예매 화면에는 좌석표나 예매 목록을 ALV로
보여 주고 싶고([Grid ALV 기초](CH17-L01.html)), 한 화면을 공연 정보·예매자 정보·상태로
나누고 싶을 수도 있다. 이 레슨은 화면 안에 **무엇을 얹을 자리**를 만드는 요소들을 다룬다.
완성 ALV는 여기서 구현하지 않는다. **자리와 구조**만 잡는다.

| 요소 | 역할 | 이 챕터에서의 범위 |
|---|---|---|
| **Custom Control** | 화면 안의 빈 **사각 영역** | ALV Grid를 얹을 자리 |
| **Custom Container** | Custom Control 영역과 control 객체를 **연결** | `CL_GUI_CUSTOM_CONTAINER` 선행 사용 |
| **Tabstrip** | 한 화면을 여러 **탭 페이지**로 분리 | 탭 title·function code·subscreen 연결 |
| **Subscreen Area** | 화면 안에 **다른 화면을 끼워** 넣는 영역 | `CALL SUBSCREEN` 흐름 |
| **Status Icon** | 상태를 **아이콘·텍스트**로 표시 | 매진·가능·오류 표시 |

## Custom Control과 Container

화면에 Custom Control 영역(`CONT100`)을 두고, 거기에 [[Custom Container]] 객체를 연결한다.

```abap
DATA go_cont TYPE REF TO cl_gui_custom_container.

MODULE create_container_0100 OUTPUT.
  IF go_cont IS INITIAL.                   " 한 번만 생성
    CREATE OBJECT go_cont
      EXPORTING container_name = 'CONT100'.  " 화면 영역 이름과 같아야
  ENDIF.
ENDMODULE.
```

> 🔎 **[선행 사용]** `TYPE REF TO`·`CREATE OBJECT`는 [Global Class 생성과 객체](CH21-L01.html)에서
> 정식으로 배운다. 여기선 "Custom Control 이름 `CONT100`에 container 객체를 연결한다"는
> 블랙박스로만 받아들이면 된다. (객체지향 언어를 다뤄 본 적 있다면 **참조 변수 선언 +
> 생성자 호출**로 읽으면 그대로 맞다.)

- ⚠️ Container를 **PBO마다 새로** 만들면 안 된다. PBO는 화면이 뜰 때마다 다시 도는 자리라,
  그때마다 container 객체가 **하나씩 새로 생기고 앞서 만든 객체는 정리되지 않는다.**
  이렇게 객체가 언제 생기고 언제 없어지는지가 어긋나는 문제를 **생명주기 문제**라고 한다.
  그래서 `IF go_cont IS INITIAL`로 **한 번만** 생성한다.
- Custom Control은 **내용물이 아니라 빈 사각 영역**이다. container와 실제 control을
  만들어야 내용이 보인다(ALV는 [Grid ALV 기초](CH17-L01.html)에서 이 `go_cont`에 얹는다).

## Subscreen — 화면 안에 다른 화면

`Subscreen Area`는 화면 안에 다른 [[Dynpro]]를 끼워 넣는 영역이다. Flow Logic에서
`CALL SUBSCREEN`으로 포함한다.

```abap
PROCESS BEFORE OUTPUT.
  CALL SUBSCREEN sub_area INCLUDING sy-repid '0110'.

PROCESS AFTER INPUT.
  CALL SUBSCREEN sub_area.
  MODULE user_command_0100.
```

한 줄이 짧아 보이지만 조각이 네 개다.

| 조각 | 뜻 |
|---|---|
| `sub_area` | Screen Painter에서 만든 **Subscreen Area 이름**(ABAP에 따로 선언하지 않는다) |
| `INCLUDING` | "이 영역에 **아래 화면을 끼워 넣어라**"를 잇는 말 |
| `sy-repid` | 끼워 넣을 화면이 들어 있는 **프로그램 이름**(보통 나 자신) |
| `'0110'` | 끼워 넣을 **화면 번호** |

- PBO에는 `INCLUDING`이 붙고 PAI에는 안 붙는다. **무엇을 끼울지 정하는 일은 화면을 그리기
  직전 한 번**이면 되고, PAI에서는 "아까 끼운 그 영역의 입력도 함께 처리하라"는 뜻이라
  영역 이름만 있으면 되기 때문이다. 대신 **PBO에 부르면 PAI에도 짝을 맞춰** 불러야 subscreen
  안의 입력이 처리된다.
- ⚠️ **Subscreen은 자체 OK field를 가질 수 없다.** 사용자 명령의 function code는 **main
  화면의 `OK_CODE`로 모인다.** 처리 책임은 main의 PAI 흐름에 있다.

## Tabstrip — 한 화면을 탭으로 나누기

탭 하나는 **탭 버튼**과 **그 탭에 보여 줄 subscreen**이 짝이다. 사용자가 탭을 누르면 그 탭의
function code가 PAI로 오고, 우리가 **지금 활성 탭**을 기록해 두면 PBO에서 그 탭에 맞는
subscreen을 끼운다.

```abap
CONTROLS tab_main TYPE TABSTRIP.     " 화면의 Tabstrip과 이어지는 제어 구조

DATA: ok_code   TYPE sy-ucomm,
      gv_subscr TYPE sy-dynnr.       " 지금 끼울 subscreen 화면 번호

MODULE tab_command_0100 INPUT.       " PAI — 탭을 눌렀다
  CASE ok_code.
    WHEN 'TAB1' OR 'TAB2'.
      tab_main-activetab = ok_code.  " 눌린 탭을 활성 탭으로 기록
  ENDCASE.
ENDMODULE.

MODULE set_tab_0100 OUTPUT.          " PBO — 활성 탭에 맞는 화면 고르기
  IF tab_main-activetab = 'TAB2'.
    gv_subscr = '0120'.              " 예매자 정보 화면
  ELSE.
    gv_subscr = '0110'.              " 공연 정보 화면
  ENDIF.
ENDMODULE.
```

Flow Logic에서는 화면 번호를 고정 대신 그 변수로 준다.

```abap
PROCESS BEFORE OUTPUT.
  MODULE set_tab_0100.
  CALL SUBSCREEN sub_area INCLUDING sy-repid gv_subscr.
```

> 🔎 **[선행 사용]** `CONTROLS tab_main TYPE TABSTRIP.`은 화면에 그린 Tabstrip과 프로그램을
> 잇는 **화면 전용 선언문**이다. 지금은 "활성 탭 이름을 담는 특별한 변수를 하나 만든다"
> 정도로 받아들이면 된다. 문법을 분석하거나 외울 필요는 없다.

## Status Icon — 상태를 아이콘으로

"매진인가 예매 가능인가"를 글자로 쓰는 대신 신호등처럼 보여 주는 요소다. Screen Painter에서
요소 타입을 **Status Icon**으로 두고, 프로그램에서는 같은 이름의 문자 필드에 **아이콘 이름**을
넣어 준다.

```abap
DATA: gv_icon TYPE c LENGTH 4,       " 화면의 Status Icon 필드와 같은 이름
      gv_left TYPE i.                " 남은 좌석 수

MODULE set_icon_0100 OUTPUT.         " PBO에서 채운다
  IF gv_left = 0.
    gv_icon = icon_red_light.        " 🔴 매진
  ELSE.
    gv_icon = icon_green_light.      " 🟢 예매 가능
  ENDIF.
ENDMODULE.
```

- `icon_red_light` 같은 아이콘 이름은 SAP이 미리 만들어 둔 상수다(타입 그룹 `ICON`).
  실제 값은 `'@0A@'` 같은 짧은 문자라, 화면에서는 그 값이 아이콘 그림으로 보인다.
- 값을 넣는 자리는 **PBO**다. 상태가 바뀌면 다음 PBO에서 다시 채워야 아이콘도 바뀐다.

> 🔶 **Table Control은 다루지 않는다.** classic 화면에는 표를 보여 주는 Table Control도
> 있지만, 표 형태 데이터 표시는 이 과정에서 [Grid ALV 기초](CH17-L01.html)로 대체한다.

## 흔한 실수와 점검

- **Container 이름 불일치** → 화면 Custom Control 이름과 `container_name`이 같아야 붙는다.
- **컨테이너를 PBO마다 생성** → `IF go_cont IS INITIAL`로 한 번만.
- **Subscreen에 OK field 기대** → 없다. 명령은 main 화면 `OK_CODE`로 처리.
- **Tabstrip을 탭만 그리고 끝** → 탭 버튼의 function code·`activetab`·subscreen area·`CALL
  SUBSCREEN`이 모두 맞아야 동작한다.
- **PBO에만 `CALL SUBSCREEN`** → PAI에도 짝을 맞춰 불러야 subscreen 안의 입력이 처리된다.
- **Status Icon에 직접 글자 입력** → 넣을 값은 `icon_...` 상수(아이콘 이름)다.

## 정리

- **Custom Control**은 ALV를 담을 **자리**, **Subscreen·Tabstrip**은 화면을 **나누는 구조**,
  **Status Icon**은 상태를 한눈에 보여 주는 **표시 요소**다.
- Tabstrip은 "탭 클릭 → `activetab` 기록(PAI) → 그 탭의 subscreen 끼우기(PBO)"라는 **한 바퀴**로
  움직인다.
- OO 문법과 Grid 구현은 뒤로 미루고, 지금은 **화면 영역과 프로그램 연결**까지만 정확히 잡는다.
