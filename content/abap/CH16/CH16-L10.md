## 🎫 종합 — 직접 설계한 예매 입력 화면

앞 레슨을 따로 보면 Dynpro가 조각처럼 느껴진다. 마지막 실습에서 예매 입력 화면 `0100`을
만든다고 가정하고, Screen Painter 요소·PBO·PAI·OK_CODE·PF-STATUS·검증을 **하나의 흐름**으로 묶는다.

> 이 실습의 성공 기준은 **DB 저장이 아니다.** 실제 저장(`INSERT`·`COMMIT WORK`)과 잠금은
> [실무 데이터 변경과 트랜잭션 제어](CH25-L01.html) 이후에서 다룬다. 여기 목표는 **값 입력 →
> 버튼 → 검증 메시지 → 안전한 화면 종료**의 흐름을 만드는 것이다.

### 요구사항

- Module Pool을 만들고 T-code로 화면 `0100`을 실행한다([Module Pool 프로그램 구조](CH16-L01.html)).
- 화면에 `GV_CONC`(F4)·`GV_PERF`·`GV_SEATS`·`GV_CUST`·`GV_STAT`·`OK_CODE`를 둔다.
- PBO에서 PF-STATUS·TITLEBAR를 켜고 상태 드롭다운을 채운다.
- PAI에서 `OK_CODE`를 `save_ok`로 옮기고 `CLEAR`한 뒤, `SAVE`면
  [잔여석 계산·예매 판정](CH10-L07.html)의 `can_book`으로 검증한다.
- 공연 정보는 DDIC `ZCONCERT`에서 오므로 `TABLES zconcert`로 잇고, 공연에 따라 달라지는
  회차 F4는 직접 만든다([Dictionary 운반](CH16-L04.html)·[F1·F4 직접 만들기](CH16-L05.html)).

## 만들기 절차 — SE80에서 순서대로

코드를 쓰기 전에 **그릇부터** 만든다. `SE80`에서 아래 순서대로 진행하면 된다.

1. **Module Pool 만들기** — `SE80` → Repository Browser에서 Program을 고르고 이름
   `SAPMZCONCERT`를 입력해 새로 만든다. Type은 **Module Pool**(M)로 고르며, 첫 줄은
   `PROGRAM sapmzconcert.`가 된다. 저장하고 **활성화**한다.
2. **화면 0100 만들기** — 같은 프로그램 아래에서 Screen을 새로 만들고 번호 `0100`을 준다.
   Attributes에서 화면 타입은 Normal, next screen은 `0100`(자기 자신, 그래야 처리 뒤 같은
   화면이 다시 뜬다)으로 둔다.
3. **Layout 그리기** — Screen Painter Layout에서 입력칸 `GV_CONC`·`GV_PERF`·`GV_SEATS`·
   `GV_CUST`, 드롭다운 `GV_STAT`, 버튼을 배치한다. Element List에서 **OK field 이름을
   `OK_CODE`로** 지정하고, `GV_STAT`의 Dropdown 속성은 `Listbox`로 둔다.
4. **Flow Logic 채우기** — `PROCESS BEFORE OUTPUT` / `PROCESS AFTER INPUT` 블록에 부를
   모듈 이름을 적는다(아래 통합 코드의 Flow Logic 부분).
5. **모듈·FORM 작성** — 모듈 이름을 더블클릭하면 SE80이 "어느 include에 만들까요?" 하고
   묻는다. 선언은 `...TOP`, PBO 모듈은 `...O01`, PAI 모듈은 `...I01`, `FORM`은 `...F01`
   include에 만들면 [Module Pool 프로그램 구조](CH16-L01.html)에서 본 표준 구조가 된다.
6. **GUI Status·Titlebar 만들기** — `SE41`(또는 SE80 안에서) `ST100`·`TB100`을 만들고
   버튼 FctCode를 `SAVE`·`BACK`·`EXIT`·`CANCEL`로 준다. 나가기 버튼 셋은 function type을
   `E`로 지정한다([PAI 처리 흐름 — OK_CODE와 화면 떠나기](CH16-L07.html)).
7. **T-code 연결** — `SE93`에서 T-code(예: `ZCONCERT01`)를 만들어 프로그램
   `SAPMZCONCERT` + 화면 `0100`을 지정한다. 이제 T-code로 실행된다.
8. **활성화** — 프로그램·화면·GUI Status를 모두 활성화한다. 하나라도 비활성이면 실행할 때
   오류가 난다.

## 통합 코드 — 화면 준비(PBO)

> 💡 아래 두 블록은 **한 코드 블록에 Flow Logic과 ABAP module을 함께** 보여 준다. 실제로는
> Flow Logic은 Screen Painter에, `MODULE ... ENDMODULE`은 program source(include)에 **따로**
> 있다. 프로그램 소스에 Flow Logic을 그대로 쓰면 구문 오류다. 블록 안의 구분선을 보고
> "여기부터는 다른 곳"이라고 읽자.

```abap
" ===== ABAP source (…TOP include) =====
PROGRAM sapmzconcert.

DATA: gv_conc  TYPE zconcert-concert_id,
      gv_perf  TYPE n LENGTH 3,
      gv_seats TYPE i,
      gv_cust  TYPE c LENGTH 30,
      gv_stat  TYPE c LENGTH 1,
      gv_ok    TYPE abap_bool,      " 예매 가능 판정 결과
      ok_code TYPE sy-ucomm,
      save_ok TYPE sy-ucomm.

DATA: gt_values TYPE vrm_values,
      gs_value  LIKE LINE OF gt_values.

" ===== Flow Logic (Screen Painter · 화면 0100) =====
PROCESS BEFORE OUTPUT.
  MODULE status_0100.
  MODULE fill_status_list.
PROCESS AFTER INPUT.
  MODULE user_command_0100.

" ===== ABAP source (…O01 include) =====
MODULE status_0100 OUTPUT.
  SET PF-STATUS 'ST100'.
  SET TITLEBAR  'TB100' WITH gv_conc.   " 제목 "공연 &1" → gv_conc
ENDMODULE.

MODULE fill_status_list OUTPUT.        " 상태 드롭다운 채우기
  CLEAR gt_values.
  gs_value-key = 'N'. gs_value-text = '신규'. APPEND gs_value TO gt_values.
  gs_value-key = 'C'. gs_value-text = '취소'. APPEND gs_value TO gt_values.
  CALL FUNCTION 'VRM_SET_VALUES'
    EXPORTING id = 'GV_STAT' values = gt_values.
ENDMODULE.
```

## 통합 코드 — 입력 처리(PAI)

```abap
" ===== ABAP source (…I01 include) =====
MODULE user_command_0100 INPUT.
  save_ok = ok_code.                   " 보조 변수로 복사
  CLEAR ok_code.                       " 즉시 비움(반복 실행 방지)

  CASE save_ok.
    WHEN 'SAVE'.
      PERFORM can_book USING gv_conc gv_perf gv_seats CHANGING gv_ok.
      IF gv_ok = abap_true.
        MESSAGE '예매 가능 — 저장은 이후 단계에서' TYPE 'S'.
      ELSE.
        MESSAGE '좌석이 부족합니다' TYPE 'E'.   " 화면 유지(정상 검증)
      ENDIF.
    WHEN 'BACK' OR 'CANCEL'.
      LEAVE TO SCREEN 0.               " 화면 종료
    WHEN 'EXIT'.
      LEAVE PROGRAM.                   " 프로그램 종료
  ENDCASE.
ENDMODULE.
```

- ⚠️ **판정 결과를 왜 `gv_ok`라고 지었을까.** `MODULE ... ENDMODULE`은 `FORM`이나 `METHOD`와
  달리 **자기만의 지역 데이터 영역이 없다.** 모듈 안에서 `DATA`로 선언해도 그 변수는
  **프로그램 전역**이 된다. 그래서 이름도 지역을 뜻하는 `lv_`가 아니라 전역을 뜻하는 `gv_`로
  붙이고, 선언도 위쪽 전역 선언부에 모아 둔다.
- `abap_bool`·`abap_true`는 [실습 — 잔여석 계산·예매 판정 모듈화](CH10-L07.html)에서 쓴 그
  이름이다. `abap_true`의 실제 값은 이 챕터에서 계속 봐 온 문자 `'X'`다. ABAP에 참/거짓
  전용 타입이 따로 있는 게 아니라, 문자 한 칸에 `'X'`나 공백을 담는 그 방식에 **읽기 좋은
  이름을 붙여 둔 것**이다.
- `can_book`은 [실습 — 잔여석 계산·예매 판정 모듈화](CH10-L07.html)에서 만든 `FORM`이다.
  이 화면 프로그램에서 부르려면 같은 `FORM`을 이 Module Pool의 `...F01` include에 옮겨 둬야
  한다. 부르기만 하고 정의가 없으면 활성화가 막힌다.

## 화면 필드 연결·입력 도움 반영

공연ID를 받는 입력칸은 우리가 만든 화면 필드 `GV_CONC`다. 여기에 DDIC `ZCONCERT`의 필드
(아티스트·공연장)까지 함께 얹고 싶으면 [[TABLES]]로 잇고, 공연에 따라 달라지는 회차 F4는
[[PROCESS ON VALUE-REQUEST]]로 직접 만든다.

```abap
" ===== ABAP source (…TOP include) =====
TABLES zconcert.                 " DDIC 필드를 얹기 위한 work area (L04)

" ===== Flow Logic (화면 0100) =====
PROCESS ON VALUE-REQUEST.        " 회차 F4 (L05)
  FIELD gv_perf MODULE value_perf.
```

- **이름이 곧 연결이다.** 공연ID 입력칸의 화면 요소 이름이 `GV_CONC`이므로, `value_perf`
  모듈도 `DYNP_VALUES_READ`로 `'GV_CONC'`를 읽어야 값이 잡힌다.
  [화면에서 F1·F4 직접 만들기](CH16-L05.html)에서 만든 모듈이 바로 그 이름으로 읽으니 그대로
  가져다 쓰면 된다. 이름이 어긋나면 회차 후보가 **항상 비어** 버린다.
- ⚠️ **`TABLES zconcert.`는 DB를 읽지 않는다.** 선언은 값을 담을 그릇을 만들 뿐이다. 화면의
  `ZCONCERT-ARTIST`에 실제 아티스트 이름을 띄우려면 PBO에서 `SELECT`로 `zconcert`를 읽어
  work area를 채워야 한다(이 실습은 거기까지 하지 않는다). 라벨과 F4는 DDIC 정의에 있는
  만큼 따라온다.
- 사용자가 입력하는 `gv_conc`와 work area의 `zconcert-concert_id`는 **이름이 다르므로 저절로
  같아지지 않는다.** 맞춰야 한다면 코드에서 직접 옮긴다(`zconcert-concert_id = gv_conc.`).
- `GV_CUST`(고객명)·`GV_STAT`(상태)은 화면에서 값을 받지만 이번 검증(`can_book`)에는 쓰이지
  않는다. **저장할 때 필요한 값**이라, 저장을 다루는 이후 챕터에서 쓰인다.
- 원리는 [Dictionary 화면 필드와 TABLES 운반](CH16-L04.html)·[화면에서 F1·F4 직접 만들기](CH16-L05.html).

## 직접 실행해 보기 — 예매 입력 Dynpro 통합 시뮬레이터

좌석 수를 바꾸고 버튼을 눌러, PBO 준비 → PAI 검증 → 메시지/종료의 한 흐름을 따라가 보자.
**좌석 과다 입력 시 `MESSAGE E`로 화면이 유지**되는지, `SAVE` 뒤 Enter가 재실행되지 않는지 확인하자.

## 검증 시나리오

| 시나리오 | 입력/행동 | 기대 결과 |
|---|---|---|
| 정상 예매 검증 | `C001`·회차 `001`·좌석 `2` · `SAVE` | 성공 메시지(저장 없음) |
| 좌석 부족 | 좌석 과다 · `SAVE` | `MESSAGE E` · 화면 유지 |
| 상태 선택 | 드롭다운 `신규` | `gv_stat = 'N'` |
| BACK | `BACK` | `LEAVE TO SCREEN 0`(화면 sequence 종료) |
| EXIT | `EXIT` | `LEAVE PROGRAM`(프로그램 종료) |
| 반복 방지 | `SAVE` 후 Enter | 이전 SAVE가 재실행되지 않음 |

## 흔한 실수와 주의

- **Flow Logic과 ABAP source를 같은 곳에** → 설명상 합쳤을 뿐, 실제 위치는 다르다.
- **`MESSAGE E` 후 화면 유지를 실패로 오해** → 정상 검증 흐름이다(잘못 입력을 막고 다시 받음).
- **저장까지 기대** → 화면·검증까지가 이 챕터. `INSERT`·`COMMIT WORK`은 이후.
- **EXIT를 `LEAVE TO SCREEN 0`으로** → EXIT는 `LEAVE PROGRAM`. 화면 종료와 프로그램 종료를 구분.
- **모듈 안에서 `DATA lv_...`** → 모듈에는 지역 데이터 영역이 없다. 전역이므로 `gv_`로 짓고
  선언부에 모은다.

## 정리

직접 만든 화면의 **생명주기를 한 번에** 묶었다 — PBO가 준비하고, 사용자가 입력하고,
PAI가 `OK_CODE`를 읽어 검증·종료한다.

```text
Dynpro    = 직접 설계한 화면
PBO       = 보여 주기 전 준비(상태·제목·목록·속성)
PAI       = 사용자 행동 뒤 처리(OK_CODE 복사→CLEAR→CASE)
화면 종료 = LEAVE TO SCREEN 0 / 프로그램 종료 = LEAVE PROGRAM
화면 표   = Table Control이 아니라 Grid ALV로 이어진다
```

내가 설계한 입력 화면을 완성했다. 이제 화면 안에 **표**(좌석·예매 목록)를 박는 법으로
넘어가자 → [Grid ALV 기초](CH17-L01.html).
