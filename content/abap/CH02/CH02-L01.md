## 리터럴의 한계

[Chapter 1](CH01-L04.html)에서 `WRITE 'Hello'.`처럼 값을 **따옴표에 직접** 적었다.
이렇게 코드에 값을 그대로 적어 넣은 것을 [[리터럴]](literal)이라 한다. 그런데 같은 값을
여러 번 쓰거나, 계산 결과를 보관하려면? 리터럴로는 안 된다.
**값을 담아 둘 그릇**, 곧 [[변수]]가 필요하다.

## DATA로 변수 선언

[[DATA]] 문으로 변수를 선언한다. `이름 TYPE 타입` 형태다.

```abap
DATA gv_name TYPE string.
DATA gv_count TYPE i.
```

- `gv_` 접두어는 관례(**g**lobal **v**ariable). 강제는 아니지만 팀 표준을 따른다.
- **전역**은 "이 프로그램 안 어디서나 보인다"는 뜻이다. 다른 프로그램과 공유된다는 말이
  아니라, **한 프로그램 안에서** 위에서 선언한 변수를 아래 어느 줄에서든 쓸 수 있다는 뜻이다.
  아직 Subroutine(프로그램을 잘게 나누는 단위)을 안 배웠으니 **선언하는 변수는 모두 전역**이고,
  그래서 `g`로 시작한다. 특정 구간 안에서만 보이는 변수는 `lv_`(로컬)라 부르는데, 그 이야기는
  나중에 한다.
- `TYPE` 뒤에 어떤 타입인지 적는다(다음 레슨들의 주제).

> 🧑‍💻 **다른 언어를 해 봤다면** 선언과 대입 자체는 낯설지 않다. 지금 모든 변수가 전역인 건
> 프로그램을 잘게 나누는 법을 아직 안 배워서일 뿐이고, 실무 ABAP도 모듈화한 뒤에는 로컬 변수가
> 기본이다. 이 레슨에서 새로 챙길 건 사실상 `LIKE` 하나뿐이니 빠르게 훑고 넘어가도 된다.

## 값 넣고 출력하기

선언한 변수에 값을 대입(`=`)하고 출력해 본다.

```abap
DATA gv_msg TYPE string.
gv_msg = 'Hello, ABAP!'.
WRITE gv_msg.
```

이제 메시지를 한 곳(`gv_msg`)에서 관리한다. 바꿀 때 한 줄만 고치면 된다.

## 선언과 동시에 초기값 — `VALUE`

`=`로 나중에 넣는 대신, 선언하면서 **바로 초기값**을 주려면 `VALUE`를 붙인다.

```abap
DATA gv_qty  TYPE i      VALUE 10.       " 선언과 동시에 10으로 시작
DATA gv_city TYPE string VALUE '서울'.   " 문자열도 같은 방식
```

`VALUE`를 안 적으면 변수는 **타입의 기본값**으로 시작한다. 숫자 타입은 `0`이다.
문자 쪽은 두 갈래인데, 길이가 정해진 문자는 그 길이만큼 **공백**으로 채워지고,
`string`은 공백조차 없는 **길이 0의 빈 문자열**로 시작한다. 참고로 뒤에서 배울
`N`·`D`·`T`는 문자형인데도 공백이 아니라 `0`으로 채워진다(그 타입을 배울 때 다시 짚는다).

지금 배우는 값 타입들에는 다른 언어의 `null`(값이 아예 없는 상태) 같은 상태가 없다.
선언만 해도 이미 기본값이 들어 있어서, 값을 넣기 전에 읽어도 오류가 나지 않는다.

## 여러 변수 한 번에 (체인)

콜론(`:`)으로 [[DATA]]를 체인해 여러 변수를 한 번에 선언한다.

```abap
DATA: gv_first TYPE string,
      gv_last  TYPE string,
      gv_age   TYPE i.
```

## TYPE 말고 LIKE — 기존 변수를 본떠

`TYPE` 뒤에는 **타입 이름**을 적지만, `LIKE` 뒤에는 **이미 선언한 변수**를 적는다.
"저 변수와 똑같은 타입으로 하나 더"라는 뜻이다.

```abap
DATA gv_qty   TYPE i.
DATA gv_total LIKE gv_qty.     " gv_qty와 같은 타입(i)
```

한 줄의 수량을 담는 `gv_qty`와 그 수량을 모두 더한 `gv_total`은 **같은 타입이어야 짝이 맞는다.**
`LIKE`로 묶어 두면 원본(`gv_qty`)의 타입이 바뀔 때 `gv_total`도 자동으로 따라 바뀐다.
"이 변수와 짝이 되는 변수"를 만들 때 편하다.

## 흔한 실수와 점검

- **선언 안 한 변수 사용** → `gv_xxx is unknown` 오류. 먼저 [[DATA]]로 선언.
- **타입 누락** → `DATA gv_x.`도 문법상 통과는 된다. 하지만 **길이 1짜리 문자**(C)로
  선언돼 버린다(타입 생략 시의 암묵 기본값). 의도한 게 아니라면 `TYPE`을 명시한다.
- **LIKE 대상이 아래에 있음** → `LIKE`는 **이미(위에) 선언된** 변수만 본뜬다.
  참조할 원본을 먼저 선언한다.

## 정리

- 값을 코드에 직접 적는 [[리터럴]] 대신, [[DATA]]로 **그릇([[변수]])을 만들어** 담는다. 바꿀 곳이 한 곳으로 모인다.
- 선언은 `이름 TYPE 타입` 형태. 지금 선언하는 변수는 모두 **전역**(이 프로그램 안 어디서나 보임)이라 `gv_`로 시작한다.
- 선언과 동시에 값을 주려면 `VALUE`. 안 주면 **타입의 기본값**(숫자 `0`, 길이가 정해진 문자는 공백, `string`은 빈 문자열)으로 시작한다.
- 콜론(`:`) 체인으로 여러 변수를 한 번에 선언한다.
- `TYPE`은 **타입 이름**을, `LIKE`는 **이미 선언한 변수**를 본뜬다. 둘 다 참조 대상이 **위에** 있어야 한다.

**적어야 하는 것**이 있다. 먼저 전자(Complete) → 다음 레슨.
