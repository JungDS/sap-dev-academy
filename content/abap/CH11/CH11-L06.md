## 🎫 3단계 — 예매 목록을 표로

[Chapter 09 · 콘서트 모델](CH09-L09.html) 데이터를 SELECT해 SALV로 깔끔히 띄운다. `WRITE` 리스트와 비교해 보자.

> ✍️ **코드를 보기 전에 30초만.** 예매 목록을 표로 띄우려면 무엇부터 해야 할까? 앞
> 레슨들에서 배운 네 단계를 순서대로 떠올려 보자. 하나는 데이터를 읽어 오는 일, 하나는
> ALV 객체를 만드는 일, 하나는 툴바를 켜는 일, 하나는 화면에 그리는 일이다. 떠올렸으면
> 아래 코드와 맞춰 보자.

```abap
DATA: gt_book  TYPE TABLE OF zbooking,
      go_alv   TYPE REF TO cl_salv_table,
      gv_count TYPE i.

" 한 공연의 예매만 읽는다
SELECT * FROM zbooking INTO TABLE gt_book
  WHERE concert_id = 'C001'.

DESCRIBE TABLE gt_book LINES gv_count.
IF gv_count = 0.
  MESSAGE '조건에 맞는 예매가 없습니다.' TYPE 'I'.
ELSE.
  TRY.
      cl_salv_table=>factory(
        IMPORTING r_salv_table = go_alv
        CHANGING  t_table      = gt_book ).
      go_alv->get_functions( )->set_all( abap_true ).
      go_alv->display( ).
    CATCH cx_salv_msg.
      MESSAGE 'ALV 생성 실패' TYPE 'I'.
  ENDTRY.
ENDIF.
```

> ⚠️ **`WHERE`를 빼면 안 되나?** 빼도 돌아가긴 한다. 다만 `SELECT *`에 조건이 없으면 예매
> 테이블의 **모든 행**을 한꺼번에 메모리로 끌어온다. 연습 데이터는 몇 건뿐이라 티가 안
> 나지만, 예매가 수십만 건 쌓인 시스템에서는 화면이 한참 멎는다. 그래서 위 코드는 공연
> 하나로 범위를 좁혔다.
>
> 그리고 예매 목록에는 누가 어떤 공연을 몇 자리 잡았는지가 들어 있다. 실무라면 "이 사람이
> 이 데이터를 봐도 되는지"부터 확인하고 조회한다. 그 확인 방법은
> [Chapter 15 · 권한 검증](CH15-L07.html)에서 배우니, 지금은 **업무 데이터를 조건 없이 다
> 읽는 건 실무에서 그냥 넘어가지 않는다**는 것만 기억해 두자.

## 직접 해 볼 과제

1. 위 코드를 실행해 예매 목록을 SALV로 띄운다.
2. 컬럼 제목이 **Data Element 라벨**([Chapter 03](CH03-L02.html))로 자동으로 뜨는지 확인.
3. `WHERE`의 공연 번호를 바꿔 다른 공연의 예매만 띄워 본다. 예매가 없는 번호를 넣으면
   안내 메시지가 뜨는지도 확인.
4. 컬럼 제목을 직접 바꾸는 `get_columns( )` 세밀 제어는 [SALV 표시 심화](CH22-L01.html)에서 배운다(지금은 라벨 자동 반영만 확인).

## 흔한 실수와 점검

- **TRY/CATCH 없이 factory** → `cx_salv_msg`는 반드시 처리해야 하는 예외다. 안 잡으면 구문
  검사에서 경고가 뜨고, 실행 중 예외가 나면 덤프로 끝난다([factory 메서드](CH11-L02.html)).
- **CATCH를 비워 두기** → 잡아 놓고 아무것도 안 하면 실패해도 화면에 아무 일이 없어 원인을
  찾기 어렵다. 위처럼 `MESSAGE` 한 줄이라도 남긴다.
- **빈 결과** → 위 `DESCRIBE TABLE`·`IF` 점검을 빼면 조건에 맞는 예매가 없을 때 빈 표만 뜬다.
