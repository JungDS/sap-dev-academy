## 인쇄까지는 됐다, 그런데 "파일로 주세요"

L01의 리포트를 실행하면 인쇄 대화상자가 뜨고, 미리보기로 확인서 모양까지
확인했다. 그런데 실무 요구는 한 발 더 나간다. 고객은 창구에서 종이를 받는 게
아니라 **이메일로 PDF 확인서**를 받고 싶어 한다. 보관용 서버 폴더에 파일로
쌓아 달라는 요구도 온다. 둘 다 "종이"가 아니라 **파일**이다.

미리보기 화면에도 PDF로 내보내는 메뉴가 있긴 하다. 하지만 그건 **사람이 화면
앞에 앉아 손으로 누르는 길**이다. 예매 백 건의 확인서를 매일 보내야 한다면,
사람이 백 번 누를 수는 없다. 우리가 원하는 것은 **프로그램이 PDF 데이터를 직접
손에 쥐는 것**이다. 손에 쥐어야 파일로 저장하든 메일에 붙이든 다음 단계로 넘길
수 있다.

다행히 Smart Forms는 처음부터 이 길을 열어 두었다. 열쇠는 두 가지다. 출력이
프린터로 가기 **전의 원형 데이터**를 이해하는 것, 그리고 그 원형을 **돌려받는
호출 옵션**을 켜는 것.

## 출력의 원형, OTF

Smart Forms가 만드는 최종 산출물은 사실 "종이"가 아니다. 생성 함수가 데이터와
양식을 합쳐 만들어 내는 것은 [[OTF]](Output Text Format. "무엇을 어느 위치에
어떤 글꼴로 찍어라" 같은 출력 명령들의 나열. 특정 프린터 **언어**에 묶이지 않은
중간 형식)라는 **출력 명령 데이터**다. 평소에는 이 OTF가 곧바로 출력
장치 쪽으로 넘어가 종이·미리보기가 되기 때문에 우리 눈에 안 보였을 뿐이다.

이 중립성이 왜 중요한가. 같은 OTF를 프린터 쪽으로 보내면 인쇄가 되고,
**변환기에 넣으면 PDF가 된다.** 원형이 하나라서 목적지를 바꿀 수 있는 것이다.
(완전한 만능은 아니다: 조판할 때 쓰인 출력장치의 **폰트 정보**는 OTF에 이미
반영돼 있어서, 글꼴·자간은 장치 설정을 따른다. 이 사실은
[오류 추적 레슨](CH37-L05.html)의 "폰트 점검"에서 다시 만난다.)
그래서 우리 전략은 이렇게 정리된다.

1. 생성 함수에게 "인쇄하지 말고 **OTF를 나에게 돌려달라**"고 옵션으로 말한다.
2. 돌려받은 OTF를 표준 변환 함수 `CONVERT_OTF`에 넣어 **PDF 데이터**로 바꾼다.

OTF의 실물은 명령 한 줄이 "명령 코드 + 인자"로 된 표(테이블)다. 눈으로 읽고
분석할 대상은 아니고, "이런 원형이 있고 그것을 통째로 변환기에 넘긴다"는 감만
잡으면 된다.

## 표준 파라미터 — 대화상자 대신 OTF를 받는다

여기서 잠깐, L01에서 생긴 오해 하나를 풀고 가자. L01에서 Form Interface는
"**내가 선언한** 데이터 계약"(`IS_BOOKING`)이었다. 그런데 생성 함수에는 내가
선언한 파라미터 말고도, **SAP이 모든 생성 함수에 자동으로 붙여 주는 표준
파라미터**가 한 벌 더 있다(호출 방식 제어·결과 회수용. L01에서 하나도 안 넘기고
도 돌아간 이유는 전부 선택 입력이라 기본값으로 동작했기 때문이다). 이번 레슨의
열쇠가 바로 이 표준 파라미터들이다.

- `control_parameters` — 호출 방식을 제어하는 옵션 구조(시스템 제공 구조
  `SSFCTRLOP`). 여기서 두 필드를 켠다:
  - `getotf = 'X'` — 출력 장치로 보내지 말고 **OTF를 결과로 돌려달라**.
  - `no_dialog = 'X'` — **인쇄 대화상자를 띄우지 말라**. 파일 경로는 사람이
    안 앉아 있는 배치에서도 돌아야 하니, 대화상자가 있으면 안 된다
    (L01 끝의 콜아웃에서 예고한 바로 그 옵션이다).
- `output_options` — 출력 옵션 구조(`SSFCOMPOP`). 대화상자를 껐으니 출력장치를
  물어볼 사람이 없다. **`tddest`에 출력장치 이름을 코드로 지정**한다.
- `user_settings = space` — 이걸 끄지 않으면(기본값 `'X'`) **사용자 개인 인쇄
  설정이 우리가 넘긴 옵션을 덮어쓴다.** 사람마다 결과가 달라지는 원인이라,
  무인 경로에서는 반드시 해제한다.
- `job_output_info` — 호출 **결과 구조**(시스템 제공 구조 `SSFCRESCL`).
  `getotf`를 켰을 때 이 구조의 **`otfdata`** 필드에 OTF 테이블이 담겨 돌아온다.

앞의 셋(제어·출력 옵션·개인 설정 해제)이 무인 호출의 **표준 3종 세트**다.
그리고 옵션을 켰는데 결과(`job_output_info`)를 안 받으면 OTF는 버려지고,
반대로 옵션 없이 결과만 받으면 `otfdata`는 비어 있다. **옵션과 결과는 항상
짝**이다.

## 완결 코드 — 조회, 옵션 호출, 변환

L01 리포트(`z_ticket_print`)를 **복사해 새 이름으로** 만든 완결형이다(인쇄용은
인쇄용대로 남겨 두는 습관). ①은 L01 그대로이고, ②③④가 이번 레슨의 내용이다.

```abap
REPORT z_ticket_pdf.

DATA gs_booking TYPE zbooking.
DATA gv_fm      TYPE rs38l_fnam.        " L01과 동일
DATA gs_ctrl    TYPE ssfctrlop.         " 호출 제어 옵션
DATA gs_output  TYPE ssfcompop.         " 출력 옵션(장치 지정)
DATA gs_job     TYPE ssfcrescl.         " 호출 결과(OTF 포함)
DATA gt_otf     TYPE TABLE OF itcoo.    " OTF 명령 줄들
DATA gt_pdf     TYPE TABLE OF tline.    " 변환 결과 조각들
DATA gv_size    TYPE i.                 " PDF 크기(바이트)

START-OF-SELECTION.
  SELECT SINGLE * FROM zbooking
    WHERE booking_id = '0001'
    INTO @gs_booking.

  " ① Form 이름 → 생성 함수 이름 조회 (L01 그대로)
  CALL FUNCTION 'SSF_FUNCTION_MODULE_NAME'
    EXPORTING  formname = 'ZSF_TICKET'
    IMPORTING  fm_name  = gv_fm
    EXCEPTIONS OTHERS   = 1.
  IF sy-subrc <> 0.
    MESSAGE '양식을 찾을 수 없습니다' TYPE 'E'.
  ENDIF.

  " ② 무인 호출 3종 세트 — OTF 회수·대화상자 끄기·장치 고정
  gs_ctrl-getotf    = 'X'.
  gs_ctrl-no_dialog = 'X'.
  gs_output-tddest  = 'LOCL'.   " 출력장치 이름(시스템에 등록된 값)

  " ③ 생성 함수 호출 — 옵션을 넘기고 결과를 받는다
  CALL FUNCTION gv_fm
    EXPORTING
      control_parameters = gs_ctrl
      output_options     = gs_output
      user_settings      = space       " 개인 인쇄 설정의 덮어쓰기 차단
      is_booking         = gs_booking
    IMPORTING
      job_output_info    = gs_job      " gs_job-otfdata = OTF
    EXCEPTIONS
      OTHERS             = 1.          " 예외 이름들은 L01과 같다
  IF sy-subrc <> 0.
    MESSAGE '양식 처리에 실패했습니다' TYPE 'E'.
  ENDIF.
  gt_otf = gs_job-otfdata.

  " ④ OTF → PDF 변환 (표준 함수)
  CALL FUNCTION 'CONVERT_OTF'
    EXPORTING
      format                = 'PDF'
    IMPORTING
      bin_filesize          = gv_size
    TABLES
      otf                   = gt_otf
      lines                 = gt_pdf
    EXCEPTIONS
      err_max_linewidth     = 1
      err_format            = 2
      err_conv_not_possible = 3
      err_bad_otf           = 4   " OTF가 비었거나 손상됨
      OTHERS                = 5.
  IF sy-subrc <> 0.
    MESSAGE 'PDF 변환에 실패했습니다' TYPE 'E'.
  ENDIF.

  WRITE: / 'PDF 데이터 생성 완료 —', gv_size, '바이트'.
```

낯선 조각들을 짚는다.

- **`TYPE TABLE OF itcoo`** — OTF 명령 한 줄의 구조가 `ITCOO`다(명령 코드와
  인자 필드). 결과 쪽 `TLINE`도 마찬가지로 시스템이 제공하는 줄 구조(고정
  길이 문자 줄)다. 둘 다 [Chapter 6](CH06-L01.html)에서 배운 Internal Table
  선언 그대로라 새 문법은 없다.
- **`tddest = 'LOCL'`** — 출력장치의 **시스템 등록 이름**이다. `LOCL`은 "지금
  접속한 PC의 기본 프린터"를 가리키는 흔한 관례 이름인데, 시스템마다 등록
  이름이 다를 수 있으니 실습 시스템의 값을 쓰면 된다. OTF만 받고 인쇄는 안
  하는데 왜 장치가 필요한가: 조판(글꼴·폭 계산)에 장치의 폰트 정보가 쓰이기
  때문이다(앞의 "완전한 만능은 아니다" 그 이야기다).
- **`TABLES` 블록** — 함수 모듈이 Internal Table을 통째로 주고받는 **옛 방식의
  전달 칸**이다([Chapter 10](CH10-L03.html)에서 "레거시 방식" 한 줄로 지나간
  그것). `CONVERT_OTF`처럼 오래된 표준 함수들이 아직 쓴다. 새 문법이 아니라
  "EXPORTING·IMPORTING 말고 칸이 하나 더 있구나"로 읽으면 된다.
- **`CONVERT_OTF`의 `format = 'PDF'`** — 이 함수는 OTF를 여러 형식으로 바꿀
  수 있어서 목표 형식을 값으로 지정한다. 우리는 PDF.
- **`bin_filesize`** — 변환된 PDF의 **정확한 바이트 크기**를 돌려준다. 0이
  아니라 수만 단위 숫자가 찍히면 변환이 실제로 일어났다는 가장 빠른 증거다.
- **`lines`의 `gt_pdf`** — 변환된 PDF 데이터가 **조각들**로 담기는 테이블이다.
  내용물은 사람이 읽는 글자가 아니라 PDF 파일의 이진 내용이라, `WRITE`로 찍어
  볼 대상이 아니다. 조각 상태는 파일로 만들기 번거로워서,
  [다음다음 레슨(L04)](CH37-L04.html)에서는 같은 함수가 제공하는 **한 덩어리로
  받는 자리**(`bin_file`)를 배워 그걸로 저장까지 간다. (인터넷의 옛 예제 중 이
  조각 테이블을 그대로 파일로 저장하는 코드가 있는데, 요즘 시스템에서 PDF가
  깨지는 고전 함정이다 — 따라 하지 말자.) 지금은 "PDF 데이터가 프로그램 손에
  들어왔다"까지가 목표다.

실행하면 이번에는 **인쇄 대화상자도 미리보기도 뜨지 않고**, 리포트 결과
리스트에 크기 한 줄만 찍힌다. 화면·프린터로 보내는 대신 데이터로 돌려받았으니
당연한 침묵이다. 눈으로 양식 모양을 다시 보고 싶으면 **②의 `gs_ctrl` 두 줄을
잠시 주석 처리**하라. L01처럼 대화상자가 떠서 미리보기로 확인할 수 있다(확인 후
반드시 되돌리자. 뒤의 [L04 파이프라인](CH37-L04.html)은 OTF를 돌려받아야 돈다).

## 흔한 실수와 점검 🚧

- **`getotf` 없이 `otfdata`를 기대** → 옵션을 안 켜면 출력은 인쇄 경로로 가고
  `otfdata`는 빈 테이블이다. 오류도 안 나서 더 헷갈린다. 옵션과 결과는 짝.
- **`no_dialog` 없이 배치 실행** → 사람이 없는 곳에서 대화상자가 뜨려다
  실패한다(L01 콜아웃의 사고가 그대로 재현된다). 파일 경로 코드에는 3종
  세트(`getotf`·`no_dialog`·장치 지정 + `user_settings = space`)를 통째로.
- **`user_settings` 깜빡** → 내 PC에서는 되는데 다른 사람 계정에서는 결과가
  다르다면 1순위 용의자다. 개인 인쇄 설정이 옵션을 덮어쓰고 있는 것.
- **`CONVERT_OTF`의 `sy-subrc` 무시** → 변환 실패를 모르고 빈 결과를 다음
  단계로 넘기면, 고장이 엉뚱한 곳(저장·발송)에서 드러나 추적이 길어진다.
  OTF를 못 받은 채 변환을 부르면 실패하거나(흔히 `err_bad_otf`) 빈 결과가
  나온다.
- **미리보기 확인 후 주석 안 되돌림** → `gs_ctrl` 두 줄이 주석인 채로는 OTF가
  안 돌아온다. "어제는 됐는데 오늘 `bin_filesize`가 0"의 단골 원인.

## 정리 📌

- Smart Forms의 산출물 원형 = **OTF**(프린터 언어에 묶이지 않는 출력 명령
  데이터). 프린터로 가면 인쇄, 변환기로 가면 PDF.
- 생성 함수에는 내가 선언한 파라미터 외에 **표준 파라미터**가 자동으로 붙는다.
  무인 호출 3종 세트 = `control_parameters`(**`getotf`+`no_dialog`**) +
  `output_options`(장치) + **`user_settings = space`**. 결과는
  `job_output_info`(`SSFCRESCL`)의 **`otfdata`**.
- 변환 = **`CONVERT_OTF`**(`format = 'PDF'`). `bin_filesize`가 0이 아니면
  변환 성공, 데이터 조각은 `lines`로.
- 별도 서버나 설치물 없이 **표준 함수만으로** 되는 경로다. 파일로 만드는
  마지막 걸음은 L04에서.

---

PDF 데이터까지 만들었다. 그런데 예매가 확정될 때 이 확인서가 **자동으로**
나가게 하려면 누가 결정하나. 출력 결정의 층, Output Control로 간다.
