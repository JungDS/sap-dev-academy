## 매진 회차를 눈에 띄게

업무 표에서 모든 행이 같은 무게로 보이면 사용자는 중요한 상태를 놓친다. 예매 목록이라면
**매진된 회차**가 먼저 눈에 들어와야 한다. 색은 데이터를 바꾸는 게 아니라 **시선을 중요한
곳으로 모으는 표시 기능**이다. 행 전체 색은 각 행에 **색 코드 컬럼**을 두고, Layout에 그
컬럼 이름을 알려 주는 방식이다.

매진 판정에는 회차별 **정원과 예약 좌석 합계**가 필요하다. 예매 행(`gt_booking`)만으로는
모자라서, [실습 — 공연별 예매현황 리포트](CH13-L08.html)에서 만든 **회차별 집계**를 그대로
가져온다. 거기에 색 코드가 들어갈 칸(`rowcolor`) 하나만 더한 행 타입을 쓴다.

```abap
TYPES: BEGIN OF ts_perf_alv,
         concert_id TYPE zperf-concert_id,
         perf_no    TYPE zperf-perf_no,
         perf_date  TYPE zperf-perf_date,
         capacity   TYPE zconcert-capacity,  " 정원은 공연 마스터(ZCONCERT)에
         booked     TYPE i,                  " 예약 좌석 합계(ZBOOKING에서 집계)
         rowcolor   TYPE c LENGTH 4,         " ← 색 코드 컬럼
       END OF ts_perf_alv.

DATA: gt_perf TYPE STANDARD TABLE OF ts_perf_alv,
      gs_perf TYPE ts_perf_alv.

" 회차별 정원·예약 합계 — 공연별 예매현황 실습의 집계 그대로
SELECT pf~concert_id pf~perf_no pf~perf_date c~capacity
       SUM( b~seats ) AS booked
  FROM zperf AS pf
  INNER JOIN zconcert AS c
    ON c~concert_id = pf~concert_id
  LEFT OUTER JOIN zbooking AS b
    ON  b~concert_id = pf~concert_id
    AND b~perf_no    = pf~perf_no
    AND b~status     <> 'C'                  " 취소 예매는 제외
  INTO CORRESPONDING FIELDS OF TABLE gt_perf
  GROUP BY pf~concert_id pf~perf_no pf~perf_date c~capacity.

LOOP AT gt_perf INTO gs_perf.
  IF gs_perf-booked >= gs_perf-capacity.     " 매진이면
    gs_perf-rowcolor = 'C610'.               " 빨강 계열 코드
    MODIFY gt_perf FROM gs_perf INDEX sy-tabix.
  ENDIF.
ENDLOOP.

gs_layout-info_fname = 'ROWCOLOR'.            " 색 코드가 든 '필드명'을 layout에
```

색이 화면에 뜨려면 **네 가지**가 맞아야 한다. 하나라도 빠지면 색이 보이지 않는다.

1. 데이터 행에 **색 코드 컬럼**(예 `rowcolor`)이 있다.
2. 각 행의 색 코드 컬럼에 **코드 값**(예 `'C610'`)을 넣었다.
3. `gs_layout-info_fname`에 그 **컬럼 이름**(`'ROWCOLOR'`)을 지정했다.
4. `set_table_for_first_display`로 **화면에 반영**했다. 이미 띄운 표에서 **색 코드 값만**
   바꿨다면 `refresh_table_display`로 충분하다. 단 `info_fname` 지정처럼 **Layout 설정
   자체**를 나중에 바꾸는 건 refresh로는 전달되지 않으니, 처음 표시 전에 채워 두는 게 좋다.

> ⚠️ `info_fname`은 **"색 코드 값"이 아니라 "색 코드가 들어 있는 필드명"** 이다.
> `gs_layout-info_fname = 'C610'`처럼 쓰면 안 된다. `'ROWCOLOR'`(필드명)를 넣는다.
> 색 코드는 임의 RGB가 아니라 `C` + **색번호(0～7)** + **강조(0/1)** + **반전(0/1)** 네
> 글자다. `'C610'`이면 색번호 6(빨강 계열)·강조 1·반전 0이라는 뜻이다.

## 직접 색칠해 보기 — 매진 판정과 색 연결

좌석 점유를 바꿔 회차 상태(여유/임박/매진)를 만들고, **색 코드 쓰기 → info_fname 연결 →
표시** 순서로 매진 행에 색이 입혀지는지 보자. `info_fname`을 틀린 필드명으로 두면 왜 색이
안 보이는지도 확인한다.

## 흔한 실수와 점검

- **`info_fname` 미지정** → 색 컬럼을 둬도 layout에 안 알리면 색이 안 먹는다.
- **`info_fname`에 색 코드 값** → 필드명(`'ROWCOLOR'`)을 넣는다. `'C610'`이 아니다.
- **색 코드 형식** → `C`로 시작하는 4자리. 임의 RGB가 아니다.
- **색 코드 컬럼이 화면에 노출** → `ROWCOLOR`는 내부용 값이라 사용자에게 보일 필요가 없다.
  [Field Catalog](CH17-L04.html)에서 이 컬럼의 `no_out`을 켜 숨긴다. 참고로 이 행 타입은
  DDIC가 아니라 **프로그램 안 로컬 타입**이라 `LVC_FIELDCATALOG_MERGE`에 넣을 DDIC 이름이
  없다. 이럴 땐 카탈로그 행을 손으로 채우거나, 비슷한 DDIC 구조로 merge한 뒤 모자란
  컬럼(`ROWCOLOR` 등)을 직접 추가한다.

## 정리

- **중요한 행을 사용자가 놓치지 않게** 색으로 표시한다.
- 데이터 행의 **색 코드 필드**와 layout의 **`info_fname`(필드명)** 이 **함께** 있어야 색이 보인다.
