## 수고가 화면으로 연결되는 지점

앞 레슨들에서 만든 [[Foreign Key]]·[[Search Help]], 그리고
[Chapter 03 · Domain](CH03-L01.html)에서 정해 둔 [[고정값]]이 실제 입력 화면
([[PARAMETERS]])에서 **자동으로** 나타나는 원리를 정리한다.
[Chapter 03 · PARAMETERS](CH03-L03.html)의 "보상"을 더 깊이 보는 셈이다.

## 자동 연결 — Data Element 경유

`PARAMETERS pa_conc TYPE zde_concert_id.` 처럼 [[Data Element]]로 타입을 주면 그 DE에
딸린 것들이 화면으로 따라온다. 다만 **무엇이 따라오고 무엇이 안 따라오는지**를 정확히
갈라 둬야 나중에 "왜 안 되지"로 헤매지 않는다.

**따라오는 것 — F4 목록**

- Data Element에 붙여 둔 **[[Search Help]]**.
- Domain에 정해 둔 **[[고정값]]**.

이 둘은 타입만 줘도 F4로 뜬다. 별도 코드가 필요 없다. 화면이 공짜로 똑똑해지는 대목이다.

**따라오지 않는 것 — Foreign Key와 값 검증**

- [[Foreign Key]]는 **테이블 필드에 거는 속성**이다. Data Element가 아니라
  `ZBOOKING-CONCERT_ID`라는 **필드 한 칸**에 붙어 있다. 그래서 같은 Data Element로
  타입을 줬다고 해서 그 관계까지 따라오지는 않는다.
- **값 검증도 자동으로 돌지 않는다.** F4 목록이 뜨는 것과 "입력된 값이 진짜 있는
  값인지 확인하는 것"은 별개의 일이다. 사용자가 목록에서 고르지 않고 손으로 아무
  값이나 쳐 넣으면 그대로 통과한다.

> ⚠️ 선택화면의 PARAMETERS가 받아 오는 입력 도움은 일반 화면보다 **제한적**이다.
> 예를 들어 "공연을 고르면 그 공연의 회차만 보여 주기"처럼 **한 칸의 입력이 다른 칸의
> 목록을 좁히는** 동작은 여기선 되지 않는다. 칸마다 따로 놀 뿐이다.

### 존재 검사까지 받고 싶다면 — VALUE CHECK

선택화면에서도 "있는 값인지"를 확인받고 싶으면 `VALUE CHECK`를 덧붙인다.

`PARAMETERS pa_conc TYPE zconcert-concert_id VALUE CHECK.`

붙이는 데 조건이 있다. 먼저 타입을 **DDIC에서 가져와야** 한다. 프로그램 안에서 직접
만든 타입엔 붙일 수 없다. 그리고 **Check Table 조회까지 받으려면 타입을 위처럼
테이블 필드로** 줘야 한다. `zde_concert_id` 같은 Data Element로 주면 Domain 고정값
범위까지만 검사하고 Check Table은 보지 않는다. 관계가 필드에 붙어 있으니, 그 관계를
쓰려면 필드를 가리켜야 한다는 이야기다.

## 명시적으로 붙이기 — MATCHCODE OBJECT

특정 검색 도움말을 직접 지정하고 싶으면:

```abap
PARAMETERS pa_conc TYPE zde_concert_id
  MATCHCODE OBJECT zsh_concert_coll.
```

- `MATCHCODE OBJECT`로 이 입력칸에 쓸 [[Search Help]]를 명시한다.

> 💡 **왜 갑자기 Matchcode인가?** Matchcode는 Search Help의 **옛 이름**이다. 예전
> 버전에서 쓰던 이름이 문법 키워드에 그대로 남았을 뿐, 다른 객체가 아니다. 검색하다
> "매치코드"라는 말이 나오면 Search Help를 가리킨다고 보면 된다.

## F4가 오는 세 경로

1. **고정값**(Domain) — 짧은 코드 목록.
2. **Foreign Key/Check Table** — 마스터 테이블 값.
3. **Search Help** — 설계된 검색 화면(가장 유연).

## Search Help는 어디에 붙이나 — 부착 지점

같은 [[Search Help]]라도 **어디에 붙이느냐**에 따라 영향 범위가 다르다.

| 붙이는 곳 | 효과 |
|---|---|
| **Data Element** | 그 DE를 쓰는 **모든 필드**에 한꺼번에(가장 광범위) |
| **테이블·Structure의 필드 하나** | 그 필드를 가져다 쓰는 화면 칸에만. 테이블 필드든 Structure 필드든 "필드 한 칸에 붙인다"는 점에서 같다 |
| **프로그램·화면 필드**(`MATCHCODE OBJECT`) | 그 입력칸 하나에 콕 |

> 💡 "널리 공유" → Data Element에, "이 칸만" → `MATCHCODE OBJECT`로. 넓게 붙일수록 재사용이 크고, 좁게 붙일수록 통제가 정확하다.

두 목록이 헷갈릴 수 있으니 관계를 짚어 두자. **세 경로**는 F4에 뜰 값이 *어디서
오는가*(재료)를 나눈 것이고, **부착 지점**은 그 도움말을 *어느 범위에 걸어 두는가*(적용
범위)를 나눈 것이다. 기준이 다른 두 분류라 순서끼리 대응하지 않는다. 외워서 맞출 것이
아니라 "재료 / 범위"로만 갈라 두면 된다.

## 흔한 실수와 점검

- **업무 코드 목록이 F4로 안 떠요** → 타입을 **Built-In Type**(`CHAR 4`처럼 SAP이 미리
  정해 둔 기본 타입)으로 직접 줬을 때 흔하다. 기본 타입엔 붙여 둔 도움말이 없으니
  가져올 목록도 없다. Data Element 경유 또는 `MATCHCODE OBJECT`로 바꾼다. 단
  **날짜·시간 타입은 예외**다. 아무것도 안 걸어도 달력·시계가 뜬다.
- **여러 도움말이 한 칸에 걸렸다** → 이럴 때 무엇이 뜨는지에는 정해진 순서가 있다.
  다음 레슨에서 그 순서를 다루니, 지금은 **`MATCHCODE OBJECT`로 하나만 콕 집어 두면
  안전하다**는 것만 기억하자.
