## 좌표는 그대로, 동사만 바뀐다

앞 레슨에서 잡은 두 좌표 — **자리(INDEX)로, 아니면 키(KEY)로** — 는 고치기와 지우기에도
그대로 반복된다. 새로 외울 원리는 없다. 동사만 `MODIFY`와 `DELETE`로 바뀔 뿐이다.

## 고치기 — MODIFY

가장 자주 쓰는 패턴부터. `READ`가 채워 준 `sy-tabix`(찾은 행 번호)로 바로 고친다.

```abap
READ TABLE gt_person INTO gs_person WITH KEY name = '정훈영'.
IF sy-subrc = 0.
  gs_person-age = 31.
  MODIFY gt_person FROM gs_person INDEX sy-tabix
         TRANSPORTING age.               " age 필드만 갱신(나머지 보존)
ENDIF.
```

두 좌표로 정리하면:

- **자리로**: `MODIFY gt_... FROM gs_... INDEX n.` — n번 행을 교체. 위 패턴처럼
  `READ` 직후 `sy-tabix`와 짝지어 쓰는 게 정석이다.
- **키로**: `MODIFY TABLE gt_... FROM gs_....` — Work Area의 **키 필드 값으로 행을 찾아서**
  나머지를 교체. 번호가 없는 HASHED에서는 이쪽이 유일한 길이다.

> `MODIFY TABLE`은 키로 행을 **식별**하는 문장이지, 키를 **바꾸는** 문장이 아니다.
> 키 필드는 찾는 데 쓰이고, 바뀌는 것은 나머지 필드들이다. "정훈영의 나이를 고친다"는 되지만
> "정훈영이라는 이름 자체를 고친다"는 이 문장의 용도가 아니다.

`TRANSPORTING f1 f2`는 "**이 필드만 옮겨라**" — 지정한 필드만 갱신하고 나머지는 보존한다.
앞 레슨의 `TRANSPORTING NO FIELDS`(하나도 옮기지 마라)와 같은 낱말의 반대 방향 용법이다.
빼먹으면 행 **전체**가 Work Area 값으로 교체되니, 일부만 고칠 땐 꼭 붙이자.

## 지우기 — DELETE

지우기도 좌표 둘에, "조건으로 한꺼번에"가 하나 더 붙는다.

```abap
DELETE gt_person INDEX 3.                     " 자리로: 3번 행 삭제
DELETE TABLE gt_person FROM gs_person.        " 키로: gs의 키 값과 같은 행 삭제
DELETE gt_person WHERE age < 20.              " 조건으로: 맞는 행 전부 삭제
```

- `WHERE`는 조건에 맞는 행을 **모두** 지운다. 하나라도 지웠으면 `sy-subrc = 0`,
  지운 행이 없으면 0이 아니다(역시 0인지로만 판정).
- 자리로 지우면 **뒤 행들의 번호가 하나씩 당겨진다**. 아까 봐 둔 `sy-tabix`가 삭제 후에도
  유효하리라 믿으면 안 되는 이유다.

## 행이 없을 때도 안전하게

READ가 실패할 수도, 테이블이 통째로 비어 있을 수도 있다. "없음"을 다루는 도구 셋을
한자리에 묶어 두면 방어 코드가 한결 쉬워진다.

```abap
IF gt_person IS INITIAL.                      " ① 테이블이 통째로 비었나
  WRITE: / '데이터가 없습니다'.
ENDIF.

DESCRIBE TABLE gt_person LINES gv_cnt.        " ② 몇 건인지 세기

READ TABLE gt_person INTO gs_person WITH KEY name = '수지'.
IF sy-subrc <> 0.                             " ③ 특정 행이 없나
  WRITE: / '수지는 명단에 없습니다'.
ENDIF.
```

- `IS INITIAL`은 [Chapter 4](CH04-L04.html)에서 배운 그 판별이다 — 테이블에도 그대로 통한다
  (행이 0개면 초기 상태).
- ①은 전체가 비었는지, ③은 특정 행이 없는지. 묻는 질문이 다르니 둘 다 습관이 돼야 한다.

## 여기까지 한눈에 — 한 행 제어 전체 지도

L05～L06에서 만난 문장들이다. 외우기 전에 "무엇을 하려는가 × 어느 좌표로"의 격자로 보자.

| 하려는 일 | 자리(INDEX)로 | 키(KEY)로 | 조건으로 |
|---|---|---|---|
| 넣기 | `INSERT ... INDEX n` | `INSERT ... INTO TABLE` | — |
| 찾기 | `READ ... INDEX n` | `READ ... WITH KEY` / `WITH TABLE KEY` | — |
| 고치기 | `MODIFY ... INDEX n` | `MODIFY TABLE ...` | — |
| 지우기 | `DELETE ... INDEX n` | `DELETE TABLE ...` | `DELETE ... WHERE` |

(`APPEND`는 "끝에"라는 특별한 자리, `TRANSPORTING`은 찾기·고치기 어디든 붙는 부속이다.)

## 흔한 실수와 점검

- **TRANSPORTING 없이 부분 수정 의도** → 행 전체가 교체된다. 안 채운 필드는 Work Area의
  현재 값(대개 초기값)으로 덮인다.
- **sy-tabix를 오래 보관** → 그 사이 정렬·삭제가 일어나면 번호의 의미가 바뀐다.
  `READ` 직후 바로 쓰고 버린다.
- **MODIFY TABLE로 키를 바꾸려 함** → 키는 식별용이다. 키 값을 바꿔야 하면
  지우고 다시 넣는 것이 정도다.
- **빈 테이블 무방비** → 데이터가 0건인 날은 반드시 온다. `IS INITIAL` 선확인 습관.
