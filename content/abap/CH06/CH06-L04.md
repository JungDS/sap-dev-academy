## 천 명 중에서 한 명 찾기

`gt_person`에 사원이 1,000명 들어 있고, 그중 '수지'를 찾아야 한다고 하자. 지금까지 우리가
만든 테이블은 이럴 때 **앞에서부터 한 행씩** 훑는다. 수지가 997번째에 있다면 996번의
허탕을 치는 셈이다. 열 명일 땐 아무 문제가 아니었지만, 만 명·십만 명이면 이야기가 달라진다.

여기서 3속성의 마지막, **Table Kind(종류)** 가 등장한다. 행을 **어떻게 저장하고 어떻게
찾을지**를 정하는 속성이다. 종류가 다르면 같은 데이터라도 찾는 속도가 하늘과 땅이다.

## 세 종류

| 종류 | 저장 / 탐색 | 번호(인덱스) 접근 | 언제 |
|---|---|---|---|
| STANDARD | 입력 순서 유지, 키 탐색은 순차 | O | 기본. 대부분의 처리 |
| SORTED | 키 순서 자동 유지, 이진 탐색 | O | 정렬 유지·빠른 키/범위 탐색 |
| HASHED | 해시로 단건 탐색(행 수와 무관) | X | 유일 키 대량 데이터 단건 조회 |

표에 처음 나온 두 낱말부터 풀어 둔다.

- **이진 탐색** — 정렬된 전화번호부를 딱 반으로 갈라 "찾는 이름이 앞쪽인가 뒤쪽인가"만 보고,
  남은 쪽을 또 반으로 가르는 식으로 좁혀 간다. 첫 장부터 한 장씩 넘기는 것보다 훨씬 적게 본다.
  대신 **정렬돼 있어야** 성립한다. SORTED는 넣는 순간부터 항상 키 순서를 유지하므로
  언제든 이 방식으로 찾는다.
- **해시** — 키 값을 계산해서 "이 값은 몇 번 사물함"인지 **바로** 알아낸다. 앞에서부터 훑지
  않으니 행이 100개든 10만 개든 한 건 찾는 시간이 비슷하다. HASHED는 행들을 줄 세우는 대신
  이 사물함 방식으로 보관한다.

## 번호가 있는 그릇, 없는 그릇 — Index Table

- STANDARD·SORTED는 **Index Table**이다. 행마다 번호가 붙어 "n번 행"으로 접근할 수 있다.
  이 번호는 **1번부터** 센다(0번 행은 없다).
- HASHED는 행을 줄 세워 관리하는 [[인덱스]](행 번호표)가 **없다**. 사물함에 번호표가 없듯,
  "37번째 행"이라는 말 자체가 성립하지 않고 **키로만** 찾는다. 이게 무슨 뜻인지는
  [빠르게 찾기 레슨](CH06-L07.html)에서 직접 실험으로 확인한다.

## 키와 종류는 세트다 — UNIQUE 매트릭스

[앞 레슨](CH06-L03.html)에서 미뤄 둔 표다. 어떤 종류에 어떤 중복 정책을 줄 수 있는지는
종류가 정한다.

| 종류 | NON-UNIQUE | UNIQUE |
|---|---|---|
| STANDARD | O (유일한 선택지) | X |
| SORTED | O | O |
| HASHED | X | O (강제) |

- STANDARD는 중복을 막는 장치가 없다 — 걸러내는 건 전부 내 코드 몫이다.
- HASHED는 반대로 **UNIQUE가 강제**다. 사물함 방식은 "키 하나 = 행 하나"가 전제라,
  키가 겹치는 데이터는 아예 담을 수 없다.

## 공짜는 없다 — 종류 선택은 거래다

세 종류의 차이는 "좋고 나쁨"이 아니라 **무엇을 지불하고 무엇을 얻는가**다.

| 종류 | 지불하는 것 | 얻는 것 |
|---|---|---|
| STANDARD | 키로 찾을 때 느림(순차) | 아무 제약 없음·넣기 빠름·순서 내 마음대로 |
| SORTED | 넣을 때마다 자리 찾는 비용·순서를 내가 못 정함 | 항상 정렬돼 있음·키/범위 탐색 빠름 |
| HASHED | 행 번호 포기·UNIQUE 강제 | 단건 키 탐색이 데이터 양과 무관하게 최속 |

그래서 선택 기준은 단순하다. **이 테이블을 어떻게 쓸 것인가**를 먼저 묻는 것이다.
순서대로 훑는 게 주 용도면 STANDARD, 키·범위로 자주 찾고 정렬이 늘 필요하면 SORTED,
유일 키로 대량 데이터에서 단건만 집어낼 거면 HASHED.

::embed CH06-L04-S01 | 어떤 Table Kind를 쓸까 — 선택 트리::

- 처음엔 **STANDARD로 충분하다.** SORTED/HASHED는 접근 패턴이 분명하고 속도가 실제로
  문제 될 때 다시 꺼내는 카드다. 이 챕터의 예제도 특별한 말이 없으면 STANDARD다.
- STANDARD에서도 빠르게 찾는 **수동 처방**이 따로 있다(정렬해 두고 이진 탐색). 그건
  [빠르게 찾기 레슨](CH06-L07.html)의 주제다.

## 흔한 실수와 점검

- **처음부터 SORTED/HASHED 남발** → 기본은 STANDARD. 어떻게 찾아 쓸지가 분명해지고
  속도가 실제 문제가 될 때 바꾼다.
- **HASHED에 번호 접근** → 번호표가 없는 그릇이다. 키로만 찾는다.
- **"standard key"와 "STANDARD(종류)" 혼동** → 앞 레슨의 확인 문장을 다시 —
  하나는 키 이야기, 하나는 저장 방식 이야기다.
