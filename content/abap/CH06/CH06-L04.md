## 여러 행을 한꺼번에

행을 하나씩 꺼내 처리(LOOP)하고, 합계를 내고, 중복을 지우고, 그룹별로 묶는다.
이번 레슨에서는 이런 대량 처리 도구를 하나씩 익힌다.

크게 두 갈래다. 앞쪽은 행을 하나씩 훑는 **순회**(LOOP 계열), 뒤쪽은 훑으면서 값을 모으는
**집계**(COLLECT·컨트롤레벨)다. 순회가 손에 익은 다음 집계로 넘어가면 부담이 덜하다.

## LOOP — 순회와 sy-tabix

```abap
LOOP AT gt_person INTO gs_person.
  WRITE: / sy-tabix, gs_person-name.   " sy-tabix = 현재 행 번호
ENDLOOP.
```

[앞 레슨](CH06-L03.html)에서 READ가 채워 주던 `sy-tabix`가, LOOP에서는 매 반복
**현재 행의 번호**를 담는다.

조건·범위로 일부만 돌 수도 있다.

```abap
LOOP AT gt_person INTO gs_person WHERE age >= 20.
  WRITE: / sy-tabix, gs_person-name.
ENDLOOP.

LOOP AT gt_person INTO gs_person FROM 2 TO 5.   " 2~5번째 행만
  WRITE: / gs_person-name.
ENDLOOP.
```

> ⚠️ `WHERE`나 `FROM/TO`로 일부만 돌면 "몇 번째 반복"과 `sy-tabix`가 어긋난다.
> `sy-tabix`는 언제나 **테이블에서의 실제 행 번호**다. 조건에 걸린 첫 행이 3번 행이면
> 첫 반복부터 `sy-tabix = 3`이고, `FROM 2`로 시작하면 첫 반복이 `sy-tabix = 2`다.

## 복사 없이 직접 고치기 — LOOP ... ASSIGNING `<fs>`

`INTO gs_...`는 행을 **복사**해 온다. 복사본을 고쳐도 테이블은 안 바뀌므로 `MODIFY`가
필요했다. 복사 없이 행을 **직접 가리켜** 그 자리에서 고치려면 [[Field Symbol]](필드 심볼,
행을 가리키는 이름표)을 쓴다.

```abap
FIELD-SYMBOLS <fs_person> TYPE ts_person.

LOOP AT gt_person ASSIGNING <fs_person>.
  <fs_person>-age = <fs_person>-age + 1.   " 테이블 행이 바로 바뀐다(MODIFY 불필요)
ENDLOOP.
```

> `<...>`로 감싼 이름이 Field Symbol이다(꺾쇠는 문법 필수). 가리키는 행을 직접 수정하니
> `MODIFY`가 필요 없다. 여기서는 기초만 보고, 본격 활용은 뒤에서 배운다.

> ⚠️ **SORTED·HASHED 테이블에서는 키 필드를 `<fs>`로 고치지 말자** — 값이 바뀌면 정렬
> 순서나 해시 자리가 어긋나기 때문에, 아예 막혀 있어 런타임 오류가 난다. 직접 고칠 수 있는
> 것은 키가 아닌 필드다.

## 집계 — COLLECT · 컨트롤레벨

지역별 매출 합계를 내 보자. 이 절에서 쓸 테이블부터 선언한다. 앞의 `ts_person`과 달리
지역과 금액 두 필드다.

```abap
TYPES: BEGIN OF ts_sales,
         region TYPE c LENGTH 10,   " 지역 이름(문자)
         amount TYPE i,             " 매출 금액(숫자, 원 단위)
       END OF ts_sales.

DATA: gs_sales TYPE ts_sales,
      gt_sales TYPE TABLE OF ts_sales.
```

`COLLECT`는 **키가 같은 행이 이미 있으면 숫자 필드를 합산**하고, 없으면 새 행으로 넣는다.

```abap
gs_sales-region = '서울'. gs_sales-amount = 100.
COLLECT gs_sales INTO gt_sales.   " 없던 키 → 새 행

gs_sales-region = '서울'. gs_sales-amount = 30.
COLLECT gs_sales INTO gt_sales.   " 같은 키 → 100 + 30 = 130
```

여기서 키는 무엇일까. 위 선언은 키를 따로 적지 않았으니
[앞 레슨](CH06-L02.html)에서 본 standard key, 즉 문자 필드인 `region`이 키다. 그래서
`region`이 같은 행끼리 `amount`가 더해진다.

- **키가 아닌 필드는 모두 숫자 타입**이어야 한다(합산 대상이므로). `ts_sales`에서 키가 아닌
  필드는 `amount` 하나고 숫자라 조건을 만족한다.
- 넣는 Work Area는 테이블의 **행 모양과 같은 타입**이어야 한다.
- 문자 필드가 하나도 없어 키가 텅 비면, 모든 필드가 숫자여야 하고 넣는 족족 첫 행에만
  합산된다. 그런 테이블이라면 키를 직접 적어 주는 편이 안전하다.
- 무조건 뒤에 붙이고 싶은 거라면 `COLLECT`가 아니라 `APPEND`다.
- ⚠️ 한 테이블에 `COLLECT`와 `APPEND`를 **섞지 말자.** 키가 같은 행이 둘로 갈라져 합계가
  쪼개진다.
- 대량 데이터라면 `COLLECT`는 SORTED·HASHED와 궁합이 좋다. STANDARD 테이블에 쓰면 다른
  문장이 테이블을 건드리는 순간 내부적으로 처음부터 훑는 방식이 되어, 행이 많을수록 느려진다.

정렬된 테이블을 **그룹 경계**로 처리하려면 컨트롤레벨(Control Level)을 쓴다.

```abap
SORT gt_sales BY region.
LOOP AT gt_sales INTO gs_sales.
  AT NEW region.        " region 그룹이 시작되는 행
    WRITE: / '지역:', gs_sales-region.
  ENDAT.
  WRITE: / gs_sales-amount.
  AT END OF region.     " region 그룹의 마지막 행
    SUM.                " 그 그룹의 숫자 필드 합계가 gs_sales에 들어온다
    WRITE: / '소계:', gs_sales-amount.
  ENDAT.
ENDLOOP.
```

- `AT FIRST`/`AT LAST` — 테이블 전체의 처음/끝(여기서 `SUM`은 전체 합계).
- `AT NEW f`/`AT END OF f` — 필드 `f` 값이 바뀌는 그룹 경계. `SUM`은 그 그룹에서
  **그룹 키 오른쪽의 숫자 필드**를 합산한다(키 필드 자체는 합산 안 됨).

여기서 말하는 "왼쪽·오른쪽"은 화면에 찍히는 자리가 아니라 **Structure를 선언할 때 적은
필드 순서**다. `ts_sales`는 `region`을 먼저, `amount`를 나중에 적었으니 `region`의 오른쪽이
`amount`다.

주의할 점이 셋 있다.

- **그룹 키는 "`f`와 그 왼쪽의 모든 필드"다.** 그래서 `f`보다 왼쪽에 있는 필드가 바뀌어도
  경계가 실행된다. 예제처럼 `f`를 첫 필드에 두면 이런 헷갈림이 없다.
- **그룹 키 순서로 정렬이 먼저**여야 한다. 같은 값이 흩어져 있으면 한 그룹이 여러 번 열린다.
- **`SUM`은 `LOOP ... INTO`에서만 쓴다.** 조금 전에 배운 `ASSIGNING`과는 함께 쓸 수 없다.

> ⚠️ **`AT ... ENDAT` 안에서는 다른 필드 값이 가려진다.** 블록에 들어가는 순간 시스템이
> Work Area를 손질하기 때문이다. 블록 안에서만 그렇고, 빠져나오면 원래 행 값으로 돌아온다.

블록 안의 Work Area는 이렇게 바뀐다.

1. **그룹 키 필드** — 그대로 남는다.
2. **키의 오른쪽에 있는 고정 길이 문자 필드** — 전부 `*`로 채워진다. 문자 필드를 찍으면
   `****`가 나오는 이유다.
3. **나머지 필드** — 초기값이 된다. `AT NEW` 블록 안에서 금액을 찍으면 0이 나오는 이유다.

> 💡 위 예제가 `AT END OF` 안에서 `SUM`을 먼저 부른 것도 이 때문이다. 초기값으로 비워진
> 숫자 필드 자리를 `SUM`이 그룹 합계로 채워 준다.

## 중복 · 개수 · 합치기

큰 두 갈래는 여기까지다. 남은 셋은 자주 쓰는 짧은 문장들이라 가볍게 보고 넘어가면 된다.

```abap
SORT gt_person BY name.
DELETE ADJACENT DUPLICATES FROM gt_person COMPARING name.  " 인접 중복 제거

DATA gv_cnt TYPE i.
DESCRIBE TABLE gt_person LINES gv_cnt.   " 행 수
```

두 테이블을 하나로 합칠 일도 잦다. 서울 지점 명단과 부산 지점 명단을 받아 전체 명단을
만드는 식이다. `LOOP`로 한 행씩 옮겨도 되지만, 통째로 이어 붙이는 문장이 따로 있다.

```abap
DATA: gt_a TYPE TABLE OF ts_person,   " 지점 명단
      gt_b TYPE TABLE OF ts_person.   " 전체 명단

APPEND LINES OF gt_a TO gt_b.         " gt_a의 모든 행을 gt_b 끝에 이어 붙인다
```

`gt_b`에 이미 행이 있으면 그 **뒤에** 붙는다. `gt_a`는 그대로 남는다(옮기는 게 아니라
복사다). 두 테이블의 행 모양은 같아야 한다.

## 흔한 실수와 점검

- **DELETE ADJACENT DUPLICATES 전에 SORT 안 함** → "인접"만 보므로 떨어진 중복이 남는다.
  정렬이 선행.
- **AT NEW/END OF 전에 정렬 안 함** → 그룹 경계가 어긋난다. 그룹 키로 SORT 먼저.
- **COLLECT를 단순 추가로 착각** → 같은 키면 행이 늘지 않고 숫자가 **누적**된다.
- **`<fs>` 미할당 사용** → ASSIGN 안 된 Field Symbol 접근은 런타임 오류(덤프).
  LOOP가 매 반복 할당해 준다.
- **HASHED 테이블에서 `sy-tabix` 기대** → 번호가 없는 테이블이라 LOOP 안에서
  `sy-tabix`는 0이다.
- **LOOP 도는 중에 그 테이블에 행 추가·삭제** → 순회가 행을 건너뛰거나 꼬일 수 있다.
  지우기는 `DELETE ... WHERE`처럼 루프 **밖에서** 한 번에. 루프 안에서는 지금 행만
  다룬다(`<fs>`로 값 고치기는 안전).

## 정리

도구가 여럿 나왔다. 한자리에 모으면 이렇다.

| 도구 | 언제 쓰나 | 핵심 한 줄 |
|---|---|---|
| `LOOP ... INTO` | 행을 하나씩 훑을 때 | 복사본을 받아 읽는다(`sy-tabix` = 실제 행 번호) |
| `LOOP ... WHERE` · `FROM ... TO` | 일부 행만 돌 때 | 반복 회차와 `sy-tabix`는 어긋난다 |
| `LOOP ... ASSIGNING <fs>` | 훑으면서 그 자리에서 고칠 때 | 행을 직접 가리켜 `MODIFY`가 필요 없다 |
| `COLLECT` | 같은 키끼리 숫자를 더할 때 | 키가 있으면 합산, 없으면 새 행 |
| `AT NEW` · `AT END OF` + `SUM` | 그룹 경계마다 소계가 필요할 때 | 그룹 키로 `SORT`가 먼저 |
| `AT FIRST` · `AT LAST` | 테이블 전체의 처음·끝에서 한 번 | 여기서 `SUM`은 전체 합계 |
| `DELETE ADJACENT DUPLICATES` | 중복 행을 지울 때 | 인접만 보므로 `SORT`가 먼저 |
| `DESCRIBE TABLE ... LINES` | 행 수가 필요할 때 | 개수를 변수에 담아 준다 |
| `APPEND LINES OF` | 두 테이블을 이어 붙일 때 | 원본은 그대로 남고 복사된다 |

순회(LOOP 계열)와 집계(COLLECT·컨트롤레벨) 두 갈래에, 짧은 문장 셋이 붙은 구조다.
