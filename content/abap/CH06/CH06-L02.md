## 한 줄에 숨은 세 가지 결정

앞 레슨 끝에서 예고했다. `TYPE TABLE OF ts_person` 한 줄은 사실 **세 가지 결정**을
한꺼번에 내리고 있다. 나중에 "이 테이블은 왜 이렇게 동작하지?" 하고 막히는 순간,
답은 거의 이 셋 중 하나에 있다.

1. **Line Type(행 모양)** — 한 행이 어떤 타입인가. ← **오늘 이것**
2. **Primary Key(기본 키)** — 행을 무엇으로 찾고 구분하나. ← [다음 레슨](CH06-L03.html)
3. **Table Kind(종류)** — 내부적으로 어떻게 저장·탐색하나. ← [그다음 레슨](CH06-L04.html)

한 번에 다 알 필요 없다. 이 레슨은 첫 번째 결정만 붙잡는다 — 나머지 둘은 자리가 있다는
것만 알아 두면 된다.

## Line Type — 행은 꼭 Structure가 아니어도 된다

행 모양은 보통 Structure지만, **숫자 하나·문자 하나** 같은 단일(elementary) 타입일 수도 있고,
회사 공용으로 등록된 DDIC 타입일 수도 있다. 세 갈래를 나란히 보자.

```abap
DATA gt_num    TYPE TABLE OF i.            " ① 행이 정수 하나
DATA gt_person TYPE TABLE OF ts_person.    " ② 행이 내가 만든 Structure
DATA gt_amt    TYPE TABLE OF zde_amount.   " ③ 행이 DDIC Data Element
DATA gt_staff  TYPE TABLE OF zst_person.   " ③ 행이 DDIC Structure
```

- ①은 "숫자 목록"처럼 필드가 하나뿐일 때 쓴다. 행에 이름이 없고 값 자체가 행이라,
  채울 때도 Structure 없이 **값을 바로** 붙인다 — `APPEND 42 TO gt_num.` 한 줄이면
  42가 한 행이 된다(꺼낼 때도 `gv_num` 같은 단일 변수로 받는다).
- ②가 우리가 지금까지 쓴 형태다. 로컬 `ts_` 타입은 이 프로그램 안에서만 보인다.
- ③의 `zde_amount`는 [Chapter 3 · Data Element](CH03-L04.html)에서 만든 그 금액 타입이고,
  `zst_person`은 [Chapter 5 · DDIC Structure](CH05-L02.html)에서 만든 그 구조다.
  회사에 이미 등록된 타입이면 행 모양으로 그대로 빌려 쓸 수 있다.
- 나중에 배울 DB 테이블(Transparent Table)의 행 모양도 같은 방식으로 Line Type이 된다
  (다음 챕터에서 직접 해 본다).

## TYPE이 아니라 LIKE — 변수를 보고 선언하기

지금까지는 전부 **타입 이름**을 보고 선언했다(`TYPE ...`). 그런데 참조할 타입 이름은 없고
**이미 선언된 변수**만 있는 경우가 있다. 그때는 [Chapter 2](CH02-L03.html)에서 배운
`LIKE`가 그대로 통한다.

```abap
DATA gs_person TYPE ts_person.
DATA gt_a      LIKE TABLE OF gs_person.   " 변수 gs_person과 같은 행 모양의 테이블
DATA gt_b      LIKE gt_a.                 " 테이블 gt_a와 완전히 같은 모양의 테이블
```

- `LIKE TABLE OF <변수>` — 그 **변수의 모양을 행으로 삼는** 테이블.
- `LIKE <테이블 변수>` — 그 테이블과 **똑같은** 테이블 하나 더.
- 구분법은 Structure 때와 같다: **TYPE은 타입 기준, LIKE는 변수 기준.**

## 타입에 이름 붙여 두기 — TYPES

행 모양(`ts_`)에 이름을 붙였듯, **테이블 모양 전체**에도 이름을 붙일 수 있다.
접두어는 `tt_`(**t**able **t**ype)가 관례다.

```abap
TYPES tt_person TYPE TABLE OF ts_person.  " 테이블 모양에 이름 붙이기

DATA gt_person TYPE tt_person.            " 이름으로 선언
DATA gt_backup TYPE tt_person.            " 같은 모양이 몇 개든 한 단어로
```

같은 모양의 테이블을 여러 개 만들 때 선언이 한 단어로 줄어든다. 지금은 이 정도 편리함으로
충분한데, 뒤에서 명단 여러 개를 다루기 시작하면 이 "이름 붙이기"가 얼마나 고마운지 몸으로
느끼게 된다 — 그때 회사 공용 자산으로 승격하는 방법까지 배운다([타입의 자산화](CH06-L10.html)).

## 흔한 실수와 점검

- **행 타입과 테이블 타입 혼동** → `ts_person`은 한 행의 모양, `tt_person`은 여러 행을 담는
  그릇의 모양. 행 모양을 먼저 정하고, 그 위에 `TABLE OF`를 얹는 순서다.
- **LIKE와 TYPE 자리 바꿈** → `TYPE gs_person`처럼 변수 이름에 TYPE을 쓰면 오류다.
  타입 이름엔 TYPE, 변수 이름엔 LIKE.
- **DDIC 타입 남발** → 회사 공용(③)은 여러 프로그램이 공유하는 약속이다. 이 프로그램만 쓸
  임시 모양이면 로컬 `ts_`/`tt_`가 맞다.
