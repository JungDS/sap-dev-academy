## 같은 모양, 네 가지 쓰임

지금까지 "구구단 한 줄"(dan·mul·result)이라는 같은 모양을 **네 가지**로 써 봤다. 이름이
서로 닮아 헷갈리기 쉬우니 한 번에 정리한다.

| 무엇 | 선언·정의 | 사는 곳 | 용도 |
|---|---|---|---|
| **Structure**(한 줄 모양 타입) | 프로그램에서 `TYPES … ts_line`([Chapter 06 · 구구단 캡스톤](CH06-L15.html)), 또는 SE11 DDIC Structure | 타입 자체는 정의만. 이 타입으로 **선언한 변수**가 메모리에 한 건 | 한 줄의 모양을 정한다. 그 변수를 "지금 다루는 한 줄"로 쓰는 **역할**이 [[Work Area]] |
| **Internal Table**(변수) | `DATA gt_gugu TYPE TABLE OF ts_line` | 메모리(여러 건) | 여러 줄을 모아 정렬·검색 |
| **Table Type**(여러 줄 모양 타입) | SE11 Table Type `ZTT_PERSON` · 🔁 [Chapter 06 · 타입의 자산화](CH06-L10.html)에서 만든 것 | 정의만(데이터 없음) | Internal Table의 모양을 전역으로 공유 |
| **Transparent Table**(DB 테이블) | SE11 Database Table `ZGUGUDAN` | **디스크** | 실행이 끝나도 남아야 하는 업무 데이터 |

먼저 갈라 둘 것은 **설계도인지 실물인지**다. Structure와 Table Type은 모양만 정해 둔
**타입**이라 그 자체로는 값을 담지 않는다. Table Type도 데이터를 담는 그릇이 아니라
Internal Table의 모양을 전역으로 정의해 둔 설계도다. 값이 실제로 들어가는 쪽은 그 타입으로
**선언한 변수**(한 줄짜리 Work Area 변수, 여러 줄짜리 Internal Table)와 DB 테이블이다.

그다음이 사는 곳이다. **타입으로 선언한 변수는 메모리에 있어 프로그램이 끝나면 사라지고,
Transparent Table만 디스크에 남는다.** 이렇게 실행이 끝나도 값이 남는 성질을
**영속**(영구 저장)이라 부르고, Transparent Table은 바로 그것을 위한 도구다.

## DB 테이블을 그대로 타입으로 쓰기

`ZGUGUDAN`을 만들어 두면 프로그램에서 **그 테이블 이름을 타입으로** 쓸 수 있다. 한 줄짜리
변수로도, 여러 줄짜리 변수로도 된다.

```abap
DATA gs_line TYPE zgugudan.            " 한 줄 (Work Area 역할)
DATA gt_line TYPE TABLE OF zgugudan.   " 여러 줄 (Internal Table)
```

[Chapter 06 · Line Type](CH06-L02.html)에서 "DB 테이블의 행 모양도 그대로 **Line
Type**으로 줄 수 있다"고 예고했던 것이 이것이다. 모양을 두 번 적을 필요가 없으니 실무에서
가장 흔한 방식이다.

단 하나 다른 점이 있다. `ZGUGUDAN`에는 첫 필드로 `MANDT`가 있으니 `gs_line`은
`mandt`·`dan`·`mul`·`result` **네 필드**를 갖는다. 메모리에서 직접 만들었던 `ts_line`
(dan·mul·result 셋)보다 하나 많다.

> 💡 원한다면 [Chapter 05 · DDIC Structure](CH05-L02.html) 방식으로 `ZST_GUGU` 같은 DDIC
> Structure를 따로 만들어 그것을 타입으로 줄 수도 있다. MANDT 없이 원하는 필드만 담을 수
> 있다. 다만 그건 테이블 정의와 **별개의 정의**라, 한쪽 필드를 고쳐도 다른 쪽이 자동으로
> 따라 바뀌지는 않는다.

## 흔한 실수와 점검

- **메모리에 영속 기대** → Internal Table은 실행이 끝나면 사라진다. 영구 저장은 DB 테이블 몫.
- **넷을 같은 것으로** → 모양만 같을 뿐 사는 곳과 쓰임이 다르다.
- **Table Type과 Transparent Table 혼동** → 두 이름에 `Table`이 겹쳐 헷갈리기 쉽다.
  `ZTT_PERSON`(Table Type)은 Internal Table의 **설계도**, `ZGUGUDAN`(Transparent Table)은
  **DB 저장소**다.
- **`TYPE zgugudan`이면 DB와 이어져 있다는 착각** → 모양만 빌려 온 **메모리 변수**다. 실제로
  값을 읽거나 쓰려면 별도의 명령이 필요하다(다음 챕터).
