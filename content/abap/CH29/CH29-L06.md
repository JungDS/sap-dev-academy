## 🏭 같은 패턴을 수천 번

야간 배치가 파트너 로그 **수천 줄**을 검사한다. 줄마다 `FIND PCRE 'E(\d{3})' ...`를
실행하면 같은 패턴 문자열을 매번 다시 해석하는 셈이다. 패턴을 **한 번만 만들어 두고
재사용**할 수는 없을까.

ABAP는 정규식을 객체로 다루는 클래스 두 개를 제공한다([Chapter 21 · OO ABAP](CH21-L02.html)
에서 배운 [[Method]] 호출 그대로다).

| 클래스 | 역할 | 비유 |
|---|---|---|
| `CL_ABAP_REGEX` | 정규식의 객체 표현(컴파일된 패턴) | 도장 — 한 번 새겨 두고 |
| `CL_ABAP_MATCHER` | 그 패턴을 특정 텍스트에 적용한 실행 상태 | 도장을 종이에 대고 있는 손 |

## 패턴 객체 만들기 — CREATE_PCRE

새 코드는 반드시 factory method `CREATE_PCRE`로 만든다.

```abap
DATA(go_regex) = cl_abap_regex=>create_pcre(
  pattern     = `E(\d{3})`
  ignore_case = abap_true ).
```

> 🚨 `NEW cl_abap_regex( )`처럼 직접 생성하는 방식도 문법상 존재하지만 **deprecated**다
> — 그 방식은 obsolete인 POSIX 문법으로 연결된다(`CREATE_POSIX`도 마찬가지).
> PCRE 시대의 입구는 `CREATE_PCRE` 하나로 기억하면 된다.

만든 regex 객체는 두 곳에서 쓴다.

1. `CREATE_MATCHER`로 matcher를 만들어 메서드로 다루기 (이 레슨)
2. `FIND ... REGEX go_regex ...`처럼 문장의 `REGEX` 자리에 넘기기.
   단, **`PCRE` 자리에는 못 넘긴다**(그 자리는 패턴 문자열 전용). 그리고 객체를 넘기면
   `IGNORING CASE` 같은 옵션은 문장에 못 쓴다. 대소문자 설정은 객체를 만들 때 정한
   `ignore_case`가 대신한다.

## matcher 만들고 — match( )는 "전체 일치"

```abap
DATA(go_matcher) = go_regex->create_matcher( text = `E404` ).

IF go_matcher->match( ) = abap_true.
  DATA(gv_code) = go_matcher->get_submatch( 1 ).
  WRITE / |오류 번호: { gv_code }|.      " 404
ENDIF.
```

여기서 아주 중요한 의미 구분이 있다. **`match( )`는 텍스트 전체가 패턴과 일치해야**
`abap_true`다.

| 텍스트 | `match( )` 결과 | 왜 |
|---|---|---|
| `E404` | ✅ true | 전체가 `E(\d{3})` 형식 |
| `E404 concert missing` | ❌ **false** | 뒤에 딴 글자가 남는다 |

"로그 문장 **안에서** 오류 코드를 찾고 싶다"면 match( )가 아니라 다음의 find_next( )다.
이 구분을 놓치면 "분명 E404가 있는데 왜 false지?"라는 미궁에 빠진다.

## find_next( ) — 순차 검색 루프

matcher는 **현재 위치**라는 상태를 가진 객체다. `find_next( )`를 부를 때마다 다음
발견으로 전진하며, 더 없으면 `abap_false`를 돌려준다.

```abap
DATA(go_scan) = cl_abap_regex=>create_pcre(
    pattern = `E(\d{3})`
  )->create_matcher(
    text = `E100 booking failed, W210 retry, E404 concert missing` ).

WHILE go_scan->find_next( ) = abap_true.
  WRITE: / |발견: { go_scan->get_submatch( 1 ) }|.
ENDWHILE.
" 발견: 100
" 발견: 404
```

`get_submatch( 1 )`은 현재 발견의 1번 그룹 값이다. 없는 그룹 번호를 요청하면
[[예외]] `cx_sy_invalid_submatch`가 나므로, 번호를 돌려 가며 읽을 때는
[Chapter 21 · Exception Class](CH21-L06.html)의 `TRY ... CATCH`로 감싼다.

```abap
IF go_matcher->match( ) = abap_true.
  DO.
    TRY.
        WRITE / go_matcher->get_submatch( sy-index ).
      CATCH cx_sy_invalid_submatch.
        EXIT.                            " 그룹 번호 소진 → 탈출
    ENDTRY.
  ENDDO.
ENDIF.
```

## 문장이냐 클래스냐 — 선택 기준

| 상황 | 선택 |
|---|---|
| 한 번 찾고 끝 | `FIND PCRE` |
| 간단히 바꾸고 끝 | `REPLACE PCRE` |
| 같은 패턴을 여러 텍스트에 반복 | `CREATE_PCRE` + matcher 재사용 |
| "전체가 이 형식인가" 검증 | `match( )` |
| "안에서 몇 개든 찾아 전진" | `find_next( )` 루프 |
| 위 어디에도 안 걸림 | 클래스로 과하게 감싸지 말 것 |

## 흔한 실수와 점검 🚧

- **match( )로 "포함" 검사** — 이 레슨 최대 함정. 전체 일치 의미다. 포함/검색은
  `find_next( )`.
- **`FIND PCRE` 자리에 객체** — `PCRE` 뒤는 패턴 문자열, 객체는 `REGEX` 자리. 헷갈리면
  문법 오류가 알려 주긴 한다.
- **객체 + `IGNORING CASE` 동시 지정** — 문장 옵션은 못 쓴다. 대소문자는
  `create_pcre( ignore_case = ... )`에서.
- **한 번 쓰고 버릴 패턴에 클래스** — 오버엔지니어링. 문장형이 더 읽기 쉽다.

## 정리 📌

- `CL_ABAP_REGEX` = 컴파일된 패턴(도장), `CL_ABAP_MATCHER` = 텍스트 위의 실행 상태(손).
- 입구는 `cl_abap_regex=>create_pcre( )` 하나. 직접 생성(NEW)·CREATE_POSIX는 옛길.
- `match( )` = **전체 일치** 검증, `find_next( )` = 순차 검색 전진. 의미가 다르다.
- `get_submatch( n )` — 없는 번호는 `cx_sy_invalid_submatch`.

---

문장으로도, 객체로도 다뤄 봤다. 마지막 남은 자리가 있다: **조건식 안**. `IF` 한 줄에서
바로 정규식을 묻는 내장 함수들로 간다.
