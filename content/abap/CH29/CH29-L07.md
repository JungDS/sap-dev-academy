## 🎛️ 문장 말고 식 안에서

`FIND PCRE`는 명령문이라 결과를 받으려면 변수·`sy-subrc`를 거친다. 그런데 실무 코드의
절반은 **조건식** 안에서 판단한다. "이메일처럼 보이면 통과" 같은 로직을 `IF` 한 줄에
쓰고 싶다.

[Chapter 18 · String Template과 내장 함수](CH18-L05.html)에서 배운 [[내장함수]]들이
여기서 다시 등장한다. 이번엔 `pcre` 인자를 들고 온다.

## 판정 두 형제 — contains와 matches

```abap
DATA(gv_email) = `hunyoung@example.com`.

" 포함 검사: 안에 @가 든 단어 모양이 있는가
IF contains( val = gv_email pcre = `\w+@\w+` ).
  WRITE / `@ 형태 포함`.
ENDIF.

" 전체 일치 검사: 문자열 전체가 이메일 1차 형식인가
IF matches( val  = gv_email
            pcre = `[\w.+-]+@[\w.-]+\.[A-Za-z]{2,}` ).
  WRITE / `이메일처럼 보임`.
ENDIF.
```

| 함수 | 묻는 것 | anchor 필요? |
|---|---|---|
| `contains( )` | 패턴이 **어딘가에 포함**되는가 | 전체 검증엔 `^...$` 필요 |
| `matches( )` | **전체가** 패턴과 일치하는가 | **불필요**(자동 전체 일치) |

`matches( )`는 지난 레슨 `CL_ABAP_MATCHER->match( )`와 같은 의미(전체 일치)의 함수판이다.
형식 검증이 목적이면 anchor를 손으로 붙이는 `contains`보다 `matches`가 정본이다.

> 💡 이 이메일 패턴은 어디까지나 **1차 검사**다. 국제 표준의 모든 이메일 규칙을 다루지
> 않는다(실무에선 요구 수준부터 정한다). 참고로 ABAP PCRE의 `\w`는 유니코드를 존중해서
> **한글도 단어 문자로 통과**한다 — "영문만 허용"이 요건이면 `[A-Za-z0-9.+-]`처럼
> 명시적으로 좁혀야 한다.

## 세고, 찾고, 꺼내고 — count·find·match

```abap
DATA(gv_log) = `E100 W210 E404`.

DATA(gv_count) = count( val = gv_log pcre = `E\d{3}` ).
" 2  (오류 코드 개수)

DATA(gv_pos) = find( val = gv_log pcre = `W\d{3}` ).
" 5  (W210의 시작 offset. 못 찾으면 -1)

DATA(gv_first) = match( val = gv_log pcre = `E\d{3}` ).
" E100  (첫 매치 문자열 자체)
```

문장형과 짝을 지어 두면 외울 게 없다.

| 함수 | 문장형 대응 | 반환 |
|---|---|---|
| `count( )` | `FIND ALL ... MATCH COUNT` | 개수 |
| `find( )` | `FIND ... MATCH OFFSET` | 위치(실패 시 **-1**) |
| `match( )` | `FIND ... + substring` | 매치 문자열 |

## 함수형 replace — 원본은 그대로

```abap
DATA(gv_messy) = `A   B    C`.

DATA(gv_clean) = replace( val  = gv_messy
                          pcre = `\s+`
                          with = ` `
                          occ  = 0 ).

WRITE: / gv_messy,                       " A   B    C  (원본 불변!)
       / gv_clean.                       " A B C
```

문장 `REPLACE`와 두 가지가 다르다.

- **원본을 바꾸지 않고** 바뀐 결과를 **반환값**으로 준다(식 안에서 바로 사용 가능).
- 몇 건 바꿀지는 `occ` 인자: 생략하면 첫 1건, **`occ = 0`이면 전부**.

## 흔한 실수와 점검 🚧

- **contains로 전체 검증** — anchor를 잊으면 "포함"이다. 전체 일치는 `matches( )`.
- **함수 결과로 원본이 바뀌길 기대** — 함수는 값을 돌려줄 뿐이다. 원본 치환은 문장
  `REPLACE`(그쪽은 반대로 원본을 바꾼다).
- **함수형 replace에 VERBATIM** — 없다. `$1`을 literal로 넣으려면 escape(`\$1`)뿐.
- **긴 패턴을 식에 직접** — `IF matches( ... pcre = '아주긴패턴' )`은 읽기 고문이다.
  `DATA(gv_pattern) = ...`로 이름을 붙이고 넣는다.
- **빈 패턴** — 함수의 `pcre`가 빈 문자열이면 예외(`CX_SY_STRG_PAR_VAL`)다. 문장형의
  `CX_SY_INVALID_REGEX`와 이름이 다를 뿐 결론은 같다: 패턴은 비면 안 된다.
- **패턴이 너무 복잡** — 문장이든 함수든 한계를 넘으면 `CX_SY_REGEX_TOO_COMPLEX`가
  난다. 정규식이 자라기 시작하면 쪼개거나 파서를 검토한다.
- ABAP SQL/CDS에도 regex 함수가 있지만(DB에서 실행) 여기 함수들과 실행 위치·규칙이
  다르다(이 챕터는 ABAP 메모리 안 이야기다).

## 정리 📌

- `pcre` 인자를 주면 내장 함수들이 정규식 도구가 된다: **식 안에서 바로**.
- 판정: `contains`(포함) vs `matches`(전체 일치·anchor 불필요).
- `count`/`find`/`match` = 문장형 옵션들의 함수판. `find` 실패는 -1.
- 함수형 `replace`는 원본 불변·반환값 사용·`occ = 0` = 전부.
- 이 밖에 `substring_from( )`처럼 pcre를 받는 함수가 더 있다. 필요할 때 같은 감각으로
  찾아 쓰면 된다.
