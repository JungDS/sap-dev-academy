## 🔤 기호가 많아 보이지만

정규식이 어렵게 느껴지는 이유는 기호가 많아서다. 하지만 이메일, 접수번호, 로그 날짜,
공백 정리 정도를 처리하는 데 필요한 기호는 생각보다 적다. 이번 레슨의 표 두 개가
이 챕터 전체에서 쓸 재료의 거의 전부다.

## 문자 클래스 — "어떤 글자 한 개"

| 기호 | 의미 | 예 |
|---|---|---|
| `.` | 줄바꿈 제외 임의 문자 **한 개** | `A.B` → `A1B`, `A-B` 모두 |
| `\d` | 숫자 한 자리 (digit) | `0`～`9` |
| `\D` | 숫자가 **아닌** 문자 한 개 | `A`, `-`, 공백 |
| `\w` | 단어 문자 한 개 (word: 글자·숫자·`_`) | `H`, `7`, `_` |
| `\s` | 공백류 한 개 (space·tab 등) | ` ` |
| `[ABC]` | 대괄호 안 문자 중 **하나** | `A` 또는 `B` 또는 `C` |
| `[A-Z]` | 범위 — A부터 Z까지 중 하나 | 대문자 한 개 |
| `[^0-9]` | 대괄호 안 `^` = **제외** | 숫자가 아닌 것 |

전부 "글자 **한 개**"를 뜻한다는 점이 중요하다. `\d`는 숫자 하나, `\d\d`는 숫자 둘.

## 수량자 — "몇 번 반복"

문자 클래스 뒤에 붙어 반복 횟수를 정한다.

| 기호 | 의미 | 예 |
|---|---|---|
| `*` | 0번 이상 | `\d*` = 숫자 없거나 여러 개 |
| `+` | 1번 이상 | `\d+` = 숫자 최소 하나 |
| `?` | 0번 또는 1번 | `-?` = 하이픈 있어도 없어도 |
| `{4}` | 정확히 4번 | `\d{4}` = 숫자 네 자리 |
| `{2,4}` | 2번 이상 4번 이하 | `\d{2,4}` |

## 그룹과 선택

| 기호 | 의미 | 예 |
|---|---|---|
| `( )` | 묶음 — [[Capture Group]](캡처 그룹, 괄호로 잡아 나중에 꺼내 쓸 수 있는 부분 패턴) | `(\d{4})` |
| `\|` | 또는 (alternation) | `N\|C` = `N` 또는 `C` |

`N|C`가 낯익지 않은가? 우리 예매 상태값(신규 `N`/취소 `C`)이다. "상태 문자가 둘 중
하나인가"를 물을 때 `^(N|C)$`처럼 쓴다.

## 조합해서 읽어 보기

지난 레슨의 접수번호 패턴을 이제 완전히 해석할 수 있다.

```text
^B-\d{4}-\d{4}$
= 시작(^) + 'B-' 그대로 + 숫자 4자리 + '-' + 숫자 4자리 + 끝($)
```

로그에서 접수번호를 찾아 위치까지 받아 보자. `MATCH OFFSET`(발견 시작 위치)과
`MATCH LENGTH`(발견 길이)는 다음 레슨의 주인공인데, 여기서는 "결과를 원문에서 다시
잘라 눈으로 확인"하는 용도로만 먼저 쓴다.

```abap
DATA(gv_log) =
  `Booking B-2026-0007 failed at 2026-07-06 14:30:05`.

FIND PCRE `B-\d{4}-\d{4}` IN gv_log
     MATCH OFFSET DATA(gv_offset)
     MATCH LENGTH DATA(gv_length).

IF sy-subrc = 0.
  DATA(gv_found) = substring( val = gv_log
                              off = gv_offset
                              len = gv_length ).
  WRITE / gv_found.                 " B-2026-0007
ENDIF.
```

`substring( )`은 [Chapter 18 · String Template과 내장 함수](CH18-L05.html)에서 배운
그 함수다. **정규식 결과를 믿기만 하지 말고 원문을 다시 잘라 확인하는 습관**. 패턴
실수를 가장 빨리 잡는 방법이다.

날짜는 그룹으로 나눠 볼 수 있다. 그룹 값을 변수로 꺼내는 `SUBMATCHES`는
[L04](CH29-L04.html)에서 정식으로 다루고, 여기서는 "괄호가 조각을 만든다"는 감각만.

```text
^(\d{4})-(\d{2})-(\d{2})$   ← 2026-07-06
  그룹1      그룹2    그룹3
```

## greedy — 수량자는 욕심쟁이

`*`와 `+`에는 성격이 있다. 기본은 [[Greedy]](탐욕적: 가능한 **많이** 잡으려는 수량자의
기본 성질)다.

```abap
DATA(gv_html) = `<i>ABAP</i><i>UI5</i>`.

" greedy: 가능한 많이 → <i>ABAP</i><i>UI5</i> 전체가 잡힌다
FIND PCRE `<i>.*</i>` IN gv_html
     MATCH LENGTH DATA(gv_len_greedy).      " 21 (전체)

" non-greedy: 가능한 적게 → <i>ABAP</i> 첫 태그만
FIND PCRE `<i>.*?</i>` IN gv_html
     MATCH LENGTH DATA(gv_len_lazy).        " 11 (첫 태그)
```

수량자 뒤에 `?`를 붙이면 non-greedy(가능한 **적게**)로 바뀐다. 첫 태그 하나만 잡고
싶은데 문서 끝까지 삼켜 버리는 사고. greedy를 모르면 반드시 한 번은 겪는다.

> ⚠️ 이 예제는 greedy 차이를 보는 용도다. HTML/XML **전체를 정규식으로 파싱하는 것은
> 금물** — 그건 전용 파서의 일이다.

## 흔한 실수와 점검 🚧

- **`.` 남용** — "아무거나"는 너무 넓게 잡힌다. 숫자면 `\d`, 단어면 `\w`처럼 **구체적인
  클래스**를 우선한다.
- **`\d+`로 자릿수 검증** — `+`는 1자리든 100자리든 통과시킨다. 자릿수가 정해져 있으면
  `{4}`처럼 개수를 명시한다.
- **`.*` 선두 배치** — 패턴 앞머리의 `.*`는 과도한 매칭과 성능 문제의 단골 원인이다.
- **공백 함정 ★** — ABAP의 PCRE는 **extended mode가 기본**이라, 패턴 안의 escape되지
  않은 공백을 **무시한다**. `B- \d{4}`라고 띄어 써도 `B-\d{4}`로 해석된다는 뜻.
  공백 자체를 찾으려면 `\s`를 쓴다(또는 `\ `처럼 escape).
- 괄호를 쓸 때는 **묶음이 목적인지, 값을 꺼낼 그룹인지** 의도를 분명히 한다
  ([L04](CH29-L04.html)에서 구분법을 배운다).

## 정리 📌

- 문자 클래스(`\d` `\w` `\s` `[ ]`) = 어떤 글자 한 개. 수량자(`*` `+` `?` `{m,n}`) = 몇 번.
- `( )` = 그룹, `|` = 또는, `^`·`$` = 시작·끝 고정.
- 수량자 기본 성질은 greedy(많이). `?`를 붙이면 non-greedy(적게).
- ABAP PCRE는 extended mode가 기본. 패턴 속 맨 공백은 무시되니 공백은 `\s`로.
- lookaround(전후 문맥 조건) 같은 고급 문법도 존재하지만 이 과정 범위 밖이다. 여기 나온
  토큰만으로 실무 초급 패턴은 대부분 읽고 쓸 수 있다.
