## 🧹 찾기의 반대편 — 정리하기

정규식은 찾기 전용이 아니다. 파트너에서 온 지저분한 텍스트를 **표준 형식으로 정리**할
때가 진짜 실력 발휘다.

- 금액 `KRW 120,000`에서 숫자만 남기기
- 이름 사이 여러 공백을 하나로
- 공연일 `2026/07/06`을 우리 표기 `2026-07-06`으로

[Chapter 4 · 문자열 다루기](CH04-L02.html)의 `REPLACE ... OF 'old' ... WITH 'new'`가
고정 문자열 치환이었다면, `REPLACE PCRE`는 **패턴 치환**이다.

## 기본형 — 숫자만 남기기·공백 정리

```abap
DATA(gv_amount) = `KRW 120,000`.

REPLACE ALL OCCURRENCES OF PCRE `\D`
        IN gv_amount WITH ``.

WRITE / gv_amount.                       " 120000
```

`\D`(숫자가 아닌 문자)를 전부 빈 문자열로 바꿨다. 통화 표기·콤마가 한 번에 사라진다.

```abap
DATA(gv_name) = `정훈영    ABAP     Academy`.

REPLACE ALL OCCURRENCES OF PCRE `\s+`
        IN gv_name WITH ` `.

WRITE / gv_name.                         " 정훈영 ABAP Academy
```

`\s+`(공백 1개 이상 연속)를 공백 하나로. 연속 공백이 몇 개든 한 방이다.

> ⚠️ `FIND`와 달리 `REPLACE`는 **원본 변수를 바꾼다**. 원본이 필요하면 복사본을 먼저
> 만들어 두는 습관을.

## group substitution — 잡은 값을 다시 끼워 넣기

날짜 구분자 표준화가 백미다. 연·월·일을 그룹으로 잡고, 치환문에서 `$1`·`$2`·`$3`으로
되부른다.

```abap
DATA(gv_date) = `2026/07/06`.

REPLACE FIRST OCCURRENCE OF PCRE
        `^(\d{4})/(\d{2})/(\d{2})$`
        IN gv_date
        WITH `$1-$2-$3`.

WRITE / gv_date.                         " 2026-07-06
```

| 치환문 표기 | 뜻 |
|---|---|
| `$0` | 매치 전체 |
| `$1`, `$2`, ... | 1번째, 2번째 캡처 그룹의 값 |

값(2026, 07, 06)은 그대로 두고 **형식만** 바꿨다. 이게 group substitution의 힘이다.

## VERBATIM — "$1을 진짜 글자로 넣고 싶은데?"

가끔은 치환 결과에 문자 그대로의 `$1`을 넣어야 한다(예: 안내 문구 템플릿 생성).
[[VERBATIM]](축자 — 치환문의 특수문자 해석을 끄는 옵션)을 붙이면 치환문이 전부
literal이 된다.

```abap
DATA(gv_text) = `A123`.

" VERBATIM 없음: $1 = 그룹 값       → 123
" VERBATIM 있음: $1 = 문자 그대로   → $1
REPLACE PCRE `A(\d+)` IN gv_text
        WITH `$1`
        VERBATIM.

WRITE / gv_text.                         " $1
```

## 치환 결과 검증 — REPLACEMENT COUNT

치환은 원본을 바꾸는 만큼 `FIND`보다 더 검증이 중요하다.

```abap
DATA(gv_text2) = `A  B   C`.

REPLACE ALL OCCURRENCES OF PCRE `\s+`
        IN gv_text2 WITH ` `
        REPLACEMENT COUNT DATA(gv_count).

WRITE: / gv_text2,                       " A B C
       / |치환 횟수: { gv_count }|.      " 2
```

- `REPLACEMENT COUNT` = 몇 번 바뀌었나. **0이면 패턴이 아무것도 못 잡았다는 경고
  신호**다(치환문 오타보다 패턴 미스가 훨씬 흔하다).
- `REPLACEMENT OFFSET`/`LENGTH`도 있다. 단, ALL 치환에서는 앞선 치환 때문에 위치가
  **밀린 뒤의 값**이라 `FIND`의 `MATCH OFFSET`과 같은 감각으로 읽으면 안 된다.
- 발견별 치환 위치가 표로 필요하면 여기도 `RESULTS`가 있다(역시 OFFSET/LENGTH와는
  같은 문장에서 택일). `REPLACE`의 RESULTS 줄에는 `FIND` 때와 달리 `submatches`
  필드가 없다(치환이 끝난 뒤라 그룹 위치가 의미 없기 때문).

## 흔한 실수와 점검 🚧

- **원본 파괴** — `REPLACE`는 제자리 치환이다. 원본 보존이 필요하면 복사 후 작업.
- **그룹 번호 변경 사고** — 패턴에 괄호를 하나 추가하면 `$2`가 가리키는 그룹이
  달라진다. 패턴 수정 시 치환문도 같이 점검.
- **`$1`을 literal로** — escape(`\$1`)도 되지만 `VERBATIM`이 더 명확하고 빠르다.
  단 치환문 **전체**가 literal이 되므로 그룹 재사용과 병행은 불가.
- **고정 길이 필드 절단** — `c` 타입 필드에 더 긴 치환 결과를 넣으면 잘린다
  (`sy-subrc = 2`). 문자열 작업은 `string` 타입에서.
- **빈 패턴 + ALL** — 빈 패턴을 ALL로 치환하면 무한 루프 예외
  (`CX_SY_REPLACE_INFINITE_LOOP`)가 난다. 패턴이 비지 않았는지 먼저 확인.

## 정리 📌

- `REPLACE PCRE` = 패턴 치환. `\D` 제거·`\s+` 정리처럼 "모양 기준 청소"에 강하다.
- `$1`·`$2`로 그룹 값을 치환문에 재사용: 값은 두고 형식만 바꾼다.
- `VERBATIM` = 치환문 특수문자 해석 끄기.
- 치환 후에는 `REPLACEMENT COUNT`로 몇 건 바뀌었는지 확인하는 습관.
