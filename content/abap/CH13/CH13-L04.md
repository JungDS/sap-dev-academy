## 집계한 다음에 거르기

`WHERE`는 **그룹 짓기 전** 행을 거른다. "운항편 5편 이상인 항공사만"처럼 **집계
결과로** 거르려면 `HAVING`이 필요하다.

## WHERE vs HAVING

| | 시점 | 대상 |
|---|---|---|
| `WHERE` | GROUP BY **전** | 개별 행 |
| `HAVING` | GROUP BY **후** | 집계 결과 |

```abap
TYPES: BEGIN OF ts_sum,
         carrid TYPE sflight-carrid,
         cnt    TYPE i,
       END OF ts_sum.

DATA gt_sum TYPE TABLE OF ts_sum.

SELECT carrid COUNT( * ) AS cnt
  FROM sflight
  INTO CORRESPONDING FIELDS OF TABLE gt_sum
  WHERE seatsocc > 0       " 먼저 개별 행 필터(예약 있는 운항편만)
  GROUP BY carrid
  HAVING COUNT( * ) >= 5.  " 그 다음 그룹 필터
```

## 두 번 거른다 — 단계로 보기

이 한 문장은 **두 번** 거른다.

1. `WHERE seatsocc > 0` — 예약 없는 운항편은 **그룹 만들기 전**에 제외(개별 **행**).
2. `HAVING COUNT( * ) >= 5` — 남은 운항편을 항공사별로 센 뒤, 5편 미만 항공사는 제외(**그룹**).

집계 조건(`COUNT`·`SUM`)은 그룹이 생긴 **뒤**에야 의미가 있으므로 `WHERE`가 아니라
`HAVING`에 둔다. `WHERE COUNT( * ) >= 5`는 잘못된 방향이다. 그 시점엔 아직 그룹이 없으니
셀 것도 없다.

두 조건은 **거르는 대상의 크기**가 다르다. `WHERE`는 행을 하나씩 보며 통과 여부를 정하고,
`HAVING`은 이미 묶인 그룹을 하나씩 보며 정한다. 몇 개를 떨어뜨리느냐가 아니라 **무엇을
단위로 판단하느냐**의 차이다. 아래 파이프라인을 한 단계씩 진행하며, 같은 데이터가 행
단위와 그룹 단위에서 각각 어떻게 걸러지는지 보자.

## 절의 순서는 정해져 있다

classic Open SQL은 절을 적는 순서가 고정돼 있다.

`SELECT` → `FROM` → `INTO` → `WHERE` → `GROUP BY` → `HAVING` → `ORDER BY`

순서를 바꿔 적으면 구문 오류가 난다. 맨 끝의 `ORDER BY`(정렬)는 아직 안 배웠으니
지금은 **자리만** 기억해 두자. 바로 다음 레슨에서 다룬다.

## 흔한 실수와 점검

- **집계 조건을 `WHERE`에** → `WHERE COUNT( * ) …`는 오류다. 세는 일은 그룹이 만들어진
  다음에 벌어지니, 집계로 거르는 조건은 `HAVING`에 적는다.
- **`HAVING`만 쓰고 `WHERE`를 안 쓰기** → 문법은 맞지만 필요 없는 행까지 다 묶었다가
  버리는 셈이다. 미리 걸러 낼 수 있는 조건은 `WHERE`에 두는 편이 DB 일감을 줄인다.
- **절 순서를 섞기** → 위 순서를 그대로 지킨다. 특히 `GROUP BY`와 `HAVING`이 뒤집히기 쉽다.
