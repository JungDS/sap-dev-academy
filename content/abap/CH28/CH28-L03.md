## 실패했는데 가리키고 있다?

동적 ABAP의 대표 버그는 이 순서로 생긴다.

1. `<lv_field>`가 `STATUS` 필드를 가리키고 있다.
2. 다음 줄에서 존재하지 않는 `UNKNOWN_FIELD`를 할당하려 한다.
3. **실패했는데** `<lv_field>`는 여전히 이전의 `STATUS`를 가리킨다.
4. 개발자가 `IS ASSIGNED`만 보고 "성공했네" 하고 이전 값을 새 값인 줄 쓴다.

동적 `ASSIGN`은 실패해도 런타임 오류가 아니라 `sy-subrc`만 바뀌는 경우가 있고, 실패 시
**이전 할당이 그대로 남을 수 있다**. 그래서 이 레슨은 문법이 아니라 **상태 관리**를 가르친다.

## 무엇인가 — 연결·해제·확인

```abap
FIELD-SYMBOLS <lv_value> TYPE any.

ASSIGN gv_status TO <lv_value>.      " 연결
IF <lv_value> IS ASSIGNED.           " 확인
  WRITE / <lv_value>.
ENDIF.

UNASSIGN <lv_value>.                 " 해제 — 아무것도 안 가리키게
```

헷갈리기 쉬운 두 문장의 차이가 이 레슨의 핵심이다.

| 문장 | 바뀌는 것 | 원본 데이터 |
|---|---|---|
| `CLEAR <lv_value>` | **가리키는 원본 값**이 초기화된다 | 지워짐! |
| `UNASSIGN <lv_value>` | **연결만** 끊긴다 | 그대로 |

## 상태 기계로 눌러 보기

아래에서 성공 할당 → 실패 할당(ELSE 유무) → CLEAR → UNASSIGN을 눌러 가며, `sy-subrc`와
`IS ASSIGNED`가 **따로 논다**는 것을 눈으로 확인해 보라.

## 어떻게 확인하는가 — 기본 습관

실패 시 이전 할당을 남기지 않으려면 `ELSE UNASSIGN`을 붙이고, **`sy-subrc`와 `IS ASSIGNED`를
함께** 본다.

```abap
ASSIGN COMPONENT gv_component
       OF STRUCTURE gs_booking
       TO <lv_field>
       ELSE UNASSIGN.

IF sy-subrc = 0 AND <lv_field> IS ASSIGNED.
  WRITE / <lv_field>.
ELSE.
  WRITE / |{ gv_component } 필드를 찾지 못했습니다|.
ENDIF.
```

| 확인 | 답해 주는 질문 |
|---|---|
| `sy-subrc = 0` | **방금 시도한** 할당이 성공했나 |
| `IS ASSIGNED` | **지금** 무언가를 가리키고 있나 (이전 할당일 수도!) |

둘은 다른 질문이다. `IS ASSIGNED`만 보면 3번 함정(이전 할당)에 빠진다.

> ℹ️ 참고 둘. ① **정적** `ASSIGN`(변수를 직접 지정)은 `sy-subrc`를 건드리지 않는다 —
> `sy-subrc` 확인은 **동적** 계열의 습관이다. ② `ELSE UNASSIGN`은 릴리스 **7.57**에 추가된
> 문법이라 아주 오래된 시스템에서는 컴파일되지 않을 수 있다.

## 흔한 실수와 점검 🚧

- **`IS ASSIGNED`만 확인** → 이전 할당을 성공으로 착각한다. 동적 할당 뒤엔 `sy-subrc`를 함께.
- **`ELSE UNASSIGN` 생략** → 실패 시 이전 할당이 남는다. 남길 *의도*가 없다면 항상 붙인다.
- **`CLEAR`로 연결을 끊으려 함** → `CLEAR <fs>`는 **원본 값을 지운다**. 연결 해제는 `UNASSIGN`.
- **`sy-subrc`가 만능이라 착각** → 잘못된 메모리 접근은 예외로 터질 수도 있다. `sy-subrc`는
  동적 할당의 실패 신호일 뿐 모든 위험의 안전망이 아니다.

## 정리 📌

- 동적 `ASSIGN`은 "**성공했나**(`sy-subrc`)"와 "**지금 무엇을 가리키나**(`IS ASSIGNED`)"를
  분리해서 본다.
- 실패 시 이전 할당을 남기지 않는 기본형 = `ASSIGN ... ELSE UNASSIGN.`
- `CLEAR` = 원본 초기화, `UNASSIGN` = 연결 해제. 반대로 쓰면 데이터 사고다.
