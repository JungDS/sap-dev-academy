## 구조마다 메서드를 또 만들 텐가

"값을 로그로 남기는 공통 도구"를 만든다고 하자. 예매 구조도, 고객 구조도, 메시지 구조도
받아야 한다면 —

```abap
METHODS write_booking  IMPORTING is_booking  TYPE ts_booking.
METHODS write_customer IMPORTING is_customer TYPE ts_customer.
METHODS write_message  IMPORTING is_message  TYPE ts_message.
```

구조가 늘 때마다 메서드가 늘어난다. 공통 도구일수록 이 중복이 아프다. 해결책은 파라미터
자리의 타입을 넓게 잡는 **[[Generic Type|generic 파라미터]]**다.

## 무엇인가 — 넓게 받는 자리

| generic type | 뜻 | 주 사용처 |
|---|---|---|
| `TYPE any` | 어떤 데이터든 받는다 | 값 표시·구조 검사 도구 |
| `TYPE data` | `any`처럼 일반 데이터를 받는 generic typing | 동적 할당 문맥 |
| `TYPE ANY TABLE` | 어떤 내부 테이블이든 받는다 | 행 수 세기·범용 표시 도구 |
| `TYPE STANDARD TABLE` | 테이블 종류만 고정, 줄 타입은 열어 둠 | 테이블 처리 도구 |

```abap
CLASS lcl_value_inspector DEFINITION.
  PUBLIC SECTION.
    METHODS count_rows
      IMPORTING it_table        TYPE ANY TABLE
      RETURNING VALUE(rv_count) TYPE i.
ENDCLASS.

CLASS lcl_value_inspector IMPLEMENTATION.
  METHOD count_rows.
    rv_count = lines( it_table ).     " 줄 타입 몰라도 행 수는 셀 수 있다
  ENDMETHOD.
ENDCLASS.
```

핵심 감각: generic 파라미터로 **"가능한 작업"과 "불가능한 작업"이 갈린다**. 행 수 세기는
줄 타입을 몰라도 되지만, `<ls_line>-booking_id`처럼 **특정 필드 접근은 불가능**하다 —
`ANY TABLE`은 줄의 모양을 모르니까.

## 어떻게 확인하는가

generic 테이블에서 첫 줄을 꺼내는 코드로 경계를 확인한다.

```abap
METHOD show_first_line.
  FIELD-SYMBOLS <ls_line> TYPE any.

  LOOP AT it_table ASSIGNING <ls_line>.
    " <ls_line>-booking_id 라고 바로 쓰면 → syntax 오류(줄 타입을 모름)
    WRITE / <ls_line>.               " 낱값이면 출력됨. 구조면 기대와 다를 수 있음
    EXIT.
  ENDLOOP.
ENDMETHOD.
```

1. `TYPE ANY TABLE`만으로는 **줄의 구조를 알 수 없다**.
2. 필드가 필요하면 **실행 중 확인**을 거쳐야 한다 — 그 도구가 [ASSIGN COMPONENT](CH28-L04.html)와
   [RTTS](CH28-L07.html)다(뒤 레슨).

## 흔한 실수와 점검 🚧

- **시그니처만 유연, 내부 검증 없음** → generic 파라미터를 쓰는 순간 메서드 안의 확인 코드는
  **늘어나는 게 정상**이다. 줄었다면 뭔가 안 하고 있는 것.
- **"어떤 테이블이든 받는다" = "같은 업무 규칙을 적용할 수 있다"로 착각** → 받는 것과
  처리하는 것은 다른 문제다.
- **`TYPE any`에 바로 산술·필드 접근·테이블 연산** → 타입 확인이 먼저다.
- **업무 규칙까지 generic 도구에** → 공통 도구가 업무 규칙을 알아야 한다면, generic이 아니라
  업무별 class·interface([Chapter 27](CH27-L03.html)의 설계)가 맞을 수 있다.

## 정리 📌

- generic 파라미터(`TYPE any`·`ANY TABLE`)는 **공통 도구**를 위한 문 — 무엇이든 받되,
  들어온 것을 **확인한 범위 안에서만** 다룬다.
- 가능한 작업(행 수 세기 등)과 불가능한 작업(필드 직접 접근)을 구분하는 게 이 레슨의 전부다.
