## 필드 이름이 코드에 없다

보통의 코드는 필드 이름을 직접 쓴다 — `WRITE / gs_booking-status.` 명확하고 안전하다.

그런데 사용자가 화면에서 **표시할 필드를 고르거나**, 설정 테이블에 저장된 필드 목록을 읽어야
한다면? 필드 이름이 코드 작성 시점이 아니라 **실행 시점에** 정해진다.

```text
사용자 선택 필드: BOOKING_ID, STATUS
읽어야 할 값   : gs_booking-booking_id, gs_booking-status
```

문자열 `'STATUS'`를 구조 필드 접근으로 바꿔 주는 공식 문법이 [[ASSIGN COMPONENT]]다.

## 무엇인가

```abap
ASSIGN COMPONENT gv_component      " 이름('STATUS') 또는 위치(1)
       OF STRUCTURE gs_booking
       TO FIELD-SYMBOL(<lv_value>)
       ELSE UNASSIGN.
```

| 지정 방식 | 예 | 뜻 |
|---|---|---|
| 이름 | `'STATUS'` | 그 이름의 필드를 찾는다 — 대소문자는 구분하지 않는다(공식 보장) |
| 위치 | `1` | 구조의 첫 번째 필드를 찾는다 |
| `0` | — | 구조 **전체**를 할당하는 특수 의미 — 입문에선 쓰지 않는다 |

필드가 없거나 구조가 아니면 `sy-subrc = 4`. [앞 레슨](CH28-L03.html)의 기본 습관
(`ELSE UNASSIGN` + `sy-subrc`·`IS ASSIGNED` 동시 확인)이 그대로 적용된다.

## 직접 골라 보기

구조 표에서 필드를 이름/위치로 골라 보고, 없는 필드(`UNKNOWN`)와 **whitelist에 없는 필드**가
각각 어떻게 거절되는지 확인해 보라.

## 어떻게 확인하는가

설정 필드 목록을 돌며 값을 출력한다 — 실패는 데이터 사고 없이 **피드백으로** 처리된다.

```abap
DATA gt_requested TYPE STANDARD TABLE OF string WITH EMPTY KEY.
gt_requested = VALUE #( ( `BOOKING_ID` ) ( `STATUS` ) ( `UNKNOWN` ) ).

LOOP AT gt_requested INTO DATA(lv_field_name).
  ASSIGN COMPONENT lv_field_name
         OF STRUCTURE gs_booking
         TO FIELD-SYMBOL(<lv_field>)
         ELSE UNASSIGN.

  IF sy-subrc = 0 AND <lv_field> IS ASSIGNED.
    WRITE / |{ lv_field_name } = { <lv_field> }|.
  ELSE.
    WRITE / |{ lv_field_name } 은(는) 이 구조의 필드가 아닙니다|.
  ENDIF.
ENDLOOP.
```

이름을 몰라도 **위치**로 전부 훑을 수도 있다(간단 인스펙터의 기초).

```abap
DO.
  ASSIGN COMPONENT sy-index
         OF STRUCTURE gs_booking
         TO FIELD-SYMBOL(<lv_comp>)
         ELSE UNASSIGN.
  IF sy-subrc <> 0.
    EXIT.                          " 필드를 다 돌면 실패 → 종료
  ENDIF.
  WRITE: / sy-index, <lv_comp>.
ENDDO.
```

단, 위치는 구조 정의가 바뀌면 의미가 변한다 — **업무 규칙에는 이름 기반**이 안전하다.

## 흔한 실수와 점검 🚧

- **사용자 입력을 그대로 필드 이름으로** → 허용 필드 **whitelist**를 먼저 통과시킨다.
  구조에 있어도 노출하면 안 되는 필드가 있다(급여·개인정보 등) — "구조에 있다 ≠ 보여 줘도 된다".
- **실패 처리 생략** → unassigned 접근 오류 또는 이전 할당 착각([앞 레슨](CH28-L03.html)의 함정).
- **위치 기반을 업무 규칙에** → 구조 순서 변경에 취약하다. 인스펙터·디버깅용으로만.
- **"짧게 쓰려고" 동적 접근** → 필드 이름을 이미 안다면 `gs_booking-status`가 정답이다.
  동적 접근은 *이름이 실행 중에 정해질 때만*.

## 정리 📌

- `ASSIGN COMPONENT 이름/위치 OF STRUCTURE ... ELSE UNASSIGN` = 실행 중 필드 선택의 공식 도구.
- 실패(`sy-subrc=4`)는 안내로 처리, 사용자 입력은 **whitelist**로 거른다.
- 구조 필드의 동적 접근에는 이 문법이 **최우선**이다 — 이름 문자열로 아무 변수나 찾는 방법
  (다음 레슨)보다 먼저.
