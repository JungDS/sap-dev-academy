## 왜 — 공통은 한 번만 🧬

일반 예매와 VIP 예매가 *대부분 같고 일부 규칙만* 다르다고 하자. 두 클래스를 처음부터 따로 만들면 잔여석 계산·정원 초과 예외·공연/회차 상태 보관 같은 **공통 로직이 중복**된다.

상속은 공통을 부모에 두고, **차이만 자식에서** 확장하게 해 준다. ABAP 클래스는 **단일 상속**(부모는 하나)이다.

```abap
CLASS zcl_vip_booking DEFINITION PUBLIC
  INHERITING FROM zcl_booking_manager
  CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS book REDEFINITION.        " 부모 메서드를 다시 정의
    METHODS apply_vip_coupon.         " 자식에서 새로 더한 VIP 전용 메서드
ENDCLASS.

CLASS zcl_vip_booking IMPLEMENTATION.
  METHOD book.
    IF iv_seats > 4.                  " VIP 전용 추가 규칙
      RAISE EXCEPTION TYPE zcx_fully_booked.
    ENDIF.
    super->book( iv_seats = iv_seats ).   " 부모의 원래 동작 재사용
  ENDMETHOD.

  METHOD apply_vip_coupon.
    " VIP 쿠폰 적용(자리만 잡아 둔다. 다음 레슨에서 이 메서드를 부른다)
  ENDMETHOD.
ENDCLASS.
```

- `INHERITING FROM` — 부모를 [[상속]]한다.
- `REDEFINITION` — 부모의 인스턴스 메서드를 **새로 구현**(오버라이드).
- `super->` — 부모의 원래 구현을 부른다(자식 검사 후 부모 동작 재사용).
- 자식은 재정의만 하는 게 아니라 `apply_vip_coupon`처럼 **새 메서드를 더할** 수도 있다.

> ⚠️ 상한 위반(1회 4석 초과)은 매진과 **원인이 다른** 실패다. 지금은 배운 예외 클래스가 `ZCX_FULLY_BOOKED` 하나뿐이라 재사용했지만, 실무에서는 `ZCX_VIP_LIMIT`처럼 **사유별 예외 클래스**를 나눈다. 예외 이름이 원인을 정확히 말해야 호출자가 바르게 대응한다(매진이면 다른 회차 안내, 상한 위반이면 좌석 수 조정).

## 정적 타입 vs 동적 타입 🎭

부모 타입 참조 변수에 자식 객체를 담을 수 있다. 그래도 **재정의된 메서드는 실제 객체(자식) 구현으로** 실행된다.

```abap
DATA lo_mgr TYPE REF TO zcl_booking_manager.   " 정적 타입 = 부모
lo_mgr = NEW zcl_vip_booking( iv_concert = 'C001' iv_perf = '01' ).
"                              ↑ 동적 타입 = 자식
lo_mgr->book( iv_seats = 2 ).   " 자식의 redefined book 이 실행된다
```

`zcl_vip_booking`에는 `constructor`를 따로 쓰지 않았는데도 공연 ID·회차를 넘겼다. **생성자도 부모에게서 물려받기** 때문이다: 자식이 생성자를 직접 선언하지 않으면 부모 `constructor`의 입력 형태를 그대로 이어받아 그 생성자가 실행된다.

변수의 **정적 타입**은 `zcl_booking_manager`지만, 담긴 객체의 **동적 타입**은 `zcl_vip_booking`이다. `book`이 재정의돼 있으면 호출은 자식 구현으로 들어간다. 이것이 [Interface 기본 설계](CH21-L05.html)에서 본 [[다형성]]이 상속 계층에서 나타나는 모습이다. 그 활용법(실제 타입 확인·분기)은 다음 레슨에서 다룬다.

## ABSTRACT · FINAL 🚧

- `ABSTRACT` — 직접 객체를 못 만들고 **상속 전용 틀**로 둔다(공통 정책의 추상 부모).
- `FINAL` — 더 이상 **상속·재정의 금지**(완성된 클래스).

둘 다 `DEFINITION` 머리에 붙는다.

```abap
" 골격 — 붙는 자리만 본다
CLASS zcl_abstract_sample DEFINITION PUBLIC ABSTRACT.   " NEW 불가: 상속 전용 틀
ENDCLASS.

CLASS zcl_final_sample DEFINITION PUBLIC FINAL.         " 더는 상속 불가: 완성형
ENDCLASS.
```

메서드 수준에도 붙일 수 있다. `METHODS book ABSTRACT.`는 부모가 몸통 없이 선언만 하고 자식이 `REDEFINITION`으로 반드시 채우는 메서드(ABSTRACT 클래스 안에서만 가능), `METHODS book FINAL.`은 자식이 더는 재정의할 수 없는 메서드다.

## 흔한 실수와 점검 🚧

- **`REDEFINITION` 없이 오버라이드** → 부모 메서드를 바꾸려면 definition에 `METHODS book REDEFINITION.`이 있어야 한다.
- **자식에서 부모 private 접근** → private은 자식에게도 안 보인다. 자식에게 열 의도면 부모에서 **protected**로 설계한다.
- **상속으로 모든 변형 해결** → "VIP는 예약 관리자의 특수한 종류"면 상속이 맞지만, "출력 가능"·"검증 가능"처럼 상속 계보와 무관하게 여러 클래스를 **가로질러** 적용되는 약속(횡단 규약)은 [Interface](CH21-L05.html)가 더 적합하다.
- **`super->` 호출을 습관적으로 넣거나 빼기** → 부모 동작을 유지하며 앞뒤로 규칙을 더할지(호출), 완전히 대체할지(생략) **설계 의도를 먼저** 정한다.
