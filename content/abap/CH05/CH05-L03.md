## Structure를 또 짜기 싫다

주소(시·도·우편번호)나 생성 이력(만든 사람·만든 날짜)처럼 **같은 필드 묶음**을 여러 Structure에
매번 다시 적기는 번거롭다. DDIC에서는 **이미 만든 Structure를 다른 Structure에 끼워 넣어** 재사용할 수 있다.
방법이 세 가지인데, "어떻게 들어가느냐"가 다르다.

## ① 중첩 — Structure를 Component로

Component의 타입에 **다른 Structure**를 주면, Structure 안에 Structure가 들어간다(중첩 Structure).

아래 예제의 `zst_order_head`는 [앞 레슨](CH05-L02.html)에서 `ZST_PERSON`을 만든 것과 똑같은
방법으로 SE11에 만들어 둔 **주문 머리** Structure다. Component는 `customer`(고객)와
`order_date`(주문일) 둘뿐이니, 예제를 직접 따라 하려면 아래 표대로 먼저 만들어 두자.

| Component | Typing | 예 | 데이터 타입 | 길이 | 설명 |
|---|---|---|---|---|---|
| CUSTOMER | Data Element | `ZDE_NAME` | CHAR | 20 | 고객 이름 |
| ORDER_DATE | Data Element | `ZDE_ORDER_DATE` | DATS | 8 | 주문일 |

`ZDE_NAME`은 앞 레슨에서 쓴 것을 그대로 재사용한다. 날짜용 `ZDE_ORDER_DATE`는
[Chapter 3 · Data Element — 의미·라벨 입히기](CH03-L02.html)에서 한 그대로, DATS 8자리
Domain을 하나 만들고 그것을 참조해 만들면 된다.

```abap
DATA: BEGIN OF gs_order,
        order_id TYPE c LENGTH 10,
        head     TYPE zst_order_head,   " Structure를 통째로 한 Component로
        qty      TYPE i,
      END OF gs_order.

gs_order-order_id      = 'SO-1001'.   " 내가 직접 선언한 칸
gs_order-head-customer = '정훈영'.     " 한 단계 더 -로 파고든다
```

- 접근 경로에 `gs_order-head-customer`처럼 **단계가 생긴다**(`-`를 두 번).
- "고객 정보는 head 안에"처럼 **묶음이 그대로 보존**된다.

## ② `.INCLUDE` — 펼쳐서 담기

DDIC Structure 편집 화면에서 다른 Structure를 `.INCLUDE`로 포함하면, 그 Structure의 필드들이
**펼쳐져서(내 필드처럼)** 들어온다. 중첩과 달리 이건 **DDIC 편집 화면에서 하는 조작**이다.

이번엔 여러 Structure가 함께 쓰는 **생성 이력**을 담아 보자. `ZST_AUDIT`은
`created_by`(만든 사람)·`created_on`(만든 날짜) 두 필드만 가진 DDIC Structure이고, 담을
쪽은 주문 Structure `ZST_ORDER`(자기 필드는 `order_id`·`customer`·`amount`)다. 둘 다 앞과
같은 방법으로 SE11에 먼저 만들어 둔다.

**`ZST_AUDIT`** — 담기는 쪽(생성 이력)

| Component | Typing | 예 | 데이터 타입 | 길이 | 설명 |
|---|---|---|---|---|---|
| CREATED_BY | Data Element | `ZDE_NAME` | CHAR | 20 | 만든 사람 |
| CREATED_ON | Data Element | `ZDE_CREATED_ON` | DATS | 8 | 만든 날짜 |

**`ZST_ORDER`** — 담을 쪽(주문)

| Component | Typing | 예 | 데이터 타입 | 길이 | 설명 |
|---|---|---|---|---|---|
| ORDER_ID | Data Element | `ZDE_ORDER_ID` | CHAR | 10 | 주문 번호 |
| CUSTOMER | Data Element | `ZDE_NAME` | CHAR | 20 | 고객 이름 |
| AMOUNT | Data Element | `ZDE_AMOUNT` | DEC | 8 (소수 2) | 금액 |

`ZDE_NAME`·`ZDE_AMOUNT`는 앞 레슨에서 쓴 것을 그대로 재사용한다. 새로 만들 것은
`ZDE_ORDER_ID`와 `ZDE_CREATED_ON` 둘뿐이다. 이 중 `ZDE_CREATED_ON`은 위 `ZDE_ORDER_DATE`와
**같은 날짜 Domain을 참조**하고 라벨만 "만든 날짜"로 다르게 주면 된다. [Chapter 3 · Data
Element — 의미·라벨 입히기](CH03-L02.html)에서 본 "한 Domain, 여러 Data Element"가 이것이다.

1. 담을 쪽 `ZST_ORDER`를 SE11에서 열고 **Components** 탭으로 간다.
2. 빈 줄의 **Component** 칸에 `.INCLUDE`라고 그대로 적는다(메뉴 **Edit → Include → Insert**도 같은 일을 한다).
3. 그 줄의 **Component type** 칸에 담을 Structure 이름 `ZST_AUDIT`을 적는다.
4. 저장하고 **활성화**(Ctrl+F3).

편집 화면에는 `.INCLUDE` 한 줄로 보이지만, 활성화하고 나면 `created_by`·`created_on`이
`ZST_ORDER`의 필드 목록에 **제 필드처럼 나란히** 놓인다. 프로그램에서 쓰는 모습은 이렇다.

```abap
DATA gs_order TYPE zst_order.

gs_order-customer   = '정훈영'.   " ZST_ORDER 자기 필드
gs_order-created_by = '유재석'.   " .INCLUDE로 들어온 필드도 한 단계로
```

- 중첩은 `head`를 거쳐 `gs_order-head-customer`로 들어가지만, `.INCLUDE`로 담은 필드는
  펼쳐져 `gs_order-created_by`로 바로 접근한다.
- "묶음 티 안 나게, 내 필드인 것처럼" 쓰고 싶을 때.

| | 중첩(Component) | `.INCLUDE` |
|---|---|---|
| 접근 | `gs_order-head-customer`(두 단계) | `gs_order-created_by`(한 단계, 펼쳐짐) |
| 느낌 | 묶음 유지 | 내 필드처럼 |

## ③ `.APPEND` — 표준에 안전하게 더하기

**`.APPEND`**(Append Structure)는 SAP **표준** Structure·테이블을 **직접 고치지 않고**, 내 필드를
**별도 Structure로 덧붙인다.** 표준 원본을 안 건드리니 **표준을 직접 고치는 것보다 훨씬 안전하다**
(확장 주제, 자세히는 한참 뒤 챕터에서). 다만 무조건 안전한 것은 아니다. 나중에 SAP이 그 표준
오브젝트 자체를 바꾸면 덧붙인 필드가 영향을 받을 수 있어, 업그레이드 뒤에는 확인이 필요하다.

SE11에서는 이렇게 한다.

1. 확장할 **표준** Structure나 테이블을 SE11에서 연다.
2. 메뉴 **Goto(이동) → Append Structure…** 를 고른다.
3. 이름을 묻는 팝업에 `Z`로 시작하는 이름(예: `ZAPP_MY_EXT`)을 적고 만든다.
4. 새로 열린 화면에 내 필드(예: `ZZGRADE`)를 적고 저장·활성화한다.

활성화하면 표준 필드 목록 **맨 아래에 `.APPEND` 줄**이 붙는다. 표준 원본의 필드 목록은
그대로 두고, 프로그램에서는 표준 필드와 똑같이 한 단계로 읽는다(`gs_mat-zzgrade`).

> 덧붙이는 **필드 이름도 고객 네임스페이스로** 짓는다. `ZZ`(또는 `YY`)로 시작하라는 것이
> SAP의 권고다. 나중에 SAP이 같은 오브젝트에 새 표준 필드를 추가해도 이름이 부딪히지 않게
> 하려는 것이다.

> `.INCLUDE`는 남의 필드를 내 것처럼 **펼쳐 담는** 방법이고, `.APPEND`는 표준을 건드리지
> 않고 내 필드를 **덧붙이는** 방법이다. 묶음을 그대로 유지하고 싶을 땐 중첩을 쓴다.

## 흔한 실수와 점검

- **중첩인데 `-` 한 번** → 중첩은 `gs_order-head-customer`(단계마다 `-`). 단계를 빠뜨리지 않는다.
- **`.INCLUDE` 이름 충돌** → 한 Structure 안 Component 이름은 **유일**해야 한다. 펼쳐
  들어오는 필드가 기존 필드와 겹치면 활성화가 거부된다. 공통 Structure의 필드명은
  전사적으로 일관되게 짓는다.
- **표준 Structure 직접 수정** → 업그레이드 때 덮어쓰여 사라진다. 표준 확장은 `.APPEND`로.
