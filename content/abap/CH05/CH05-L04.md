## 묶었으면 다뤄야 한다

Structure를 통째로 복사하거나, 비우거나, **이름이 같은 필드만 골라 옮기는** 일이
자주 생긴다. 기본기 몇 가지를 익힌다.

## 통째로 대입 / 초기화

같은 타입이면 Structure끼리 **통째로** 대입된다. `CLEAR`로 전체를 비운다. 아래
`zst_person`은 [DDIC Structure](CH05-L02.html) 레슨에서 SE11에 만들어 둔 그 Structure다.

```abap
DATA: gs_a TYPE zst_person,
      gs_b TYPE zst_person.

gs_a-name = '정훈영'.
gs_b = gs_a.        " 모든 Component 복사
CLEAR gs_a.         " gs_a를 초기값으로
```

`gs_b = gs_a.`는 **값을 통째로 베껴 담는다.** 베끼고 나면 두 변수는 서로 남남이라, 바로
다음 줄에서 `gs_a`를 비워도 `gs_b`에 담긴 값은 그대로 남는다.

> 🧑‍💻 **다른 언어를 해 봤다면** — 객체를 대입하면 둘이 같은 것을 함께 가리키게 되는
> 언어와 달리, ABAP의 Structure 대입은 **값 복사**다. `gs_b`는 `gs_a`의 별명이 아니라
> 내용만 같은 별개의 변수다.

## MOVE-CORRESPONDING — 이름이 같은 필드만

타입이 다른 두 Structure 사이에서 **이름이 같은 Component만** 골라 옮긴다. 어떤 필드가
옮겨지고 어떤 필드가 남는지, 세 가지 경우가 다 들어 있는 예로 보자.

```abap
DATA: BEGIN OF gs_src,
        name   TYPE c LENGTH 20,
        age    TYPE i,
        amount TYPE p LENGTH 8 DECIMALS 2,   " 대상엔 없는 필드
      END OF gs_src.

DATA: BEGIN OF gs_tgt,
        name TYPE c LENGTH 20,
        age  TYPE i,
        city TYPE c LENGTH 20,               " 원본엔 없는 필드
      END OF gs_tgt.

gs_src-name   = '정훈영'.
gs_src-age    = 30.
gs_src-amount = '1500.50'.
gs_tgt-city   = 'Seoul'.

MOVE-CORRESPONDING gs_src TO gs_tgt.
" name·age만 복사된다. amount는 갈 곳이 없고, city는 건드리지 않는다
```

- **이름이 같은** `name`·`age`만 복사된다.
- 원본에만 있는 `amount`는 갈 곳이 없어 **무시**되고, 대상에만 있는 `city`는
  **건드리지 않는다**.
- 화면·테이블·DB의 Structure가 조금씩 다를 때 아주 유용하다.

> ⚠️ **"건드리지 않는다"가 함정이 된다** — 대상에만 있는 필드(`city`)는 **이전 값이
> 그대로 남는다.** 새로 채우는 Structure라면 옮기기 전에 `CLEAR gs_tgt.`부터. 안 그러면
> **지난 건의 값이 이번 건에 섞인다.**

> ⚠️ **이름이 같아도 모양까지 같은 건 아니다** — MOVE-CORRESPONDING은 **이름만 보고**
> 옮긴다. 원본 `name`이 30자인데 대상 `name`이 20자면 뒤 10자가 **조용히 잘리고**, 글자가
> 담긴 칸을 숫자 칸으로 옮기면 실행 중 오류로 멈추기도 한다. 이름이 같다고 안심하지 말고
> **길이와 타입도 같은지** 확인한다.

> 🧑‍💻 **다른 언어를 해 봤다면** — 이름이 같은 필드끼리 자동으로 옮겨 주는 도구(자바의
> ModelMapper, C#의 AutoMapper 같은 것)를 써 봤다면 그 자리에 해당한다. 다른 점은 ABAP에서는
> 라이브러리가 아니라 **문법에 들어 있다**는 것이다.

## 흔한 실수와 점검

- **모양이 다른데 통째 대입** → 통째 대입(`=`)은 **Component 구성이 같을 때** 쓴다. 구성이
  다르면 문법 오류가 나거나, 문자 계열로만 이뤄진 Structure끼리는 이름과 상관없이
  **앞에서부터 자리로** 밀려 들어가 엉뚱한 값이 조용히 섞인다. **Component 구성이 다르면**
  [[MOVE-CORRESPONDING]]으로 옮긴다.
- **대상 잔존값** → 대상에만 있는 필드는 이전 값이 남는다. 새 건을 채울 땐
  `CLEAR` 먼저.
- **CLEAR vs REFRESH** → Structure는 `CLEAR`. (여러 행을 담는 [[Internal Table]] 비우기는
  다음 챕터에서.)
