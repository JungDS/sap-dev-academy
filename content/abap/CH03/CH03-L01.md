## 로컬 타입의 벽

[Chapter 2](CH02-L04.html)의 [[TYPES]]는 편했지만 **그 프로그램 안에서만** 유효하다. 회사 전체가 쓰는 "금액", "통화코드"
같은 타입을 매 프로그램이 또 정의하는 건 낭비고, 정의가 갈리면 사고다.

> 😵 A 프로그램은 금액을 `DEC 8,2`, B 프로그램은 `DEC 11,2`로 정의했다면?
> (`DEC 8,2`는 "십진수 8자리, 그중 소수가 2자리"라는 뜻이다. 곧 배운다.)
> 같은 "금액"인데 자릿수가 달라 데이터가 어긋난다. **한 곳에서 한 번만** 정의하고 싶다.

이제 타입을 **전역**으로 올린다. 그 시작이 [[DDIC]]의 [[Domain]]이다.

## Domain의 역할 — 기술 속성만

[[DDIC]](ABAP Dictionary)는 시스템 전체의 데이터 정의를 한 곳에서 관리하는 중앙 사전이다.
그 안에서 [[Domain]]은 **순수한 기술 속성**만 담는다.

| Domain이 아는 것 | Domain이 모르는 것 |
|---|---|
| 데이터 타입·길이·소수·대소문자·허용값 | 이 값이 "금액"인지 "단가"인지 (**의미**) |
| (선택) 허용 값 = Fixed Values(고정값) 또는 [[Value Table]] | 화면에 뜰 **라벨** |

> 의미·라벨은 다음 레슨의 [[Data Element]]가 맡는다. **기술은 Domain, 의미는 Data Element**로 역할이 갈린다.

> 🧭 **이름에 속지 말 것** — 다른 개발 분야에서 "도메인"이라고 하면 보통 업무 의미 쪽을 가리킨다.
> 그런데 DDIC의 Domain은 정반대로 **의미를 뺀 기술 계층**이다. 의미를 맡는 쪽은 [[Data Element]]다.

> ⚠️ Domain에는 타입과 길이가 들어 있다. 그래서 프로그램에서 변수를 선언할 때 바로 갖다 쓸 수 있을 것처럼 보인다.
> 하지만 **Domain은 항상 [[Data Element]]에만 사용된다**는 점을 꼭 기억하자. Data Element는 다음 레슨에서 다룬다.

## Domain의 속성, 하나씩

Domain을 만들 때 채우는 칸들이다. 하나씩 차분히 보자.

> ⏩ 다른 언어에서 타입·길이를 이미 다뤄 봤다면, 이 절은 표 두 개만 훑고 다음 절로 건너뛰어도 된다.

**① 데이터 타입** — 값이 "어떻게 생겼는지". 자주 쓰는 것만:

| DDIC 데이터 타입 | 뜻 | ABAP 변수로 선언하면 |
|---|---|---|
| **CHAR** | 문자(텍스트) | `TYPE c` |
| **NUMC** | 숫자만 담는 문자(자릿수 고정, 앞 0 유지) | `TYPE n` |
| **DEC** | 십진수(소수 가능 · 금액 등) | `TYPE p` |
| **INT4** | 정수 | `TYPE i` |
| **DATS** | 날짜(YYYYMMDD, 8자리) | `TYPE d` |

> 📌 이 표는 **키워드끼리의 짝**일 뿐이다. 길이·소수는 함께 따라오지 않아 변수 쪽에 따로 적어야 한다
> ([Chapter 2](CH02-L03.html)의 `LENGTH`·`DECIMALS`). 게다가 길이를 세는 단위도 다르다.
> DDIC의 `DEC 8`은 **자릿수 8**이지만, ABAP `TYPE p LENGTH 8`은 **8바이트**(자릿수로는 15자리)다.
> 숫자만 베껴 옮기면 엉뚱한 크기가 된다.

> ⚠️ **헷갈리기 쉬운 점** — 문자 타입이 **DDIC의 Domain에서는 `CHAR`**, 그런데 **ABAP 변수를 선언할 땐 키워드가 `c`이다.**
> 같은 "문자"인데 이름이 다르다. ([Chapter 2](CH02-L03.html)에서 `DATA gv_x TYPE c`를 봤다면, 그 **Domain 버전이 `CHAR`**.)

**② 그 밖의 속성**:

| 속성 | 뜻 |
|---|---|
| **길이(Length)** | 담을 수 있는 자릿수 (예: CHAR 10 = 글자 10칸) |
| **출력 길이(Output Length)** | 화면에 표시될 칸 너비. 보통 길이와 같지만, **부호·천단위 구분기호** 때문에 더 길 수 있다 |
| **소수(Decimals)** | 소수점 이하 자릿수 (DEC 등 십진 타입에서 지정, 길이보다 작아야 함) |
| **부호(Sign)** | **음수를 담을 수 있는지.** 음수가 필요한 숫자 값이면 켠다(예: 금액의 마이너스, 재고 증감). 참고로 NUMC는 음수를 담지 못한다 |
| **대소문자(Lower Case)** | 체크 안 하면 **화면에서 입력할 때** 자동으로 대문자로 바뀐다(CHAR 기본). 소문자를 살리려면 체크. 코드에서 대입한 소문자는 그대로 남는다 |

## 값을 제한하는 두 가지 — Fixed Values vs Value Table

특정 값만 받게 하려면 **두 가지** 방법이 있다. 상황에 따라 **둘 중 하나**를 쓴다.

| | Fixed Values(고정값) | Value Table(값 테이블) |
|---|---|---|
| 무엇 | Domain 안에 **직접 적은** 허용 값 목록 | 허용 값이 든 **다른 테이블**을 가리킴 |
| 잘 맞는 곳 | 거의 안 바뀌는 **몇 개**의 값 | 자주 바뀌는 **목록** |
| 예 | `O`=Open, `C`=Closed | 항공사 목록 테이블 `SCARR` |
| 이어짐 | 화면 [[F4]]·입력 검증(이 챕터 마지막 레슨) | 외래 키(Foreign Key)의 바탕(뒤 챕터) |

오른쪽 칸의 **테이블**은 값이 줄줄이 저장된 표다(정식으로는 뒤 챕터에서 만든다). 예로 든 `SCARR`은
SAP가 연습용으로 기본 제공하는 **항공사 목록 표**다.

> 🧑‍💻 **다른 언어를 해 봤다면** — Fixed Values는 `enum`에, Value Table은 "허용 값이 든 다른 표를 가리키는 참조"에 가깝다.

> 💡 둘 다 "허용 값을 제한"하지만 **동시에 쓰지 않는다.** 값이 고정이면 Fixed Values, 값이 계속 늘어나는 목록이면 Value Table.
> 단, **Value Table은 적어 두는 것만으로는 검사가 일어나지 않는다.** 뒤 챕터에서 외래 키(Foreign Key)로 연결해야
> 비로소 검사·[[F4]]의 바탕이 된다. 반면 **Fixed Values는 그 자체로 F4 목록이 되고, 입력 검증에도 그대로 쓰인다**
> (검증을 켜는 방법은 [이 챕터의 PARAMETERS 레슨](CH03-L03.html)에서 배운다).

## SE11에서 직접 만들기

이제 속성을 알았으니 직접 만들어 보자. `SE11`(Dictionary) → Domain → 이름(우리는 금액용 `ZDO_AMOUNT`) → Create.
아래 시뮬레이터에서 값을 채우고 **💾 저장 → ✓ 검사 → 🔥 활성화** 순서로 눌러, DDIC 객체가
활성화되는 과정을 따라가 보자.

> 📦 **실제 SE11에서 처음 저장하면** — "이 오브젝트를 어느 패키지에 넣을까?" 창이 먼저 뜬다.
> 학습 단계라면 **Local Object**를 눌러 [[$TMP]]에 두면 된다.
> ([Chapter 1 · T-code와 SE38 첫 실행](CH01-L02.html)에서 프로그램을 저장할 때 한 것과 똑같다.)

::embed CH03-L01-S01 | Domain 생성 시뮬레이터 — 속성·저장·검사·활성화 | 640::

> 🖱️ 예제 칩을 눌러 보라. **금액**(DEC 8,2), **상태**(CHAR 1 + [[고정값|Fixed Values]] O/C),
> **항공사 코드**(CHAR 3 + [[Value Table]] SCARR), **이메일**(CHAR + 소문자 허용),
> **재고 증감**(INT4 + 부호), **대기번호·연도**(NUMC)까지 여섯 가지가 준비돼 있다.
> 데이터 타입을 바꾸면 위에 **"ABAP 변수로는 TYPE …"** 대응이 뜨고, CHAR일 때만 **대소문자** 옵션이 나타난다.

**금액 Domain을 만들었다면, 같은 요령으로 상태 Domain도 하나 더 만들어 두자.** 이름 `ZDO_STATUS`,
데이터 타입 CHAR, 길이 1, 값 범위 탭에 [[고정값|Fixed Values]] `O`(Open)와 `C`(Closed). 시뮬레이터의
**상태** 칩이 그대로 이 목표다. 이 상태 Domain은 [이 챕터 마지막 레슨](CH03-L03.html)에서 화면 F4와
입력 검증을 직접 확인할 때 다시 쓴다.

> 💬 **금액 예제에 한 가지만 미리** — 우리 `ZDO_AMOUNT`는 배우기 좋게 단순화한 금액이다.
> 실무의 금액 필드는 통화마다 소수 자릿수가 달라서, 금액 값 옆에 **어느 통화인지 알려 주는 키**를
> 짝으로 두는 전용 타입을 쓴다. 그 짝은 테이블을 배우는 뒤 챕터에서 만난다.

## 활성화 — DDIC의 철칙

방금 봤듯, **저장만 하면 객체는 "비활성(inactive)"** 상태라 [[런타임]]에서 쓸 수 없다.
[[활성화]](Ctrl+F3)를 해야 **런타임 객체가 생성**되고, 비로소 다른 객체가 이 Domain을 참조할 수 있다.
여기서 **런타임 객체**는 시스템이 실제 실행에 쓰려고 내부에 따로 만들어 두는 완성본이다.
우리가 SE11 화면에 적은 정의가 설계도라면, 런타임 객체는 그 설계도로 찍어 낸 실물인 셈이다.

| 상태 | 의미 |
|---|---|
| **비활성** (저장만 함) | 작업 중인 초안(런타임에서 못 씀) |
| **활성** (활성화 완료) | 런타임 객체 생성됨(참조·실행 가능) |

> 🔁 **활성화는 껐다 켜는 스위치가 아니다** — 정의를 실행 가능한 형태로 **한 번 변환**하는 일에 가깝다.
> 프로그램을 컴파일하는 것과 비슷하다고 보면 된다. 그래서 정의를 고칠 때마다 다시 해 줘야 한다.

> ⚠️ 활성화한 뒤 정의를 바꾸면 그 변경은 **새 비활성 버전**으로 저장되고, **기존 활성 버전은 그대로 남는다.**
> 즉 재활성화 전까지 런타임은 예전 활성판을 계속 쓴다. 바꾼 내용을 실제로 반영하려면 **재활성화**해야 한다.
> (시뮬레이터에서 활성화 후 길이를 고치면 배지가 바로 "비활성"으로 돌아간다.)

## 흔한 실수와 점검

> ⚠️ **검사에서 타입 오류가 난다** — Domain 칸에 `c`라고 적지 않았는지 보라. Domain 데이터 타입은 `CHAR`,
> 변수 선언 키워드가 `c`다. 둘은 같은 "문자"지만 쓰는 자리가 다르다.

> ⚠️ **이름 규칙** — 전역 객체도 `Z`/`Y`로 시작. (시뮬레이터에서 `AMOUNT`로 검사하면 막힌다.)

> ⚠️ **저장만 하고 끝** — 비활성이라 아무도 못 쓴다. 반드시 **[[활성화]]** 까지.

> ⚠️ **허용 값을 적어 뒀는데 화면에서 아무 일도 안 일어난다** — [[Value Table]] 쪽에만 적어 둔 경우다.
> 값 테이블은 뒤 챕터의 외래 키와 연결돼야 일한다. 지금 당장 목록을 보이게 하려면 [[고정값|Fixed Values]]다.

## 정리

- 같은 타입을 프로그램마다 다시 정의하는 낭비를 막으려 타입을 **전역**으로 올린다 → [[DDIC]]의 [[Domain]].
- [[Domain]]은 **기술 속성**(데이터 타입·길이·출력길이·소수·부호·대소문자·허용값)만 담는다. 의미·라벨은 [[Data Element]] 몫.
- 문자 타입은 **DDIC=`CHAR`, 변수=`c`**. 허용 값은 **[[고정값|Fixed Values]] 또는 [[Value Table]]**(둘 중 하나).
- DDIC 객체는 **[[활성화]]해야** 런타임에서 쓸 수 있다. 저장만 하면 비활성이다.
- 이 레슨의 산출물은 둘이다. 금액용 `ZDO_AMOUNT`, 상태용 `ZDO_STATUS`. 다음 레슨에서 여기에 의미를 입힌다.
