DDIC Domain·Data Element + PARAMETERS

Data Element — 의미·라벨 입히기

Domain에 의미와 라벨을 입혀, 필드가 참조할 단위를 만든다.

Track 1Chapter 3Lesson 2입문

의미와 이름표가 빠졌다

은 "8자리 소수 2"라는 기술 속성만 안다. 하지만 화면이나 테이블에서 이 값이 "송장 금액"인지 "단가"인지, 라벨을 뭐라 띄울지는 모른다. 그 의미·라벨 계층이 다.

Data Element = 의미 + 라벨 (+ Domain)

는 위에 의미를 입힌다.

  • 어떤 Domain을 쓰는지(기술 속성 상속)
  • 필드 라벨(Short / Medium / Long / Heading)
  • (선택) 문서 / F1 도움말

테이블이나 화면의 각 필드는 보통 Data Element를 참조한다 → 타입·라벨·도움말을 한꺼번에 물려받는다.

SE11에서 Data Element 만들기

SE11 → → ZDE_AMOUNT → Create.

  • Data Type 탭에서 참조할 에 ZDO_AMOUNT를 적는다(앞 레슨에서 만든 것).
  • Field Label 탭으로 넘어가 길이별 라벨을 채운다 → 저장 → 활성화.

Field Label 칸이 왜 넷일까? 화면마다 라벨을 넣을 자리 넓이가 다르기 때문이다. 시스템이 자리에 맞는 라벨을 골라 쓰므로, 넷을 다 채워 두면 어느 화면에서도 빈 라벨이 나오지 않는다.

칸 최대 길이 주로 쓰이는 곳 입력 예
Short 10 자리가 좁은 화면·목록 금액
Medium 20 일반 화면의 입력칸 옆 송장 금액
Long 40 자리가 넉넉한 상세 화면 송장 총 금액
Heading 55 표(리스트)의 열 제목 송장금액

📌 여기 "최대 길이"는 라벨 글자 수다. 앞 레슨에서 정한 Domain의 길이(값의 자릿수)와는 다른 이야기니 헷갈리지 말자.

이제 gv_amount는 회사 표준 금액 정의를 그대로 따른다.

앞 레슨에서 ZDO_STATUS도 만들어 뒀다. 같은 방식으로 ZDE_STATUS도 하나 만들어 두자. 참조 Domain은 ZDO_STATUS, 라벨은 "예매 상태"로. 다음 레슨에서 이 둘(ZDE_AMOUNT·ZDE_STATUS)로 화면의 보상을 직접 확인한다.

Domain vs Data Element 한눈에
담당 기술 속성(타입·길이·) 의미·라벨·도움말
비유 "8자리 소수 2" "이건 '금액'이다"
참조 — Domain을 참조

🧑‍💻 다른 언어를 해 봤다면 — Domain은 컬럼의 물리 타입(어떻게 생긴 값인지), Data Element는 그 위에 얹는 의미 타입(이 값이 무엇이고 화면에 뭐라 쓸지)에 가깝다. 관심사를 둘로 나눠 둔 것이다.

한 Domain, 여러 Data Element

하나의 을 여러 가 서로 다른 의미로 나눠 쓸 수 있다. 공항 코드가 그렇다. 출발이든 도착이든 코드는 똑같이 3자리(같은 Domain)지만, "출발 공항"과 "도착 공항"은 의미도 라벨도 다르다.

Data Element 라벨 참조 Domain
ZDE_FROM_AIRP 출발 공항 ZDO_AIRPORT(3자리)
ZDE_TO_AIRP 도착 공항 ZDO_AIRPORT(3자리)

→ Domain은 기술 속성을 한 번 정의해 재사용하고, Data Element는 그 위에 의미·라벨을 따로 입힌다. 이게 두 계층을 나눈 이유다.

계층을 눈으로 — 상속 보드

말보다 그림이 빠르다. 아래에서 한 곳의 길이를 바꾸면 상속받는 둘이 동시에 바뀌는 걸 확인해 보자.

🧑‍💻 여기서 말하는 "상속"은 객체지향의 클래스 상속이 아니다. Data Element가 Domain을 참조해서 기술 속성을 그대로 쓰는 것을 편하게 부르는 말이다.

⚠️ 실무에서 Domain 하나를 고치는 건 큰일이다 — 방금 본 대로 변경이 참조하는 모든 Data Element로 퍼지고, 그 Data Element를 쓰는 화면·테이블까지 줄줄이 영향을 받는다. 특히 길이를 줄이면 이미 들어 있던 값이 잘릴 수 있다. 그래서 고치기 전에 이 Domain을 어디서 쓰고 있는지 먼저 확인하는 것이 규율이다 (SE11 화면의 "사용처 조회 / Where-Used List" 버튼).

💡 참고 — Data Element에는 Parameter ID라는 칸도 있다. 사용자가 마지막에 넣은 값을 기억해 뒀다가 다음에 같은 칸을 미리 채워 주는 편의 기능에 쓰인다. 다만 여기에 이름을 적어 둔다고 저절로 되는 건 아니고 화면 쪽에서도 "기억해라 / 꺼내 써라"를 켜 줘야 한다. 지금은 "그런 속성이 있다" 정도만 알아 두자.

흔한 실수와 점검

  • 없이 → 가능은 하지만(직접 타입 지정), 보통은 Domain을 둬서 기술 속성을 재사용한다.
  • 라벨 비움 → 화면이나 에서 빈 라벨이 뜬다. Field Label을 채운다. (ALV는 ABAP List Viewer의 줄임말로, 결과를 표 형태로 보여 주는 표준 도구다. 뒤 챕터에서 정식으로 배운다.)
  • 화면에서 라벨 뒷글자가 잘린다 → 그 자리에 쓰이는 칸(Short 등)의 길이보다 라벨 글자가 길어서다. 칸마다 길이에 맞는 표현을 넣자(짧은 칸엔 "금액", 넉넉한 칸엔 "송장 총 금액").

정리

  • 는 위에 의미와 라벨을 입힌 계층이다. 화면·테이블의 필드는 보통 이 Data Element를 참조한다.
  • Field Label 4종(Short/Medium/Long/Heading)은 자리 넓이별 이름표다. 넷 다 채워 두면 빈 라벨이 없다.
  • 한 Domain을 여러 Data Element가 서로 다른 의미로 나눠 쓸 수 있다(출발 공항·도착 공항).
  • Domain을 고치면 참조하는 쪽 전부에 퍼진다. 실무에서는 어디서 쓰는지 확인하고 손대는 것이 규율이다.
  • 이 레슨의 산출물도 둘이다. ZDE_AMOUNT(금액)와 ZDE_STATUS(예매 상태).

전역으로 정의는 했다. 그런데 이 수고가 어디서 빛을 보나? 바로 화면에서다. 에 Data Element를 쓰면 체크 한 번으로 라벨이, Domain의 로 가 따라온다 → 다음 레슨.
