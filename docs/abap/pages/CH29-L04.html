고급 문자열 처리: PCRE 정규식

SUBMATCHES — Capture Group으로 값 추출

괄호 그룹의 값을 변수로 꺼내고, optional·non-capturing까지 관리한다.

Track 2Chapter 29Lesson 4중급

✂️ 매치 전체가 아니라 "그 안의 값"

파트너 장애 로그 한 줄에서 보고서를 만들어야 한다.

TEXT
1
Booking B-2026-0007 failed for user HUNYOUNG

필요한 건 매치 전체가 아니라 그 안의 조각들이다.

원하는 값 예
접수 연도 2026
일련번호 0007
사용자 HUNYOUNG

L02에서 괄호 ( )가 을 만든다고 했다. SUBMATCHES는 그 그룹들의 값을 왼쪽 괄호 순서대로 변수에 담아 준다.

DATA(gv_text) =
  `Booking B-2026-0007 failed for user HUNYOUNG`.

FIND PCRE `B-(\d{4})-(\d{4}).*user\s+(\w+)`
     IN gv_text
     SUBMATCHES DATA(gv_year) DATA(gv_serial) DATA(gv_user).

IF sy-subrc = 0.
  WRITE: / gv_year, gv_serial, gv_user.   " 2026  0007  HUNYOUNG
ENDIF.
그룹 패턴 조각 담기는 값
1 (\d{4}) 2026
2 (\d{4}) 0007
3 (\w+) HUNYOUNG

변수 개수와 그룹 개수가 어긋나면?

공식 규칙이 정해져 있다. 오류가 아니라 조용히 처리되니 더 조심해야 한다.

  • 변수가 그룹보다 적으면 → 남는 그룹은 무시된다.
  • 변수가 그룹보다 많으면 → 남는 변수는 초기값이 된다.
  • ALL OCCURRENCES와 함께 쓰면 → 마지막 발견의 그룹 값이 담긴다 (L03의 MATCH OFFSET과 같은 규칙).

여러 발견의 그룹 정보 — RESULTS의 submatches

발견이 여러 개라면 SUBMATCHES 대신 RESULTS를 쓴다. 지난 레슨에 보였던 submatches 필드가 여기서 열린다.

DATA(gv_list) = `B-2026-0007 B-2026-0008`.

FIND ALL OCCURRENCES OF PCRE `B-(\d{4})-(\d{4})`
     IN gv_list
     RESULTS DATA(gt_result).

LOOP AT gt_result INTO DATA(gs_result).
  LOOP AT gs_result-submatches INTO DATA(gs_sub).
    DATA(gv_piece) = substring( val = gv_list
                                off = gs_sub-offset
                                len = gs_sub-length ).
    WRITE: / |그룹 값: { gv_piece }|.
  ENDLOOP.
ENDLOOP.

🚨 가장 중요한 구분: RESULTS의 submatches에 들어 있는 것은 그룹의 값이 아니라 offset/length(위치 정보)다. 값이 필요하면 위처럼 원문에서 substring( )으로 잘라야 한다. 반면 SUBMATCHES s1 s2 ...는 값 자체를 준다. 이름이 비슷해서 정말 자주 헷갈린다.

도구 주는 것 몇 건에 대해
SUBMATCHES DATA(v1) ... 그룹 값 한 건(ALL이면 마지막)
RESULTS의 submatches 그룹 위치(offset/length) 모든 발견

optional group — 있을 수도, 없을 수도

파트너 로그에는 좌석 수가 붙기도 하고 안 붙기도 한다.

TEXT
1
2
Booking B-2026-0007 seats=2
Booking B-2026-0008

( )?로 그룹 전체를 0회 또는 1회로 만들면 두 줄 다 매치된다.

ABAP
1
2
3
FIND PCRE `Booking\s+(B-\d{4}-\d{4})(?:\s+seats=(\d+))?`
     IN gv_text
     SUBMATCHES DATA(gv_booking_id) DATA(gv_seats).

두 가지 새 얼굴이 있다.

  • (?: ... ) — non-capturing group. "묶기만 하고 값은 안 꺼낼" 괄호다. 이걸 안 쓰면 \s+seats=... 묶음도 그룹 번호를 하나 차지해 SUBMATCHES 순서가 밀린다.
  • optional group이 매치에 불참하면 — gv_seats는 초기값(빈 문자열)이 된다. "seats가 없는 예약"을 업무 로직으로 처리해야 한다(0으로 볼지, 별도 안내할지).

직접 추출해 보기

그룹별 색상으로 원문↔변수 연결을 확인하고, optional·non-capturing을 켜 보라.

흔한 실수와 점검 🚧

  • 그룹 순서 헷갈림 — 그룹 번호는 여는 괄호의 순서다. 그룹이 4개를 넘으면 순서 실수가 급증한다. 패턴을 쪼개거나 주석을 붙인다.
  • 값만 꺼낼 게 아닌 괄호 — 단순 묶음이면 (?: )로. 그룹 번호가 줄어 관리가 쉽다.
  • RESULTS의 submatches를 값으로 착각 — 위치 정보다. substring( )으로 잘라야 값.
  • optional group 미대비 — 불참 그룹의 변수는 초기값. IS INITIAL 분기를 준비한다.

정리 📌

  • SUBMATCHES = 괄호 그룹의 값을 왼쪽 괄호 순서대로 변수에.
  • 변수/그룹 개수 불일치는 오류 없이 조용히 처리된다. 순서·개수는 스스로 관리한다.
  • 여러 발견의 그룹 정보는 RESULTS(단, submatches = 위치 정보).
  • (?: ) = 묶지만 캡처하지 않는 괄호. optional group 불참 = 변수 초기값.

찾고, 세고, 꺼냈다. 이제 반대 방향, 패턴으로 바꾸는 차례다. 그룹 값을 치환문에 다시 끼워 넣는 $1이 등장한다.
