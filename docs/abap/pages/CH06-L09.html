Internal Table

명단 합치기와 중복 제거 — APPEND LINES OF · DELETE ADJACENT DUPLICATES

지점별 명단을 하나로 — 통째로 이어 붙이고, 겹친 사람을 걸러낸다.

Track 1Chapter 6Lesson 9초급

명단이 세 개

교육 담당 정훈영에게 서울 지점과 부산 지점의 수강 신청 명단이 따로 도착했다. 할 일은 둘이다 — 하나로 합치고, 두 지점에 모두 신청한 사람(중복)을 걸러낸다.

그릇부터 준비하자. 같은 행 모양의 테이블이 세 개 필요하다.

ABAP
1
2
3
DATA: gt_seoul TYPE TABLE OF ts_person,   " 서울 지점 명단
      gt_busan TYPE TABLE OF ts_person,   " 부산 지점 명단
      gt_all   TYPE TABLE OF ts_person.   " 합칠 전체 명단

(같은 TYPE TABLE OF ts_person을 벌써 세 번 적었다. 어딘가 아깝다는 느낌이 들었다면 정확한 감각이다 — 이 찜찜함은 다음 레슨에서 해결한다.)

통째로 이어 붙이기 — APPEND LINES OF

LOOP로 한 행씩 옮겨도 되지만, 모든 행을 한 문장에 이어 붙이는 도구가 따로 있다.

ABAP
1
2
APPEND LINES OF gt_seoul TO gt_all.   " 서울 명단 전체를 gt_all 끝에
APPEND LINES OF gt_busan TO gt_all.   " 이어서 부산 명단 전체를
  • gt_all에 이미 행이 있으면 그 뒤에 붙는다(교체가 아니다 — L01의 통째 대입 gt_all = gt_seoul.과의 차이가 바로 이것이다).
  • 원본(gt_seoul·gt_busan)은 그대로 남는다. 옮기는 게 아니라 복사다.
  • 두 테이블의 행 모양은 같아야 한다.
  • 일부만 붙이고 싶으면 APPEND LINES OF gt_seoul FROM 2 TO 5 TO gt_all.처럼 범위도 된다.

겹친 사람 걸러내기 — DELETE ADJACENT DUPLICATES

두 지점에 모두 신청한 홍길동이 gt_all에 두 번 들어 있다. 중복 제거 문장은 이렇다.

ABAP
1
2
SORT gt_all BY name.                                     " ① 반드시 먼저 정렬
DELETE ADJACENT DUPLICATES FROM gt_all COMPARING name.   " ② 이름이 같은 인접 행 제거

문장 이름을 뜯어 보면 동작이 그대로 보인다 — ADJACENT(인접한) DUPLICATES(중복들). 이 문장은 바로 옆에 붙어 있는 중복만 지운다. 그래서 순서가 생명이다:

  • 같은 이름이 3번 행과 9번 행에 떨어져 있으면 → 둘 다 남는다(인접하지 않으니까).
  • SORT를 먼저 하면 같은 이름끼리 나란히 모이고 → 그제야 중복이 지워진다.

COMPARING name은 "무엇이 같아야 중복으로 볼 것인가"다. 생략하면 테이블 키 기준이 되는데, 키 레슨의 함정(내 의도와 다른 키)이 그대로 이어지니 비교 필드를 직접 적는 편이 안전하다. COMPARING name age처럼 여러 필드도 된다(전부 같아야 중복).

💡 SORT와 DELETE ADJACENT DUPLICATES는 항상 짝으로 다닌다. 정렬 기준과 비교 필드가 같아야 한다는 것까지가 짝이다. SORT ... BY name 후 COMPARING age로 지우면 나이 중복이 인접해 있으리란 보장이 없어 또 샌다.

SORT gt_all BY name.

DATA gv_cnt TYPE i.
DESCRIBE TABLE gt_all LINES gv_cnt.
WRITE: / '전체 수강 인원:', gv_cnt.

흔한 실수와 점검

  • SORT 없이 DELETE ADJACENT DUPLICATES → 떨어져 있는 중복이 살아남는다. 에러도 안 나서 숫자가 조용히 틀린다. 정렬이 언제나 선행.
  • 정렬 키 ≠ 비교 필드 → 위와 같은 함정의 변형. 두 문장의 기준을 맞춘다.
  • 동명이인 주의 → COMPARING name은 이름만 같으면 지운다. 이름 같고 나이 다른 두 사람을 한 명으로 만들 수 있다. 진짜 중복의 기준이 무엇인지(이름? 이름+나이? 사번?)를 업무로 정하고 그대로 적자.
  • 합치기 순서 무시 → APPEND LINES OF는 붙이는 순서대로 쌓인다. 순서가 중요하면 합친 뒤 SORT로 정리한다.

명단은 하나로 정리됐다. 그런데 아까 그 찜찜함 — 같은 타입 선언을 세 번 반복한 것 — 을 해결할 때다. 타입에 이름을 붙여 자산으로 만들자 → 타입의 자산화.
