Dynamic ABAP: Field Symbol 심화와 Generic

ASSIGN (name) — 이름 문자열로 찾기

문자열이 변수 이름으로 해석된다 — 강력한 만큼 위험한 문법.

Track 3Chapter 28Lesson 5고급

문자열이 변수가 될 때

실무 코드를 읽다 보면 이런 문장을 만난다.

ABAP
1
2
3
DATA(gv_name) = `SY-DATUM`.

ASSIGN (gv_name) TO FIELD-SYMBOL(<lv_value>) ELSE UNASSIGN.

문자열 SY-DATUM이 실제 시스템 필드 sy-datum으로 연결된다. 괄호 안의 문자열을 실행 중에 data object 이름으로 해석하는 ASSIGN (name)이다. 처음 보면 마법 같고 편리해 보이지만, 이 레슨의 절반은 왜 함부로 쓰면 안 되는가다.

무엇인가 — 그리고 왜 위험한가

ABAP

DATA gv_status TYPE c LENGTH 1 VALUE 'N'.
DATA gv_name   TYPE string VALUE 'GV_STATUS'.

ASSIGN (gv_name) TO FIELD-SYMBOL(<lv_dyn>) ELSE UNASSIGN.

IF sy-subrc = 0 AND <lv_dyn> IS ASSIGNED.
  <lv_dyn> = 'C'.                  " 원본 gv_status가 'C'로 바뀐다
ENDIF.

위험의 뿌리는 **검색 순서(search order)**다. 실행 위치에 따라 로컬 변수 → 보이는 속성 → 프로그램 전역 → TABLES 작업 영역 순으로 이름을 찾는다. 그래서 —

  • 오타가 syntax check에 안 잡힌다 — 문자열이니까.
  • 같은 이름의 로컬/전역/속성이 있으면 의도와 다른 데이터를 찾을 수 있다.
  • 사용자 입력을 그대로 넣으면 내부 데이터 노출 위험이 생긴다.

공식 문서도 이 변형(variant)을 더 이상 권장하지 않으며, 특히 구조 필드 접근에는 ASSIGN COMPONENT가 우선이라고 안내한다. 이 레슨의 목표는 "읽을 수 있되, 새 코드에서 쉽게 선택하지 않기"다.

검색 사다리를 타 보기

이름을 넣고 어느 범위에서 찾아지는지(검색 사다리), whitelist가 없으면 어떤 이름까지 닿는지 확인해 보라. 구조 필드를 넣으면 도구가 왜 ASSIGN COMPONENT 모드를 권하는지도.

안전 설계 — whitelist가 기본

ASSIGN (name)을 정말 써야 한다면, 문자열을 그대로 믿지 않는다.

DATA gt_allowed TYPE STANDARD TABLE OF string WITH EMPTY KEY.
gt_allowed = VALUE #( ( `SY-DATUM` ) ( `SY-UZEIT` ) ( `SY-UNAME` ) ).

READ TABLE gt_allowed WITH KEY table_line = gv_name TRANSPORTING NO FIELDS.
IF sy-subrc <> 0.
  WRITE / |{ gv_name } 은(는) 허용되지 않은 이름입니다|.
  RETURN.
ENDIF.

ASSIGN (gv_name) TO FIELD-SYMBOL(<lv_value>) ELSE UNASSIGN.

whitelist는 "이 도구가 접근해도 되는 이름"의 명단이다. 사용자 입력·설정 테이블·외부 파일에서 온 이름을 검사 없이 (name)에 넣지 않는다.

흔한 실수와 점검 🚧

  • 구조 필드를 (name)으로 → 'GS_BOOKING-STATUS'도 찾아지긴 하지만, 구조 필드 선택은 ASSIGN COMPONENT가 더 안전하고 의도가 선명하다(앞 레슨).
  • 오타 과신 → 'GV_STATSU'는 컴파일이 잡아 주지 않는다. sy-subrc = 4로 조용히 실패할 뿐.
  • 사용자 입력 직결 → whitelist 없는 (name)은 내부 데이터 열람 도구가 될 수 있다.
  • 다른 프로그램 변수 접근((PROG)DOBJ) → 존재는 알아 두되, 캡슐화를 깨는 내부용 경계다. 일반 실무 코드에서 쓰지 않는다.

정리 📌

  • ASSIGN (name) = 문자열을 실행 중 변수 이름으로 해석 — 읽을 줄은 알아야 하지만 새 코드의 기본 선택지가 아니다.
  • 위험 3종 = 검색 순서 오해·오타 침묵·입력 노출 → 쓴다면 whitelist + ELSE UNASSIGN이 전제.
  • 구조 필드는 ASSIGN COMPONENT, 이름 진단 도구만 (name) — 역할을 가른다.

기존 데이터를 찾는 법은 다 봤다. 이제 실행 중에 데이터 자체를 새로 만드는 쪽으로 — REF TO data와 CREATE DATA.
