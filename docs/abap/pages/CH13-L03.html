GROUP BY와 Aggregate

묶어서 세고 합산한다 — GROUP BY와 집계 함수.

묶어서 요약하기

"항공사별 운항편 수", "항공사별 예약 좌석 합계"처럼 그룹마다 요약하고 싶다. GROUP BY와 (집계 함수)다.

TYPES: BEGIN OF ts_sum,
         carrid TYPE sflight-carrid,
         cnt    TYPE i,                        " COUNT( * ) 결과를 받을 칸
         total  TYPE p LENGTH 9 DECIMALS 0,    " SUM( ) 결과를 받을 칸
       END OF ts_sum.

DATA gt_sum TYPE TABLE OF ts_sum.

SELECT carrid COUNT( * ) AS cnt SUM( seatsocc ) AS total
  FROM sflight
  INTO CORRESPONDING FIELDS OF TABLE gt_sum
  GROUP BY carrid.
  • 함수: COUNT( * ), SUM( ), MAX( ), MIN( ), AVG( ).
  • 묶는 기준이 되는 필드를 GROUP BY에 적는다. 이 필드를 그룹 키라고 부른다.
  • 그룹 키가 아닌 필드는 반드시 집계 함수로 감싸야 한다. 한 그룹에 여러 값이 섞여 있는데 그중 무엇을 보여 줄지 DB가 정할 수 없기 때문이다. 예를 들어 항공사별로 묶어 놓고 connid(노선 번호)를 그냥 적으면, 그 항공사의 여러 노선 중 어느 것을 내놓아야 할지 알 수 없으니 오류가 난다.
  • 집계 결과에는 원래 이름이 없으니 AS cnt처럼 별칭을 붙여 이름을 지어 준다.

📝 괄호 안 공백은 표기 습관이다. 이 과정은 COUNT( * )처럼 괄호 안쪽을 띄우는 표기로 본문·코드를 통일한다. 실무 코드에서 붙여 쓴 형태를 보더라도 다른 문법이라고 오해하지 말자.

결과 받기 — 그릇을 먼저 만든다

결과는 어느 테이블의 모양과도 같지 않다. carrid는 sflight에서 왔지만 cnt와 total은 방금 계산해 낸 값이기 때문이다. 그래서 위처럼 TYPES로 결과 구조를 직접 만들고, 별칭과 같은 이름의 칸을 둔 다음 INTO CORRESPONDING FIELDS OF TABLE로 받는다.

받는 칸의 타입은 넉넉하게 잡는다. 좌석 수 하나는 작아도 수천 편을 더한 합계는 훌쩍 커질 수 있어서다. 합계용으로는 타입이 무난하다. 소수점을 정확히 다루는 숫자 타입이고(Chapter 04 · 산술 연산과 대입), TYPE p LENGTH 9 DECIMALS 0은 "9짜리 정수 자리"라는 뜻이라 웬만한 합계는 다 담긴다. 반대로 칸이 좁으면 값이 넘쳐 엉뚱한 수가 담기거나 실행이 멈출 수 있다.

⚠️ AVG( )는 결과가 소수다. 평균은 나눗셈이라 12.5 같은 값이 나온다. 이걸 TYPE i(정수) 칸으로 받으면 소수점 아래가 잘려 나간다. 평균을 받을 칸은 TYPE p LENGTH 9 DECIMALS 2처럼 소수 자리를 둔 타입으로 잡자.

⚠️ 값이 없는 행을 세는 방식이 함수마다 다르다. COUNT( * )는 행 수를 세므로 값이 비어 있어도 한 행으로 친다. 반면 SUM·AVG·MAX·MIN은 값이 없는 칸은 아예 빼고 계산한다. 앞 레슨에서 본 LEFT OUTER JOIN처럼 오른쪽이 비는 결과를 집계할 때 이 차이가 그대로 드러난다.

직접 묶어 보기

그룹 키를 바꾸면 결과 행 수가 어떻게 달라지는지, GROUP BY와 DISTINCT가 어떻게 다른지 직접 확인해 보자.

JOIN한 결과를 그대로 묶기

앞 두 레슨의 JOIN과 이번 는 한 문장 안에서 같이 쓸 수 있다. 순서만 기억하면 된다. DB는 먼저 JOIN으로 표를 합쳐 넓은 결과를 만들고, 그다음 GROUP BY로 그 결과를 묶는다. 그러니 집계 대상은 "합쳐진 뒤의 표"라고 생각하면 된다.

항공사 코드 대신 항공사 이름으로 요약해 보자. 이름은 SCARR에 있으니 JOIN이 필요하다.

TYPES: BEGIN OF ts_carr_sum,
         carrid   TYPE sflight-carrid,
         carrname TYPE scarr-carrname,
         cnt      TYPE i,
         total    TYPE p LENGTH 9 DECIMALS 0,
       END OF ts_carr_sum.

DATA gt_carr_sum TYPE TABLE OF ts_carr_sum.

SELECT f~carrid s~carrname
       COUNT( * ) AS cnt SUM( f~seatsocc ) AS total
  FROM sflight AS f
  INNER JOIN scarr AS s
    ON f~carrid = s~carrid
  INTO CORRESPONDING FIELDS OF TABLE gt_carr_sum
  GROUP BY f~carrid s~carrname.
  • 집계하지 않은 필드는 f~carrid와 s~carrname 둘이니, GROUP BY에도 둘 다 적는다. s~carrname을 빼먹으면 "그룹 키가 아닌 필드"가 되어 오류가 난다.
  • 같은 항공사 코드에는 이름도 하나뿐이라, 이름을 그룹 키에 더해도 그룹이 쪼개지지 않는다.
  • JOIN 쪽 문법은 INNER JOIN 레슨과 똑같다. 달라진 건 뒤에 GROUP BY가 붙었다는 것뿐이다.

흔한 실수와 점검

  • 그룹 키가 아닌 필드를 그냥 SELECT → 오류로 막힌다. 함수로 감싸든지, 그 필드를 GROUP BY에 함께 적든지 둘 중 하나를 고르자.
  • 합계 오버플로 → 받는 칸이 좁으면 큰 합계가 담기지 않는다. SUM을 받을 칸은 TYPE p로 넉넉하게 잡는 습관을 들이자.
  • 평균을 정수 칸으로 → AVG( ) 결과는 소수 자리가 잘려 버린다. 소수 자리가 있는 타입으로 받자.

그룹 요약은 됐다. "운항편 5편 이상인 항공사만"처럼 집계 결과로 필터하려면? → HAVING(다음 레슨).
