화면 없이 조건 만들기

지금까지는 사용자가 Selection Screen에 입력하면 이 만들어졌다. 하지만 모든 조건이 화면에서 오지는 않는다.

밤마다 혼자 도는 정산 프로그램을 떠올려 보자. 새벽 2시에 사람 없이 실행되니 조건을 입력해 줄 사람이 없다. 그래도 "취소(C) 건은 빼고 집계한다" 같은 조건은 필요하다. 이럴 때는 코드가 직접 조건 행을 만들어야 한다. (다른 프로그램이 조건을 넘겨주며 부르는 경우, 기본값을 미리 채워 두는 경우도 마찬가지다.)

이때 필요한 게 Range Table 직접 조작이다. 구조(SIGN/OPTION/LOW/HIGH)는 이미 Range Table 구조에서 배웠다. 코드로도 결국 그 네 칸을 채운 행을 만들어 APPEND하면 된다.

⚠️ "그럼 권한대로 자동으로 좁히면 되겠네"는 반만 맞다. 코드가 range를 좁히면 보이는 데이터는 줄지만, 그건 화면 정리일 뿐 권한 통제가 아니다. 그 줄을 지운 다른 프로그램은 그대로 다 읽는다. "이 사람이 이 데이터를 봐도 되는가"는 별도의 권한 검사로 확인해야 하고, 그 방법은 Chapter 15 · 권한 검증에서 배운다.

DATA: gr_stat TYPE RANGE OF zbooking-status,
      gs_stat LIKE LINE OF gr_stat,
      gt_book TYPE TABLE OF zbooking.

CLEAR gs_stat.
gs_stat-sign   = 'I'.
gs_stat-option = 'EQ'.
gs_stat-low    = 'N'.
APPEND gs_stat TO gr_stat.

SELECT * FROM zbooking INTO TABLE gt_book
  WHERE status IN gr_stat.

줄별 의미는 이렇다.

코드 의미
gr_stat TYPE RANGE OF zbooking-status 상태 필드와 같은 타입의 을 만든다.
gs_stat LIKE LINE OF gr_stat Range Table 한 행을 담을 를 만든다.
CLEAR gs_stat. 이전 행 값이 남지 않게 비운다.
gs_stat-sign/option/low 포함(I)·정확히 같음(EQ)·상태 N으로 한 행을 채운다.
APPEND gs_stat TO gr_stat. 완성한 조건 행을 Range Table에 추가한다.
SELECT * … WHERE status IN gr_stat 만든 조건으로 조회한다(SELECT *는 WHERE … IN에서 말한 학습용 형태 그대로다).

💡 옛 코드에는 RANGES r_stat FOR zbooking-status. 형태도 보인다. 화면 없이 Range Table을 선언하는 옛 방식인데, 공식 문서에도 "이제 쓰지 말 것"으로 표시돼 있다. 이 문장은 Chapter 06 · Internal Table 기초에서 본 Header Line (테이블에 같은 이름의 Work Area가 딸려 오는 단축)까지 함께 만든다. 읽을 수는 있어야 하지만 새 코드는 위처럼 TYPE RANGE OF를 쓴다. 참고로 는 같은 Range Table을 화면 입력칸과 함께 만들고, TYPE RANGE OF는 코드 안의 표만 만든다.

한 줄씩 따라가기

핵심은 APPEND 전에는 gr_stat이 비어 있다는 점이다. gs_stat에 값을 채워도 그건 일 뿐, APPEND해야 비로소 에 행이 생긴다. 한 줄씩 실행하면 gs_stat와 gr_stat은 각각 어느 시점에 바뀔까?

흔한 실수와 점검

  • SIGN/OPTION을 비운 채 APPEND → 행은 네 칸이지만 최소 SIGN·OPTION·LOW는 조건에 맞게 채워야 한다.
  • CLEAR 생략 → 를 재사용할 때 안 비우면 앞 행 값이 남는다. 특히 앞 행이 BT라 HIGH를 썼고 다음이 EQ라면, HIGH가 남아 해석을 헷갈리게 만든다.
  • RANGES를 새 기준처럼 쓴다 → 옛 코드를 알아보기 위한 것일 뿐, 새 코드는 TYPE RANGE OF.

정리

  • 화면 없이도 TYPE RANGE OF로 을 만들 수 있다.
  • 한 조건 행은 에 SIGN·OPTION·LOW(·HIGH)를 채운 뒤 APPEND한다.
  • SELECT-OPTIONS는 화면 입력칸까지 함께, TYPE RANGE OF는 코드 안의 표만 만든다.
  • RANGES는 옛 코드를 알아보기 위해서만 알아 둔다.

화면에서 만든 조건이든 코드로 만든 조건이든, 결국 같은 Range Table이다. 이제 이 챕터에서 배운 것을 모아 공연·상태 조건으로 예매 목록을 필터링하는 실습으로 마무리하자 → 다음 레슨.
