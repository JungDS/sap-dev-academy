Classic DDIC View·유지보수 객체

SE16N 데이터 브라우저

테이블 내용을 빠르게 조회하는 만능 브라우저 — SE16N.

Track 1Chapter 14Lesson 7중급

빠르게 들여다보는 만능 도구

지금까지 데이터를 SE11 Create Entries(한 건씩, Chapter 7 · Transparent Table)· TMG/SM30(표준 유지보수 화면, Chapter 14 · TMG/SM30)으로 다뤘다. 그런데 "아무 테이블이나 빠르게 내용만 보고 싶다"면? 그게 SE16N이다. 정식 이름은 General Table Display(일반 테이블 조회)다.

📎 이름이 닮은 형제가 있다. SE16은 Data Browser로, SE16N보다 먼저 있던 조회 화면이다. SE11에서 테이블을 열어 두고 Utilities → Table Contents로 들어가는 길도 같은 자리로 간다. SE16N이 막혀 있거나 아예 없는 시스템이라면 SE16으로 가면 된다. 이 레슨의 내용은 그대로 통한다.

SE16N로 조회

SE16N → 테이블명 입력 → 조건(선택) → 실행(F8). 별도 화면을 만들지 않고 행을 바로 조회한다.

  • 컬럼별 조건·정렬·레이아웃 저장 등 편의 기능이 풍부하다.
  • ZCONCERT·ZBOOKING 같은 우리 테이블은 물론, SFLIGHT(Chapter 8 · 연습 데이터에서 읽어 본 항공편 표준 테이블)처럼 SAP이 기본으로 주는 테이블도 이름만 알면 열어 본다.

⚠️ "이름만 알면 다 본다"는 아니다. 조회에도 권한 검사가 걸린다. 테이블마다 묶여 있는 권한 그룹(S_TABU_DIS)이나 테이블 이름 단위 권한(S_TABU_NAM)이 없으면 열리지 않는다. 앞 레슨에서 TMG의 Authorization Group을 정한 것도 결국 이 통제와 이어진다.

아래에서 SM30으로 새 회차 한 건을 저장한 뒤 SE16N으로 확인해 보자. 조건 없이/key/오타로 조회하고, 원본 테이블과 Database View 결과가 왜 다를 수 있는지도 보자.

왜 '마지막에' 배우나

SE16N은 너무 편해서, 먼저 보여 주면 앞에서 배운 Maintenance View·TMG를 만들 이유가 사라져 보인다. 하지만 SE16N은 개발자용 빠른 점검 도구이고, 실제 사용자가 쓰는 정식 입력 화면은 Maintenance View·전용 프로그램이다. 역할이 다르다.

⚠️ 운영 데이터 직접 편집 주의. SE16N의 기본 화면은 조회용이다. 편집은 명령창에 &SAP_EDIT를 넣는 식의 특수 모드로만 열리고, 그렇게 바꾼 값은 별도 변경 기록 테이블(SE16N_CD_*)에 남는다. 릴리스와 시스템 정책에 따라 이 기능이 아예 잠겨 있기도 하다. 잠겨 있지 않더라도 업무 화면이 하는 검증과 이력을 통째로 건너뛰는 길이라, 운영 데이터에는 손대지 않는 게 기본이다.

흔한 실수와 점검

  • 조건 없이 대용량 조회 → 조건을 안 넣고 큰 테이블을 실행하면 시스템 부담이 크다. 항상 key나 조건을 넣어 좁혀 조회하는 습관을 들인다.
  • SE16N을 정식 입력 화면으로 → 개발·점검용이다. 사용자 입력은 유지보수 화면이나 전용 화면으로 받는다.
  • 권한 → 조회와 편집은 서로 다른 권한이다. 편집이 안 열린다고 설정 문제로 단정하지 말고 권한부터 확인한다(교육 시스템에서는 안내받은 범위 안에서만 시도한다).

정리

  • SE16N(General Table Display)은 테이블 내용을 빠르게 들여다보는 개발자용 도구다.
  • 조회도 권한 검사를 거치고, 편집은 특수 모드와 별도 기록이 따르는 예외적인 길이다.
  • 사용자가 쓰는 정식 입력 경로는 여전히 TMG로 만든 표준 유지보수 화면이다.

DDIC View와 유지보수·조회 도구를 마쳤다. 그런데 이 클래식 View들은 현대의 CDS View로 진화한다. 그 비교를 준비하자 → 다음 레슨.
