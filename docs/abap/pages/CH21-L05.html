같은 규약, 다른 구현 🤝

종류가 달라도 같은 약속을 지켜야 할 때가 많다. 예매 내역·공연 정보·오류 로그는 서로 다른 지만, **"화면에 출력할 수 있다"**는 점은 같다. 그렇다고 태생이 다른 셋을 억지로 '한 가족'으로 묶는 건 어색하다. 필요한 건 핏줄이 아니라 "출력할 수 있다"는 규약이다. (클래스를 부모·자식으로 잇는 이라는 도구는 Inheritance / Redefinition에서 정식으로 배운다. 지금은 이름만 알아 두자.)

그 규약을 정하는 게 (인터페이스)다. 이름과 입·출력 형태(·반환값)를 약속하고, 실제 방법은 각 클래스가 알아서 한다.

2
3
INTERFACE zif_printable PUBLIC.
  METHODS print.
ENDINTERFACE.

클래스에서 구현 — INTERFACES 🧩

는 INTERFACES로 규약을 받아들이고, 구현 는 인터페이스~메서드 이름으로 쓴다.

ABAP

CLASS zcl_booking DEFINITION PUBLIC CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES zif_printable.          " 이 규약을 따른다
ENDCLASS.

CLASS zcl_booking IMPLEMENTATION.
  METHOD zif_printable~print.          " 인터페이스~메서드
    WRITE: / '예매 내역 출력'.
  ENDMETHOD.
ENDCLASS.

zcl_booking은 예매 내역 한 건의 출력을 맡는 별도 예시 클래스다. 관통 예제 zcl_booking_manager와 이름이 비슷하지만 다른 클래스이니 헷갈리지 말자.

인터페이스 참조 — 다형성의 기반 🎭

핵심은 여기다. 타입 참조 변수(TYPE REF TO zif_printable)에 어떤 구현 의 를 담느냐에 따라, 같은 호출이 다르게 실행된다.

ABAP
1
2
3
4
DATA lo_printable TYPE REF TO zif_printable.

lo_printable = NEW zcl_booking( ).
lo_printable->print( ).              " "예매 내역 출력"

호출자는 실제 클래스가 무엇인지 몰라도 "이 객체는 출력 가능하다"는 약속만 보고 print( )를 부른다. 클래스 이름에 덜 묶일수록 나중에 구현을 갈아끼우기 쉽다. 이게 이다. 한 가지 더 보자: 인터페이스 참조로 부를 때는 lo_printable->print( )처럼 ~ 없이 이름만 쓴다. ~는 구현부(METHOD zif_printable~print)에서, 그리고 클래스 타입 참조로 인터페이스 메서드를 부를 때(lo_booking->zif_printable~print( ))만 쓰는 소속 표시다.

흔한 실수와 점검 🚧

  • 구현 누락 → INTERFACES로 규약을 받았으면 그 메서드를 전부 구현해야 활성화된다.
  • ~ 위치 혼동 → 구현은 항상 인터페이스~메서드(METHOD zif_printable~print). 호출은 참조 종류를 따른다: 참조로는 lo_printable->print( )처럼 ~ 없이, 타입 참조로 부를 때만 lo_booking->zif_printable~print( )처럼 ~를 붙인다. 외부에서 부를 때는 인터페이스 참조 사용이 권장이라, 실전에서는 ~ 없는 호출 형태를 주로 보게 된다.
  • 인터페이스를 "빈 부모 클래스"처럼 → 상태를 받는 도구가 아니라 외부 규약을 고정하는 도구다.
  • 한 클래스 = 인터페이스 하나로 오해 → 한 클래스는 INTERFACES를 여러 줄 써서 인터페이스를 여러 개 받아들일 수 있다. 다만 너무 많으면 그 클래스가 무슨 책임을 지는지 흐려진다.
  • 인터페이스가 비대해짐 → zif_printable이면 출력에 필요한 약속만. 예매·취소·검증까지 넣으면 모든 구현 클래스가 그 의무를 떠안는다.
  • 인터페이스 참조로 구체 메서드 → 인터페이스 참조로는 인터페이스에 선언된 것만 보인다. 구체 클래스 전용 메서드는 그 클래스 타입 참조라야 보인다.

규약으로 묶었다. 그런데 처리 중 오류가 나면? 오류를 로 다루는 를 보자 → Exception Class — TRY / CATCH / CX 계층.
