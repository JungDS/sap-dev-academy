화면 출력이 아니라 "문서"를 만든다 — 전통 양식의 구조와 호출.

Track 3Chapter 37Lesson 1중급

화면은 됐고, 이제 "문서"다

Chapter 36까지 우리는 데이터를 빠르게 만들고 화면에 보여주는 법을 배웠다. 그런데 공연 예매가 확정되면 고객에게 예매 확인서가 나가야 한다. 회사 로고가 정해진 자리에 있고, 공연명·좌석이 정확한 위치에 찍히고, 하단에 취소 규정이 들어간 문서다.

WRITE도 ALV도 여기엔 안 맞는다. 둘은 화면용이고, 로고·여백·페이지 넘김·법적 문구를 다루는 도구가 아니다. 더 위험한 대안은 ABAP 코드로 위치와 줄바꿈을 전부 조립하는 것이다. 문구 하나 바뀔 때마다 프로그램을 수정·이송해야 한다.

그래서 SAP은 계산은 ABAP, 모양은 양식 도구로 책임을 나눈다. 전통 도구가 (SMARTFORMS에서 만드는 SAP의 고전 양식 도구)다. 고전이라고 과거형이 아니다. 기존 시스템에 자산이 많아 유지보수에서 반드시 만나고, 이 챕터에서는 인쇄부터 PDF 파일까지 이 도구 하나로 완주한다. 이 레슨의 목표는 구조를 읽고 호출하는 것이다.

🔭 기대 관리 — 양식 자체는 SMARTFORMS 화면(트리 + 그래픽 편집기)에서 만든다. 코드가 아니라 도구 조작이라 이 페이지에서는 구조를 시뮬레이션으로 익히고, 실제 화면 세부는 실습 시스템에서 확인한다.

구조 — 설계도 한 장을 여섯 조각으로

구성 쉬운 설명 문제가 생기면 볼 곳
Form 양식 전체 설계도(ZSF_TICKET) ABAP이 부르는 논리적 이름
Page 출력되는 페이지(첫 장·다음 장) 페이지가 넘어갈 때의 연결
Window 페이지 안의 출력 영역 MAIN(흐르는 본문) vs 고정 영역(머리글·바닥글)
Node 실제 출력 요소(Text·Table·Graphic) 문구·표·이미지·줄바꿈
Form Interface ABAP → 양식 데이터 계약 값이 안 나오면 가장 먼저
Global Definitions 양식 내부 보조 변수(표시용 가공값·합계 등) 업무 로직을 넣는 곳이 아님

핵심 흐름은 하나다: ABAP 데이터 → Form Interface → Window/Node 배치. 좌석 목록처럼 줄 수가 변하는 내용은 MAIN window에 둬야 페이지를 타고 흐른다. 이유는 간단하다: 고정 window(머리글·바닥글)는 페이지마다 같은 자리·같은 크기로 반복해 그려지는 영역이라 내용이 넘쳐도 다음 페이지로 흘러갈 수 없고, MAIN만 넘친 내용을 다음 페이지로 이어 준다.

어떻게 만드는가 — 도구에서 다섯 걸음

  1. Form 생성 — SMARTFORMS에서 이름(ZSF_TICKET)으로 새 Form. 저장할 때 패키지·이송요청을 묻는 팝업이 뜬다(Chapter 1 · 이송요청에서 본 그 창이다). 양식도 이송 대상 오브젝트라는 뜻이다.
  2. Form Interface 정의 — 트리 상단의 Form Interface에서 예매 데이터를 Import 로 선언한다: 이름 IS_BOOKING, 타입 ZBOOKING(DDIC 테이블 이름은 그대로 구조 타입으로 쓸 수 있다 — Chapter 7에서 배운 그대로). 접두어 is_는 Interface의 Import 구조 파라미터에 흔히 쓰는 관례다(i = importing, s = structure). 프로그램 안의 gv_/gs_와는 다른 축의 이름 규칙이니 헷갈리지 말자. 좌석 목록처럼 여러 줄인 재료도 Import 파라미터로 함께 선언한다: 이름 IT_SEATS, 타입은 DDIC Table Type(Chapter 6에서 만든 ZTT_… 그것이다). 이 it_도 파라미터 관례(i=import, t=table)로, 프로그램 변수의 Header Line 규칙과는 다른 축이다. (화면에 보이는 구형 Tables 탭은 옛 호환용 자리라 새로 쓸 일이 없다.)
  3. Page/Window 배치 — 첫 페이지에 HEADER(로고)·MAIN(본문)·FOOTER(규정).
  4. Node 작성 — MAIN window 아래에 Text node를 만들고 &IS_BOOKING-CUSTOMER&처럼 쓴다. &…&로 감싸는 것은 전용 표기다: 양식 텍스트 안에서 이렇게 감싼 부분만 "글자 그대로"가 아니라 필드 값으로 치환된다. 좌석 목록처럼 여러 줄인 내용은 Table node로 배치한다(노드 종류별 세부는 도구에서 익힌다).
  5. 활성화 — SE38처럼 활성화 아이콘을 누른다. 이때 시스템이 생성 함수 모듈(/1BCDWB/SF… 이름)을 만든다. 저장만 하면 호출할 산출물이 없다.

어떻게 부르는가 — 이름을 조회해서 호출

생성 함수 모듈의 이름은 시스템마다 다를 수 있다. 이송으로 넘어가는 것은 양식 설계도(Form)이고, 함수 모듈은 각 시스템이 활성화 시점에 일련번호를 붙여 새로 만들기 때문이다. 반면 Form 이름(ZSF_TICKET)은 어느 시스템에서나 같은 안정적 계약이다. 그래서 운영 코드는 함수명을 박아 두지 않고, Form 이름으로 현재 이름을 조회해 호출한다(SAP Help가 안내하는 표준 흐름). 코드에 로 박아도 되는 것은 Form 이름까지다.

예제 데이터는 우리가 직접 만든 예매 테이블 zbooking이다(Chapter 9 · 콘서트앱 테이블 실습). 실습 시스템에 없다면 그 레슨부터 만들어 두자.

REPORT z_ticket_print.          " SE38 테스트 리포트면 충분하다

DATA gs_booking TYPE zbooking.
DATA gv_fm      TYPE rs38l_fnam.   " 함수 모듈 이름용 DDIC Data Element

START-OF-SELECTION.
  " 출력할 예매 한 건 준비(정훈영의 예매)
  SELECT SINGLE * FROM zbooking
    WHERE booking_id = '0001'
    INTO @gs_booking.

  " ① Form 이름 → 현재 생성 함수 모듈 이름 조회
  CALL FUNCTION 'SSF_FUNCTION_MODULE_NAME'
    EXPORTING
      formname = 'ZSF_TICKET'
    IMPORTING
      fm_name  = gv_fm
    EXCEPTIONS
      no_form            = 1  " Form 자체가 없다
      no_function_module = 2  " 저장만 하고 활성화를 안 했다
      OTHERS             = 3.
  IF sy-subrc <> 0.
    MESSAGE '양식을 찾을 수 없습니다' TYPE 'E'.
  ENDIF.

  " ② 조회한 이름으로 호출 — 이름이 '변수'인 CALL FUNCTION
  CALL FUNCTION gv_fm
    EXPORTING
      is_booking = gs_booking
    EXCEPTIONS
      formatting_error = 1
      internal_error   = 2
      send_error       = 3
      user_canceled    = 4  " 대화상자에서 사용자가 취소
      OTHERS           = 5.
  IF sy-subrc = 4.
    RETURN.                 " 취소는 오류가 아니다 — 조용히 끝낸다
  ELSEIF sy-subrc <> 0.
    MESSAGE '양식 출력에 실패했습니다' TYPE 'E'.
  ENDIF.

②가 처음 보는 모양일 것이다. Chapter 33까지의 CALL FUNCTION은 항상 '따옴표 이름'이었는데, 여기는 변수에 담긴 이름을 호출한다(동적 함수 호출이라는 공식 문법이다). 생성 함수처럼 "이름이 실행 시점에 정해지는" 상황을 위한 형태다.

실행하면 양식 미리보기/인쇄 대화상자가 뜬다. 우리가 켠 적 없는 창이 뜨는 이유는, 출력 옵션을 따로 안 넘기면 대화상자가 기본값이기 때문이다. 창에서 인쇄 미리보기(Print preview)를 누르면 실제 인쇄 없이 화면으로 확인할 수 있다. 여기까지가 "만들고 → 부른다"의 완결 경로다.

이 예제 코드는 좌석 목록 없이 예매 구조 한 건만 넘기는 최소형이다. 좌석까지 찍는 완성형은 Interface에 테이블 를, MAIN에 Table node를 더하는 확장이고, L05의 도전 과제에서 직접 해 본다.

⚠ 자동·배치 출력이라면 — 대화상자 기본값은 사람이 앉아 있는 화면 전용이다. 배치에서는 대화상자를 띄울 수 없어 그대로 실패하고, 생성 함수의 호출 제어 옵션(대화상자 끄기 등)을 명시적으로 넘겨야 한다. 그 옵션 구조는 바로 다음 레슨에서 직접 쓰게 되니, 지금은 "옵션을 안 넘긴 코드가 배치로 가면 사고"라는 것만 기억하자.

값이 안 나올 때 — 어디부터 보나

빈칸의 원인은 세 층 중 하나다. 순서대로 좁힌다. (값 이전에 호출 자체가 실패한다면 그건 층이 아니라 앞 단계 문제다 — 활성화 누락·이름 조회 실패. 아래 시뮬레이터의 네 번째 신호등이 그 자리다.)

  1. ABAP 데이터 — gs_booking-customer가 채워졌는가(디버거, Chapter 4 · 디버깅 입문).
  2. Interface 계약 — ABAP이 넘긴 이름과 Form Interface 이름이 같은가.
  3. Node 배치 — 참조(&IS_BOOKING-…&)와 window 위치가 맞는가.

아래 시뮬레이터에서 네 가지 고장을 직접 눌러 원인 층을 구분해 보라.

흔한 실수와 점검 🚧

  • 생성 함수명 하드코딩 → 개발기에서 우연히 맞아도 운영 이송 후 깨진다. 안정적인 이름은 Form 이름이고, 함수명은 SSF_FUNCTION_MODULE_NAME으로 조회한다.
  • 양식 안에 업무 로직 → 할인 계산·유효성 판단은 ABAP에서 끝내고, 양식엔 출력할 형태의 데이터만 넘긴다. 양식 속 로직은 테스트·추적이 어렵다.
  • 흐르는 내용을 고정 영역에 → 좌석 목록을 HEADER에 넣으면 페이지가 넘어갈 때 깨진다. 반복·본문은 MAIN으로.
  • 저장만 하고 활성화 생략 → 생성 함수가 없어 호출이 실패한다.

정리 📌

  • 문서 출력 = **계산(ABAP) + 모양(양식 도구)**의 분업. 는 전통 도구로, 유지보수에서 반드시 만난다.
  • 구조 = Form → Page → Window → Node, 데이터는 Form Interface로.
  • 호출 = SSF_FUNCTION_MODULE_NAME으로 이름 조회 → 동적 CALL FUNCTION. 하드코딩 금지.
  • 빈 값 추적 순서 = ABAP 데이터 → Interface 계약 → Node 배치.

만들고 부르고 인쇄 미리보기까지 됐다. 그런데 고객은 종이가 아니라 이메일로 받을 PDF 파일을 원한다. 인쇄 대화상자 어디에도 우리 프로그램이 쥘 수 있는 파일은 없다. 출력의 원형 데이터를 돌려받아 PDF로 바꾸는 길로 간다.
