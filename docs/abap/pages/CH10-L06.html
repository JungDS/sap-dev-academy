셋 중 무엇을 쓰나

(FORM) · · (메서드) — 도구가 셋이다. 상황별로 정리한다.

한눈에

도구 범위 권장도 언제
(FORM) 프로그램 내부 ▲ 레거시 기존 코드 유지보수
전역 재사용 ○ 절차적 재사용, 원격 호출(), 표준
/ Method Local은 프로그램 내부 · Global은 전역 재사용 ◎ 권장 신규 개발 전반(현대 표준)

왜 이런 서열이 됐나

셋은 태어난 시대가 다르다.

FORM은 가장 오래된 도구다. SAP 공식 문서가 새로 쓰지 말 것으로 분류한(obsolete) 문법이라, 지금은 읽고 고치는 용도로만 남았다.

에는 아직 대체할 수 없는 자리가 있다. 다른 시스템이 원격으로 부르는 창구()와 SAP 표준 업무 인터페이스()가 대부분 이 형태로 만들어져 있다.

는 데이터와 로직을 한 덩어리로 묶어(캡슐화) 검증과 재사용이 쉽다. 그래서 신규 개발의 표준이 됐다. 표의 권장도는 취향이 아니라 이런 배경에서 나왔다.

원칙

  • 신규 코드는 클래스(메서드)로 — 현대 ABAP의 기본.
  • 은 여전히 유효 — 원격 호출(), 다수의 표준 인터페이스가 이 형태다.
  • (FORM)은 새로 만들지 말 것 — 읽고 유지보수하는 용도로만 안다.

판단이 갈리는 실전 장면 둘만 미리 보자. ① "잔여석 계산을 새로 만든다" — 신규 로직이니 클래스 메서드. ② "외부 시스템이 우리 잔여석을 조회하게 해 달라" — 원격 호출이 필요하니 그 메서드를 감싸는 **RFC 가능한 Function Module**을 하나 더 만든다. 둘은 경쟁이 아니라 역할 분담이다(로직은 클래스에, 원격 창구는 Function Module에).

직접 해 보기

상황 카드를 ·· 중 어디에 둘지 골라 보고, 왜 그런지 이유를 확인해 보자.

흔한 실수와 점검

  • 신규에 FORM 사용 → 지양. 메서드로.
  • 무조건 클래스 → 원격 호출이 필요하면 가능한 을 쓴다.

이제 코드를 재사용 단위로 묶을 수 있다. 배운 를 콘서트앱에 적용해 잔여석·예매 판정 로직을 만들어 보자 → 실습 — 잔여석 계산·예매 판정 모듈화.
