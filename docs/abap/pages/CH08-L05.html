조건을 정교하게

WHERE로 필요한 행만 추린다. 비교할 값을 ABAP 변수에 담아 두고 그 변수를 조건에 그대로 적을 수 있다. 이렇게 SQL 문장 안에 끼워 쓰는 ABAP 변수를 host 변수라 부른다. SQL 문장을 품고 있는 집(host)이 ABAP 프로그램이라서 붙은 이름이다.

ABAP
1
2
3
4
5
DATA gv_carr TYPE sflight-carrid VALUE 'KE'.
DATA gt_flight TYPE TABLE OF sflight.

SELECT * FROM sflight INTO TABLE gt_flight
  WHERE carrid = gv_carr.        " classic: host 변수를 그대로 적는다

classic 표기는 host 변수를 아무 표시 없이 그대로 적는다. 요즘 표기에서는 변수 앞에 표시를 하나 붙이는데, 그 차이는 Chapter 19 · Host Variable에서 배운다.

🧑‍💻 다른 언어를 해 봤다면 변수를 SQL 문장에 그냥 붙여 놓은 모습이 문자열을 이어 붙여 만드는 SQL처럼 보여 불안할 수 있다. 그렇지 않다. 컴파일러가 이 자리를 "값이 들어갈 자리"로 미리 잡아 두고 실행할 때 값만 끼워 넣는다. 변수에 무엇이 들어 있든 문장의 구조가 바뀌지 않으므로 SQL Injection 걱정은 없다.

💡 아래 예제들은 조건 자체에 집중하려고 IF sy-subrc = 0. 확인을 생략했다. 실제 프로그램에서는 SELECT 바로 다음 줄에 꼭 붙인다.

비교·논리 연산자

행을 고르는 비교 기호는 다른 언어와 같다.

기호 약어 뜻
= EQ 같다
<> NE 다르다
< LT 작다
> GT 크다
<= LE 작거나 같다
>= GE 크거나 같다

오른쪽 약어는 Equal·Not Equal 같은 영어 이름을 두 글자로 줄인 것이다. WHERE fltime GT 300 처럼 기호 대신 약어를 써도 똑같이 동작한다. 둘 중 하나만 골라 쓰면 되고, 이 과정에서는 눈에 익은 기호 쪽을 쓴다.

조건 여러 개는 AND(둘 다 만족)·OR(둘 중 하나)로 잇고 NOT으로 뒤집는다. 둘을 섞어 쓸 때는 괄호로 묶어 순서를 분명히 한다.

범위·목록·패턴

ABAP
1
2
3
4
SELECT * FROM sflight INTO TABLE gt_flight
  WHERE fldate BETWEEN '20260101' AND '20261231'   " 범위
    AND carrid IN ('KE', 'LH', 'AA')               " 목록
    AND connid LIKE '07%'.                          " 패턴
  • BETWEEN a AND b — a부터 b까지, 양 끝을 포함한 범위.
  • IN ( ... ) — 괄호에 적은 값 중 하나라도 맞으면 통과.
  • LIKE — 패턴으로 맞춰 보기. %는 임의 길이(0글자여도 된다), _는 정확히 한 글자를 뜻한다. '07%'는 07로 시작하는 모든 값이다.

IS NULL

NULL은 ABAP 초기값(0·공백)과 다르다. 0이나 공백은 "값이 들어 있는데 그 값이 0/공백"인 상태이고, NULL은 DB에 값 자체가 없는 상태다. 이 NULL인 행만 골라내는 조건이 IS NULL이다.

ABAP
1
2
3
4
DATA gt_spfli TYPE TABLE OF spfli.

SELECT * FROM spfli INTO TABLE gt_spfli
  WHERE fltime IS NULL.

그런데 이 문장을 실제로 돌려 보면 늘 0건이다. 잘못 쓴 게 아니다. SE11로 만드는 DDIC 테이블은 컬럼을 "비어 있을 수 없음"으로 잡고, 값을 넣지 않으면 초기값(0·공백)으로 채운다. 그래서 우리가 다루는 업무 테이블 안에는 애초에 NULL이 없다. 문법은 있지만 이 조회에서는 걸릴 행이 없는 것이다.

그럼 NULL은 어디서 만나는가. 두 테이블을 합쳐 읽을 때 짝이 없어 빈자리가 생기는 경우가 대표적이다. 그건 실제로 NULL이 나오는 장면과 함께 Chapter 13 · LEFT OUTER JOIN에서 배운다. 지금은 "우리 테이블엔 NULL이 없다, 그래서 이 조건은 0건이다"까지만 알면 된다.

조건 칩을 켜고 끄며 AND/OR로 조합해 보자. 각 행이 통과인지 제외인지, 왜 탈락했는지를 즉시 보여 준다.

흔한 실수와 점검

  • modern 표기 습관 → 이 챕터는 classic이라 host 변수를 그대로 쓴다(요즘 표기는 Chapter 19 · Host Variable).
  • LIKE 기호 혼동 → %는 임의 길이(0글자 포함), _는 정확히 한 글자.
  • 단일값 vs 범위 → 범위·다중은 IN/BETWEEN. 사용자가 화면에서 범위를 직접 넣게 하려면 SELECT-OPTIONS를 쓰는데, 그건 Chapter 12 · SELECT-OPTIONS 기본에서 배운다.

조건을 정교하게 추렸다. 그런데 같은 조건이라도 어떤 컬럼으로 찾느냐에 따라 DB가 데이터를 찾아가는 길이 달라진다. 키로 찾을 때와 아닐 때가 어떻게 다른지 → 다음 레슨.
