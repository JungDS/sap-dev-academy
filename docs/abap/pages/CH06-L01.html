Internal Table

Internal Table 기초 — 선언·APPEND·비우기

덮어쓰지 않고 쌓는다 — 여러 행을 담는 그릇의 첫 사용법.

Track 1Chapter 6Lesson 1초급

한 건으로는 부족하다

Chapter 5 · Structure에서 만든 Structure는 사람 한 명을 담는다. 구구단 캡스톤에서도 봤듯, 반복이 돌 때마다 gs_line은 덮어써졌다. 화면에는 WRITE 줄이 9줄 남지만, 에는 늘 마지막 한 줄뿐이었다.

그런데 실제 업무는 거의 항상 여러 건을 다룬다.

상황 한 건 여러 건
사원 사원 한 명 사원 명단
주문 주문 한 건 오늘의 주문 목록
구구단 2 x 1 = 2 한 줄 2～9단 72줄

같은 모양의 행을 여러 개 쌓아 두는 그릇이 필요하다. 그게 (내부 테이블)이다. 이 챕터는 이 그릇 하나를 처음부터 끝까지 배운다. 만들고(이번 레슨), 뜯어보고, 넣고 찾고 고치고, 무리 지어 계산하는 것까지.

⚠️ Internal Table ≠ Database Table — 가장 흔한 입문 오해다. Internal Table은 프로그램이 도는 동안만 메모리에 있다가 끝나면 사라진다. 영구 저장은 DB 테이블(Chapter 7 · Transparent Table)의 몫이다. 이 둘을 구별하지 못하면 로직 설계 전체가 흔들린다.

선언 — TYPE TABLE OF

행의 모양(Structure 타입) 위에 TABLE OF를 붙인다.

ABAP
1
2
3
4
5
6
7
TYPES: BEGIN OF ts_person,
         name TYPE string,
         age  TYPE i,
       END OF ts_person.

DATA: gs_person TYPE ts_person,          " 한 건(Work Area)
      gt_person TYPE TABLE OF ts_person. " 여러 건(Internal Table)
  • gt_ 접두어가 관례다(global table). 지금 배우는 선언은 모두 프로그램 전체에서 보이는 자리라 g로 시작한다.
  • 한 건을 담는 (gs_)와 짝지어 쓴다. Work Area는 "지금 만들고 있는 한 행"을 담는 그릇이다.
  • 행 모양 ts_person은 Chapter 5 · Local Structure에서 만든 것에서 금액(amount)을 뺀 단순화 버전이다. 이번 챕터는 name·age 두 필드로 시작한다.

TYPE TABLE OF 한 줄이면 오늘 배우는 모든 것이 된다. 사실 이 한 줄에는 행 모양 말고도 정보가 두 가지 더 숨어 있는데(무엇으로 행을 구분하는지, 어떤 방식으로 저장하는지), 그건 다음 레슨들에서 하나씩 꺼내 본다. 지금은 이 최소형으로 충분하다.

행 추가 — APPEND

에 값을 채우고 APPEND로 테이블 끝에 쌓는다.

ABAP
1
2
3
4
5
6
gs_person-name = '정훈영'. gs_person-age = 30.
APPEND gs_person TO gt_person.

CLEAR gs_person.                 " 다음 행을 채우기 전에 Work Area 비우기(습관!)
gs_person-name = '홍길동'. gs_person-age = 25.
APPEND gs_person TO gt_person.

이제 gt_person에는 행이 둘이다. 여기서 중요한 사실 하나. APPEND는 Work Area를 테이블 안으로 옮기는 게 아니라 현재 값을 복사해 새 행을 만든다. 그래서 쌓은 뒤에 gs_person을 바꿔도 이미 들어간 행은 그대로다.

🧑‍💻 다른 언어를 해 봤다면 여기가 정반대라 놓치기 쉽다. Java·C#에서 리스트에 객체를 담으면 그 객체를 가리키는 참조가 들어가서, 나중에 원본을 고치면 리스트 안 것도 같이 바뀐다. ABAP의 APPEND는 값을 통째로 복사해 넣으므로 원본을 고쳐도 쌓인 행은 그대로다.

행이 몇 개인지는 DESCRIBE TABLE로 센다.

ABAP
1
2
DATA gv_cnt TYPE i.
DESCRIBE TABLE gt_person LINES gv_cnt.   " gv_cnt = 2

눈으로 직접 확인하기 — 디버거

은 에만 있어서 WRITE를 하기 전에는 눈에 보이지 않는다. "내가 넣은 게 정말 들어갔나?" 불안할 때는 Chapter 4 · 디버깅에서 배운 도구를 그대로 쓰면 된다.

ABAP
1
2
APPEND gs_person TO gt_person.
BREAK-POINT.                     " 여기서 멈춰서 gt_person을 들여다보자

디버거가 멈추면 변수 목록에서 GT_PERSON을 더블클릭한다. 지금까지 쌓인 행이 표 모양 그대로 펼쳐진다. 이 확인 습관은 챕터 내내(그리고 실무 내내) 쓰인다. 이 챕터의 체험 위젯들이 보여 주는 "표가 자라는 화면"이 바로 디버거의 이 화면을 본뜬 것이다.

테이블 통째로 복사하기

행을 하나씩만 옮길 수 있는 건 아니다. 같은 행 모양이면 테이블끼리 통째 대입이 된다.

ABAP
1
2
DATA gt_backup TYPE TABLE OF ts_person.
gt_backup = gt_person.           " 행 전체가 복사된다

APPEND가 한 행을 복사해 넣듯, 이 대입도 전체를 복사한다. 복사한 뒤 gt_person을 바꿔도 gt_backup은 그대로다(반대도 마찬가지). 단, 대입은 덮어쓰기다 — gt_backup에 원래 있던 행들은 사라지고 gt_person의 행들로 교체된다. "뒤에 이어 붙이기"는 다른 도구가 따로 있는데, 명단 합치기 레슨에서 만난다.

비우기 — CLEAR / FREE

그릇(gt_)과 한 건(gs_) 모두 비우는 도구는 같은 CLEAR다. 나란히 정리하면:

ABAP
1
2
3
CLEAR gs_person.   " Work Area 한 건의 값 비우기 — APPEND 전 습관
CLEAR gt_person.   " 테이블의 행 전체 삭제(초기 메모리는 남겨 둠)
FREE  gt_person.   " 행 삭제 + 초기 메모리까지 전부 반환

여기서 초기 란 테이블을 선언할 때 행이 하나도 없어도 시스템이 미리 잡아 두는 작은 공간을 말한다. 이 공간이 남아 있으면 다시 채울 때 그만큼 빨리 들어간다.

  • 곧 다시 채울 테이블은 CLEAR. 남겨 둔 초기 메모리 덕에 다시 채우기가 빠르다.
  • 대용량 테이블을 다 쓰고 더 안 쓸 때는 FREE. 초기 메모리까지 돌려주니 그만큼 여유가 생긴다.
  • 옛 코드에는 REFRESH gt_...라는 문장도 보인다. 행 전체를 비우는 옛 문장으로, 공식적으로 obsolete(더는 권장하지 않고 새 문법에서 퇴출 중인 상태)다. 새 코드는 CLEAR/FREE만 쓴다. 옛 코드 읽는 법은 별도 레슨에서 몰아서 배운다.

흔한 실수와 점검

  • APPEND 전에 CLEAR 안 함 → 이전 값이 남아 섞일 수 있다(name만 바꾸면 age는 앞사람 값 그대로). 새 행을 채우기 전에 CLEAR gs_person 습관.
  • 에 넣었으니 저장됐다는 착각 → 일 뿐이다. 프로그램이 끝나면 사라진다.
  • 통째 대입을 "이어 붙기"로 착각 → gt_b = gt_a는 gt_b를 교체한다. 원래 행이 필요하면 대입 전에 따로 보관하자.

행을 쌓고, 세고, 비우고, 통째로 복사까지 했다. 다음은 아까 미뤄 둔 질문이다 — TYPE TABLE OF 한 줄에는 정확히 무엇이 들어 있나? → 선언 한 줄 해부.
