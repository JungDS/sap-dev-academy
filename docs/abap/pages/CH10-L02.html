모듈화 기초

USING / CHANGING 파라미터

서브루틴에 값을 주고(USING) 결과를 돌려받는다(CHANGING).

Track 1Chapter 10Lesson 2초급

값을 주고받기

서브루틴이 바깥 값을 받아 처리하고 결과를 돌려주려면 ****가 필요하다. FORM에서는 USING과 CHANGING으로 한다.

USING(입력) / CHANGING(입출력)

START-OF-SELECTION.
  DATA: gv_amount TYPE p LENGTH 8 DECIMALS 2,
        gv_out    TYPE p LENGTH 8 DECIMALS 2.

  gv_amount = 1000.
  PERFORM add_tax USING gv_amount CHANGING gv_out.
  WRITE gv_out.

FORM add_tax
  USING    iv_amount TYPE p
  CHANGING cv_result TYPE p.
  cv_result = iv_amount * '1.1'.
ENDFORM.
  • USING — 주로 입력값(관례). CHANGING — 돌려줄 값.
  • 접두어 관례: iv_(input), cv_(changing).
  • 넘기는 값은 변수로 준비해 두면 안전하다. 정의 쪽 타입과 넘기는 값의 타입이 어긋나면 호출 자체가 막힐 수 있다.

엄밀히 USING도 참조로 넘어가 바뀔 수 있다. 값 보호가 필요하면 USING value(iv_x)로 값 전달(by value). 관례상 입력은 USING, 출력은 CHANGING으로 의도를 표현한다.

세 가지 전달 방식

차이는 결국 하나다. 원본을 직접 건드리느냐, 복사본을 건드리느냐. 참조 전달은 서브루틴이 원본 변수 자체를 가리켜서, 안에서 값을 바꾸면 바깥 원본이 바로 바뀐다. 값 전달은 복사본을 만들어 넘기므로 안에서 아무리 바꿔도 원본은 그대로다.

방식 문법 뜻
Call by Reference USING iv_x · CHANGING cv_x 원본을 가리킴(빠름, 바뀔 수 있음)
Call by Value USING value(iv_x) 값 복사 — 원본 보호(입력 전용)
Call by Value and Result CHANGING value(cv_x) 복사해 처리 후 정상 종료 시 되돌려 씀

세 번째의 "정상 종료"는 서브루틴이 ENDFORM까지 무사히 끝난 경우를 뜻한다. 도중에 오류로 프로그램이 멈추면 복사본은 버려지고 원본은 원래 값 그대로 남는다. 절반만 바뀐 값이 원본에 새는 걸 막아 주는 방식이다.

  • 입력만 → USING value(...)로 원본을 보호한다.
  • 돌려줄 값 → 보통 CHANGING(reference).
  • 타입 명시 → USING iv_x TYPE p처럼 타입을 적으면 안전하다(권장).

빠져나오기 — RETURN

RETURN은 서브루틴을 즉시 빠져나간다(아래 남은 코드는 건너뛴다). 더 진행할 이유가 없을 때 쓴다.

FORM divide_safe
  USING    iv_a TYPE i
           iv_b TYPE i
  CHANGING cv_r TYPE i.

  IF iv_b = 0.
    RETURN.              " 0으로 나눌 수 없다 — 여기서 끝
  ENDIF.

  cv_r = iv_a / iv_b.
ENDFORM.

값이 남는 변수 — STATICS

FORM 안의 DATA는 호출이 끝나면 사라진다(FORM / PERFORM 기본 호출에서 본 로컬 변수). STATICS로 선언하면 호출이 끝나도 값이 남아 다음 호출에 이어진다.

FORM count_visit.
  STATICS lv_count TYPE i.     " DATA와 달리, 호출이 끝나도 값이 남는다

  lv_count = lv_count + 1.
  WRITE: / '이 FORM을 부른 횟수:', lv_count.
ENDFORM.

두 번 부르면 1, 2가 찍힌다. 같은 자리에 DATA를 썼다면 두 번 다 1이었다.

편해 보이지만 숨은 상태다. 값이 언제 바뀌었는지 호출하는 쪽 코드만 봐서는 알 수 없고, 같은 FORM을 다른 용도로 다시 부르면 이전 호출의 값이 섞여 든다. 꼭 필요할 때만 쓰고, 평소에는 로 주고받는 편이 안전하다.

FORM은 정의에 적은 파라미터를 하나도 빠뜨리지 않고 넘겨야 한다. 일부를 선택 사항으로 만들거나(OPTIONAL) 기본값을 미리 정해 두는(DEFAULT) 기능은 FORM에는 없다. 이런 편의 기능은 다음 레슨의 Function Module이나 메서드처럼 더 나중에 나온 도구에서 쓸 수 있다.

직접 해 보기

전달 방식을 바꿔 가며 FORM이 값을 바꿨을 때 원본이 보호되는지/바뀌는지 비교해 보자. RETURN(조기 종료)·STATICS(값 유지)도 직접 눌러 보자.

흔한 실수와 점검

  • USING/CHANGING 순서·타입 불일치 → 호출과 정의의 가 맞아야 한다.
  • 출력을 USING으로 → 의도가 흐려진다. 돌려줄 값은 CHANGING.

서브루틴은 같은 프로그램 안에서만 산다. 여러 프로그램이 공유하는 재사용 블록은? → Function Module(다음 레슨).
