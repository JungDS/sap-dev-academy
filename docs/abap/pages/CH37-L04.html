PDF 바이트와 다운로드

PDF는 글자가 아니라 바이트다 — xstring으로 받아 BIN으로 저장한다.

Track 2Chapter 37Lesson 4중급

PDF를 만들었다, 그런데 이건 글자가 아니다

L02에서 CONVERT_OTF로 PDF 데이터를 만들었다(설정 이야기였던 L03을 지나, 코드 흐름은 그 z_ticket_pdf 리포트에서 그대로 이어진다). 생성과 변환은 거기서 끝났고, 이 레슨은 그 결과 를 파일로 만드는 이야기다(이메일 첨부·보관도 같은 바이트에서 출발하지만 이 레슨 범위 밖이다 — 아래 경계 표에서 위치만 잡는다). 여기서 입문자가 가장 많이 넘어지는 지점이 있다. PDF는 사람이 읽는 텍스트가 아니라 바이트들의 묶음이다. 뷰어가 글자를 보여줄 뿐, 파일 안은 이진 데이터다. 텍스트처럼 다루는 순간 깨진다.

그래서 새 타입이 필요하다. Chapter 2에서 배운 STRING이 "글자의 가변 길이 나열"이었다면, (가변 길이 바이트 스트링 타입. 글자가 아닌 이진 데이터를 담는다)은 그 바이트 판이다. 길이도 글자 수가 아니라 바이트 수로 세며, 그 함수가 xstrlen( )이다(둘 다 공식 keyword doc 확인). 글자 수와 바이트 수가 왜 다른가: 예를 들어 한글 "가" 한 글자는 UTF-8에서 3바이트다. 글자 수 1 ≠ 바이트 수 3 — 바이트의 세계에서 크기를 빼먹거나 어림잡으면 안 되는 이유가 여기서 나온다.

시작점을 먼저 잡는다. L02의 CONVERT_OTF는 PDF 데이터를 lines의 조각 테이블(gt_pdf)로 돌려줬다. 파일 하나를 만들려면 조각이 아니라 한 덩어리 바이트가 필요한데, 다행히 CONVERT_OTF에는 그걸 위한 결과 자리(bin_file)가 따로 있다. 이 레슨은 그 자리를 받을 새 타입(xstring)을 배우고, 거기서부터 파일까지 잇는다.

단계 의미
1 bin_file(CONVERT_OTF) 변환이 돌려주는 PDF 바이트 한 덩어리
2 gv_pdf TYPE xstring 바이트 스트링으로 보관
3 xstrlen( gv_pdf ) 바이트 길이(0이면 생성·변환 실패부터 의심)
4 solix_tab 다운로드·첨부용 바이너리 테이블
5 filetype = 'BIN' 문자 변환 없이 바이트 그대로 저장

완결 코드 — 받아서, 재고, 바꿔서, 저장한다

L02 리포트에 이어 붙인다. 세 걸음이다: DATA 두 줄은 선언부(L02의 DATA 줄들 아래)에 넣고, ④ CONVERT_OTF 호출을 아래 완전형으로 교체(IMPORTING에 bin_file 한 줄이 는 것뿐이다)한 뒤, 나머지 실행문을 그 다음에 잇는다.

" ▼ 선언부에 추가
DATA gv_pdf TYPE xstring.
DATA gt_bin TYPE solix_tab.        " 바이너리 테이블(시스템 제공 타입)

" ▼ L02의 ④를 이 완전형으로 교체 — bin_file 한 줄이 늘었다
  CALL FUNCTION 'CONVERT_OTF'
    EXPORTING
      format                = 'PDF'
    IMPORTING
      bin_filesize          = gv_size
      bin_file              = gv_pdf   " PDF 전체를 한 덩어리 바이트로
    TABLES
      otf                   = gt_otf
      lines                 = gt_pdf
    EXCEPTIONS
      err_max_linewidth     = 1
      err_format            = 2
      err_conv_not_possible = 3
      err_bad_otf           = 4
      OTHERS                = 5.
  IF sy-subrc <> 0.
    MESSAGE 'PDF 변환에 실패했습니다' TYPE 'E'.
  ENDIF.

" ▼ 여기부터 이어 붙인다
  " ① 비어 있으면 저장 문제가 아니라 생성·변환(L02) 문제다
  IF xstrlen( gv_pdf ) = 0.
    MESSAGE 'PDF가 생성되지 않았습니다' TYPE 'E'.
  ENDIF.

  " ② xstring → 바이너리 테이블 (BCS 제공 변환 헬퍼)
  gt_bin = cl_bcs_convert=>xstring_to_solix( gv_pdf ).

  " ③ SAP GUI를 통해 사용자 PC에 바이너리로 저장
  cl_gui_frontend_services=>gui_download(
    EXPORTING
      filename     = 'C:\temp\ticket.pdf'
      filetype     = 'BIN'                " 텍스트('ASC')가 아니라 BIN!
      bin_filesize = xstrlen( gv_pdf )    " 바이트 길이(생략 금지)
    CHANGING
      data_tab     = gt_bin
    EXCEPTIONS
      OTHERS       = 1 ).
  IF sy-subrc <> 0.
    MESSAGE '파일 저장에 실패했습니다' TYPE 'E'.
  ENDIF.

처음 보는 부품 둘을 짚는다(둘 다 커리큘럼 첫 등장이다).

  • cl_bcs_convert=>xstring_to_solix( ) — 을 바이너리 테이블(solix_tab — 고정 길이 바이너리 행 구조의 이름)로 바꿔 주는 변환 헬퍼. BCS(Business Communication Services. 메일·문서 발송을 담당하는 SAP 표준 서비스)에 딸린 인데, 변환 헬퍼로 널리 쓰인다. 테이블로 바꾸는 이유는 단순하다: gui_download가 데이터를 한 덩어리가 아니라 테이블(행 단위)로 받는 API이기 때문이다. 손으로 자르지 말고 이걸 쓴다.
  • cl_gui_frontend_services=>gui_download( ) — SAP GUI 창을 통해 사용자 PC에 파일을 쓰는 클래스(공식: presentation server 접근). "사용자 PC"라는 말이 곧 한계다: 아래 경계 참조.

코드에서 세 가지를 더 짚는다.

  • 클래스 인데 EXCEPTIONS? — Chapter 21 · Exception Class에서 배운 클래스 는 TRY…CATCH였다. cl_gui_frontend_services는 오래된 GUI 표준 클래스라 함수 모듈식 옛 스타일 예외(EXCEPTIONS + sy-subrc)를 그대로 쓴다. 문법을 잘못 이해한 게 아니라 클래스가 옛 방식인 것이다.
  • bin_filesize가 왜 필수인가 — solix_tab의 행은 고정 길이 조각이라, 마지막 행에는 빈 자리(패딩)가 남는다. 정확한 바이트 길이를 따로 알려주지 않으면 그 패딩까지 파일에 기록된다. PDF는 뷰어가 눈감아 주고 열어 주는 경우도 있지만 원본과 바이트가 달라진 시점에 이미 실패이고(포맷에 따라 아예 못 연다), 그 판정 기준은 L05의 도전 과제에서 다시 쓴다. 값은 ④가 돌려준 gv_size와 같지만, 여기서 xstrlen( gv_pdf )로 다시 재는 것은 지금 저장하려는 실물의 길이를 재는 습관이다(실물과 크기가 어긋날 가능성 자체를 없앤다).
  • 저장했는데 파일이 없다? — 최신 SAP GUI는 보안 규칙상 로컬 파일 쓰기 전에 허용/거부 팝업을 띄우고, 거부되면 대개 예외로 드러난다(sy-subrc <> 0 → 우리 오류 메시지). 오류가 떴는데 코드가 맞다면 GUI 보안 설정부터 확인하라.

예제는 경로를 'C:\temp\ticket.pdf'로 박았는데, 이건 교육용 최소형이다. 그 폴더가 없으면 저장이 실패하니 먼저 만들어 두자. 실무에서는 같은 클래스의 파일 저장 대화상자(file_save_dialog)로 사용자가 위치를 고르게 하고, 배치에서도 도는 프로그램이라면 sy-batch(백그라운드 실행이면 'X'가 담기는 시스템 필드 — sy-subrc와 같은 sy- 가족)로 실행 환경을 갈라 GUI 다운로드 자체를 피한다(여기서는 존재만 알아 둔다). 저장이 끝났으면 탐색기에서 파일을 PDF 뷰어로 열어 보는 것까지가 확인이다. 열리지 않으면 이 레슨의 고장 카드('ASC' 저장·크기 오류)부터 의심하라.

위 두 클래스의 세부 시그니처(전체 ·예외)는 시스템 릴리스에 따라 다를 수 있어 ADT(F2)에서 확인한다. cl_bcs_convert는 구 릴리스에 없을 수도 있고(그때는 전통 변환 함수가 대신한다), ABAP Cloud에서는 released API가 아니라 둘 다 못 쓴다 — 경계 표의 Cloud 칸은 다운로드만이 아니라 이 변환 경로 전체에 해당한다. 여기서는 표준 사용형을 익힌다.

실행 위치의 경계 — 어디서는 되고 어디서는 안 되나

gui_download는 SAP GUI로 실행하는 대화(dialog) 상황 전용이다. 사용자의 PC가 있어야 쓰기 때문이다.

상황 PC 다운로드(gui_download) 대신 쓰는 것
SAP GUI에서 리포트 실행 ✅
배치(background) 작업 ❌ PC가 없다 서버 파일(Chapter 33)·스풀
자동 이메일 발송 ❌ BCS 메일 첨부(이름만 알아 둔다, 이 과정 범위 밖)
ABAP Cloud ❌ GUI 자체가 없다 released API 기반 출력 서비스(Chapter 24)

텍스트 모드로 저장하면 어떻게 되나 — 해부와 고장 카드

코드 부품을 클릭해 역할을 확인하고, 고장 카드 4장('ASC' 저장·크기 생략·빈 PDF·배치에서 gui_download)으로 무엇이 왜 깨지는지 판별해 보라.

흔한 실수와 점검 🚧

  • 텍스트 모드('ASC') 저장 → 문자 변환(code page)이 끼어들어 가 바뀐다. 원본과 달라진 시점에 이미 실패다. 반드시 BIN.
  • 크기를 strlen으로 재려는 습관 → strlen은 문자 전용이라 에는 아예 컴파일이 안 된다. 그렇다고 bin_filesize를 생략하거나 어림잡으면 마지막 행 패딩까지 기록돼 원본과 달라진다. 답은 하나, xstrlen.
  • 빈 PDF를 저장부터 의심 → xstrlen( ) = 0이면 다운로드 코드가 아니라 ① getotf 옵션을 켰는지(L02에서 미리보기 확인용으로 주석 처리했다면 되돌렸는지) ② CONVERT_OTF의 sy-subrc·bin_filesize(L02) ③ 양식 호출 순서로 본다. 생성 실패와 저장 실패를 섞지 말 것.
  • 배치·서버 처리에 gui_download → PC가 없는 곳에선 동작하지 않는다. 실행 위치의 경계 표를 기억하라.

정리 📌

  • PDF = 스트링(xstring). 길이는 xstrlen, 저장은 BIN, 테이블 변환은 xstring_to_solix.
  • 파이프라인 = bin_file() → (검사) → 바이너리 테이블 → gui_download.
  • gui_download는 SAP GUI 대화 전용. 배치는 서버 파일·스풀, Cloud는 released API.
  • 빈 PDF는 생성·변환(L02) 문제, 깨진 PDF는 저장 모드·크기 문제. 층을 나눠 의심한다.

만들고, 결정하고, 저장까지 했다. 마지막 관문은 운영이다. "확인서가 안 나와요" 티켓이 접수됐을 때, 어느 층에서 멈췄는지 좁혀 가는 법.
