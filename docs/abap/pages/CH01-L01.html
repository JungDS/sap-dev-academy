SAPGUI 로그온과 화면 구성

SAP 시스템에 접속해 개발을 시작할 환경을 연다.

Track 1Chapter 1Lesson 1입문

왜 여기서 시작하나

코드를 한 줄 쓰기도 전에, 우리는 먼저 SAP 시스템에 들어가야 한다. ABAP은 내 PC가 아니라 서버(애플리케이션 서버) 위에서 돌아가고, 그 서버에 접속하는 창구가 바로 다. 코드도, 데이터도, 실행도 전부 서버 쪽에 있다. 내 PC의 SAPGUI는 그 서버를 들여다보고 조작하는 창일 뿐이다. 이 레슨의 목표는 단 하나: 로그온해서 개발을 시작할 화면 앞에 앉는 것.

SAPGUI와 접속 구조

는 서버에 접속하는 내 PC용 프로그램이다. 이렇게 서버에 붙어서 화면을 보여 주는 프로그램을 흔히 "클라이언트"라고 부른다. 실행하면 "SAP Logon" 창이 뜨고, 접속할 시스템 목록이 보인다. 시스템 하나하나는 System ID(SID) 와 접속 정보로 구분한다.

  • Application Server — ABAP이 실제로 돌아가는 서버. 어느 서버에 붙을지 여기서 정한다.
  • Instance(인스턴스) — 그 서버 위에서 돌아가는 실행 단위 하나. 쓰는 사람이 많은 시스템은 인스턴스를 여러 개 두고 접속을 나눠 받는다.
  • System ID (SID) — 시스템을 구분하는 3글자 코드 (예: DEV, NPL)

접속 항목이 없다면 관리자나 교육용 시스템의 안내에 따라 새 항목을 등록한다.

로그온하기

접속 항목을 더블클릭하면 로그온 화면이 나온다. 네 가지를 입력한다.

  • Client — 같은 시스템 안의 독립된 작업 공간(3자리 숫자, 예: 100)
  • User — 사용자 ID
  • Password — 비밀번호 (최초 로그온 시 변경 요구될 수 있음)
  • Language — KO(한국어) 또는 EN(영어)

Client가 뭐죠? 한 시스템 안에 여러 개의 분리된 환경이 있다고 보면 된다. Client 100과 200은 업무 데이터가 서로 보이지 않는 별개의 방이다. 로그온할 때 어느 방에 들어갈지 고르는 것. 단, 갈라지는 건 거기까지다. 우리가 앞으로 만들 프로그램은 시스템 전체가 함께 쓰기 때문에, Client 100에서 만든 프로그램을 Client 200에서 그대로 실행할 수 있다.

⚠️ 같은 "클라이언트"라도 뜻이 다르다 — 앞에서 말한 클라이언트는 내 PC의 접속 프로그램()이고, 로그온 화면의 Client는 서버 안의 작업 공간 번호다. 앞으로 영어로 Client라고 적힌 건 언제나 뒤쪽 뜻이다.

✅ 지금 어디에 들어와 있지? — 로그온 뒤에는 화면 오른쪽 아래 상태 표시줄에서 현재 시스템(SID)·Client·사용자를 언제든 확인할 수 있다. 나중에 여러 시스템을 오가게 되면, 이 확인이 실수를 막는 습관이 된다.

SAP Easy Access — 첫 화면

로그온에 성공하면 메뉴가 나타난다. 여기서 두 가지만 기억하면 된다.

  1. 메뉴 트리 — 기능들이 폴더처럼 정리돼 있다. 하지만 우리는 이걸 잘 안 쓴다(느리다).
  2. 명령창(Command field) — 화면 왼쪽 위의 입력칸. 여기에 코드를 쳐서 어디든 바로 간다. 다음 레슨의 주인공이다.

흔한 실수와 점검

  • 로그온이 안 돼요 → Client 번호가 맞는지, Language가 지원되는지 확인.
  • 비밀번호 잠김 → 관리자에게 초기화 요청. 교육 시스템은 보통 안내 문서가 있다.
  • 화면이 영어로 떠요 → Language에 KO를 넣고 다시 로그온.

정리

  • ABAP은 내 PC가 아니라 서버에서 돌아간다. 는 그 서버를 들여다보는 창이다.
  • 로그온에는 Client · User · Password · Language 네 가지가 필요하다.
  • Client는 시스템 안의 작업 공간이다. 업무 데이터가 Client별로 갈리고, 프로그램은 함께 쓴다.
  • 로그온 뒤 첫 화면이 이고, 왼쪽 위 명령창이 앞으로의 주 통로다.

이제 시스템 안에 들어왔다. 그런데 원하는 화면(에디터)까지 메뉴를 일일이 뒤지자니 답답하다. "어디든 바로 가고 싶다." 그 열쇠가 다음 레슨의 다.
