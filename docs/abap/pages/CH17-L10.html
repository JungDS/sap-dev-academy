Grid ALV 기초

종합 실습 — 예매 목록 Grid ALV 완성

배운 조각을 책임별 FORM으로 나눠 하나의 화면으로 조립하고, 행 색상은 마무리 과제로 완성한다.

Track 1Chapter 17Lesson 10중급

조각을 하나의 화면으로

지금까지는 조각을 하나씩 배웠다: 자리·그리드·데이터·Field Catalog·Layout·Variant·display·refresh·색. 실무에선 조각이 아니라 하나의 화면이 필요하다. 사용자가 공연 번호를 입력하고, Module Pool 프로그램 구조의 화면 0100 안 CONT100 영역에서 예매 목록을 보고, 새로고침해도 화면이 안정적으로 유지되어야 한다.

골격은 컨테이너부터 refresh까지를 담는다. 행 색상 기초의 색은 출력 테이블 구조를 바꿔야 해서, 골격에는 자리만 잡아 두고 과제 1에서 직접 완성한다.

전체 골격 — 책임을 FORM으로 나눈다

긴 코드를 한 덩어리로 보면 어느 줄이 어떤 책임인지 놓친다. FORM으로 나누면 조립 순서가 FORM 이름에 드러난다. PBO에서 처음 한 번만 ALV를 만들고, 이후엔 [조회]로 데이터가 새로 담겼을 때만 refresh한다.

DATA: go_cont    TYPE REF TO cl_gui_custom_container,
      go_grid    TYPE REF TO cl_gui_alv_grid,
      gt_booking TYPE STANDARD TABLE OF zbooking,
      gt_fcat    TYPE lvc_t_fcat,
      gs_layout  TYPE lvc_s_layo,
      gs_variant TYPE disvariant,
      gv_conc    TYPE zbooking-concert_id,   " 화면 0100의 입력 필드와 같은 이름
      gv_refresh TYPE abap_bool,             " 재조회 직후인지 표시하는 깃발
      gv_error   TYPE abap_bool,             " 조립 실패 깃발 — build_alv 참고
      ok_code    TYPE sy-ucomm,              " OK field
      save_ok    TYPE sy-ucomm.

MODULE status_0100 OUTPUT.
  IF go_grid IS INITIAL.
    PERFORM build_alv.          " 처음 한 번 — 조립
  ELSEIF gv_refresh = abap_true.
    PERFORM refresh_alv.        " 재조회 직후에만 — 갱신
    CLEAR gv_refresh.
  ENDIF.
ENDMODULE.

MODULE user_command_0100 INPUT.
  save_ok = ok_code.
  CLEAR ok_code.
  CASE save_ok.
    WHEN 'SEL'.                 " [조회] — 새 공연번호로 재조회
      PERFORM select_booking.   " 데이터만 다시 담고
      gv_refresh = abap_true.   " 다음 PBO에서 refresh하도록 표시
    WHEN 'BACK'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.

FORM build_alv.
  CLEAR gv_error.
  PERFORM select_booking.     " 1. 데이터
  PERFORM create_grid.        " 2. 컨테이너 + 그리드
  PERFORM build_fieldcat.     " 3. 컬럼 설명서
  IF gv_error = abap_true.    " 컬럼 설명서가 없으면 여기서 조립 중단
    RETURN.
  ENDIF.
  PERFORM build_layout.       " 4. 표 모양 + variant
  PERFORM display_grid.       " 5. 처음 띄우기
ENDFORM.
  • gv_conc는 Module Pool에서 배운 대로 화면 필드와 이름이 같은 전역 변수다. 화면의 공연번호 입력값이 PAI 때 자동으로 이 변수에 들어온다.
  • 재조회 고리: [조회] 버튼(기능 코드 SEL)이 PAI에서 select_booking을 다시 부르고, 깃발(gv_refresh)을 세운다. 다음 PBO의 refresh_alv가 화면을 새 데이터에 맞춘다. Refresh와 Stable Refresh 기초의 "데이터 변경 → 화면 갱신" 고리가 여기서 닫힌다.
  • PBO는 엔터만 쳐도 매번 실행되므로, 깃발 없이 무조건 refresh하면 데이터가 안 바뀌어도 매번 표를 다시 그리는 낭비가 생긴다. 그래서 재조회 직후에만 refresh한다.
  • 실패 깃발(gv_error): USING / CHANGING 파라미터에서 배운 대로 RETURN은 지금 실행 중인 FORM 하나만 끝낸다. build_fieldcat 안에서 RETURN해도 호출자 build_alv는 다음 PERFORM을 그대로 이어 가므로, 실패를 깃발로 알려 호출자가 조립을 멈추게 한다. 안 그러면 빈 Field Catalog인 채로 display까지 가 버린다.

FORM select_booking.
  SELECT * FROM zbooking INTO TABLE gt_booking
    WHERE concert_id = gv_conc.
  IF sy-subrc <> 0.
    MESSAGE '해당 공연의 예매 데이터가 없습니다.' TYPE 'S'.   " 빈 결과는 정상일 수 있음
  ENDIF.
ENDFORM.

FORM create_grid.
  CREATE OBJECT go_cont EXPORTING container_name = 'CONT100'.
  CREATE OBJECT go_grid EXPORTING i_parent = go_cont.
ENDFORM.

FORM build_fieldcat.
  DATA ls_fcat TYPE lvc_s_fcat.
  CALL FUNCTION 'LVC_FIELDCATALOG_MERGE'
    EXPORTING i_structure_name = 'ZBOOKING'
    CHANGING  ct_fieldcat      = gt_fcat
    EXCEPTIONS OTHERS          = 1.
  IF sy-subrc <> 0.
    " PBO 경로라 'E' 대신 'S' + RETURN — 이유는 CH17-L07 참고
    MESSAGE 'Field Catalog를 생성하지 못했습니다.' TYPE 'S'.
    gv_error = abap_true.   " RETURN은 이 FORM만 끝낸다 — 호출자에게 깃발로 알림
    RETURN.
  ENDIF.
  LOOP AT gt_fcat INTO ls_fcat.
    IF ls_fcat-fieldname = 'SEATS'.
      ls_fcat-coltext = '좌석수'. ls_fcat-outputlen = 8.
      MODIFY gt_fcat FROM ls_fcat INDEX sy-tabix.
    ENDIF.
  ENDLOOP.
ENDFORM.

FORM build_layout.
  gs_layout-zebra      = abap_true.
  gs_layout-grid_title = '예매 목록'.
  gs_layout-cwidth_opt = abap_true.
  " 색의 자리: 과제 1에서 색 컬럼을 단 뒤 gs_layout-info_fname = 'ROWCOLOR'. 를 여기에
  gs_variant-report    = sy-repid.
ENDFORM.

FORM display_grid.
  go_grid->set_table_for_first_display(
    EXPORTING is_layout  = gs_layout
              is_variant = gs_variant
              i_save     = 'A'
    CHANGING  it_outtab       = gt_booking
              it_fieldcatalog = gt_fcat
    EXCEPTIONS OTHERS          = 1 ).
  IF sy-subrc <> 0.
    MESSAGE 'ALV Grid를 처음 표시하지 못했습니다.' TYPE 'S'.
    RETURN.
  ENDIF.
ENDFORM.

FORM refresh_alv.
  DATA ls_stable TYPE lvc_s_stbl.
  ls_stable-row = abap_true.
  ls_stable-col = abap_true.
  go_grid->refresh_table_display( EXPORTING is_stable = ls_stable
                                  EXCEPTIONS OTHERS   = 1 ).
ENDFORM.

개념 자가점검 (펼치기)
  • CONT100과 CL_GUI_CUSTOM_CONTAINER는 어떻게 다른가? go_cont는 그중 무엇인가?
  • 그리드(go_grid)만 만들면 왜 표가 안 보이나? 무엇이 더 필요한가?
  • Field Catalog와 출력용 Internal Table은 각각 무슨 역할인가?
  • Layout과 Variant는 무엇이 다른가?
  • set_table_for_first_display와 refresh_table_display는 언제 각각 쓰나?
  • Stable Refresh는 무엇을 지켜 주나?
  • 행 색상이 안 보일 때 점검할 네 가지는?
  • 셀 색상··편집 Grid는 왜 이 챕터가 아니라 뒤 챕터인가?

직접 해 볼 과제

  1. 취소 예매 행 색상 — 골격의 build_layout에 잡아 둔 색의 자리를 완성한다. 코드는 새로 짜지 말고 행 색상 기초의 색 흐름(색 코드 컬럼 → 색 판정 LOOP → info_fname)을 그대로 재사용하되, 조건은 간단하다: status가 'C'(취소)인 행에 색을 넣는다. 지금 골격의 gt_booking은 DDIC 구조(zbooking) 그대로라 색 컬럼을 더할 자리가 없으니, 색 코드 컬럼을 가진 로컬 행 타입으로 출력 테이블을 바꾸고 Field Catalog를 손본다(로컬 타입은 merge에 넣을 DDIC 이름이 없다 — 그 레슨의 "흔한 실수" 참고). 출력 구조를 갈아 끼우는 만큼 손이 가장 많이 가는 과제다. 더 가려면 그 레슨의 회차별 를 곁들여 매진 회차의 예매 행까지 다른 색으로 구분해 보자.
  2. 좌석수 합계 — Field Catalog의 SEATS에 do_sum = abap_true(Grid ALV Column 제어 심화 맛보기).
  3. 위치 보존 새로고침 — 데이터 변경 후 Refresh와 Stable Refresh 기초의 is_stable로 위치를 지킨다.

막히면 해당 조각 레슨으로 돌아가 확인한다. "어느 조각이 어디서 쓰이는지"를 손으로 맞춰 보는 게 이 실습의 목적이다.

흔한 실수와 점검

  • "처음 구성"과 "이후 갱신" 섞기 → set_table_for_first_display는 처음 한 번, refresh_table_display는 이후. 이 원칙을 화면 흐름에 고정한다.
  • Custom Control 이름 불일치 → 화면과 코드의 container_name이 같아야 한다.
  • merge 실패 무시 → LVC_FIELDCATALOG_MERGE가 실패했는데 확인 없이 display로 넘어가는 실수. sy-subrc 검사 후 FORM 안에서 RETURN만 하면 그 FORM만 끝나고 호출자는 계속 진행하니, gv_error 같은 깃발로 호출자까지 멈춰야 빈 카탈로그로 표를 그리지 않는다.
  • 0건을 오류로 → 조회 결과 없음은 정상 업무 상황일 수 있다.

정리

  • 이 챕터는 "표를 보여 주는 코드"가 아니라 "화면 안 표 컨트롤을 조립하는 코드" 다.
  • 컨테이너·그리드·데이터·Field Catalog·Layout·Variant·display·refresh가 각자 맡은 책임을 알아야, 이후의 표시 제어··편집 Grid를 흔들리지 않고 배운다.

조각을 하나로 완성했다. 그런데 이 classic 코드에서 값을 만들고 가공하는 대목이 길다. 화면 조립(컨테이너·Field Catalog)은 당분간 이 모습 그대로 두고, 값 만들기부터 더 짧고 현대적으로 쓰는 길로 → Inline Declaration.
