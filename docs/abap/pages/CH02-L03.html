Incomplete 타입(C·N·P)

길이(와 소수 자릿수)를 함께 지정해야 하는 타입.

Track 1Chapter 2Lesson 3입문

"길이를 정해야" 완성되는 타입

앞 레슨의 타입들은 길이를 신경 쓸 필요가 없었다. 이번엔 반대쪽 도구를 꺼낸다. 어떤 타입은 길이를 함께 지정해야 비로소 완전해진다. 이를 이라 한다. 대표는 C·N·P다.

C · N · P

타입 뜻 지정할 것
C 고정 길이 문자(character) 길이
N 숫자형 문자(numeric text) 길이
P 패킹 십진수(packed number) 길이 + 소수 자릿수

DATA: gv_code TYPE c LENGTH 4,            " 4글자 코드
      gv_zip  TYPE n LENGTH 5,            " 우편번호(숫자 문자)
      gv_amt  TYPE p LENGTH 8 DECIMALS 2. " 금액, 소수 2자리

gv_code = 'ABCD'.
gv_amt  = 7 / 2.    " 3.50 (정확)
WRITE: / gv_code, / gv_amt.
  • C LENGTH n — 딱 n글자. 모자라면 공백으로 채워진다.
  • N LENGTH n — 숫자처럼 보이지만 문자다(앞의 0이 보존됨, 예: 우편번호).
  • P LENGTH n DECIMALS d — 숫자 두 자리를 한 칸에 눌러 담는 방식이라 packed다. 금액·수량 등 정확한 소수 계산용이고, 정수부도 함께 담는다.

왜 N을 쓰나? 우편번호 01234를 정수 I에 넣으면 앞의 0이 사라져 1234가 된다. "숫자처럼 보이지만 계산하지 않는 값"은 N(또는 C)으로 둔다. 여기 예시는 숫자 5자리인 한국 우편번호 기준이다. 영문자가 섞이는 나라의 우편번호까지 담아야 하면 N이 아니라 C를 쓴다.

💡 P의 LENGTH는 "글자 수"가 아니라 칸() 수 — C·N은 LENGTH가 곧 글자 수지만, P는 칸(=1바이트) 수다. 결론만 먼저 외우면 된다. LENGTH 8이면 숫자 최대 15자리(소수 자릿수 포함)다. 금액은 P LENGTH 8 DECIMALS 2면 대부분 충분하다.

왜 하필 15자리인가 (더 보기)

문자는 한 칸에 1개 들어가지만, P는 한 칸을 둘로 쪼개 숫자 두 자리를 담는다. 그래서 8칸이면 16자리처럼 보인다. 단 마지막 칸의 한 자리는 숫자가 아니라 부호(+/−) 자리라 한 자리가 빠진다. 8 × 2 − 1 = 15자리가 되는 이유다.

💡 한 가지 전제 — P의 소수 계산이 정확하려면 프로그램 속성 중 고정소수점 연산(Fixed point arithmetic)이 켜져 있어야 한다. SE38로 새로 만든 프로그램은 기본으로 켜져 있으니 그대로 두면 되고, 남이 만든 옛 프로그램에서 소수가 이상하면 이 속성부터 확인한다.

일부만 떼어 보기 — offset/length

문자형(C·N) 변수는 일부 구간만 읽거나 쓸 수 있다. 변수+시작(길이) 형태이고, 시작 위치는 0부터 센다.

아래 예제는 자리를 세는 게 눈에 잘 보이라고 날짜 모양의 값을 일부러 문자(C)에 담았다. 실제로 날짜를 다룰 때는 앞 레슨에서 배운 D를 쓴다.

ABAP
1
2
3
4
5
DATA gv_date TYPE c LENGTH 8 VALUE '20260623'.

WRITE gv_date+0(4).    " 2026  (앞 4글자 = 연)
WRITE gv_date+4(2).    " 06    (5번째부터 2글자 = 월)
gv_date+6(2) = '01'.   " 끝 2글자(일)만 '01'로 교체 → '20260601'

날짜·코드처럼 자리마다 의미가 정해진 문자열에서 특정 부분만 다룰 때 유용하다.

🧑‍💻 다른 언어를 해 봤다면 두 가지가 다르다. 첫째, 괄호 안은 끝 위치가 아니라 길이다 (Java의 substring(시작, 끝)과 달리 C#의 Substring(start, length) 쪽에 가깝다). 둘째, 이 표기를 등호 왼쪽에도 쓸 수 있어 문자열의 일부를 그 자리에서 바꾼다. 위 예제의 마지막 줄이 그것이다. 문자열을 못 바꾸는(immutable) 언어에서 왔다면 낯선 지점이다.

칸으로 그려 보기

말보다 그림이 빠르다. LENGTH가 만드는 칸을 직접 보자. C의 빈칸 채움과 잘림, N의 앞 0, P의 칸(그리고 부호 반 칸)이 한눈에 보이고, offset이 어느 칸을 집는지도 눌러서 확인할 수 있다.

흔한 실수와 점검

  • 길이 누락 → DATA gv_x TYPE c.는 길이 1로 선언된다. LENGTH를 명시.
  • 금액에 F 사용 → 부동소수점은 오차가 난다. 이 과정에서 금액은 P … DECIMALS로 다룬다. (실무의 금액 필드는 "얼마"만으로 부족하고 통화마다 다른 소수 자릿수까지 함께 알아야 하는데, 그 이야기는 뒤 챕터에서 다시 만난다.)
  • N에 알파벳 대입 → 오류로 막히는 게 아니라 숫자만 남기고 조용히 바뀐다. 'A1B2'를 N LENGTH 5에 넣으면 00012가 된다. 오류보다 조용한 쪽이 더 위험하니, 알파벳이 섞이는 값은 처음부터 C에 담는다.
  • offset 범위 초과 → +시작(길이)가 변수 끝을 넘으면 오류다 (시작+길이 ≤ 전체 길이). 8글자 변수에 +7(2)는 한 글자 벗어난다.

정리

  • 은 길이를 함께 적어야 완성된다. C·N은 길이, P는 길이와 소수 자릿수를 준다.
  • C는 남는 자리를 공백으로 채우고, N은 앞의 0을 보존한다(계산하지 않는 숫자 모양 값에 쓴다).
  • P의 LENGTH는 글자 수가 아니라 칸 수다. LENGTH 8이면 숫자 15자리까지.
  • 정확한 금액·수량은 P … DECIMALS로 다룬다. F는 근삿값이라 쓰지 않는다.
  • 변수+시작(길이)로 문자열의 일부만 읽고 쓸 수 있다. 시작은 0부터 세고, 범위를 넘으면 오류다.

자주 쓰는 표준 타입은 다 봤다. 그런데 TYPE p LENGTH 8 DECIMALS 2를 변수마다 또 적자니 번거롭다. "한 번 정의해 재사용하고 싶다." 그게 다 → 다음 레슨.
