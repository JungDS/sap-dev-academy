🪜 판단은 끝났다, 수단이 남았다

Chapter 35 · 대량 데이터 처리와 Package 설계에서 결론을 하나 얻었다. "ABAP으로 100만 행을 끌어와 합산하지 말고, DB에서 해 결과만 받아라." 그 판단 기준(데이터 이동량·ST05의 records)은 이미 손에 있다.

그런데 실무에서 바로 다음 질문이 나온다. "그래서, 뭘로 내리는데?" SQL 한 문장으로 될 때도 있고, 여러 프로그램이 같은 계산을 공유해야 할 때도 있고, DB 안에서 여러 단계의 절차(집계한 결과를 다시 나누고 조합하는 식)가 필요할 때도 있다. 이 챕터는 그 수단들을 하나씩 배우고, 마지막에 고르는 눈을 만든다.

이 방향을 (연산을 데이터가 있는 DB 쪽으로 내려보내는 설계 원칙)이라 부른다. 반대로 데이터를 ABAP 서버로 끌어와 처리하는 전통 방식은 Data-to-Code라 한다.

사다리 — 내려갈수록 보호가 줄고 책임이 는다

푸시다운 수단은 사다리처럼 늘어서 있다. 흔한 오해와 달리 아래(DB 가까이)로 갈수록 "고급·고속"이 아니다. 위쪽은 ABAP 플랫폼이 문법 검사·client 처리·권한 같은 보호를 많이 해 주고, 아래로 내려갈수록 그 보호가 개발자의 책임으로 바뀐다.

순서 수단 어울리는 일 플랫폼 보호 개발자 책임
1 Modern Open SQL (Chapter 19) ··필터·SQL 식 높음 SQL 설계·측정
2 CDS View (Chapter 23) 여러 소비자가 공유하는 모델 높음 뷰 계층·권한(DCL)·활성화 관리
3 AMDP (이 챕터) DB 안의 여러 단계 절차 로직 중간 — 활성화·의존성은 시스템이 관리 SQLScript(HANA의 프로시저 언어 — 다음 레슨)·client·테스트
4 ADBC / Native SQL (이 챕터) DB 고유 SQL이 불가피할 때 낮음 client·보안·이식성 전부

💡 이 챕터 후반에 하나가 더 나온다. CDS에서 DB 함수 결과를 뷰처럼 읽게 해 주는 CDS Table Function이다. 몸은 AMDP(책임은 3번 수준), 소비는 CDS 세계(2번 수준)에 걸친 다리인데, 지금은 이름만 알아 두면 된다.

네 가지 질문으로 고른다

  1. SQL 한 문장으로 되는가 — WHERE·JOIN·GROUP BY··SQL 식으로 표현되면 Modern Open SQL이 1순위다. 가장 단순하고, 문법 검사와 이식성이 좋다.
  2. 여러 곳이 같은 계산을 쓰는가 — 같은 ·계산이 리포트·OData·배치에서 반복되면 CDS View로 올린다. CDS는 SQL 복사본이 아니라 재사용되는 의미 모델이다.
  3. DB 안에서 절차가 필요한가 — 중간 결과를 여러 번 만들고 다시 조합하는 로직이 DB 안에서 꼭 필요할 때만 AMDP 후보가 된다.
  4. DB 고유 기능이 불가피한가 — 위 셋으로 표현할 수 없는 DB 전용 SQL만 ADBC 후보다. "기술적으로 가능"과 "운영에 배포해도 됨"은 별개다.

근거는 언제나 측정이다. ST05에서 DB가 읽은 행 수와 업무가 실제 쓰는 행 수(결과 내부 테이블의 lines( ))를 비교하라. 결과는 50행인데 100만 행이 ABAP으로 넘어오고 있다면 푸시다운 후보다.

끌어오기와 내려보내기의 전송량 차이를 본 다음, 상황 카드에서 알맞은 수단을 골라 보라.

흔한 실수와 점검 🚧

  • 성능 얘기만 나오면 AMDP부터 → 대부분 Open SQL/CDS로 충분하다. 단순 를 AMDP로 감싸면 복잡도만 는다.
  • "전부 DB로"라는 오해 → 검증·권한·메시지·재처리 로그· 경계 같은 업무 통제는 ABAP 계층에 남긴다.
  • 측정 없이 전환 → 전환 전후의 records·전송 행 수·시간을 기록해야 개선이라 말할 수 있다(Chapter 35 · 측정 루프).
  • "DB로 내리면 "라는 오해 → Clean Core는 released API와 업그레이드 안정성 이야기다. DB 종속 코드는 오히려 더 엄격한 근거가 필요하다(Chapter 24 · ABAP Cloud와 Released API 원칙).

정리 📌

  • = 데이터를 끌어오는 대신 연산을 내려보내 이동량을 줄이는 원칙.
  • 수단은 사다리다: Open SQL → CDS → AMDP → ADBC. 아래로 갈수록 보호가 줄고 책임이 는다. 항상 위에서부터 검토한다.
  • 선택 근거 = 네 가지 질문 + ST05 수치. 이름이 아니라 이동량이 성능을 만든다.

사다리의 3번째 칸부터 이 챕터의 새 내용이다. ABAP 안에 DB 프로시저를 담는 AMDP로 간다.
