FIND PCRE 결과 검증 — MATCH COUNT·OFFSET·LENGTH·RESULTS

"찾았다"에서 멈추지 않고 몇 개·어디서·얼마나를 검증한다.

Track 2Chapter 29Lesson 3중급

🧾 "찾았다"만으로는 부족하다

운영 로그 한 줄을 받았다.

TEXT
1
E100: booking failed, W210: retry scheduled, E404: concert missing

정훈영의 질문은 sy-subrc로 답할 수 없는 것들이다.

  • 오류 코드(E***)가 몇 개인가?
  • 첫 오류는 몇 번째 글자에서 시작하나?
  • 모든 오류의 위치를 표로 볼 수 있나?

FIND에는 이 질문에 답하는 결과 옵션들이 있다.

옵션 알려 주는 것
MATCH COUNT 발견 개수
MATCH OFFSET 발견 시작 위치(0부터)
MATCH LENGTH 발견 길이
RESULTS 발견마다 offset·length를 담은 구조/테이블

⚠️ 한 가지 미리: MATCH OFFSET/LENGTH와 RESULTS는 같은 FIND 문장에서 함께 쓸 수 없다(택일). 낱값 몇 개면 전자, 표가 필요하면 후자다.

그리고 옛 기억 하나를 지우자. 예전 SEARCH 명령(지금은 obsolete)이 채우던 sy-fdpos는 FIND가 채우지 않는다. 위치는 반드시 MATCH OFFSET으로 받는다.

개수 세기 — ALL OCCURRENCES + MATCH COUNT

기본 FIND는 첫 발견에서 멈춘다. 전부 세려면 ALL OCCURRENCES OF를 붙인다.

DATA(gv_log) =
  `E100: booking failed, W210: retry scheduled, E404: concert missing`.

FIND ALL OCCURRENCES OF PCRE `E\d{3}`
     IN gv_log
     MATCH COUNT DATA(gv_error_count).

WRITE / |오류 코드 개수: { gv_error_count }|.    " 2

FIND FIRST OCCURRENCE OF PCRE `E\d{3}`
     IN gv_log
     MATCH OFFSET DATA(gv_offset)
     MATCH LENGTH DATA(gv_length).

IF sy-subrc = 0.
  DATA(gv_code) = substring( val = gv_log
                             off = gv_offset
                             len = gv_length ).
  WRITE / |첫 오류 코드: { gv_code }|.           " E100
ENDIF.

지난 레슨의 습관 그대로, offset/length로 원문을 다시 잘라 눈으로 확인한다.

🚨 ALL OCCURRENCES와 MATCH OFFSET을 같이 쓰면? 동작은 하지만 offset에는 마지막 발견의 위치가 남는다(공식 규칙). "전부 다 어디에 있나"가 궁금하면 다음의 RESULTS가 정답이다.

전체 발견을 표로 — RESULTS

FIND ALL OCCURRENCES OF PCRE `E\d{3}|W\d{3}`
     IN gv_log
     RESULTS DATA(gt_match).

LOOP AT gt_match INTO DATA(gs_match).
  DATA(gv_token) = substring( val = gv_log
                              off = gs_match-offset
                              len = gs_match-length ).
  WRITE: / gs_match-offset, gs_match-length, gv_token.
ENDLOOP.

RESULTS DATA(gt_match)처럼 ALL OCCURRENCES와 함께 인라인 선언하면 발견마다 한 줄씩 쌓이는 테이블(MATCH_RESULT_TAB 타입)이 된다. 각 줄에는 offset·length, 그리고 submatches라는 필드도 보이는데 이건 다음 레슨의 재료다.

offset length 잘라낸 값
0 4 E100
22 4 W210
45 4 E404

같은 로그에 옵션을 바꿔 가며 실행해 보라. ALL + OFFSET일 때 offset이 어느 발견을 가리키는지 특히 확인.

흔한 실수와 점검 🚧

  • 실패했는데 offset을 읽음 — 검색 실패 시 MATCH OFFSET/LENGTH 변수는 이전 값이 그대로 남거나 초기값이다. 반드시 sy-subrc 확인 후 사용.
  • ALL + OFFSET 착각 — 위에서 봤듯 마지막 발견 기준이다. 모든 위치 = RESULTS.
  • OFFSET/LENGTH와 RESULTS 동시 지정 — 같은 문장에서 택일이다(문법 오류).
  • RESULTS 초기화 규칙 — 테이블로 받으면 검색 전에 비워진다. 단, 실패 시 테이블은 빈 채로, (구조로 받았다면) 구조는 이전 값이 보존된다는 비대칭이 있다.
  • sy-fdpos 참조 — FIND는 채우지 않는다. 옛 코드 리딩에서만 만나는 유물이다.
  • 대소문자 무시 검색은 IGNORING CASE를 명시한다(기본은 RESPECTING CASE).

정리 📌

  • FIND PCRE는 "찾았나"만 묻는 도구가 아니다: 몇 개(MATCH COUNT), 어디서/얼마나(MATCH OFFSET/LENGTH), 전부 표로(RESULTS).
  • MATCH OFFSET/LENGTH ↔ RESULTS는 한 문장에서 택일.
  • ALL OCCURRENCES + OFFSET = 마지막 발견. 전체 위치는 RESULTS.
  • 위치·길이로 원문을 다시 잘라 확인하는 습관이 패턴 실수를 가장 빨리 잡는다.

오류 코드의 위치는 알았다. 그런데 로그에서 정말 꺼내고 싶은 건 접수번호 안의 연도, 사용자 이름 같은 매치의 일부다. 괄호 그룹의 값을 변수로 받는 SUBMATCHES로 간다.
