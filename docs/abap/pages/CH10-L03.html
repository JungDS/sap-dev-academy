프로그램을 넘어 재사용

은 한 프로그램 안에 갇힌다. 여러 프로그램이 공유하는 재사용 블록이 (함수 모듈)이다. SE37에서 만들고 관리한다.

DATA gv_out TYPE p LENGTH 8 DECIMALS 2.

CALL FUNCTION 'Z_ADD_TAX'
  EXPORTING
    iv_amount = 1000          " 넘겨줄 값
  IMPORTING
    ev_result = gv_out        " 돌려받을 값
  EXCEPTIONS
    invalid   = 1
    OTHERS    = 2.

IF sy-subrc <> 0.
  WRITE: / '함수 호출 실패 — sy-subrc =', sy-subrc.
ENDIF.
  • EXPORTING — 함수에 넘기는 값(호출자 입장).
  • IMPORTING — 함수에서 돌려받는 값.
  • CHANGING — 넘겼다가 수정되어 돌아오는 값(입출력).
  • TABLES — 전달(레거시 방식).
  • EXCEPTIONS — 오류를 sy-subrc로 받는다(바로 아래에서 자세히).

방향이 헷갈린다: 호출문의 EXPORTING/IMPORTING은 호출자 기준이다. 내가 함수로 EXPORT(내보냄) → 함수가 받음. 반대로 SE37에서 함수 자신을 정의하는 화면은 함수 기준이라 이름이 뒤집혀 보인다. 내가 EXPORTING으로 넘긴 값이 정의 화면에서는 Import 탭에 들어 있다. 한쪽이 내보내면 다른 쪽이 받는 것이니 뒤집히는 게 정상이다.

오류를 번호로 받기 — EXCEPTIONS

EXCEPTIONS 절은 함수가 알려 오는 오류 이름에 번호를 붙이는 곳이다. invalid = 1은 "invalid 오류가 나면 sy-subrc를 1로 채워 달라"는 뜻이고, OTHERS = 2는 "여기 적지 않은 나머지 오류는 전부 2로"라는 뜻이다. 번호는 우리가 정한다.

  • 안 적으면 프로그램이 죽는다 — 함수가 일으킨 오류를 EXCEPTIONS에 하나도 적지 않으면 sy-subrc로 오지 않고 그 자리에서 런타임 오류(덤프)로 멈춘다.
  • 적어 놓고 안 보면 소용없다 — 이 방식은 오류를 번호로 돌려주기만 한다. 저절로 위로 전달되지 않으니 호출 바로 다음 줄에서 sy-subrc를 확인해야 한다.
  • OTHERS를 마지막에 하나 두면 예상 못 한 오류까지 걸러진다.

어디서 찾나

직접 만들지 않아도 되는 표준 함수가 이미 많다. SE37 첫 화면에서 이름이나 설명으로 검색하면 되고, 찾은 함수를 열면 어떤 값을 주고받는지(Import·Export·Exceptions 탭) 바로 볼 수 있다. 그중 업무 처리의 표준 창구로 SAP이 제공하는 것을 (Business Application Programming Interface)라 부르고, 다른 시스템이 원격으로 부를 수 있게 만든 것을 (Remote Function Call, 원격 함수 호출)라 한다. 둘 다 Chapter 33 · 인터페이스 실무에서 본격적으로 다룬다.

직접 해 보기

정상/음수 금액을 호출해 sy-subrc가 어떻게 바뀌는지, EXPORTING·IMPORTING을 호출자 기준으로 읽는다는 게 무슨 뜻인지 확인해 보자.

흔한 실수와 점검

  • EXPORTING/IMPORTING 방향 혼동 → 호출자 기준으로 생각.
  • EXCEPTIONS 무시 → sy-subrc 확인 누락은 단골 버그.

은 절차적 재사용의 표준이었다. 그런데 현대 ABAP의 중심은 클래스다 — 가볍게 맛보자 → Local Class(다음 레슨).
