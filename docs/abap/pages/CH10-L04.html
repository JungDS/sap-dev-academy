Subroutine 말고, 클래스라는 묶음

지금까지 코드를 ·로 묶었다. 또 하나의 묶음 도구가 (클래스)와 (메서드)다. 여기선 맛보기만 — 그것도 객체를 안 만들어도 되는 정적(static) 메서드부터.

💡 왜 맛보기인가 — 클래스를 제대로 설계하려면 아직 배우지 않은 것이 많다. 그래서 이 챕터의 예제는 Subroutine/Function Module 중심이고, 클래스는 "이렇게 만들고 이렇게 부른다"까지만 본다. 학습 순서 때문에 미루는 것이지, 실무에서 클래스가 특수한 도구라는 뜻이 아니다 — 새로 만드는 코드의 기본은 클래스다(정리는 Subroutine / Function Module / Class 선택 기준). 본격적인 설계는 Chapter 21 · OO 기초에서 배운다.

클래스의 두 부분 — DEFINITION / IMPLEMENTATION

는 "무엇이 있는지"(DEFINITION)와 "실제 코드"(IMPLEMENTATION) 둘로 나뉜다. 공개할 것은 PUBLIC SECTION, 감출 것은 PRIVATE SECTION에 둔다.

CLASS lcl_calc DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS add_tax
      IMPORTING iv_amount        TYPE p
      RETURNING VALUE(rv_result) TYPE p LENGTH 8 DECIMALS 2.
ENDCLASS.

CLASS lcl_calc IMPLEMENTATION.
  METHOD add_tax.
    rv_result = iv_amount * '1.1'.
  ENDMETHOD.
ENDCLASS.
  • CLASS-METHODS — 정적 메서드(객체 없이 클래스로 직접 부르는 메서드).
  • IMPORTING(받는 값)·RETURNING(돌려줄 값 하나)으로 를 선언한다.
  • RETURNING에 적은 rv_result가 곧 돌려줄 값의 자리다. 메서드 안에서 여기에 값을 대입하면 그게 반환이고, "돌려줘라"라는 문장을 따로 쓰지 않는다.
  • VALUE( )는 RETURNING에 항상 붙는다. USING / CHANGING 파라미터의 value(...)는 골라 쓰는 선택지였지만, 여기서는 빠뜨릴 수 없는 표기다.
  • rv_는 return value(돌려주는 값)를 뜻하는 접두어다.

RETURNING의 타입은 TYPE p처럼 뭉뚱그리면 안 되고 길이·소수 자릿수까지 적어야 한다(TYPE p LENGTH 8 DECIMALS 2). 받는 쪽(IMPORTING)은 넘겨주는 변수를 따라가면 되지만, 돌려주는 값은 메서드가 직접 만들어 내보내므로 크기가 정해져 있어야 하기 때문이다.

이름이 비슷한 USING / CHANGING 파라미터의 STATICS와는 다른 개념이다. STATICS는 호출이 끝나도 값이 남는 변수, 여기의 정적(static) 메서드는 객체 없이 부를 수 있는 메서드다.

정적 메서드 호출 — =>

정적 메서드는 객체를 만들 필요 없이 "클래스이름=>메서드"로 부른다.

START-OF-SELECTION.
  DATA: gv_amount TYPE p LENGTH 8 DECIMALS 2,
        gv_out    TYPE p LENGTH 8 DECIMALS 2.

  gv_amount = 1000.
  gv_out = lcl_calc=>add_tax( gv_amount ).   " 객체 생성 불필요
  WRITE gv_out.

클래스 정의(DEFINITION·IMPLEMENTATION)는 프로그램 위쪽에 먼저 두고, 부르는 실행문은 그 아래 START-OF-SELECTION에 둔다. FORM / PERFORM 기본 호출에서 본 표지판이 여기서도 실행 시작점을 가른다. FORM을 프로그램 맨 아래에 모으던 것과 반대인데, 클래스는 쓰기 전에 이미 정의돼 있어야 하기 때문이다.

설계도와 객체 (개념만)

는 "설계도"이고, 그 설계도로 찍어낸 실체가 **객체(Object)**다(쿠키틀과 쿠키). 객체를 만들어 "객체->메서드"로 부르는 인스턴스 메서드도 있지만, 객체 생성과 참조 변수는 본격 OO 단계에서 다룬다. 지금은 정적 메서드(=>)면 충분하다.

직접 해 보기

DEFINITION(계약)·IMPLEMENTATION(본문)·정적 호출(=>)을 색으로 구분해 보고, PUBLIC·RETURNING을 빼면 어떤 오류가 나는지 실험해 보자.

흔한 실수와 점검

  • DEFINITION만, IMPLEMENTATION 없음 → 메서드 본문이 없어 오류.
  • 정적인데 객체 만들기 → CLASS-METHODS는 객체 없이 =>로 부른다.
  • => vs -> → 정적은 =>(클래스로 직접), 인스턴스는 ->(객체로).
