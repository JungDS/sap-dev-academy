SELECT 형태 — SINGLE · INTO TABLE · UP TO n ROWS

한 건만, 여러 건, 줄여 읽기 — 결과 형태에 맞는 SELECT.

Track 1Chapter 8Lesson 3초급

결과가 한 건? 여러 건?

읽는 결과의 모양에 따라 SELECT 형태가 달라진다. 앞 레슨에서 정리한 네 가지 중 INTO를 무엇으로 두느냐의 문제다.

이번 레슨부터는 예제에 WHERE가 붙는다. WHERE의 연산자와 조합은 Chapter 08 · WHERE 상세에서 제대로 다루니, 여기서는 "= 로 값을 지정해 그 행만 고른다" 정도로만 읽고 넘어가면 된다.

SELECT SINGLE — 키로 딱 한 건

특정 한 행이 필요하면 . 결과는 하나(INTO gs_)에 담긴다. Work Area는 Chapter 06 · Internal Table 기초에서 쓰던 "한 행짜리 그릇"과 같다.

DATA gs_flight TYPE sflight.   " 한 행을 담을 Work Area

SELECT SINGLE * FROM sflight
  INTO gs_flight
  WHERE carrid = 'KE' AND connid = '0701' AND fldate = '20260623'.

IF sy-subrc = 0.
  WRITE: / gs_flight-seatsocc, '/', gs_flight-seatsmax.
ENDIF.
  • 키 전체로 조회하면 결과는 많아야 한 행이다. 같은 키를 가진 행이 둘일 수 없기 때문이다. 다만 "반드시 한 행이 나온다"는 뜻은 아니다. 그런 키를 가진 행이 아예 없으면 0건이니, 위 예제처럼 sy-subrc부터 확인하고 값을 쓴다.

💡 따옴표가 붙은 값과 안 붙은 값. connid = '0701'·fldate = '20260623'을 따옴표로 감싼 이유는 이 컬럼들이 숫자처럼 보여도 문자 계열이기 때문이다. 날짜(DATS)는 YYYYMMDD 8자리 문자이고, 노선 번호(NUMC)는 숫자만 담되 자리수가 고정된 문자다. 따옴표를 빼고 connid = 701이라 쓰면 앞의 0이 사라져 찾지 못한다. 반대로 진짜 정수 컬럼은 따옴표 없이 dan = 5처럼 적는다.

INTO TABLE — 여러 건 한 번에

여러 행은 앞 레슨에서 이미 쓴 INTO TABLE로 그대로 담는다(= ).

ABAP
1
2
3
4
DATA gt_flight TYPE TABLE OF sflight.

SELECT * FROM sflight INTO TABLE gt_flight
  WHERE carrid = 'KE'.

SELECT … ENDSELECT — 한 행씩 (지양)

담을 곳을 INTO gs_(한 행짜리 그릇)로 두고 SINGLE을 붙이지 않으면, 조건에 맞는 행을 한 행씩 넘겨받는 SELECT…ENDSELECT 루프가 된다. 같은 INTO gs_라도 SINGLE이 있으면 한 건으로 끝나고, 없으면 루프가 된다는 것이 갈림길이다.

ABAP
1
2
3
4
SELECT * FROM sflight INTO gs_flight
  WHERE carrid = 'KE'.
  WRITE: / gs_flight-fldate.
ENDSELECT.

⚠️ SELECT…ENDSELECT는 DB와의 연결을 오래 붙들고 있는 방식이다. 행마다 DB를 한 번씩 왕복하는 건 아니고 여러 행을 한 묶음씩 미리 받아 두지만, 루프가 끝날 때까지 읽던 자리를 잡고 있어야 한다. 가능하면 INTO TABLE로 한 번에 받아 놓고 LOOP로 처리하는 편이 낫다.

⚠️ 루프 안의 SELECT는 특히 조심한다. 바깥 SELECT가 도는 동안 그 안에서 또 SELECT를 부르는 모양이다. 바깥이 100행이면 조회가 1 + 100 = 101번 일어난다.

SELECT 노선 100건 → 한 행마다 → SELECT 그 노선의 운항편 … 100번 반복

이렇게 조회 수가 불어나는 모양을 N+1 문제라 부른다. 해결책은 두 테이블을 한 문장으로 합쳐 읽는 것이고, 그게 Chapter 13 · INNER JOIN이다. 지금은 "루프 안에 SELECT가 보이면 의심한다"만 챙겨 두자.

UP TO n ROWS — 줄여 읽기

전부는 필요 없고 몇 건만 보고 싶을 때 행 수를 제한한다.

ABAP
1
SELECT * FROM sflight INTO TABLE gt_flight UP TO 10 ROWS.

주의할 점이 하나 있다. 여기서 오는 10건은 "처음 10건"이 아니라 아무 10건이다. DB 테이블에는 정해진 순서라는 게 없어서, 정렬을 지정하지 않으면 어느 10건이 올지 보장되지 않는다. 같은 문장을 두 번 실행하면 다른 10건이 올 수도 있다. 순서가 중요하면 정렬을 함께 지정해야 하고, 그 방법은 Chapter 13 · ORDER BY 정렬 조회에서 배운다.

아래 실험실에서 같은 데이터를 네 형태로 바꿔 보며 담기는 모양·행 수·반복 횟수를 비교해 보자.

흔한 실수와 점검

  • 부분 키로 SINGLE → 조건에 맞는 행이 여럿이면 그중 아무 한 행이 온다. 의도한 단건은 키 전체로.
  • SINGLE에 UP TO 같이 쓰기 → SINGLE은 이미 한 건이다. UP TO와 함께 쓰지 않는다. 몇 건만 = UP TO(TABLE), 의도한 단건 = SINGLE.
  • ENDSELECT 남용 → 대량은 INTO TABLE. 루프 안의 SELECT는 특히 의심한다.
  • sy-subrc 미확인 → SINGLE도 없음(4)일 수 있다.

형태는 골랐다. 그런데 결과를 어디에 어떻게 담을지(INTO 대상)도 여러 가지다 → 다음 레슨.
