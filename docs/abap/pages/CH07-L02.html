Transparent Table (SE11)

Create Entries로 구구단 입력 · 데이터 조회

만든 테이블에 손으로 데이터를 넣고(SE11 Create Entries) 확인한다.

Track 1Chapter 7Lesson 2초급

빈 테이블 채우기

ZGUGUDAN을 만들었으니 값을 넣어야 조회도 의미가 있다. 학습 단계에선 SE11의 Create Entries로 한 건씩 손으로 입력한다.

SE11 Create Entries — 한 건씩 손입력

SE11 → ZGUGUDAN 표시 → 메뉴 Utilities → Table Contents → Create Entries. 입력 화면이 뜨면 DAN·MUL·RESULT를 채우고 저장한다.

먼저 2단 9행을 넣어 보자. 2×1부터 2×9까지다.

TEXT
1
2
3
4
5
DAN  MUL  RESULT
 2    1     2
 2    2     4
 ...
 2    9    18

여유가 있으면 3단 9행을 더 넣어 총 18행으로 만들어도 좋다. 9행까지만 넣어도 이번 레슨에서 겪어야 할 것은 다 겪는다. 입력 절차, 키 중복, 클라이언트 분리 셋이다.

⚠️ Create Entries로 테이블에 값을 직접 꽂는 건 개발·교육 시스템에서만 하는 일이다. 실제로 돌아가는 업무 시스템에서 이렇게 넣는 것은 금지이고 감사 대상이다. 업무 데이터를 정식으로 넣는 수단은 따로 있고, 뒤 챕터에서 배운다.

😵 아홉 줄을 손으로 넣는 것만 해도 슬슬 지친다. Chapter 06 · 구구단 캡스톤에서는 같은 구구단을 프로그램으로 72행이나 순식간에 만들었다. 손입력은 학습·소량 확인용이고 대량은 프로그램이라는 감을 잡아 두자. 프로그램에서 DB에 값을 직접 넣는 법은 Chapter 25 · 프로그램으로 DB에 값 넣기에서 배우니 지금 외울 필요는 없다.

넣은 값 다시 보기 — Table Contents

SE11 → ZGUGUDAN → Utilities → Table Contents → Display로 방금 넣은 행을 조회한다. 조건을 주면 해당 행만 나온다.

키 중복은 안 된다

키가 같은 행을 두 번 넣을 수 없다. MANDT + DAN + MUL이 키라면 DAN과 MUL이 같은 조합은 하나뿐이다. 2×3을 이미 넣어 두고 또 넣으려 하면 두 번째가 거부된다.

흔한 실수와 점검

  • Create Entries가 안 열림 → Chapter 07 · Transparent Table 생성에서 정한 **Data Browser/Table View Maint.**가 Display/Maintenance Allowed인지 먼저 확인한다. 입력 권한은 교육 시스템 안내를 따른다. 활성화된 테이블이라야 입력된다.
  • 클라이언트 혼동 → 다른 Client에서 넣은 데이터는 안 보인다( 분리).
  • 키 중복 → 같은 키 조합 재입력은 거부된다.
  • DB가 값까지 맞춰 줄 거란 착각 → 키는 중복만 막는다. 2×2인데 RESULT=5처럼 계산이 틀린 값도 손입력으로는 들어간다. 값이 업무적으로 맞는지는 별도 검증의 몫이다.

이제 넣은 값이 디스크에 영구히 남았다. 그런데 "구구단 한 줄"이라는 같은 모양을 우리는 여러 자리에서 써 왔다. Chapter 06 · 구구단 캡스톤의 Work Area(한 줄을 담는 변수)와 Internal Table, Chapter 06 · 타입의 자산화의 Table Type, 그리고 방금 만든 Transparent Table까지 넷이다. 넷은 어떻게 다를까? 정리하고 가자 → 다음 레슨.
