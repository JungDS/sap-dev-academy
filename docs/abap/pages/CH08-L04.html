같은 SELECT, 다른 담는 그릇

읽은 결과를 담는 그릇은 여러 가지다. 앞 레슨까지 그중 둘을 이미 썼다.

ABAP
1
2
3
4

8
DATA gs_flight TYPE sflight.            " 한 행짜리 Work Area
DATA gt_flight TYPE TABLE OF sflight.   " 여러 행짜리 Internal Table

" 복습 — 한 건은 Work Area로
SELECT SINGLE * FROM sflight
  INTO gs_flight
  WHERE carrid = 'KE' AND connid = '0701'
    AND fldate = '20260623'.

이번 레슨은 여기서 갈라지는 세 가지를 더 본다. 값 몇 개만 변수로 받기, 이름을 맞춰 담기, 그리고 지우지 않고 이어 붙이기다.

INTO (v1, v2) — 값을 변수로 직접 받기

행 전체가 아니라 값 두어 개만 필요할 때가 있다. 이때는 읽을 DB 필드를 순서대로 적고, 받을 ABAP 변수를 괄호 안에 같은 순서로 적는다. 개수와 순서가 1:1로 맞아야 하며 이름은 달라도 된다.

ABAP
1
2
3
4

7
DATA: gv_occ TYPE sflight-seatsocc,
      gv_max TYPE sflight-seatsmax.

SELECT SINGLE seatsocc seatsmax FROM sflight
  INTO (gv_occ, gv_max)
  WHERE carrid = 'KE' AND connid = '0701'
    AND fldate = '20260623'.

CORRESPONDING FIELDS OF — 이름 맞춰 담기

읽은 필드와 받는 쪽의 같은 이름 필드끼리 자동으로 맞춰 담는다. 순서가 달라도 이름만 같으면 제자리를 찾아간다. Chapter 08 · SELECT 4요소에서 컬럼을 골라 읽을 때 미리 한 번 써 본 그 표현이고, 여기서 정식으로 뜯어본다.

ABAP
1
2
3
SELECT carrid connid fldate FROM sflight
  INTO CORRESPONDING FIELDS OF TABLE gt_flight
  WHERE carrid = 'KE'.

⚠️ Work Area 하나로 받을 때는 짝이 없는 필드가 지워지지 않고 남는다. INTO CORRESPONDING FIELDS OF gs_처럼 한 행짜리 그릇에 담는 형태가 그렇다. 이름이 맞은 필드만 새 값으로 바뀌고, 짝이 없는 나머지 필드에는 직전에 들어 있던 값이 그대로 남는다. 옛 값과 새 값이 한 그릇에 섞여 조용한 버그가 된다. 새로 담기 전에 CLEAR gs_flight.로 비우는 습관이 안전하다.

반대로 위 예제처럼 OF TABLE gt_로 받으면 행이 새로 만들어지므로, 짝이 없는 필드에는 남는 값 없이 초기값(숫자는 0·문자는 공백)이 들어간다. 잔존을 조심할 곳은 Work Area 쪽이다.

💡 편한 만큼 대가도 있다. CORRESPONDING은 실행 중에 양쪽 필드 이름을 하나씩 대조하므로 순서대로 곧장 담는 INTO보다 조금 느리다. 이름이 이미 딱 맞는 상황이면 그냥 INTO가 낫다.

APPENDING — 기존 테이블에 덧붙이기

INTO TABLE은 기존 내용을 지우고 채우지만, APPENDING TABLE은 이어 붙인다.

ABAP
1
SELECT * FROM sflight APPENDING TABLE gt_flight WHERE carrid = 'LH'.

탭을 눌러 같은 조회 결과가 그릇마다 어떻게 담기는지 직접 확인해 보자(순서 어긋남·이름 불일치·덮어쓰기 함정 포함).

흔한 실수와 점검

  • INTO (v1, v2) 순서 어긋남 → 읽는 필드 순서와 변수 순서가 1:1로 맞아야 한다.
  • CORRESPONDING 이름 불일치 → 이름이 다르면 그 필드는 담기지 않는다. 받는 쪽 이름을 맞추거나, 조회할 때 별칭을 붙여 이름을 맞춘다(별칭 AS는 Chapter 13 · INNER JOIN에서 다룬다).
  • INTO vs APPENDING → INTO는 덮어쓰기, APPENDING은 누적.
  • sy-dbcnt를 누적 행 수로 오해 → sy-dbcnt는 직전 SELECT가 넘긴 행 수다(테이블 총 누적 아님). APPENDING으로 이어 붙였다면 총 행 수는 DESCRIBE TABLE gt_flight LINES gv_cnt.로 따로 센다. Chapter 06 · Internal Table 기초에서 쓰던 그 문장 그대로다.

담는 법까지 익혔다. 이제 어느 행만 읽을지를 정교하게 다듬는다. WHERE 상세 → 다음 레슨.
