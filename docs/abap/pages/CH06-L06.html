Track 1Chapter 6Lesson 6초급

구구단 전체를 메모리에 담는다

Chapter 5 · 구구단 캡스톤에서 구구단 한 줄을 Structure로 묶었지만 한 번에 한 줄뿐이었다. 이제 같은 모양의 행을 에 쌓으면 72줄을 통째로 들고 있을 수 있다. 이 실습은 이번 챕터에서 배운 것들을 한 프로그램에 모으는 자리다.

배운 개념 구구단에서의 역할
Line Type dan·mul·result를 묶은 행 모양(ts_line)
Work Area 지금 만들고 있는 한 줄(gs_line)
Internal Table 72줄을 담는 표(gt_gugu)
APPEND 한 줄씩 쌓기
SORT 결과 기준 재배열
LOOP 쌓인 72줄 출력

TYPES: BEGIN OF ts_line,
         dan    TYPE i,
         mul    TYPE i,
         result TYPE i,
       END OF ts_line.

DATA: gs_line TYPE ts_line,
      gt_gugu TYPE TABLE OF ts_line,
      gv_cnt  TYPE i.

DO 8 TIMES.
  gs_line-dan = sy-index + 1.            " 2~9단
  DO 9 TIMES.
    gs_line-mul    = sy-index.
    gs_line-result = gs_line-dan * gs_line-mul.
    APPEND gs_line TO gt_gugu.           " 한 줄씩 쌓는다
  ENDDO.
ENDDO.

DESCRIBE TABLE gt_gugu LINES gv_cnt.     " gv_cnt = 72

이제 gt_gugu에는 구구단 72행이 전부 들어 있다. 출력 후에도 사라지지 않고 정렬·검색에 쓸 수 있다.

SORT gt_gugu BY result DESCENDING.       " 결과 큰 순서로

LOOP AT gt_gugu INTO gs_line.
  WRITE: / gs_line-dan, 'x', gs_line-mul, '=', gs_line-result.
ENDLOOP.

한 줄씩 출력만 하던 지난 챕터의 구구단과 달리, 모아 두었기에 "결과가 큰 순서" 같은 원하는 기준으로 마음대로 재배열할 수 있다.

디버거로 행들 보기

APPEND 다음 줄에 BREAK-POINT를 걸고(디버깅 입문) gt_gugu를 펼치면, 안쪽 루프가 한 번 돌 때마다 행이 1개, 2개, 3개 … 72개로 하나씩 늘어나는 모습이 보인다.

더 해 보기 — 미션 둘

쌓아 두면 정렬 말고도 할 수 있는 일이 많다. 이번 챕터에서 배운 문장을 이 프로그램에 직접 붙여 보자.

  • 미션 1 · 한 줄만 콕 집어 찾기 — gt_gugu에서 "7 x 8" 줄을 찾아 결과만 출력해 보자. READ TABLE gt_gugu INTO gs_line WITH KEY dan = 7 mul = 8.으로 찾고, 찾았는지는 sy-subrc = 0으로 확인한다. 없는 값(mul = 10)으로 실패도 한 번 겪어 보자.
  • 미션 2 · 단마다 소계 내기 — SORT gt_gugu BY dan.으로 단 순서를 맞춘 다음, LOOP 안에 AT END OF dan.과 SUM.을 넣어 단별 합계를 찍어 보자. dan이 첫 필드라 그룹 키가 단순하다. AT 블록 안에서 mul을 같이 찍어 보면 값이 가려진다는 그 규칙도 눈으로 확인된다.

흔한 실수와 점검

  • 바깥 sy-index와 안쪽 sy-index 혼동 → 안쪽 루프에 들어가면 는 안쪽 회차다. 그래서 바깥쪽에서 정한 단 값은 안쪽 루프에 들어가기 전에 gs_line-dan에 저장해 둔다.
  • APPEND 위치 → mul·result가 채워진 뒤에 실행돼야 한다. 안쪽 루프 밖에 두면 단마다 한 줄만 쌓인다.
  • 정렬 후 원래 순서 기대 → SORT 후에는 순서가 바뀌고, 그것만으로는 되돌릴 방법이 없다. 원래 순서가 필요하면 쌓을 때 순번을 담는 필드를 하나 더 두고 1, 2, 3 … 을 같이 넣어 둔다. 나중에 그 필드로 SORT하면 입력 순서로 돌아온다.
다른 언어를 해 봤다면 — 이번 챕터 개념 대조표 (더 보기)

낯선 이름이 많았지만, 대부분은 이미 쓰던 물건에 다른 이름이 붙은 것이다.

  • STANDARD / SORTED / HASHED — 순서대로 담는 리스트 / 키 순서가 유지되는 맵 / 해시로 찾는 맵에 각각 대응한다.
  • COLLECT — 키로 묶어 합계를 내는 그룹 합산이다. SQL을 안다면 GROUP BY 뒤의 합계, 맵을 쓴다면 "키가 있으면 더하고 없으면 새로 넣기"와 같다.
  • ASSIGNING <fs> — 복사가 아니라 그 자리를 가리키는 참조다. 다른 언어에서는 이쪽이 오히려 기본 동작이라, 특별한 기법이 아니라 익숙한 그것이라고 보면 된다.
  • sy-subrc 확인 — 실패를 예외로 던지지 않고 반환 코드로 알리는 방식이다. 확인하지 않으면 프로그램은 아무 일 없다는 듯 그대로 진행한다. READ 다음 줄의 IF sy-subrc = 0이 습관이어야 하는 이유이자, 경력자가 가장 자주 걸리는 지점이다.

정리 — 그리고 다음 불편

구구단 전체를 에서 자유롭게 다뤘다. 그런데 프로그램이 끝나면 gt_gugu는 흔적도 없이 사라진다. 다시 실행하면 또 처음부터 만들어야 한다. 값을 영구히 저장해 두고 싶다 → Chapter 7 · Transparent Table.
