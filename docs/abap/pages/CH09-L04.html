DDIC 관계와 입력도움말(F4)

Elementary Search Help

F4 목록을 설계한다 — 단일 소스 Elementary Search Help.

Track 1Chapter 9Lesson 4초급

F4를 제대로 설계하기

Foreign Key의 F4는 "Check Table 그대로"다. 그런데 F4를 눌렀을 때 뜨는 팝업(어떤 컬럼을 보여줄지, 무엇으로 값을 좁힐지)을 직접 설계하고 싶다. 그것이 (검색 도움말)이다. 가장 기본은 Elementary(단일 소스) 검색 도움말.

💡 이름이 여러 개라 헷갈릴 수 있다. 셋은 층이 다르다. F4는 사용자가 누르는 키 이름이다. 그 키를 눌렀을 때 값을 골라 주는 기능 전체가 입력 도움(Input Help) 이다. 그리고 그 입력 도움을 만들어 내는 DDIC 객체 중 하나가 Search Help다. 그래서 "F4를 누르면 입력 도움이 뜨고, 그 내용은 Search Help가 정한다"가 정확한 문장이다.

Elementary Search Help 구성

SE11 → → ZSH_CONCERT → Create (Elementary). (이 도움말은 이 챕터의 실습에서 실제로 만든다 — 여기서는 설계 원리를 익힌다.)

핵심 요소:

  • Selection Method — 값을 가져올 테이블/뷰. 우리는 ZCONCERT를 쓴다.
  • Parameters — 이 도움말이 다루는 필드들. 공연 도움말이면 CONCERT_ID·ARTIST·VENUE 셋을 올린다.

각 파라미터에는 네 가지 표시를 달아 준다. ARTIST를 예로 들며 보자.

  • IMP(Import) — 도움말이 화면에서 받아 오는 값이다. F4를 누른 순간 그 칸에 이미 적혀 있던 값을 그대로 가져와, 검색의 출발 조건으로 삼는다. 아티스트 칸에 "안"까지 쳐 두고 F4를 누르면 그 "안"이 넘어오는 식이다.
  • EXP(Export) — 목록에서 한 줄을 고르면 화면 칸으로 돌려줄 값이다. 공연 도움말에서 정작 입력칸에 꽂혀야 하는 건 CONCERT_ID니, EXP는 CONCERT_ID에 준다.
  • LPos — Pos는 Position(위치)의 줄임이다. LPos는 고를 값들이 죽 나오는 결과 목록(List) 에서 이 필드가 몇 번째 칸인지를 뜻한다. 0이면 목록에 안 보인다.
  • SPos — 후보가 너무 많을 때 먼저 뜨는 조건 입력창(Selection) 에서 몇 번째 칸인지다. 여기 자리를 줘야 사용자가 그 필드로 범위를 좁힐 수 있다.

💡 여기서의 Parameters는 PARAMETERS 명령이 아니다. 이름만 같고 서로 다른 것이다. Search Help의 Parameters는 이 도움말이 주고받는 필드 목록이고, Chapter 03 · PARAMETERS에서 배운 PARAMETERS는 선택화면에 입력칸을 하나 만드는 ABAP 명령이다. 둘이 만나는 자리는 뒤(PARAMETERS와 DDIC F4 Help 연결)에서 따로 본다.

어디에 붙이나

검색 도움말은 ****나 테이블 필드에 붙인다(Attach). 그러면 그 타입을 쓰는 모든 화면·PARAMETERS에서 F4가 이 도움말로 동작한다.

Chapter 03 · Data Element에서 "Data Element에 라벨·도움말이 붙는다"고 했다. 그때 이름만 스치고 지나갔던 그 '도움말'의 정체가 바로 이 다. 이제야 실물을 본 셈이다.

직접 해 보기

F4 팝업을 직접 조립해 보자. 무엇으로 검색하고, 무엇을 목록에 보이고, 무엇을 입력칸에 돌려줄지(EXP)를 정한다. EXP를 빼면 어떻게 되는지도 체험해 보자.

흔한 실수와 점검

  • EXP 미지정 → 골랐는데 화면에 값이 안 돌아온다. 돌려줄 파라미터를 EXP로.
  • Selection Method 범위 → 큰 테이블이면 적절한 뷰·검색조건으로 제한.

소스가 하나면 Elementary로 충분하다. 그런데 "공연 ID로도, 아티스트로도, 공연장으로도" 여러 방식으로 찾고 싶다면? → Collective (다음 레슨).
