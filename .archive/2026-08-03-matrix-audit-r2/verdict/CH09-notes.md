# CH09 R2 본선 판정 노트 (예비 — 소스 실측 완료분)

> 작성: 본선(Fable). 수거 완주 전 선행 실측. 최종 판정서(R2-SUMMARY)의 재료.
> R2 수합: 94발견/57클러스터/28벌/dropped 0 (R1: 148/69 — 볼륨 63%).

## conflict 확정 (코퍼스 기왕 확정 사실로 판정)

- **C002 기각(재발 오판 — 기각 사전 ⑪)**: "DE 부착 SH가 Check Table보다 위" 주장(5벌).
  코퍼스 ABENABAP_DYNPROS_VALUE_HELP_AUTO ascending: 달력/시계→고정값→**DE 부착 SH**→Check Table(콘텐츠→text table→부착 SH)→필드 직접 부착 SH.
  본문 팁 "Check Table보다 아래"(L07:31)가 정확. R1에서 동일 계열 기각 이력.
- **C001 채택(높음→구성 결함)**: L07 사다리 6단(실측 L07:22～28)에 "DE 부착 SH" 단 자체가 없음 —
  팁(L07:30～31)만 그 자리를 언급. 교정 = 4단(Check Table)과 5단(고정값) 사이에 단 삽입(7단화)
  + 위젯 S01·S02(·고아 S03) 동반 갱신. 성격 = R1 보강(6단 재구성)의 불완전 이행.

## L09 실측 확정

- **C003 채택(높음·사실 오류)**: L09:58-59 "SE11에서 Delivery Class를 정하면 첫 키 필드로 자동으로 붙는다"
  — Delivery Class와 클라이언트 필드는 독립 속성. MANDT는 개발자가 첫 키 필드로 직접 선언(CLNT).
  표 3곳의 "(자동)" DE 표기도 동반 정정 대상(표준 DE `MANDT` 명시가 정석). 판정서에서 코퍼스 재확인 예정.
  주의: CH07-L01 서술과의 정합도 함께 볼 것(참조가 그쪽을 가리킴).
- **C004 채택(높음·재현성)**: L09:62-65 감사필드 6개 이름만 나열, DE·타입·키 없음 — 다른 필드는 전부 표로 명세.
  교정 = 표준 참조 DE로 6행 표 추가(하류 CH25 전제와 정합 확인 필요).
- **C009 채택(중간으로 하향 제안)**: L09:102 "ZPERF의 키가 두 칸이니 대응도 두 줄" — 같은 파일 표(L09:47～)가
  MANDT ✔ 포함 3칸 키를 명시 → 자기모순. SE11이 MANDT 대응을 자동 제안하므로 실제 차단은 아님 → 높음 아님.
  교정 = "업무 키가 두 칸"으로 정밀화 + MANDT 대응은 자동 생성 1문장.
- **C007 채택(높음·오진 유발)**: §4(L09:111-112) ZSH_CONCERT 파라미터 = ID·아티스트·장소(NAME 없음),
  ZBOOKING-CONCERT_ID에 부착. ②-3(L09:168-169)은 "공연명 나오면 ZCONCERT_T 연결 성공" 판정 —
  부착 SH(사다리 3단)가 Check Table 경로(4단, text table 포함)를 가리므로 정상 수행자일수록 공연명 없음 = 실패 오진.
  교정 후보(판정서에서 확정): SH 파라미터에 text table NAME 추가(Selection Method의 text table 필드는
  SH 파라미터로 허용 — SAP 표준) + ②-3 문구를 SH 목록 기준으로 정합화.
- **C028 채택(중간)**: ②-4 "ZSH_CONCERT_COLL을 붙인 칸" — 부착 지시가 §4 어디에도 없고,
  §4는 같은 칸에 ZSH_CONCERT 부착 지시(112) → 한 칸=도움말 하나 원칙과 배타.
  교정 = 최종 부착을 COLL로 통일(ZSH_CONCERT는 COLL 구성요소로), ②-3·4 재정렬.
- **C052 채택(낮음)**: L09:156 ZCONCERT_T NAME 값 미제시(다른 표는 값 전부 제공) — 공연명 3건 명시 제안.
