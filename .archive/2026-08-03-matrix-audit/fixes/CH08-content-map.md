## E. 판정문 문구와 다르게 실행한 6건 (신고)

1. **C003 배치 선택** — 판정문은 "L02 콜아웃 **또는** L05 주석". **L02 콜아웃**을 택하고 L05 IN 예제에는 주석을 달지 않았다. 이유: C073이 콤마 언급 상한을 2회(콜아웃+코드 주석)로 못박아, L05에 한 번 더 달면 상한을 넘긴다. L02 콜아웃 문구를 **선제형**("뒤 레슨에서 괄호로 묶은 목록 안에 콤마가 보이더라도…")으로 써서 L04 `INTO (v1, v2)`와 L05 `IN ( … )` 두 곳을 한 번에 커버했다.
2. **C044를 2곳에 배치** — 판정문 문구는 "LOOP AT 첫 사용부"(=L07)만. 클러스터 claim의 근거가 "CH06 회상이 **챕터 전체 0건**, CH07 상기는 잘돼 있어 비대칭"이라, 챕터가 CH06을 처음 밟는 지점인 **L02 Internal Table 첫 등장부**에도 복습 링크를 넣었다(2곳). 링크 대상은 성격에 맞춰 분리: L02 → CH06-L01(Internal Table 기초), L07 → CH06-L04(다중 행 제어 = LOOP AT 도입 레슨).
3. **C049를 접기 박스 밖에 배치** — 판정문 T2는 "접기 박스 후보", T5의 C050은 "C024·C049·C074 흡수". 실제로는 **L05 host 변수 절의 🧑‍💻 콜아웃**으로 분리했다. 이유: 접기 박스는 L01(챕터 입구)에 있고 host 변수는 L05에서야 나오므로, L01에 넣으면 아직 보지 못한 표기를 두고 "안전하다"고 안심시키는 꼴이 된다. C024·C074는 지시대로 접기 박스에 흡수했다.
4. **C067에 L06 `prereq` 보정 포함** — 판정문은 "prevRel 실제 관계로 정정(메타 전용)"만. C070 실행으로 L06 예제가 `INTO CORRESPONDING FIELDS OF TABLE`(L04 소유 개념)을 쓰게 되어, L06 `prereq`를 `["CH08-L02"]` → **`["CH08-L02","CH08-L04"]`**로 보정했다. 읽는 순서상 L04가 앞서므로 R15 위반은 없고, front-matter가 사실과 어긋나는 것을 막는 **선언 정정**이다(개념 추가 아님).
5. **C070 실행 방식** — "SELECT * 1곳 이상 필드 나열로"를 L06 일반 필드 예제에 적용했는데, classic에서 필드 목록을 내부 테이블로 받으려면 대상 구조가 정확히 맞거나 `INTO CORRESPONDING FIELDS OF TABLE`이 필요하다. 새 구조체 타입을 만들어 노이즈를 늘리는 대신 후자를 택했고, 그 대가로 §E-4의 prereq 보정이 따라왔다.
6. **C002에서 기존 코드 블록 유지** — 판정문은 "관찰 불가한 정식 도입은 축소". 기존 `SELECT … WHERE fltime IS NULL` fenced 블록을 **지우지 않고 남긴 뒤**(선언 1줄 추가·2줄로 접음) 바로 아래에서 "돌려 보면 늘 0건, 잘못 쓴 게 아니다"를 설명하는 형태를 택했다. 코드를 지우면 "0건이 나오는 걸 직접 확인"이라는 정직한 관찰 자체가 불가능해지고, 신규 블록이 아니므로 R2 체험 의무도 새로 생기지 않는다.
