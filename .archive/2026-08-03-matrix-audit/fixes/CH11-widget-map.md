## 3. 신규 발견 — 동시 교정 3건

### 3.1 코드 하이라이터가 **맨 숫자를 통째로 삭제** (엔진 · 잠복 버그)

본문 정합으로 숫자가 든 줄이 처음 들어오면서 드러났다.

- `salv-grid-simulator.js`의 토큰 정규식 마지막 대안이 `[^A-Za-z0-9_']+` 라 **어느 대안에도 안 걸리는 숫자**가 출력에서 사라진다.
- 실측: `SELECT … UP TO 20 ROWS.` → 화면에 **`UP TO  ROWS.`** 로 렌더. L06의 `IF gv_count = 0.`은 **`IF gv_count = .`** 이 됐을 것(가드 코드를 넣는 이 작업에서 바로 터질 자리였다).
- 처리: 마지막 대안에서 `0-9`를 빼 `[^A-Za-z_']+`로. 식별자는 앞 대안(`[A-Za-z_][A-Za-z0-9_]*`)이 먼저 먹으므로 `gt_flight` 같은 이름은 영향 없음.
- 재실측: `UP TO 20 ROWS.` · `IF gv_count = 0.` 정상 · 거터/코드 줄 수 **15/15·22/22**(1:1, R5) · 코드 가로 스크롤 없음(745/745·730/730).

### 3.2 L06의 0행 예제가 **본문 신설 가드와 모순** (본문 변경이 만든 신규 불일치)

- 본문 L06은 C019로 `DESCRIBE TABLE` + `IF gv_count = 0. MESSAGE … ELSE. (ALV) ENDIF.` 가드를 **실코드로 편입**했다. 그런데 위젯의 "빈 테이블(0행)" 예제는 여전히 **빈 그리드**를 띄워 "0행이면 표가 아니라 안내가 뜬다"는 새 교훈을 화면에서 반박한다(C027과 같은 계열).
- L02는 반대로 본문이 "빈 그리드가 뜬다"를 가르치므로 **동작이 달라야 한다** → 엔진에 `SALV_CFG.emptyGuard`를 추가해 **레슨별로 갈랐다**(미지정 = 종전 동작).
- L06 실측: 예제 칩 `빈 테이블 (0행)` → **`예매 없는 공연 (0행)`**(과제 3의 "예매가 없는 번호"와 같은 상황), display 시 그리드 대신 `🛈 행이 0건입니다. 본문 코드는 DESCRIBE TABLE로 센 뒤 IF gv_count = 0에서 걸러 "조건에 맞는 예매가 없습니다." 안내만 띄우고 표는 열지 않습니다.` · **ALV 패널 hidden=true**. 정상 예제로 복귀 시 6행 재렌더.
- L02는 종전대로 빈 그리드(`빈 테이블 — 표시할 행이 없습니다 (오류는 아님)`) 유지 — 본문 흔한 실수 3번째 항목과 일치.
- 아울러 L06 코드 패널을 **본문 21줄과 1:1**로 맞췄다(WHERE·DESCRIBE·IF/ELSE·`CATCH`의 `MESSAGE` 포함). 종전엔 조건 없는 `SELECT *`에 빈 `CATCH`였다.

### 3.3 `_dark.css`가 stale — **내 엔진이 아니라 CH09 엔진 몫** (인계)

- `node tools/gen-embed-dark.mjs` 재실행 결과 **23줄 추가**. 전수 귀속 확인: `concert-model-checklist` 3 · `validation-router` 16 · `value-vs-fk` 4 — **전부 CH09 위젯 작업자가 고친 엔진**(해당 `.css` mtime 08-09 12:41, 내 작업 이전)이고 그 뒤로 생성기가 안 돌았다.
- **내가 추가한 CSS의 기여분 = 0줄**(`salv-grid-simulator`·`salv-function-switch`·`alv__prev` 매칭 0건). 새 규칙을 `var()`/`rgba()`로만 쓴 결과이며, 생성기는 **hex 리터럴만** 변환하므로 계약이 성립한다.
- 처리: `_dark.css`는 `직접 수정 금지(재생성됨)` 표기의 생성물이라 **재생성 결과를 그대로 둔다**(되돌리면 CH09의 새 CSS가 다크에서 라이트색 그대로 남는다). 남의 범위 변경이므로 여기 기록해 본선에 알린다.
- 다크 렌더 실측(토큰 전환 확인): `.alv__prev` color `rgb(59,91,219)` → **`rgb(122,162,255)`**(`--brand`) · border `rgb(230,232,239)` → **`rgb(51,56,69)`**(`--line`) · L03 `.tok-com` `rgb(148,160,184)` → **`rgb(107,116,136)`**(`--soon`).

## 4. 판단·재량 기록

1. **L02는 옵션①(프리뷰 라벨)** — 옵션②(set_all 전 툴바 비활성)는 ★②가 명시했듯 본문 🖱️ 콜아웃("위 시뮬레이터는 그 기능들이 **켜진 뒤의 모습**을 미리 보여 준다")을 함께 고쳐야 해서 **본문 재작업을 유발**한다. 게다가 이 위젯의 학습 목표는 *factory와 display의 차이*이고 툴바는 곁가지라, 툴바를 2단 상태로 만들면 초점이 흐려진다(툴바 켜기는 L03 위젯이 전담). 캡션 한 줄로 계약을 명시하는 편이 본문·위젯 양쪽에 손해가 없다.
2. **L03에 시나리오 1종 추가(`display 뒤에 set_all`)** — ★②의 점검 요구("display 뒤에 눌러도 켜지면 새 불일치")에 대한 답은 "그런 경로가 없다"였다. 다만 본문 L03에는 **순서 논점**과 흔한 실수 항목(`set_all`을 `display` 뒤에 두면 버튼이 안 생긴다)이 새로 들어왔는데 위젯에서 확인할 방법이 없어 R2(코드=체험) 관점의 공백이 생긴다. 버튼 하나로 코드 순서가 뒤집히고(`display( )`가 위, `set_all`이 취소선+`" 이미 그려진 뒤라 소용없다`) 툴바가 비는 걸 보이게 했다.
3. **L01 링크 목적지 변경은 §2 ⑥의 근거로** — 판정문의 지시는 "경로+target"이지만 ★⑥이 본문 정책과 맞추는 선택지를 열어 두었다. 정보를 없애는 대신(옵션: 링크 제거) **L05로 보내는** 쪽을 골랐다 — 학습자에겐 클릭 가능한 실제 목적지가 남고, L05가 본문이 정한 경계 안내의 단일 홈이다.
4. **L05 카드에 정답 `now`가 2장인 이유** — 종전엔 `now` 1장 + 나머지 5장이 전부 "나중"이라, 표를 안 봐도 **소거법**으로 풀렸다. 표에 아예 없는 상황(툴바 합계·표준 필터)을 `now` 쪽에 넣어 "지금 되는 게 어디까지인지"를 실제로 판단하게 했다.
5. **L04 컬럼을 3개로 유지** — 3칸 파이프라인 레이아웃이 좁아 SFLIGHT의 좌석 컬럼까지 넣으면 가로 스크롤이 생긴다. 본문 `SELECT *`의 대표 컬럼 3개(`carrid`·`connid`·`fldate`)만 노출했고 실측상 가로 스크롤 없음.
6. **L02 코드 패널도 본문과 1:1로** — C015가 지적한 건 "방금 읽은 코드에 없는 변수명"인데, 같은 위젯의 코드가 본문(C029로 `SELECT` 추가·C007로 `CATCH`에 `MESSAGE`)과 어긋난 채면 같은 결함이 남는다. 12줄 → 15줄로 맞췄다.

## 7. 후속 인계

1. **`_dark.css` 23줄은 CH09 엔진 몫**(§3.3) — 내 커밋에 섞여 들어간다. CH09 작업자가 생성기를 안 돌린 결과이며, 되돌리면 CH09 위젯이 다크에서 깨진다.
2. **본문 리빌드 미실행** — content 작업자와 동일하게 `npm run build:abap`은 돌리지 않았다(본선 몫). `docs/abap/pages/CH11-*.html`은 아직 구 빌드라 본문↔위젯 최종 대조는 빌드 후 한 번 더 보는 편이 안전하다(임베드 iframe src는 불변이라 위젯 동작 자체는 영향 없음).
3. **`gen-embed-dark.mjs`를 챕터 작업 종료 루틴에 넣을지** — 배치 3에서만 두 챕터 연속으로 stale이 발견됐다(CH09 미실행 → 내가 대신 재생성). 엔진 CSS를 건드린 작업자가 반드시 재실행하도록 프로토콜에 못 박을 여지가 있다(범위 밖 관찰).
4. **`salv-grid-simulator`의 하이라이터는 여전히 최소 구현** — §3.1로 숫자는 살렸지만 `->`·`=>` 같은 연산자나 `abap_true` 류는 토큰 색이 없다. CH11 범위에선 문제되지 않아 손대지 않았다.
