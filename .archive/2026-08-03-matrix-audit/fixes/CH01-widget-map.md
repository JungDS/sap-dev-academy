## 클러스터별 처리

### C003 (높음) — `/:` 콜론 체인을 파서가 거부
**처리 · 반영.** `WRITE` 문 해부를 새로 씀. 문자열 밖의 첫 콜론을 찾아 **콜론 왼쪽 = 항목마다 반복되는 prefix**로 두고, 각 항목을 `prefix + 항목`으로 합쳐 평가한다(본문 CH01-L04 "콜론 왼쪽 전체를 각 항목마다 반복" 규칙 그대로). 앞쪽 `/`는 개수를 세어 1개면 줄바꿈, 2개 이상이면 "콜론 왼쪽 `/`가 이미 반복된다"는 설명형 오류.
- 파일: `write-output.js`(`parseWrite`·`takeSlashes`) · 예제 칩 5번째(`/:` 비교 예제) 추가.
- 검증: `WRITE /: 'A','B'.` → 두 줄 / `WRITE: / 'A','B','C'.` → 한 줄 / `WRITE:/ 'A','B'.`(공백 없음) / `WRITE /:'A','B'.`(공백 없음) / `/:` 3개 + `: /` 3개 혼합 → 4줄 / `WRITE /: / 'A'.` → 슬래시 중복 오류. **6케이스 통과.**

### C006 (높음) — L05가 정식 도입한 옵션을 위젯이 미지원
**처리 · 반영(요구 4종 전부).** 값 선택을 **키 방식**으로 바꾸고 엔진에 값 카탈로그(VALUES)를 뒀다. 리터럴 3종 + **`gv_qty`(TYPE n)·`gv_amt`(TYPE p)·`sy-datum`** 3종. 값 종류에 맞는 옵션만 켜지고(안 맞는 옵션은 비활성 + 이유 안내), 코드에는 본문과 같은 `DATA … VALUE …` 선언문이 함께 생성된다.
- **NO-ZERO** — TYPE n `0001` → `   1`(전부 0이면 전부 공백).
- **DECIMALS n** — 필드 자리수를 덮어씀(`100.00` → `DECIMALS 4` → `100.0000`).
- **CURRENCY cur** — 저장 정수(10000)를 통화 소수 자리로 다시 읽음. KRW·JPY 0자리 → `10,000` · USD·EUR 2자리 → `100.00`. 출력 아래에 **중간 단계 설명**(저장값 100.00 = 내부 10000 → 통화 자리수 0 → 10,000)을 붙였다.
- **날짜 형식** — `DD/MM/YY` · `DD/MM/YYYY` · `MM/DD/YYYY` · `YYMMDD` + "지정 없음". 애디션을 주면 **적은 순서 그대로**(채택된 C032와 일치), 안 주면 사용자 설정 형식.
- 예제 칩 3개 추가(수량·NO-ZERO / 금액·CURRENCY / 오늘 날짜·형식) → 새 옵션이 눈에 띄게.
- R15 준수: 변수·시스템 필드 선택 시 **[선행 사용] 안내 줄**이 뜬다(front-matter `advanceUse`와 일치).
- 검증: NO-ZERO on/off · DECIMALS 0/2/4/없음 · CURRENCY KRW/JPY/USD/없음 · 날짜 5형식 · 값 종류별 옵션 활성 상태 3세트. **23케이스 통과.**
- **미구현(보고 대상)**: `FORMAT COLOR … / FORMAT RESET`(색 지속) — 이 위젯은 **WRITE 한 줄**만 그리는 구조라 "다음 줄부터 계속 적용"을 보여줄 화면이 없다. 여러 줄 출력 모델로 재설계해야 해서 이번 범위에서 제외.

### C028 (중간) — NEW-LINE·SKIP·ULINE 무시
**처리 · 반영.** `NEW-LINE`(다음 출력을 새 줄에서), `SKIP [n]`(빈 줄 n개), `ULINE`(가로 구분선 행)을 실제로 실행한다. 그리고 **모르는 문장은 조용히 넘기지 않고** 상태줄에 "이 시뮬레이터가 모르는 문장 `DATA` 은(는) 실행하지 않고 건너뛰었어요"로 알린다.
- 게이팅 배려: **SKIP·ULINE은 CH01-L05 개념**이라 위젯 UI(노트·칩)에서 광고하지 않고 동작만 지원한다. 노트는 L04에서 배운 `REPORT`·`WRITE`·`NEW-LINE`만 명시(R15/P11 선노출 회피).
- 검증: NEW-LINE 줄바꿈 · SKIP 1개/2개 · ULINE 행 · 미지원 문장 있어도 출력 정상 + 안내 노출. **7케이스 통과.**

### C029 (중간) — 문장 중간 마침표 누락 미검출
**처리 · 반영.** 문장 분리기가 **각 문장이 어느 줄에서 왔는지(segs)** 를 기록하도록 바꿨다. 한 문장 안에서 두 번째 이후 줄이 문장 키워드로 시작하면 = 앞 줄 마침표 누락 → "**N번째 줄 끝에 마침표(.)가 없어요. … 다음 줄(M번째 줄)까지 한 문장으로 붙어 버립니다**". 마지막 문장 누락도 줄번호를 함께 보여준다.
- SAP 원문 오류 메시지는 **인용하지 않았다**(실기 대조 불가 → 지어내지 않음, 14 §5).
- 검증: `WRITE 'first'`(마침표 없음) + 다음 줄 WRITE → 3번째 줄 지목 · `REPORT zhello`(마침표 없음) → 1번째 줄 지목 · 마지막 문장 누락. **5케이스 통과.**
- 오검출 회피 확인: 여러 줄에 걸친 정상 체인(`WRITE: / 'A','B','C',` ⏎ `/ 'D','E'.`)은 오류로 잡히지 않음(예제 3 통과).

### C035 (중간) — 폭 초과 시 절삭
**처리 · 반영.** 폭보다 값이 길면 **숫자(정수·packed)는 폭만큼 `*`로 채우고**, 문자·NUMC·날짜는 뒤가 잘린다(본문 "잘리거나 `*`로 표시된다"와 정확히 대응). 두 경우 모두 출력 아래에 왜 그런지 안내가 뜬다(특히 문자 절삭은 "경고 없이 잘려서 더 위험"이라고 명시).
- 폭 슬라이더 하한을 6 → **2**로 내려 문자 절삭도 UI에서 재현 가능하게 했다(기존엔 한글 3자 값이 어떤 폭에서도 안 잘려 절삭 분기가 사실상 도달 불가).
- 검증: `1250000` 폭6 → `******` · 폭 복귀 시 값 복원 · `'정훈영'` 폭2 → `정훈` · 날짜 `DD/MM/YYYY` 폭8 → 절삭 + 각 안내. **7케이스 통과.**

### C049 (중간) — 로그온 스크린샷 불일치
**처리 · 반영(캡션 교정). 단, 발견의 전제는 실물 확인 결과 다름.**
- **판단 근거**: `assets/img/abap/CH01-L01-logon.png`(878×550)를 (20,90)–(480,340) 영역 3배 확대해 픽셀 확인. "New password"는 **화면 제목이 아니라 응용 도구모음(application toolbar) 자리의 푸시버튼**이고, 화면 본문 입력칸은 `Client`·`User`·`Password`·`Logon Language` 4개뿐이다. 강제 변경 화면이라면 있어야 할 `New Password`/`Repeat Password` 입력칸이 **없다** → 표준 SAP 로그온 화면이 맞다(발견자는 툴바 버튼 라벨을 화면 제목으로 읽은 것으로 보인다).
- 그래서 "다른 화면으로 갈아 끼우기"가 아니라, **학습자가 그 버튼 때문에 헷갈리지 않도록** 캡션·alt에 한 문장을 더했다: "입력칸 위의 **New password**는 비밀번호를 바꿀 때만 쓰는 버튼이라 평소 로그온에는 누르지 않는다."
- 대체 이미지 조사: `assets/img/abap/`에는 CH01용 이미지 5개(logon·easy-access·abap-editor·abap-dictionary·object-navigator)뿐이라 **더 적절한 기존 이미지 없음**.

### C050 (중간) — 선행 공백 뒤 `*`를 주석으로 처리
**처리 · 반영.** 주석 판정을 `^\s*\*` → **`^\*`(컬럼 1 전용)** 로 바꾸고, 실행 전에 "공백 + `*`" 줄을 먼저 검사해 **줄번호와 함께 오류**를 낸다(L03의 "별표는 첫 칸" 규칙과 동일한 설명). 줄 중간 주석은 큰따옴표라는 안내도 함께.
- 검증: 들여쓴 `*` → 2번째 줄 지목 오류 · 컬럼1 `*` → 정상 · 인라인 `"` 주석 → 정상. **4케이스 통과.**

### C051 (중간) — COLOR 없이 INVERSE 켜면 아무 변화 없음
**처리 · 반영(시각 변화 부여).** 기본색을 토큰(`var(--ink)`/`var(--surface)`)으로 정의해, **COLOR 미지정 + INVERSE**도 전경/배경이 실제로 뒤집힌다(다크 모드에서도 반전이 유지되도록 하드코딩 색 대신 토큰 사용).
- 검증: COLOR 없음+INVERSE → `background:var(--ink);color:var(--surface)` · COLOR 3+INVERSE → 색 교환 · INVERSE 해제 → 원복 · 둘 다 없음 → 스타일 없음. **5케이스 통과.**

### C079 (낮음) — disabled로 실수를 원천 차단 → **부분 반영**
**처리.** ③단계 진입(프로그램 생성) 시점에 **저장·활성화·실행 세 버튼을 모두 활성**으로 열고, 다음에 눌러야 할 버튼만 `.ready`로 강조한다. 순서를 어겨도 막지 않으므로 준비돼 있던 경고 분기가 **도달 가능**해졌다.
- 저장 전 실행 → "아직 저장도 안 했어요…", **저장 후 활성화 없이 실행 → 원래 있던 "⚠ 활성화 안 된 변경은 실행에 반영되지 않아요 — 🔥 활성화부터! (가장 흔한 실수)"** 가 그대로 뜬다. F8 단축키도 같은 경로.
- 생성 직후 안내에 "순서를 어겨 ▶ 실행부터 눌러 봐도 됩니다"를 넣어 실수 경로를 **권유**한다.
- **부분인 이유**: 실제 SE38에서 미활성 프로그램을 F8로 돌리면 (이전 활성본 실행 / 프로그램 없음 오류 등) 상황별로 반응이 갈리는데, 이 위젯은 그 분기를 재현하지 않고 **챕터가 가르치는 한 가지 메시지**로 수렴시킨다. 실기 대조 없이 SAP 반응을 추가로 지어내지 않기 위해 여기서 멈췄다.
- 검증: 코드 경로 검토 + 버튼 상태 전이(생성→3버튼 활성 / 저장→활성화 `.ready` / 활성화→실행 `.ready`) 확인. 실제 클릭 체감은 **본선 브라우저 검증 대상**.

## 연동 수정 (코디네이터 승인·추가 지시)

### C071-SYNC — 정렬 애디션이 없을 때의 **타입별 기본 정렬**
**처리 · 반영.** `fieldCell()`이 `st.just || defaultJust()`를 쓰도록 바꿨다. 사용자가 `LEFT-JUSTIFIED`·`CENTERED`·`RIGHT-JUSTIFIED`를 고르면 **그 옵션이 항상 우선**이고, "기본"일 때만 타입이 정렬을 정한다. 코드 생성은 그대로여서 "기본"에는 정렬 키워드가 붙지 않는다(= 애디션 없이 타입이 정한다는 사실 자체가 화면에 드러남). 정렬 "기본"이 무엇으로 정해졌는지는 옵션 패널 안내 줄에 한 줄로 표시된다("… 정렬 **기본**은 수를 담는 타입이라 **오른쪽**입니다").

**⚠️ 지시와 한 곳 다르게 구현했다 — `N`(NUMC)** . 지시문은 "숫자형(P·I·F·**N** 등)은 기본 우측"이었으나, "실제 ABAP classic 리스트 동작이 정본"이라는 지시의 전제에 따라 **공식 keyword doc을 대조**한 결과 `n`은 수치형이 아니라 **문자형**이라 좌측 정렬이 맞다. 근거(오프라인 코퍼스, [14 §5](../../../.project-docs/14_REFERENCE_CORPUS.md) 규율대로 웹검색 없이 grep):
- `ABENWRITE_FORMATS.md` — *"The following table shows the predefined alignment for the built-in ABAP types"* → **Numeric = Right-aligned · Character-like = Left-aligned · Byte-like = Left-aligned · Date/time = Left-aligned.**
- `ABENBUILTIN_TYPES_CHARACTER.md` — 문자형 표에 **`c`·`n`·`string`** 이 실려 있고 *"`c`와 `string`은 일반 문자형이고 `n`은 특별한 성질을 가진다"* 라고 명시. `ABENBUILTIN_TYPES_NUMERIC.md`의 수치형 목록(b·s·i·int8·p·decfloat16·decfloat34·f)에 `n`은 **없다**.
- 같은 문서의 다른 대목도 일관 — *"character-like data types with a fixed length (`c`, `n`)"*, NO-ZERO 설명의 *"data type `c`, `n`, or `string`"*.

→ 최종 구현: **`i`·`p`(수치형) = 오른쪽** · **`c`·`n`·`d`(문자형·날짜) = 왼쪽**. 본문 C071 수정("수는 오른쪽에 붙는다" = 타입 i 리터럴)과 정확히 일치하고, 본문이 새로 넣은 경고("따옴표에 담긴 숫자는 왼쪽으로 흐른다")와도 어긋나지 않는다. **N을 우측으로 바꿔야 한다면 되돌리기는 한 줄**(`defaultJust()`)이니 지시만 주면 된다.

**`write-output.js`는 해당 없음** — 이 시뮬레이터에는 출력 길이·패딩 모델 자체가 없다(CH01-L04는 `(len)`을 가르치지 않고, 값을 공백 하나로 이어 붙이기만 한다). 정렬/폭 관련 식별자 검색 결과 0건.

**검증**: 정수·금액 기본 → 오른쪽 / 문자·수량(NUMC)·날짜 기본 → 왼쪽 / 명시 LEFT·CENTERED·RIGHT가 타입 기본을 이김 / 기본일 때 정렬 키워드 미생성 / 안내 문구. **12케이스 추가, 전체 65 PASS / 0 FAIL.** `write-output` 31 PASS 회귀 없음.

### C007-SYNC — 릴리스를 '반영'으로 읽히게 하던 위젯 문구
**처리 · 반영.** `CH01-L06-S02.html` 하단 note를 본문 C007 교정 방향으로 교체했다.
- before: "이 Request를 **릴리즈(Release)** 하면, 묶인 프로그램들이 `STMS`를 통해 **다음 서버(품질·운영)로 전송**됩니다."
- after: "이 Request를 **릴리스(Release)** 하면 요청이 **봉인되어 나갈 준비**가 된 것이고, 실제 반영은 `STMS`(Transport Management System)로 **품질 서버에 임포트(Import)될 때** 일어납니다. 운영 서버는 그다음 순서입니다."
- 본문 현재 서술(`CH01-L06.md`)과 대조 확인: "릴리스하면 … 도장이 찍히고" · "반영되는 건 그 서버에서 **임포트(Import)** 를 실행하는 순간" · "**품질 서버에 임포트되어 검증을 통과한 뒤**에야 운영 서버로" · 정리 절 "릴리스는 내보낼 준비를 끝내는 것, 실제로 들어가는 건 임포트" → **일치**.
- 표기: '릴리즈' → **'릴리스'**(C023 통일). 같은 레슨의 `CH01-L06-S01.html` 흐름 라벨에도 '릴리즈'가 하나 남아 있어 **함께 '릴리스'로** 고쳤다(한 페이지 안 표기 불일치 방지 · 의미는 원래 맞았음). 지시 범위를 한 단어 넘어선 부분이라 여기 밝혀 둔다.

## 관찰 (이번 범위 밖 — 수정하지 않음)

① ~~숫자 기본 정렬~~ → **해결됨**(위 C071-SYNC). 단 `N`(NUMC) 분류를 지시와 다르게 문자형(좌측)으로 구현했으니 그 판단만 확인해 주면 된다.

② **날짜 기본 형식 예시가 본문과 다르다.** 본문은 사용자 설정 예로 `19.06.2026`(DD.MM.YYYY)을, 위젯은 `YYYY.MM.DD`를 "가정"으로 쓴다. 둘 다 "설정에 따라 다르다"고 명시하므로 오류는 아니지만, 한쪽으로 맞추면 더 깔끔하다.

③ **콜론 없는 콤마 나열을 여전히 허용한다.** `WRITE / 'A', 'B'.`(콜론 없이 콤마)는 실제 ABAP에선 구문 오류인데 위젯은 관대하게 출력한다. 기존 동작을 유지했다(백로그 밖). 잡으려면 "콤마를 쓰려면 콜론(:)이 필요하다"는 교육형 오류를 넣으면 된다.

④ **엔진 2종이 소비자 0이 됐다.** C080 삭제로 `command-field-sim.{js,css}`·`tcode-prefix-cards.{js,css}`를 쓰는 위젯이 없다. 삭제 지시는 위젯 2개뿐이라 엔진은 남겼다(다른 챕터가 재활용할 여지도 있음). 정리하려면 별도 지시.

⑤ **`sample/` 원본이 엔진과 벌어졌다.** `sample/code-learning/write-output-simulator.html`·`write-format-playground.html`은 추출 원본(일회용 `tools/_extract-embed.mjs`)이라 이번 개선이 반영돼 있지 않다. 카탈로그 참고용이라 동작에는 영향 없지만, 샘플을 보고 베끼면 옛 파서를 복제하게 된다.

⑥ **정수 리터럴에 천단위 구분이 없다.** `1250000`은 그대로 찍히는데 CURRENCY 결과는 `10,000`으로 구분 기호가 붙는다(본문 표기 그대로). 실제 SAP은 둘 다 사용자 설정 구분 기호를 적용한다. 백로그 밖이라 손대지 않음.

⑦ **`_index.md` 상태 칸.** L04-S01·L05-S01은 ✅(브라우저 검증 완료)로 남겨 뒀다. 이번 변경분의 브라우저 실측은 본선 몫이므로, 실측 후 재확인이 필요하다.

⑧ **커밋하지 않았다.** 지시 범위(수정·보고)까지만 수행. 작업 트리에는 **다른 작업자의 `content/abap/CH01/*.md` 변경이 함께** 올라와 있으니, 커밋 시 분리하거나 함께 묶을지 판단이 필요하다.
