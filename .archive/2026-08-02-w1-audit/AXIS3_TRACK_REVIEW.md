# 축3 — Track 구성 백지 검토 (W1 감사)

> 산출: 2026-08-02 W1 감사. **리포트만 — 실행은 사용자 승인 후 별도 작업.**
> 전제 = 단 하나: **39챕터 학습 순서 불변**(재배열 기각 실측 — CH36←CH35·CH39←CH38 강의존). 트랙 = 순서 위에 얹는 "학습 구간 라벨"이며, 몇 개로 어떻게 묶느냐는 백지에서 검토했다.

## 1. 근거 데이터 (레슨 front-matter `prereq` 그래프 + 본문 크로스 링크 실측)

- **허브(피의존 상위)**: CH06(14개 챕터가 의존)·CH21(10)·CH08(9)·CH03(7)·CH10(7)·CH25(7). 기초 사슬(CH01～10)이 전 커리큘럼의 토대라는 정량 확인.
- **선형 사슬**: CH01→…→CH10은 직전 챕터 의존이 연속(한 덩어리). CH11～17은 화면·조회 실무 클러스터(11·12·13·15·16·17 상호 참조 밀집).
- **CH18～24 블록**: 내부 사슬 강함(18→19→20 문법 계열·21→22 OO 계열·23→24 CDS→RAP). 이 블록의 **외부 의존은 전부 CH17 이하** — 뒤 블록(CH25+)을 전혀 참조하지 않는 자기완결 구간.
- **CH25의 의존 = CH06·CH08뿐** — Track-2 시작점이 기초로 "회귀"하는 실무 재출발점이라는 구조가 데이터로 확인됨.
- **CH25～39**: 상호 독립성 큼(각자 다른 실무 도메인). 강한 내부 사슬은 CH35→36(성능→푸시다운)·CH38→39(운영→캡스톤) 두 곳뿐.
- 크기: Track-1 = 24챕터(전체 62%) · Track-2 = 15챕터.

## 2. 후보안

### A안 — 현행 2트랙 유지 (변경 0)
- **비용**: 0.
- **문제**: ① Track-1 24챕터 = 한 구간이 과대(완주 단위가 길어 동기부여형 정체성과 상충) ② "ABAP 기초" 라벨이 CH18～24(Modern 문법·OO·CDS·RAP)와 부정합 — 09 원장 헤더조차 "기초～입문 실무"로 얼버무리는 중 ③ classic→modern이라는 커리큘럼 최대 경계(R6·로드맵 BOUNDARY 마커)가 트랙 구조에 드러나지 않음.

### B안 — 3트랙: CH01～17 / CH18～24 / CH25～39 ★권고
- 라벨(시안): **T1 "ABAP 기초 — Classic 완결"**(17) / **T2 "Modern ABAP과 새 개발 모델"**(7 — 문법 경계·OO·CDS·RAP 입문) / **T3 "실무 심화"**(15).
- **근거**: ① 경계가 이미 존재하는 **CH18 BOUNDARY 마커**(classic→modern)와 정확히 일치 — 구조가 서사를 따라감 ② CH18～24는 외부 의존이 전부 앞 블록뿐인 자기완결 구간(§1) ③ 라벨 정직성 회복(기초=classic까지) ④ 완주 단위 17/7/15 — 중간 성취 지점 신설 ⑤ 학습자 안내: "T2부터 문법이 새 세대로 바뀐다"는 큰 그림이 로드맵 구조로 전달.
- **비용(실측 기반, 소)**: `_tracks.md` 트랙 1항목 추가 + `CH18～24` 7개 `_chapter.md`의 `track` 키 변경 + 빌드 2종 재생성 + 문서(09 §A 헤더·02) — prev/next는 **전 커리큘럼 평탄화 구현이라 무영향**(shell.js 실측), 로드맵 트랙 렌더·점프 칩·레슨 "Track N" 태그는 제네릭이라 자동. 반나절 미만.
- **리스크(소)**: "Track 2"라는 표현을 쓰는 라이브 문서 몇 곳의 번호 재조정(아카이브 문서는 동결 원칙 그대로 두고 각주만). 학습자 북마크·URL은 영향 없음(레슨 URL은 트랙 무관).

### C안 — 4트랙: CH01～10 / CH11～17 / CH18～24 / CH25～39
- 완주 단위가 더 짧아짐(10/7/7/15). 기초 사슬(01～10)과 화면·데이터 실무(11～17)의 분리는 의존 데이터와도 부합.
- **단점**: CH11～17 묶음의 라벨 정체성이 상대적으로 흐리고("화면과 데이터 실무" 정도), 트랙 4개는 로드맵 점프·서사가 파편화되기 시작하는 수. 편익 대비 라벨 관리 비용 증가.

### (기각) Track-2 추가 분할 — CH25～31 / CH32～39
- 경계 후보는 있으나 CH25+는 상호 독립 도메인이라 "구간 완주" 효익이 낮고, 관통예제 밖 4개 챕터(32·34·35·38)는 **독립 모듈 배지가 이미 구분을 제공**. 분할 비권고.

## 3. 개별 질문 판정

| 질문 | 판정 |
|---|---|
| Track-1(24)이 과대한가 | **그렇다** — 전체 62%가 한 라벨. 자연 경계(CH18)가 이미 존재하므로 분할 실익 있음 |
| Track-1↔2 경계(CH24/25)는 적절한가 | **적절** — CH25는 CH06·08만 의존(기초 회귀 재출발점), CH24 = 입문 트랙의 정점(RAP 맛보기) 서사 유지 |
| Track-2(15)도 분할? | **비권고** — 상호 독립 도메인 + 독립 모듈 배지로 충분 |
| 관통/독립 배지가 학습 안내로 충분한가 | **충분** — 배지는 관통예제 소속 축, 트랙은 학습 구간 축으로 서로 직교. 재편과 무관하게 유지 |

## 4. 권고

**B안(3트랙)** 채택을 권고한다. 순서·번호·URL 불변 + 라벨만 재편이라 비용이 배지 작업과 동급으로 작고, 커리큘럼의 가장 큰 개념 경계(classic→modern)가 구조로 드러난다. 차선 = A안 유지 시 트랙 intro 문구만 보정("기초～Modern 입문까지"로 라벨 정직화).

실행 여부는 사용자 결정 대기. 채택 시 별도 브랜치(`struct/track-3way`)로 1커밋 작업.
